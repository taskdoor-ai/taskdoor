# Minimalist AgentDoor 改造 Technical Assessment / TODO（历史方案）

> 本文包含“取消待办、文件夹替代任务层级”等已被 2026-08-26 决策否定的建议。当前实施请以 [产品定义 V2](./product-v2/README.md) 为准。

> 日期：2026-08-25  
> 状态：待产品确认，待 Reviewer 评审  
> 范围：基于老板提出的“文件统一信息资源、文件夹承载深层业务结构、默认 List、移除自定义视图”方向，对当前前端原型进行改造评估。

## 1. 改造目标

将当前以“任务看板 + 自定义视图 + 阶段工作流 + 独立资源库”为中心的原型，收敛为四个基础概念：

1. **文件夹**：表达项目、阶段、模块、客户等业务结构，支持无限嵌套。
2. **任务**：表达需要推进的事务，必填字段仅为标题、唯一负责人、状态。
3. **文件**：统一承载需要共享和沉淀的信息资源。
4. **List**：文件夹内容和任务工作的唯一默认呈现方式，不提供自定义视图。

核心边界：文件夹表达结构，任务表达责任和状态，文件表达内容。三者在界面中可以出现在同一目录，但数据模型不应合并为同一种实体。

## 2. 当前实现与目标的差距

| 领域 | 当前实现 | 目标状态 | 主要影响 |
| --- | --- | --- | --- |
| 导航 | “任务”“我的待办”“资源”分离 | 以文件夹目录为统一工作空间 | `WorkspaceSidebar.tsx` 需要重构 |
| 默认视图 | 默认任务看板，可切换时间线和 List | 仅保留默认 List | 删除看板、甘特图及自定义视图状态 |
| 业务层级 | 状态分组、资源库分组、阶段链 | 文件夹无限嵌套 | 新增目录节点模型和树形导航 |
| 任务模型 | Owner 为数组，阶段/进度是核心字段 | 唯一负责人；最小必填字段为标题、负责人、状态 | 收紧类型和创建流程 |
| 任务状态 | 待开始、进行中、待审核、已阻塞、已完成、已取消 | 未开始、进行中、已完成、取消、挂起、归档 | 全局状态迁移 |
| 信息资源 | 独立资源库及 `EnterpriseSource` | 统一为目录中的 File | 合并资源入口与文件模型 |
| 子任务/待办 | 阶段生成待办，按关联任务组织 | 业务拆分优先使用文件夹；是否保留个人待办需确认 | `demoTodos`、阶段交接流程需降级 |
| 存储 | Demo 常量 + localStorage 单任务 | 可持久化的目录、任务、文件、讨论、活动模型 | 原型阶段先做统一前端 Store，后续接后端 |

## 3. 产品决策 TODO（P0，编码前确认）

- [ ] **P0-01 明确目录列表展示规则**：进入文件夹后，默认展示“直接子文件夹 + 直接任务 + 直接文件”；“包含下级内容”仅作为临时开关，不保存为视图。
- [ ] **P0-02 明确任务与文件夹的关系**：每个任务只归属一个主文件夹；跨目录使用引用或标签，不复制任务。
- [ ] **P0-03 明确任务是否允许包含文件夹**：建议不允许。任务详情可显示关联文件，但层级只由工作空间文件夹提供，避免重新形成第二棵树。
- [ ] **P0-04 明确个人待办去留**：建议首版取消独立待办实体，“我的任务”改为系统固定筛选（负责人是我且未结束）。
- [ ] **P0-05 明确阶段能力去留**：建议从基础任务模型移除阶段链、阶段负责人、阶段进度和阶段交接；需要阶段时，用主任务文件夹下的阶段文件夹组织任务。
- [ ] **P0-06 明确讨论归属**：建议任务、文件、文件夹均可讨论；讨论不是普通文件，但可以被搜索、引用并由 AI 摘要为文件。
- [ ] **P0-07 明确活动记录归属**：建议作为不可篡改的系统事件流，不实现为普通文件；界面上可在文件夹或任务内统一查看。
- [ ] **P0-08 明确“归档”语义**：建议归档是终态且默认隐藏；恢复后回到归档前状态。取消表示不再执行，挂起表示暂时停止但预期恢复。
- [ ] **P0-09 明确 AI 状态管理权限**：AI 可建议或自动变更状态，但所有变更必须进入活动记录；取消、归档建议保留明确确认。

## 9. 风险与建议

1. **“文件统一一切”容易演变成类型混乱**：建议只统一导航和访问体验，不把任务、讨论、活动在底层强行存成普通文件。
2. **用文件夹替代子任务会丢失父子进度语义**：极简首版可以接受；如后续需要汇总进度，应从目录内任务状态动态计算，不增加手工维护字段。
3. **无限层级会降低可发现性**：必须同时提供面包屑、全局搜索、最近访问和移动操作，且建议对默认展开深度进行限制。
4. **状态由 AI 自动管理存在误判风险**：所有自动变更需有原因、来源和操作者记录；终止类状态保留确认。
5. **当前原型没有真实后端**：本轮可以验证信息架构和交互，但不能据此认定多人并发、文件版本和权限已具备技术闭环。
6. **现有阶段协作代码投入较重**：不要立即物理删除；先从主路径下线并完成新 List 验证，再清理无引用组件，降低回退风险。
