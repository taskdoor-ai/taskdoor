# 团队文件与任务外协作动态

> 状态说明：新增团队文件模块、保留任务内文件层级、支持文件夹与人际 Handoff 清晰已确认；task-scope File 同 ID 发布、团队动态导航、Handoff Manifest 与默认范围是建议默认，见决策台账。

## 一、团队文件模块的定位

团队文件是在团队统一命名空间中、按策略可发现、可组织、可授权、可版本化的信息层。它不是把任务中的文件再复制一份，也不是要求 AgentDoor 替代企业已有网盘。

团队文件模块解决：

- 团队拥有哪些可复用信息。
- 文件放在哪里、由谁维护、当前有效版本是什么。
- 哪些任务正在引用某文件。
- 当前用户和其 Agent 分别可以访问到什么程度。
- 文件发生更新时，哪些任务可能受到影响。

## 二、团队文件与任务文件的关系（发布协议待确认）

```text
团队文件 / 零售业务 / POS / 优惠券规则 v3.2
             ↑ 同一 File ID
任务 A / 文件 / 需求与规则 / 优惠券规则（跟随最新）
任务 B / 文件 / 证据 / 优惠券规则（固定 v3.1）
```

- File / FileVersion 是唯一内容真相；File 当前可以处于 task scope 或 team scope。
- 团队文件夹是已发布 File 的规范组织位置；任务文件夹是面向当前目标的投影视图。
- 任务可以固定版本，也可以跟随最新版本。
- 任务自产文件先以 `scope=task` 的同一个规范 File 存在。发布到团队时默认保持 File ID，原子提升为 `scope=team` 并选择团队文件夹；该动作需要明确确认新的 audience / 权限范围，可能显式扩大团队可发现或可访问范围。
- 只有用户明确选择“衍生副本”才创建新 File ID，并记录 `derivedFromFileId`。衍生后两份文件不承诺自动同步。

## 三、团队文件模块建议界面

### 左侧

- 文件夹树，支持无限嵌套。
- 最近访问、与我共享、Agent 产出、待审核文件等固定入口。

### 主列表

- 文件夹与文件混合 List。
- 名称、类型、维护人、当前版本、更新时间、权限状态、被引用任务数。
- 搜索、类型、维护人和权限筛选。

### 文件详情

- 预览和结构化摘要。
- 版本历史与当前有效版本。
- 维护责任与权限。
- 被哪些任务引用、各自固定哪个版本。
- 与文件相关的标注、决定和动态。
- “添加到任务”入口，但添加前显示将共享的范围。

## 四、文件夹规则

- 文件夹只负责组织文件，不承担任务状态或责任。
- 禁止移动到自身或后代。
- 删除非空文件夹前必须选择迁移、归档或逐项处理。
- 同一 File 在当前 scope 内只有一个规范位置；跨任务和跨视图使用 Placement / 快捷引用，不复制真相。
- 文件夹权限可以继承，但文件允许收紧，不允许无提示放宽。

## 五、人与 Agent 共用的 Handoff Manifest

Handoff 时不克隆完整文件树，也不复制整段聊天。人类接收者和 Agent 都先得到经过权限过滤的最小 File List；Agent 再按任务需要请求正文。[11-human-handoff.md](./11-human-handoff.md) 的 `HandoffContextItem` 是唯一规范 Schema，下面只是接收者可见的 Manifest UI 投影：

```ts
type HandoffManifestProjection = {
  fileId: string;
  title: string;
  purpose: string;
  versionMode: "pin-version" | "follow-latest";
  resolvedVersionId: string;
  contentDigest: string;
  permissionBasisDigest: string;
  receiverAccess: "metadata" | "summary" | "read" | "edit";
  freshness: string;
  retrievalHint?: string;
};
```

- 关键证据、批准依据和交付物默认固定 FileVersion；持续编辑文件可以跟随最新，但激活时记录实际解析版本。
- 发出者可先看“接收者视角预览”，确认对方真正能看到哪些标题、摘要和正文。
- `receiverAccess=hidden` 只存在于发送者预检结果，不进入接收者 Manifest 投影；接收者端不得返回原 `fileId`、标题、来源或数量，只能提示“必要上下文尚未就绪”，避免元数据泄露。
- Handoff 等待期间若关键版本发生实质变化，显示 diff 并使依赖该版本的旧 Consent 失效。
- 私人对话不自动进入 Manifest；需要共享时先形成有来源、受权限控制的摘要对象。

Agent 按任务需要请求正文。系统以 Agent Principal 为实际 actor，并记录其代表的成员，然后再次检查：

- 当前用户权限。
- Agent Connector 权限。
- 任务作用域。
- 文件版本与敏感级别。
- 请求用途。

“用户能读”不自动等于“该 Agent 能读”；同样，“发出者能读”不等于“接收者能读”。实际权限是主体授权、委托、对象/版本策略与 Task scope 的交集；撤销委托或授权后下一次请求立即失效。Handoff 和 TaskFilePlacement 本身不授予权限，发送前和激活前都必须以接收者身份重新检查。

## 六、团队动态模块的定位

团队动态不是按时间排序的所有系统日志。它是任务之外的协作发现空间，帮助团队暴露需求、经验、风险和机会。

建议一级类型：

- 求助：我缺少信息、经验、权限或执行支持。
- 提供帮助：我在某个范围有经验或时间窗口。
- 发现：某任务中出现可能影响其他工作的结论。
- 风险：多个任务存在共同阻塞或文件冲突。
- 机会：可以跨团队共同探索的新方向。

系统变更日志不进入团队动态主流，只在审计或对象活动中查询。

## 七、求助广播生命周期

```text
draft → published → responding → matched → converted/linked → closed
                    ↘ no-response → refine audience / clarify need
```

### 发布前 AI 辅助

- 把模糊问题整理成具体缺口。
- 提取已有信息和缺失信息。
- 检查广播内容是否泄露任务或文件权限。
- 建议合适可见范围。
- 提醒是否已有相似问题、文件或可直接邀请的人。

### 响应方式

- 我可以提供帮助。
- 我知道谁更合适。
- 我有一份相关文件。
- 需要补充信息。
- 关注结果，但不承担责任。

响应不自动成为任务参与者，也不自动获得文件权限。

### 收敛

- 选择响应者后，用户按语义进入私密路径：新工作发协作邀请，接受前不添加参与者、不产生 Responsibility；已有上下文、Todo 或责任接续则直接发出 Handoff Offer，不重复一张普通邀请。
- 需要持续推进时，动态可以创建新任务或关联已有任务。
- 若只需要形成 Todo，必须先指定已有 Task；否则先创建 Task，避免出现无归属待办。
- AI 自动总结有效回答和未决问题。
- 关闭时记录帮助来源并给予可见贡献，但不做排行榜。

## 八、信息噪音与心理安全

企业社交网络能够通过可见沟通提高“谁知道什么”的元知识，但也可能制造噪音、打断和透明压力。

设计约束：

- 广播必须选择作用域，默认不面向全公司。
- 用户可以关注主题而不是关注全部动态。
- AI 合并重复问题，摘要长讨论，提醒仅推给高相关成员。
- 允许私密回应和私密拒绝。
- 不公开谁看过但没有回应，避免制造道德压力。
- 不把响应次数做成绩效榜。
- 敏感问题先推荐定向邀请，不进入公开动态。

研究依据：可见沟通可提高员工对“谁知道什么、谁认识谁”的准确度，并降低后续知识转移摩擦；与此同时，企业社交工具也存在数字中断与透明偏好差异。[Leonardi 2015](https://aisel.aisnet.org/misq/vol39/iss4/3/)、[Leonardi 与 Meyer 2015](https://doi.org/10.1177/0002764214540509)、[企业社交媒体设计研究](https://doi.org/10.25300/misq%2F2023%2F16499)。

## 九、权限检查

发布动态时分别检查：

- 动态文字本身的可见范围。
- 引用任务是否可发现。
- 引用文件元数据是否可见。
- 文件正文是否可读。
- 回复者加入任务后获得什么权限。
- AI 是否可以读取和汇总回复。

当权限不足时，系统应允许发布抽象后的问题，例如隐藏客户名和原文件标题，而不是直接扩大权限。

## 十、Demo 验收

- 可以在团队文件中浏览三层文件夹并打开版本历史。
- 三个权限测试账号分别看到“完全隐藏”“只见安全元数据”“可读正文”，不能仅靠前端按钮隐藏模拟。
- 同一文件在两个任务中分别以跟随最新版和固定版本出现。
- 文件更新后，AI 提醒受影响任务，但不自动替换固定版本。
- 任务自产文件发布到团队后保持原 File ID；显式衍生时才产生新 ID 和血缘。
- 用户从任务创建流程发布求助广播。
- 响应者提供文件或推荐人，但不会自动加入任务。
- 用户选择响应者、确认权限并发出邀请。
- 已有工作交接时，接收者能看到最小 Manifest、复述范围；关键版本变化会阻止旧协议激活。
- 广播最终关联任务并由 AI 形成可追溯摘要。
