# TaskDoor 六类业务 Skill 设计与接入边界

版本：2026-09-08.1。状态：项目内 Skill 与测试工作台加载已接入；生产持续分析和业务写回仍需独立接入。

产品规则以 [PRD](PRD-AgentDoor-协作任务全流程.md) 为源；[设计清单](../../skills/registry.json) 记录入口、输出版本与直接调用依赖。此清单不会自动注册运行时工具。

本版按 PRD 重写六个 SKILL.md：明确触发条件、输入缺失处理、业务步骤、输出、更新失效与场景边界。各入口只保留执行所需正文；五类分析的字段类型、空值和 JSON 示例放入各自 references/output-contract.md，创建规划保留 v0.2 契约。删除正文中的过时实现声明，复杂关系核对留在规划引用文件。

规则快照同时覆盖流程章节和第 7 章，不再只截取一个 Skill 小节。共用读取、更新规则及已批准的常驻助手路径补充单独同步。普通创建按 PRD 3.9 允许未分配，不增加提交门槛；助手直接指派与创建者兜底只作用于该创建路径。EWD 估算明细补齐稳定 ID，与进度核对逐项对应。

测试工作台按清单加载入口、共用文件、引用和依赖 Skill 的完整资料，去重并检查循环；保存版本使用不可变快照。修改工作区不回写旧保存版本或历史运行。

## 调用关系

人员责任分析 → 用户确认后的正式责任版本 → 创建时人员匹配。创建不必先运行责任分析，未经确认的建议也不进入匹配。换人时重新解释现选人的责任覆盖、具体贡献和缺口；不能只是替换姓名。

创建 → EWD 的 estimate 模式；任务状态分析 → 按需引用任务诊断和 EWD 的 progress／trend 模式。同版本已有有效结果就复用，不反复生成。我的工作推荐读取有效诊断事实或从授权原文识别事实，不强制先为每项任务运行完整状态分析；其算分是固定规则，不由诊断自由定分。

## 输入输出与确认

五个新能力共用 [证据与更新契约](../../skills/shared/evidence-and-updates.md)，各入口定义专属 result。字段是接入候选，不冒充现有 API。输入包括身份与团队、来源及版本、读取覆盖、判断时间、实际可用能力；输出含规则版本、未知项和逐项证据。部分资料不可用时返回 partial，而不是推断“没有”。

已有 planner 继续遵守 `agentdoor.task-plan.v0.2` 与原 JSON Schema；不把新包络混进旧协议。新语义中的人天由 EWD 转成已有 `estimate.ewdHours`（人天 × 8）；执行建议复用 `tips`；前置依赖复用 `dependsOnTaskIds`；人员理由复用推荐字段及其 evidenceRefs。不能凭新增产品术语擅自增加旧 Schema 不允许的字段。

责任更新不是自动改职责：先有当前版本的建议，再由用户确认最终文本／操作，最后由业务服务验证权限、版本和幂等并写回。Skill 负责组织流程及解释回执，服务端负责实际写入。没有写能力时仍能完成建议，但必须说明更新待接入。确认责任不等于接受任务，不能联动修改 Owner、参与人或权限。

## 更新触发与失效

| 变化 | 刷新范围 | 不自动改变 |
| --- | --- | --- |
| 本人实际分工、贡献、职责变化或纠正 | 受影响的责任候选；确认后刷新匹配依据 | 未确认的正式责任、任务人员 |
| 需求、目标、标准、范围、人员选择或责任版本 | 受影响计划与人员理由；工作范围变了才重估 | 已完成结果与无关任务 |
| 文件正文、当前确认或标准变化 | 受影响结果项核对、诊断、状态分析和祖先汇总 | 正式任务状态 |
| 期限档位、风险、等待、标签及参与关系变化 | 当前用户推荐排名 | 标签、优先级字段、任务状态 |
| 证据撤销、权限丢失或版本更新 | 失效旧结果并重新核对，不再展示失效依据 | 用户的新修改、历史真实快照 |

持续跟进是业务事件驱动和用户主动触发，不是此文档创建了定时任务，也不是后台训练模型。没有证据变化不制造新分析时间。

验证只覆盖上述产品决策，输出为关键字段摘录；没有完整生产元数据的样例未声称通过生产 JSON Schema。六入口基础校验、10项针对性文档检查、规则快照同步检查通过。同步 PDF 的改动页另作排版检查。

接入顺序：受控读取与版本 → 新能力结构化输出校验 → 人工确认绑定 → 受控责任写回 → 业务变更触发与失效 → 小范围真实场景验证。新能力尚需生产输入／输出 JSON Schema、鉴权及写回实现；离线说明和场景通过不代表线上准确率。

## 规则维护

先编辑 PRD，再运行 `node scripts/sync-agentdoor-skill-rules.mjs`，各 Skill 的 `references/product-rules.md` 自动更新。校验用 `node scripts/sync-agentdoor-skill-rules.mjs --check`。修改判断语义需同时调整入口并升级相关规则版本；旧结果保留原版本。HTML 用现有技术章节同步脚本更新，PDF 从 HTML 导出。
