# TaskDoor 场景验收与自动化流程

测试平台中的团队、人员、任务、文件和讨论是预置测试资料，用于构造可重复的输入条件。模型回复只在点击“开始运行”或使用命令行 `--run` 后获取；预检不会调用模型，也不生成模型通过报告。

## 验证什么

十个行业各有四条流程，共 40 条流程，组织本次新增的 180 个场景。规则依据为当前产品 PRD 和六类 Skill 的输出契约。

| 流程 | 场景数 / 最大调用数 | 验证内容 |
| --- | --- | --- |
| 交付判断与当前风险 `delivery` | 4 / 4 | 文件进展与正式状态、下游版本冲突、真实执行阻塞、当前异常与本人待办 |
| 变更后的多轮回归 `changes` | 4 / 8 | 局部重规划、补证后单项完成、冲突修订后重新诊断、异常解除后重排 |
| 任务规划与责任边界 `responsibility` | 5 / 7 | 新范围、查重复用、实际贡献、临时协助、责任版本更新 |
| 人员权限与工作量 `effort` | 5 / 6 | 执行人员范围、受限资料、三点估算、核对撤销、工作量历史变化 |

## 场景与目标结果示例

| 场景 | 初始条件 / 变化 | 目标结果及判定 |
| --- | --- | --- |
| 制造：新版文件与正式状态分别判断 | 控制单 v2 已提交；正式任务仍进行中；工作量基线 720 分钟 | 自动核对正式状态保持进行中，完成比例约 76.7%；人工核对是否采用有效版本、是否遗漏下游缺口 |
| 制造：补齐输入后的单项解除 | 首轮缺少当前批次的签章 CoC；次轮收到有效输入并完成本项核对 | 次轮正式状态为已完成；人工核对是否仅完成当前项，未宣称整个项目验收 |
| 软件发布：下游版本冲突 | 升级说明仍保留旧结论，签名包已修订 | 自动核对诊断列表包含 `decision_conflict`；人工核对冲突双方及适用版本 |
| 软件发布：异常解除后重新排序 | 首轮异常仍持续，两个工作停等；次轮异常完成、等待方恢复 | 自动核对首轮候选包含异常任务、次轮排除该完成任务；人工核对旧损失及等待信号是否失效 |
| 人员责任：版本改变后旧建议失效 | 先读取原责任，次轮本人更新责任边界 | 自动核对每轮责任版本；人工核对旧建议没有覆盖新责任，临时协助没有变成长期责任 |
| EWD：已知完成量与核对撤销 | 首轮已完成 552/720 分钟；次轮撤销主体内容核对 | 自动核对 progress 模式、首轮完成量 552、次轮整体比例为 null；人工核对仍有效完成量与待确认明细 |
| 人员权限：仅使用可见文件 | 普通成员没有商务底稿读取范围 | 自动预检任务可见性和授权名单，运行输入及引用按人员过滤；人工核对是否推测私密金额或把未知当成没有 |

每个场景可编辑验证目标、初始条件、逐步目标结果、前置检查、自动断言和人工核对项。前置检查面向输入资料；自动断言面向模型输出。目标结果、断言和人工核对清单不发送给模型。

## 页面使用

1. 在“用例库”点击“测试流程”，选择团队和流程。
2. 查看各场景的验证目标，点击名称可打开文件、讨论、每步预期和断言。
3. 点击“检查初始条件”。检查用例启用状态、资料基线、责任版本、步骤输入、可见范围和 Skill 版本；条件不符时不能启动流程。
4. 预检通过后选择模型，检查各场景执行人员和 Skill 版本，再点击“开始运行”。服务端会在入队时重新检查。
5. 队列依次运行；每个用例使用独立团队快照，内部步骤按顺序应用事件并传递前轮输出。每批最多 5 个场景、20 个步骤；错误原文保留，不自动修复或付费重试。
6. “运行报告”显示整个流程的自动结果及逐例详情，可取消本次流程、导出报告和记录人工结论。

流程使用每个场景保存的人员，覆盖不同角色。调整执行人员时可编辑场景及其初始条件；单独运行用例也可以临时切换人员。

## 命令行与 CI

启动项目后，在项目目录执行：

```sh
# 列出流程
npm run lab:workflow -- --list

# 只检查初始资料，默认也是此模式
npm run lab:workflow -- --team lab-manufacturing --flow delivery --check

# 显式执行模型流程
npm run lab:workflow -- --team lab-manufacturing --flow changes --run --model pa/gpt-5.5-pro

# 继续读取已经提交的批次，不创建新运行
npm run lab:workflow -- --batch <批次ID>
```

命令行调用本机测试 API，不读取或打印 API Key。报告默认写到 `data/test-lab/reports/`，可用 `--out` 指定目录。预检报告注明 `modelCalled: false`；真实运行报告为 JSON 与 JUnit XML。

提交前会打印并保存请求 ID。网络中断后，可使用同一 `--request-id` 重试原请求，或用已经取得的 `--batch` 查看报告；不要更换请求 ID 重复提交。默认等待 1200 秒，可用 `--timeout` 调整，最大 3600 秒。客户端等待超时不表示后台已取消。

| 退出码 | 结果 |
| --- | --- |
| 0 | 预检模式：初始条件满足；运行模式：自动检查和所需人工核对都通过 |
| 1 | 预检失败、调用失败、自动断言失败或人工判失败 |
| 2 | 运行仍在等待、被取消或中断、结果未知、尚需人工核对 |

JUnit 将未完成和待人工核对记为 skipped，不将这些结果记为通过。CI 应同时检查退出码。人工通过不能覆盖自动失败；历史输入、首次模型输出和版本快照不被改写。
