# AgentDoor 对话交接摘要模板

这份模板用于让其他 AgentDoor 对话把已经形成的产品结果交给 PRD 维护对话。它只记录结论与证据，不复述讨论过程。

## 可直接复制到其他对话的请求

```text
请为当前对话生成一份《AgentDoor 产品交接摘要》，供另一个对话更新完整 PRD。

要求：
1. 只记录本对话已经确认的产品结论和实际完成的实现，不把讨论过程、被否决方案或你的推测写成现状。
2. 每项内容必须标注状态：已实现、已确认未实现、计划中、已移除、待确认。
3. “已实现”必须附当前代码文件、测试或实际页面截图作为证据；无法提供证据时降级为“待确认”。
4. 明确写出相对旧版新增、修改、移动和删除了什么，尤其注明已经取消的页面、Tab、字段和操作。
5. 页面功能按“展示内容—可用操作—操作步骤与结果”连续描述。
6. 如果涉及界面，请列出页面入口、关键状态和截图路径；真实截图与设计示意必须明确区分。
7. 不要直接修改完整 PRD，只输出下面格式的交接摘要。

请严格使用《AgentDoor 对话交接摘要模板》的结构输出。
```

## 状态使用规则

- `已实现`：当前产品代码中存在，并有代码、测试或实际页面证据。
- `已确认未实现`：产品方向已经确定，但当前代码尚未完成。
- `计划中`：只有候选方向或排期，不能写成当前能力。
- `已移除`：旧版曾存在，当前产品已经取消；正式 PRD 应删除或改写相关描述。
- `待确认`：对话中存在冲突、证据不足或无法判断，不进入正式 PRD。

同一功能同时存在产品决定和实现差异时，应拆成两行分别记录，不用一句话把“目标状态”和“当前状态”混在一起。
