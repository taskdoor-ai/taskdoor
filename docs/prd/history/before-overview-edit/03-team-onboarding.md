# 首次进入与团队建立

## 1. 目的

让完成身份验证的用户明确自己在哪个团队工作，以及以什么角色进入。新用户可以创建团队，也可以通过管理员分享的通用邀请链接或邮箱定向邀请进入已有团队；只有有效成员关系建立后才算团队激活。

## 2. 范围和边界

本模块覆盖首次团队选择、创建团队、通过链接加入团队、团队信息查看与编辑和邀请确认，不定义发送邀请与持续成员管理，链接生成、邮箱邀请和后续成员管理见模块 09。通用邀请链接不绑定指定邮箱，默认以成员身份加入；邮箱定向邀请绑定受邀邮箱和指定角色。首版只有管理员和成员两种角色；“待加入”是邀请状态，不是获得访问权限的第三种角色。加入团队不等于参与某个任务，更不等于接受任务负责人责任。

## 3. 详细功能设计

### 3.1 无团队的进入页

**当前 MVP。** 本地注册验证后，无团队且无邀请的账号直接进入“创建你的团队”，有邀请链接时进入邀请确认。已有团队的设置选择页可进入团队、创建团队或粘贴邀请链接；新用户也可直接打开邀请链接走注册或登录。创建页显示当前邮箱和退出登录入口，不把内部存在的加入步骤误写为所有无团队用户首屏都有的按钮。

**上线目标。** 用户无有效团队不能绕过引导读取受保护工作区；邀请地址由服务端解析并校验，无效输入就地提示，未确认前不建立关系。

![创建团队、通用邀请链接和邮箱定向邀请三条路径汇合到有效成员关系后进入工作区的目标流程](../../assets/team-onboarding/team-entry-flow.svg)

*FIG-TEAM-001 · 目标流程：创建者成为管理员；通用链接经登录确认后以成员加入；邮箱定向邀请还需核对受邀邮箱和指定角色。*

### 3.2 创建团队

**当前 MVP。** 创建页显示团队名称输入和当前创建账号，名称去除首尾空白后为 1–40 字。创建团队后将创建者记为管理员，保存浏览器本地团队目录与会话，进入空工作区，不注入演示任务。任务列表空态提供“新建任务”，成员邀请从设置中的成员入口发起，顶栏提供“连接 AI”指南；入口可实际打开对应界面，但连接指南不是已连接 CLI 的证明。

**上线目标。** 提交时重新校验邮箱已验证、账号有效及输入合法，原子创建团队与创建者的管理员成员关系；创建后的空工作区保持上述可用入口。

创建提交中锁定重复动作，失败保留名称并给重试入口；超时使用原幂等键查询或重试，不能生成同名重复团队。名称只是展示名，后续访问以团队稳定 ID 和成员关系为准。服务端记录创建者、时间和团队创建事件。

### 3.3 通过邀请链接加入团队

用户可以直接打开管理员分享的链接，也可以在“设置你的团队 → 加入团队”中粘贴完整链接并点击“查看邀请”。系统识别当前站点的 `/signup?invite=…`、`/login?invite=…`、`/onboarding?invite=…` 或兼容的团队加入地址；只输入 token、非本站地址或无法解析团队的链接均不进入确认页。

| 链接类型 | 当前约束 | 确认前展示 | 加入结果 |
| --- | --- | --- | --- |
| 通用团队邀请链接 | 从“设置 → 成员”复制，可多人使用；不绑定邮箱；管理员重新生成后旧链接失效 | 团队名称、加入身份“成员” | 已验证账号主动确认后加入团队，不创建邮箱邀请记录。 |
| 邮箱定向邀请链接 | 发给指定邮箱，当前本地原型有效期为 7 天；可指定成员或管理员 | 团队名称、指定角色；邮箱不匹配时提示切换账号 | 仅匹配的已验证邮箱可以确认，成功后把对应待加入记录转为有效成员。 |

**当前 MVP 操作步骤。**

1. 未登录用户打开链接后进入注册或登录，邀请 token 在两种认证方式切换、邮箱验证和返回修改邮箱时继续保留；已有账号可以直接登录。
2. 已登录用户也可以从团队选择页进入“加入团队”，粘贴完整邀请链接并点击“查看邀请”。
3. 系统解析链接并读取本地团队目录或邀请记录；有效时进入确认页，无效、过期、撤销或邮箱不匹配时显示对应原因和恢复动作。
4. 确认页展示团队名称和加入身份（团队成员或团队管理员），当前 MVP 不展示邀请人。用户点击“立即加入”后才建立本地成员关系；已是成员时按钮改为“进入团队”，不重复创建关系。
5. 加入成功后将该团队设为当前团队并进入工作区。返回、关闭页面或切换账号均不等于接受邀请，也不产生任何任务参与或负责人责任。

当前引导页没有“拒绝邀请”按钮；离开页面不等同于已拒绝。通用链接和邮箱定向链接都只在保存了团队数据的同一浏览器中形成完整本地闭环，其他设备无法读取本机团队目录，不能把当前页面成功提示视为生产邀请已经可跨端使用。

**上线目标。** 只有已认证用户进入需要身份核对的确认步骤。邀请信息由服务端查询，确认页以团队名称、加入身份及必要的受邀邮箱、状态和有效期帮助核对，不把当前未展示的邀请人列为已实现字段，不允许用户编辑授权信息。通用链接可配置启用状态与有效期，重新生成后旧 token 立即失效；打开链接不能在确认前泄露成员列表、任务或团队私有资料。

邮箱定向邀请只有在受邀邮箱与当前账号规范化邮箱一致、邀请待加入且团队可用时，才能接受或拒绝。接受时重新检查邀请版本、有效期和接收人，原子将邀请置为已接受、建立有效成员关系，保存当前团队并进入工作区。拒绝时将邀请置为已拒绝并记录处理人和时间，不产生成员关系；已有其他团队可返回该工作区，否则回到创建或粘贴邀请入口。通用链接没有独立的个人拒绝状态，用户取消确认即保持未加入。

团队邀请本身不产生任务责任，不替代任务参与邀请或负责人变更确认。接受与拒绝结果写入团队事件和邀请状态，邀请人可在管理列表看到结果；用户通知按有效权限生成，不公开受邀者其他团队或账号资料。

### 3.4 邀请状态与异常恢复

**当前 MVP。** 本地流程检查无效、过期、撤销、受邀邮箱不匹配与已是成员；没有服务端并发裁决。以下完整状态机与拒绝回执属于**上线目标**：

| 当前状态或条件 | 页面内容与允许动作 | 成功结果或恢复 |
| --- | --- | --- |
| 通用链接有效，账号已验证 | 展示团队名称和成员身份，可确认加入或取消返回 | 确认后建立成员关系；取消不留下待加入记录。 |
| 通用链接已重新生成或停用 | 显示链接不可用，不展示团队私有信息 | 联系管理员获取当前链接；旧链接不能恢复。 |
| 待加入，邮箱一致 | 展示完整确认内容，可接受或拒绝 | 只有一次状态转换生效，重复请求返回原结果。 |
| 受邀邮箱不匹配 | 标明当前账号与受邀邮箱不匹配，禁用接受和拒绝，提供切换账号 | 保留邀请上下文；用受邀邮箱登录后重新读取邀请，不能把邀请改给当前账号。 |
| 已接受 | 展示已处理结果，有有效成员关系时提供进入团队 | 重复接受不重复创建成员关系；若成员关系后来失效，不凭旧邀请重新加入。 |
| 已拒绝 | 展示拒绝结果，不再提供接受 | 需要加入时由管理员重新邀请。 |
| 已撤销 | 展示邀请不可继续使用 | 不建立关系，联系邀请人获取新的邀请。 |
| 已过期 | 显示过期及重新邀请说明 | 不因刷新延长有效期，需新的邀请。 |
| 已是成员 | 核对当前有效关系后提供进入团队 | 不重复建立关系、不覆盖现有角色；待加入邀请在确认接受后记录为已接受。 |
| 无效链接或团队不可用 | 显示无法使用该邀请，提供返回入口 | 不泄露邀请之外的成员、任务或已删除团队详情。 |

首版邀请状态固定为待加入、已接受、已拒绝、已撤销、已过期。页面打开后的过期、撤销或并发处理由提交时检查发现，更新为最新可公开状态并停止原动作；不能保留旧按钮继续接受。被拒绝或撤销的邀请不原地重新激活。

### 3.5 团队信息查看与编辑

**当前 MVP。** 团队资料来自浏览器目录；以下成员鉴权、`team_version`、幂等与审计是**上线目标**，不能用本地保存替代。

团队设置的“团队信息”对当前有效成员展示团队名称、稳定团队标识和允许公开的创建信息；成员列表入口继续指向模块 09，不在本页复制邀请或角色管理。所有读取绑定当前 `activeTeamId`，切换团队后先清空旧投影再加载，不能把旧团队名称当作新团队事实。

只有持有 `team.settings.update` 的 Team admin 可以编辑团队名称；普通成员只读。编辑保存提交 `team_version`、名称补丁、明确操作理由和幂等键，服务端重新校验 Membership 与 TeamRole，成功后返回新版本并写入团队审计。Team admin 权限只覆盖团队基础信息，不授予 Task ACL、File ACL 或 Owner 修改权。

名称为空、超长或与当前值相同时分别阻止、提示或返回 no_change。并发冲突保留用户输入并展示当前名称与版本，重新确认后再保存；失败不提前更新顶栏。加载、空、失败、无权限、窄屏和键盘状态沿用模块 15，关闭编辑后焦点回到原字段。

### 3.6 加载、失败与操作方式

**当前 MVP。** 团队写入浏览器后显示带团队名称的加载过渡，等待工作区模块加载完成才切换页面。目录保存或模块加载失败保留错误与重试入口；重复进入受到防重保护，不以白屏或演示任务填补过渡。

**上线目标。**

读取邀请期间显示正在核对，不能先展示“可加入”再等待权限结果。网络失败保留链接和安全的返回上下文并提供重试；无权限时不展示缓存团队资料。受邀邮箱只用于核对身份，不在公共未认证页面任意暴露邀请详情。

创建和确认页面在移动端按名称、身份、说明、操作的顺序单列展示。键盘可访问全部输入和按钮，切换账号后焦点回到邀请标题；接受或拒绝的反馈可被辅助技术读取，处理过程中不会重复提交。

## 4. 验收标准

当前 MVP 验收：创建团队进入无演示任务的空工作区；通用链接和邮箱定向链接在注册／登录后都进入团队核对页，显示团队名称和加入身份且不展示邀请人；确认前不建立本地成员关系，进入失败可重试。

以下为上线目标验收：

- 已验证用户提交 1–40 字团队名称后，只产生一个团队和一个管理员成员关系，并进入真实空工作区。
- 无团队用户无法读取受保护工作区，可以创建团队或从邀请链接进入；登录、注册和邮箱验证后仍保留待处理邀请上下文。
- 通用团队链接可以直接打开，也可以在团队选择页粘贴；有效链接只展示必要的团队名称和成员身份，用户确认前不建立成员关系。
- 通用链接默认以成员身份加入并可由多人使用；管理员重新生成或停用后旧链接不能继续加入。邮箱定向链接仍按受邀邮箱、指定角色和有效期独立校验。
- 确认页展示团队名称、加入身份及必要的受邀邮箱和状态；邮箱不匹配不能接受或拒绝，可以切换账号继续。
- 接受产生有效成员关系，拒绝不产生关系；两个动作均不改变任何任务负责人或参与关系。
- 过期、撤销、无效和已处理邀请不能再次授予权限；已是成员不会被重复加入或被邀请覆盖现有角色。
- 当前成员可查看团队信息；只有具备 `team.settings.update` 的 Team admin 能以 `team_version` 保存名称变更并生成审计，成员管理仍从模块 09 进入。
- 并发接受与撤销只允许一个有效结果，失败有恢复入口，键盘与移动端可完成创建团队、通用链接加入和邮箱定向邀请三条进入路径。
