# TaskDoor CLI 连接

## 1. 目的

让成员在本地终端及个人 Agent 中读取和操作与 Web 相同的任务，同时清楚知道谁授权、在哪个团队、允许哪些操作，以及如何停止访问。连接成功只表示设备具备明确授权，不意味着 Agent 已经接单、执行工作或完成任务。

## 2. 范围和边界

本模块把当前 MVP 的“连接 AI”与上线目标中的 TaskDoor CLI 分开。当前页面、弹窗、上下文预览和工具打开尝试见 3.0；3.1–3.6 的安装引导、设备授权、设备管理、上下文绑定和调用权限均为上线目标，未形成当前可用的 CLI 闭环。文件、文件版本、讨论与正式 Commit 的具体行为由模块 10、11 定义；删除、影响确认与恢复由模块 13 定义，不能从此处的删除入口绕过。本模块不要求复制长期 Token，不把本地缓存当作独立任务系统。

上线目标中的首版 CLI 支持读取任务、创建根任务和子任务、更新允许字段、获取影响预览和删除任务，并沿共用业务接口执行讨论、文件和提交能力。账号、团队、成员邀请和角色管理仍为 Web-only，不开放万能请求或任意管理工具。

## 3. 详细功能设计

### 3.0 当前 MVP：连接 AI

当前已挂载独立连接页面与全局引导弹窗，提供 ChatGPT、Claude Code、WorkBuddy、Cursor 工具 Tab，展示连接状态和最近连接时间。页面默认记录来自演示数据，不代表真实设备授权、CLI 登录成功或外部工具已接单。任务与讨论使用共享“连接 AI”弹窗，其中同一 ChatGPT 工具标识的展示名为 Codex；快捷按钮可按本地最近使用记录尝试打开工具，该记录也不是设备清单。

任务入口的“带入的信息”只展示当前任务卡片：名称、目标、完成标准、负责人、参与人、截止时间、标签。讨论入口在任务卡片之外，额外展示对应动态及回复、附件，不混入其他动态；草稿入口保留未发送草稿的身份，已删除原文不带入。预览使用自然语言卡片，不展示 JSON。卡片展示与传输快照须区分：当前任务构造器的传输内容还包含状态、发起人、已有执行建议、待接受责任说明，以及调用方明确提供时的直接主任务；它不读取其他讨论、整个文件库或全工作区。我的工作入口只带本人正式负责的任务列表投影，不受左侧筛选影响，不扩展为他人任务或完整详情。

讨论入口的附件只带引用、版本等元数据及讨论中已经引用的摘录，不自动传完整文件正文；需要完整文件时须另行明确选择并校验权限，当前连接入口未实现该流程。

当前普通模式先复制上下文，再通过工具链接尝试打开客户端；复制失败不继续打开，打开失败可手动粘贴，取消不等于连接成功。快捷连接完成尝试后，页面顶部 Toast 只展示本次结果说明和关闭按钮，不提供“查看带入信息”或重新打开上下文的操作；需要核对带入内容时，应在发起连接前使用连接弹窗中的预览。传输包内部仍使用 JSON 包装材料，这不改变自然语言预览规则；预览模式不复制或唤起外部工具。无论工具是否打开，连接本身都不自动写回任务、接受责任或扩大权限，浏览器无法确认工具已启动或完成工作。来源快照与页面权限提示不能充当生产服务端鉴权证明。

证据：`src/components/AiConnectionPage.tsx`、`AiConnectionDialog.tsx`、`AiConnectionButton.tsx`、`src/lib/taskAiConnection.ts`、`personalWorkbenchAiConnection.ts`、`taskDiscussionAi.ts` 及对应连接测试。页面中的安装和操作示例均是拟定语法，未验证可执行；服务端授权、设备管理和真实命令实现仍属上线目标。

### 3.1 上线目标：安装与发起登录

本节所有命令，包括 `npm i -g @taskdoor/cli`、`taskdoor login` 与页面任务操作示例，均为拟定语法，未验证可执行；发布包、参数和安装渠道须经 CLI 实现确认后才能作为正式安装说明。

用户从全局“连接 AI/CLI”弹窗进入安装指南，按操作系统显示经过发布验证的安装命令、版本检查与故障说明。命令可复制，复制成功只反馈已复制；不能标记已安装或已连接。未检测到运行回执时保持待连接，网络或安装失败提示检查条件并重试。文档不把尚未发布的包地址或示例命令冒充可用分发渠道。

正式发布后的目标流程中，用户运行登录命令（拟定语法：`taskdoor login`）。CLI 向服务申请设备授权会话，显示验证地址、短验证码、设备名称、权限请求和有效截止时间，并尝试打开浏览器。浏览器未能自动打开时用户可以手动打开同一验证地址并输入短码，无需复制长期凭据。

### 3.2 上线目标：设备授权与结果反馈

浏览器要求有效的已验证账号。登录后显示当前账号、发起设备、短验证码、待授权团队和权限范围；用户先核对终端与页面短码一致，再选择有有效成员关系的团队并明确允许或拒绝。请求范围逐项说明用途，用户不能授权自己没有的权限，也不能通过确认连接自动加入团队。

短验证码与待授权设备会话绑定，单次、短时有效；有效时长由服务端发布配置，并在两端显示一致的截止时间。重复使用、错误短码、过期或已拒绝会话不能签发凭据；超限显示可重试时间。批准前页面不显示连接成功，拒绝不生成有效设备授权。用户选择拒绝或会话过期后，CLI 停止等待并提示重新运行登录。

用户批准后服务端原子写入授权人、设备主体、团队范围、权限范围与生效时间。CLI 按受控轮询间隔领取设备凭据，凭据只存于本机受保护的凭据存储，不输出到日志、聊天、命令回显或普通配置。浏览器确认完成和终端成功回执分别说明授权及领取结果，只有 CLI 取得有效凭据才显示“已连接”。领取超时查询同一授权结果，不重复建立设备授权；无法恢复时重新发起并让旧会话失效。

Web 退出登录不自动撤销独立设备授权；账号停用、设备撤销或团队成员关系失效会限制后续调用。更改团队或扩大权限必须重新进入明确授权流程，不借已有登录静默扩权。

### 3.3 上线目标：已连接设备与撤销

个人中心中的“已连接设备”读取服务端设备清单，每项显示设备名、首次授权时间、最近使用时间、团队范围、权限范围和当前状态。尚未使用显示“尚未使用”，未知或加载失败不伪装为从未使用；空列表提供连接入口。有效与已撤销设备有明确区分，用户只能查看和撤销自己的设备。

用户选择撤销时确认设备及影响范围，服务端将授权置为已撤销并记录安全审计，页面显示结果。撤销后下一次调用必须失败，包括读取、写入及旧幂等回执重放；CLI 清理失效凭据并引导重新登录。撤销失败保留可核实状态并提供重试，不先显示已撤销。团队成员被移除时，对应团队范围立即失效，设备其他团队的有效范围不能被当作继续访问原团队的理由。

### 3.4 上线目标：绑定任务上下文

用户可通过任务链接或显式任务 ID 绑定上下文。CLI 先只显示当前账号、授权团队和用户输入的任务引用；服务端按用户、设备、团队、对象和操作完成权限校验后，才返回并展示任务标题、内容及允许读取的元数据，并保存绑定。绑定只保存上下文引用，不复制另一份正式任务。用户输入的链接或 ID 不构成权限证明，也不代表服务已确认该对象存在；无权、跨团队、不存在或已删除的目标统一返回不含任务资料的通用结果。

绑定失败不披露目标是否属于其他团队，也不跨团队静默切换。用户可以根据自己掌握的任务信息显式选择有权团队，具备相应授权后重新绑定；无授权先走设备授权。Web 的团队切换也不改变 CLI 绑定。每次命令显示或可查询当前团队与已授权任务范围；上下文被删除、撤权或失效时停止依赖该上下文的操作并清除失效展示，引导重新选择。

### 3.5 上线目标：操作范围、审计与恢复

| 能力 | CLI 允许行为 | 执行边界 |
| --- | --- | --- |
| 读取 | 读取有权任务、上下文、当前版本及回执 | 权限过滤后返回，不通过数量、标题或错误差异泄露隐藏任务。 |
| 创建 | 创建根任务或指定父任务下的子任务 | 使用统一创建规则和幂等键；创建子任务重新检查父任务权限；Owner 为 `0..1`，不默认回填创建者或首位成员。 |
| 更新 | 更新契约允许的普通字段 | 携带资源版本和幂等键；状态、负责人、ACL、正式验收必须用受控命令，不能普通更新。 |
| 删除 | 获取最新影响预览，确认范围后删除 | 绑定当前影响摘要、版本和幂等键；后代范围显式确认，具体规则见模块 13。 |
| 协作与结果 | 讨论、文件版本、提交草稿与正式 Commit | 复用模块 10、11 的确认和权限规则，正式提交不自动完成任务。 |

每次调用按用户、设备、团队、对象和操作重新校验，实际权限取用户权限、设备授权、对象 ACL、任务范围与用途的交集。Agent 操作记录实际 actor 和 on-behalf-of 成员，并关联设备、授权依据、请求与操作回执；用户和 Agent 不能伪造 Activity。无权限响应不包含隐藏对象标题、ID、版本、数量或缓存摘要。

写入成功以正式业务回执为准，Web 与 CLI 返回同一资源 ID 和版本。网络超时先查询原 operation 或使用同一幂等键重试；版本冲突读取仍有权的最新版本，展示差异并重新确认，不能静默覆盖。无变化返回 no_change，不产生虚假活动。撤权后即使携带旧幂等键也重新鉴权，不回显先前敏感结果。

### 3.6 上线目标：交互状态与可访问性

终端明确区分等待授权、用户拒绝、授权过期、网络失败、已连接及凭据失效；等待期间允许取消，取消停止领取并终止待授权会话。连接弹窗关闭不会被当作授权成功，重新打开可查询有效授权状态。授权页面在窄屏单列显示账号、团队、设备及权限，批准前无需横向滚动；键盘可核对范围、切换账号、批准或拒绝。日志和错误反馈均不包含设备凭据或长期 Token。

## 4. 验收标准

当前 MVP 验收：页面与弹窗可切换工具；任务入口显示当前任务卡片，讨论入口额外显示对应线程；自然语言预览不出现 JSON。快捷连接结果 Toast 只包含结果说明和关闭按钮，不出现“查看带入信息”等后续操作。演示连接记录、本地最近使用、复制和打开尝试均不冒充已授权或已执行结果。

以下为上线目标验收，须在正式 CLI 发布后验证：

- 从安装指南运行登录命令（拟定语法：`taskdoor login`）后可自动或手动进入浏览器，核对短验证码、账号、团队与权限范围并完成授权，不要求复制长期 Token。
- 未批准、拒绝、过期或重复使用短码都不能取得凭据；只有 CLI 领取成功才显示已连接，失败可以重新发起。
- 已连接设备完整展示规定字段，撤销后下一次 API 调用失败，旧幂等回执不能绕过撤权读取内容。
- 任务链接和显式 ID 均在服务端完成用户、设备、团队、对象及操作权限校验后才展示任务并保存绑定；无权目标不展示标题、ID、版本或内容，无权、跨团队与不存在目标使用不含任务资料的统一反馈。用户输入引用的原样显示不视为服务返回的任务资料，失败反馈不得确认其对应对象存在；跨团队目标不会静默切换上下文或扩大授权。
- 同一设备可在允许范围读取、创建、更新及预览删除任务，Web 可查看同一结果；普通更新无法修改受控字段。
- 每次 Agent 写入有 actor/on-behalf-of、设备及回执记录，超时重试不重复创建，冲突不覆盖已有变更。
- Web 退出不会误撤销设备，账号停用和成员关系失效会按范围阻止后续调用；键盘、移动端授权及终端取消均有明确结果。
