# 任务列表

## 1. 目的

任务列表是用户查找和进入任务的主要入口。它需要让用户先按自己与任务的关系确定范围，再通过搜索、筛选和排序定位工作，并把需要持续关注的任务固定在当前结果顶部，减少重复搜索。

## 2. 范围和边界

本模块覆盖任务工作区中的任务范围、搜索、筛选、排序、打开任务和个人置顶；服务端连续加载、权限与恢复为上线目标。任务正文、任务内讨论、文件管理以及任务创建和编辑流程由各自模块定义；当前列表不依赖“我的工作”的推荐结果。

## 3. 详细功能设计

### 3.1 页面结构

**当前 MVP。** 页面由“任务”标题与新建按钮、常显搜索框与高级筛选按钮、外部范围／状态快捷筛选与排序控件、置顶区和普通列表组成。在当前团队本地任务集合上依次应用范围、搜索、筛选和排序，再拆为置顶与普通两个互斥分区；同一个任务只出现一次。没有置顶结果时不展示空置顶区。

**上线目标。** 服务端必须先确定完整可读集合再执行相同查询；当前本地投影不证明权限过滤或跨设备同步已实现。

搜索框与筛选按钮等高，桌面 36px、窄屏 44px；新建与筛选按钮大小一致、左右边缘上下对齐。范围和状态在左侧紧凑成组，排序独立靠右，不加分隔线。当前英文页面见本节截图。

### 3.2 关系视图与任务范围

**当前 MVP · 展示内容。** 列表只提供“全部任务”“我负责的”“我参与的”三个任务范围，首次进入及切换团队默认“全部任务”，不默认限制状态。没有独立的未完成／已结束范围开关，流程状态通过状态控件选择。

**当前 MVP · 可用操作。** 用户可在三个范围间切换，保留搜索词及状态、标签、日期条件。“我负责的”按当前用户 ID 匹配正式 `ownerId`，“我参与的”按正式 `participantIds` 匹配；创建人或拟负责人不等于正式负责人。桌面初次没有选择或当前任务不再匹配时自动选中首项；当前任务仍匹配时保持选择，空结果不显示筛选外详情。

**已确认调整。** 按现行交互基线，切换范围后应选择新结果集第一条；其他筛选变化时，当前任务仍在结果中则保持，否则选择第一条，空结果不保留筛选外详情。其他查询与空结果的同步已在主工作区落实；“切换范围即使当前项仍匹配也无条件改选首条”仍未落实，不能把本次入口样式更新视为该行为已完成。

**当前 MVP · 未分配任务。** 正式 Task 的负责人／Owner 基数为 `0..1`。未分配任务可从“全部任务”查找；普通列表没有独立人员筛选或“待确认负责人”分组。负责人空值显示未分配，不把提议人选当作正式负责人。

**上线目标 · 未分配任务找回。** 本人创建的未分配任务（`ownerId = null`）可通过“待确认负责人”恢复入口找回，但不进入正式“我负责的”结果集合，也不进入“我的工作”排序或连接 AI 的负责任务快照。该恢复入口尚未在普通列表外露；服务端读取必须受权限约束。创建者、首位成员、Participant 或待接受人选都不能作为 Owner 回填来源。

### 3.3 搜索、筛选与排序

**当前 MVP · 搜索。** 搜索框常显，前置搜索图标，提示文案为“输入”，无障碍名称为“搜索任务列表”。空输入时隐藏清除叉，有内容才显示；点击叉或按 Escape 只清空关键词，搜索框继续显示，范围与其他条件保持。搜索仅匹配任务名称，去除关键词首尾空白且不区分大小写，不检索目标或全文；输入即更新本地结果并滚回列表顶部。

**当前 MVP · 范围菜单。** 范围移至搜索框外的快捷栏，不在搜索框内嵌胶囊，也不在高级筛选重复出现。范围为单选，三个选项为“全部任务／我负责的／我参与的”；当前快捷栏用范围文字与下拉箭头表示选择。菜单数量表示保留关键词、状态、标签和日期条件后，分别切换至各范围的任务数；个人范围可重叠，不能相加。菜单文字为 13px，数量为同字体 12px、常规字重、辅助色、等宽数字右对齐。选中项与状态菜单统一使用浅蓝圆角底色和蓝色勾选，文字和数量颜色保持不变。

**当前 MVP · 状态与排序。** 状态多选与高级筛选共享条件；无条件时显示“全部状态”，单选显示状态名称，多选显示“N 个状态”；选择全部只清空状态。范围或状态限定时，其入口文字高亮。右侧排序入口保持中性色并显示上下箭头，菜单仅保留“最近更新／最新创建”文字和选中勾选，不重复添加波形或日历图标。按所选时间降序，未知时间置后，同时间按名称再按任务 ID 排列；排序切换保留全部查询条件。

**当前 MVP · 高级筛选。** 面板只保留状态、标签、截止日期、创建日期；支持搜索筛选类型，以及搜索状态和标签选项。每个状态、标签各计一项，未打标签、截止日期和创建日期各计一项；范围、关键词和排序不计入，快捷状态不重复计数。没有条件时不显示数字徽标。日期支持快捷项、未知日期与包含边界的自定义区间；截止日期的“已逾期”不包含已完成或已取消任务。

**当前 MVP · 条件操作。** 分类行展示图标、名称、已选摘要和统一右对齐的展开箭头，不添加分类清除叉。进入分类后的标题行右侧保留“清除”，只清空当前字段。已选条件在弹层底部以紧凑 Chip 展示，每个条件可单独移除；“清除全部”位于同一底部条件区右侧，清空范围、状态、标签与日期，保留搜索关键词和排序。全部条件清除后隐藏底部条件区。弹层随内容收缩，不重复显示结果总数、顶部清除全部或额外关闭叉。

**当前 MVP · 键盘与窄屏。** 菜单沿用方向键、Enter、Escape 与焦点返回；移除条件后焦点转至邻近条件，最后一个条件移除后返回分类入口。窄屏快捷栏可换行，控件满足触控高度；列表与详情沿用返回操作。

**当前 MVP · 组合规则。** 同一维度的多个值按 OR 计算，例如状态为“进行中或已阻塞”；不同维度按 AND 计算，例如“我负责的”并且“标签为合规审核”。日期缺失只在日期不限或选择“日期未知”时命中，未打标签可以和其他标签取并集。

**当前 MVP · 操作步骤与结果。** 用户修改关键词或条件后立即刷新结果并回到列表顶部，保持仍有效的条件。筛选面板只收起时保留条件；清空单项不影响其他项。真正无任务时显示“还没有任务”和“新建任务”，无匹配时显示“没有匹配的任务”与“查看全部任务”；后者同时清空搜索和筛选，保留排序。

#### 标签目录与“管理标签”

**当前 MVP。** 标签分类底部的“管理标签”打开本地目录界面。以下目录版本、服务端权限与审计、查询失败及安全缓存规则属于**上线目标**。

标签筛选分类底部提供二级入口“管理标签”，进入当前 Team 的扁平标签目录。目录支持按名称查询、在明确权限下新增标签、改名和归档；不建立标签组，也不把标签当作任务状态或 Owner。有效成员可查询当前有权使用的活动标签；新增、改名和归档要求服务端 `label.manage` capability，Team admin 仍需该能力，不能仅凭角色跳过授权。

新增和改名提交目录版本、规范名称和幂等键；同名、版本冲突或权限变化时保留输入并展示安全差异。已使用标签不得因目录操作破坏历史，首版优先归档而不是物理删除：归档后不再出现在新选择器中，历史 Task、Activity 和筛选快照仍按原标签 ID 与名称快照可追溯；任务上标签的增加或移除仍属于模块 08 的 Task 更新，不在目录页批量改写。

目录空态说明尚无可用标签并向有权用户提供新增入口；加载失败不显示为空目录，无权限不泄露隐藏名称或数量。窄屏按列表—编辑逐层进入，操作不产生横向滚动；键盘可到达查询、新增、改名、归档和返回筛选，Dialog 关闭后回到原标签行或“管理标签”入口。

查询请求失败时，旧结果仅可在同一 principal、同一团队、同一权限版本和同一查询上下文下暂时保留，并明确标注数据可能已过期；查询上下文包括任务范围、搜索、筛选和排序。每次请求携带不可复用的上下文代次，迟到响应与当前代次不一致时直接丢弃。团队切换、退出登录、成员被移除或授权版本变化时，立即清空任务内容、候选项、数量、置顶集合与游标，展示不含受保护数据的安全空态，再根据新身份重新请求；不能以“加载失败时保留旧结果”为由继续显示旧安全上下文的数据。

### 3.4 任务列表、进入与加载

**当前 MVP · 展示内容。** 每行显示状态、单行任务标题、负责人头像与按需操作；“我负责的”范围省略重复的负责人头像。创建或更新时间不常显，仍用于排序与无障碍描述。长标题提供完整名称，并可在悬停时缓慢滚动读取，移开后恢复。

**当前 MVP · 可用操作。** 点击任务项打开详情；悬停或键盘聚焦任务项时，右侧显示图钉和更多操作，已置顶图钉持续可见。触屏显示可触达的图钉和更多按钮；当前更多菜单提供删除任务。

**当前 MVP · 操作步骤与结果。** 用户打开任务后在同一工作区查看详情，原查询条件保留；修改范围或筛选时的选择同步差异见 3.2。更多菜单靠近当前任务项打开，不另占列表正文。跨路由、分页与服务端更新后的完整恢复是上线目标。

| 展示内容 | 可用操作 | 操作步骤与结果 | 必要说明 |
| --- | --- | --- | --- |
| 完整任务项 | 打开任务 | 点击任务项或按回车进入任务；返回后恢复列表上下文。 | 主点击区域不与右侧快捷操作重叠。 |
| 右侧图钉 | 置顶、取消置顶 | 点击后任务在置顶区和普通任务区之间移动。 | 悬停或键盘聚焦时显示；触屏直接操作图钉。 |
| 右侧更多入口 | 查看其他可用操作 | 打开贴近当前任务项的菜单，执行后就地反馈。 | 菜单内容由任务权限决定。 |

**当前 MVP · 分页或加载。** 当前展示本地投影的全部匹配任务，尚未接入服务端分页或连续加载。

**上线目标 · 分页或加载。** 采用基于游标的连续加载。每次首批请求携带安全上下文和查询条件；服务端先对完整可见集合应用任务范围、查询、筛选和稳定排序，再基于同一查询快照和置顶快照返回两条数据流。置顶区通过独立游标分页，首批响应包含置顶首批和 `pinned_cursor`；普通区返回普通首批和 `regular_cursor`，普通任务游标始终排除同一快照中的置顶任务。两区分别接近底部时加载各自下一页，一个区域失败不清空另一区域。

置顶与普通区沿用所选排序，使用时间降序、名称及 `task_id` 组成稳定排序键；客户端以 `task_id` 做最后一道去重，并忽略旧上下文代次或旧游标的迟到响应。两个游标都记录查询摘要、权限版本、查询快照、置顶快照版本和最后排序键，任何不匹配都返回 cursor_stale，不拼接可能重复或遗漏的数据。重新搜索、筛选或切换范围会取消旧请求并从两区首批结果开始。

### 3.5 置顶区

**当前 MVP。** 置顶按当前用户与团队的键保存在 localStorage，点击后立即在本地分区移动；存储失败时仍保留当前会话内偏好，没有服务端回执或跨设备同步。

**展示内容。** 置顶区位于普通任务之前，只显示当前关系视图、任务范围、搜索和筛选结果中已置顶的任务。区标题为“置顶”；置顶任务仍按当前排序规则排列，不再出现在普通任务区。切换条件不会删除个人置顶偏好，只会决定它是否出现在当前结果。置顶与普通任务同时有结果时，两组之间显示 1px 浅色实线，上下各留 8px，左右与列表内容对齐；仅有一组或结果为空时不显示分隔线，不额外增加“其他任务”标题。

**可用操作。** 用户悬停或用键盘聚焦任务项时，可点击右侧图钉置顶或取消置顶。已置顶状态使用实心或高亮图钉，并提供可被辅助技术读取的状态名称。

**上线目标 · 操作步骤与结果。** 服务端置顶回执及 `anchor_cursor` 尚未实现。接入后点击图钉可以先显示待确认状态，但不能把当前页的乐观移动当成最终位置。回执返回新的查询／置顶快照版本、目标分区、稳定排序位置和锚点游标。置顶时锚点指向新置顶快照中包含该任务的置顶页；取消置顶时锚点指向排除置顶后的新普通快照中包含该任务的普通页。

任何置顶变化都会让置顶区游标和普通区游标同时失效。客户端停止旧请求、清空两区旧游标，以新快照重新拉取两区首批，并用 `anchor_cursor` 额外获取目标分区中包含该任务的页；响应后以 `task_id` 定位任务、滚动到稳定排序位置并恢复焦点。置顶任务即使不在置顶首批、取消置顶任务即使不在普通首批，也不能只拉首批后丢失定位。锚点页与首批发生重叠时仍以 `task_id` 合并，避免重复。

如果任务因并发状态、权限或当前筛选变化而不再可见，回执不返回可用锚点，只返回不泄露隐藏内容的 `visibility_reason`。客户端将焦点转到明确的状态提示，说明任务不再可见的原因及可执行动作，例如清除筛选或返回列表顶部；不能把焦点留在已移除节点，也不能为了定位绕过当前查询或权限。

请求失败时任务恢复原位置、原状态和原置顶快照，并提示用户重试。置顶是用户个人偏好，不改变任务本身，也不影响其他用户看到的列表。

## 4. 验收标准

当前 MVP 验收：

- 默认全部任务，可切换我负责的或我参与的；范围与状态、标签、日期及名称搜索同时生效。
- 搜索常显、提示为“输入”，空输入无叉，有内容才显示；Escape 或清除只清空关键词，不收起输入框。
- 范围与状态在外部快捷栏左侧分组，排序独立靠右；范围与状态选中项浅蓝底、蓝色勾选。
- 范围菜单数量随其他条件更新，13px 选项文字配 12px 常规辅助数字；排序菜单只有文字与勾选，外部入口保留上下箭头。
- 输入框与筛选按钮等高，新建与筛选按钮左右边缘上下对齐；窄屏控件高度满足 44px。
- 高级筛选无重复范围入口，分类无清除叉、箭头右对齐；范围和关键词不计入条件数，状态仅计一次。
- 已选条件可在面板内逐项移除，收起后筛选按钮显示准确数量；清除全部保留关键词和排序，查看全部任务同时清空关键词与条件。
- 置顶按用户和团队本地保存，分区不重复，悬停、键盘和触屏都可操作；任务行不常显时间。

已确认调整验收：切换范围应无条件选中首项；当前实现仅在无选择或原任务不匹配时选择首项，仍匹配时保持原选择，此差异待落实。其他查询变化保持仍有效的选择、空结果不保留筛选外详情已按主工作区实现。

以下为上线目标验收：

- 搜索、筛选和排序后，置顶区与普通任务区共同构成完整结果，且不存在重复任务。
- “全部任务”“我负责的”“我参与的”结合状态条件只返回符合关系、状态及读取权限的任务；待接受提议不冒充正式责任。
- 同维度多选按 OR、不同维度按 AND 组合；默认“最近更新”排序在连续加载前对全部结果生效。
- 置顶区与普通区使用同一查询／置顶快照和各自的独立游标分页；普通任务游标始终排除置顶任务，两区稳定排序并以 `task_id` 去重，翻页与迟到响应不会造成重复或遗漏。
- 置顶或取消置顶后两区游标同时失效；回执通过 `anchor_cursor` 定位包含该任务的新分区页面，即使目标不在首批也能恢复焦点。
- 任务并发变化后不再符合筛选或权限时，不强行定位；焦点进入说明原因和下一步的状态提示。
- 查询失败只在同一 principal、团队、权限版本及查询上下文保留旧结果；团队切换、退出登录、成员移除或授权版本变化立即清空受保护内容并进入安全空态。
- 用户能从有权任务集合及未来“待确认负责人”恢复入口找回未分配任务，不会把它们计入“我的工作”。
- 标签筛选的“管理标签”可以查询、新增、改名和归档扁平标签；已使用标签归档后保留历史引用，目录操作不会批量改写任务标签。
- 没有置顶结果时不显示空置顶区；出现首个置顶结果后，该区域位于普通任务区上方。
- 鼠标、键盘和触屏用户都能访问打开任务、置顶、取消置顶和更多操作。
- 置顶或取消置顶成功后，任务立即移动到正确分区；失败后恢复原状态并提供可理解的反馈。
- 连续加载失败不会清空已加载任务，列表底部提供可执行的重试入口。
- 从任务页面返回列表时，团队、关系视图、任务范围、搜索、筛选、排序、已加载页、折叠状态和滚动位置保持不变。
