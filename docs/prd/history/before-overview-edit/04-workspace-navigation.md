# 工作区与全局导航

## 1. 目的

让用户进入工作区后能够确认当前团队、找到要推进的任务，并从通知或个人入口安全地继续工作。导航只组织入口与查看上下文，不通过增加看板、统计或独立 AI 页面制造新的工作对象。

## 2. 范围和边界

覆盖团队恢复与切换、全局入口、任务与我的工作之间的导航、通知来源跳转及跨设备布局。任务查询细节见模块 06，通知业务语义见模块 10；个人信息查看与编辑见模块 02，团队信息查看与编辑见模块 03，成员管理见模块 09，退出／离开团队与账号停用见模块 14。本轮目标布局以此处为准；历史原型中仅改变界面的团队切换不能证明已完成真实权限隔离。

## 3. 详细功能设计

### 3.1 最小工作区布局

**当前 MVP。** 顶部左侧为当前团队及切换团队，右侧依次为通知、连接 AI、账户头像。账户菜单提供主题切换、“设置”和“退出登录”；设置进入个人中心。“连接 AI”打开连接指南，不表示设备已获真实授权。通知使用当前本地／演示状态，服务端未读与权限过滤尚未核验。

**当前 MVP。** 默认进入任务工作区，左侧为任务列表、新建、范围、搜索与筛选，右侧为当前任务或空状态。代码仍保留“我的工作”内容组件，但当前任务索引没有独立“我的工作”入口，不将旧工作台默认入口写成现状。

**上线目标。** 全局入口保持当前团队上下文，通知只展示经过权限过滤的真实状态，未知不显示零；设备授权详见模块 05。下文涉及我的工作的聚合与返回、服务端团队恢复和责任文档版本均为目标合同，不能由保留的组件证明用户可用。

### 3.2 恢复与切换团队

**当前 MVP。** 顶栏团队菜单列出本地账号可用团队、名称及角色，选择后切换本地工作范围；当前菜单没有创建／加入团队按钮。首次进入由模块 03 的引导承接，服务端成员状态与跨团队权限尚未实现或核验。

**上线目标。**

登录后先读取账号的有效成员关系，再恢复上次有效团队。上次团队已失效时展示其他可进入团队供选择；没有有效团队回到模块 03。查询中显示加载状态，加载失败提供重试，不能因为请求失败就判断用户没有团队。

“切换团队”菜单只列用户有有效成员关系的团队并显示当前选择。选择后重新校验关系并加载目标团队数据；存在未保存修改时先让用户保存或明确放弃。成功后更新当前团队与最近访问记录，任务、通知均切换到对应范围；旧团队的延迟响应不得覆盖新团队。失败保留原有效团队，并显示目标团队进入失败及恢复动作。

团队切换仅改变 Web 工作范围，不静默修改 CLI 已绑定上下文或自动扩大设备授权。被移除或团队失效时立即关闭对应内容与写入入口，重新选择有效团队；不能等到下次登录才收回可见数据。

### 3.3 任务与我的工作

**当前 MVP。** 任务列表可查找、创建并打开当前团队本地任务；进入创建页不清空原搜索、筛选与选择。首次创建团队后没有演示任务，列表空态有“新建任务”，设置中的成员管理可邀请成员，顶栏有连接 AI 指南。无匹配结果时可“查看全部任务”恢复查询。

**上线目标。**

任务入口支撑查找、打开和创建任务，读取当前团队内有权数据；我的工作聚合本人已生效的责任和可处理事项，不能把待接受邀请当作已经负责。进入任务后保留任务 ID、来源和返回位置；从我的工作进入原任务详情后，返回恢复原查看上下文。左侧搜索、筛选和滚动位置按团队分别保存，不跨团队复用任务内容。

空工作区沿用任务创建、成员邀请和连接 AI 的现有入口；邀请动作按角色权限提供给可邀请者，其他成员可以查看邀请说明并联系管理员，不显示可执行但必然失败的按钮。任务空状态区分“团队还没有可见任务”和“没有符合条件的任务”，分别提供创建入口或调整查询。我的工作若恢复可用入口，空态应显示暂无本人待处理工作，不伪造负载、统计或推荐事项。

### 3.4 通知与个人中心

**当前 MVP。** 通知入口打开抽屉，账户菜单中的“设置”进入个人中心；成员、资料和通知的数据处理仍以本地状态为主。以下跨团队来源跳转、服务端鉴权及设备撤销属于**上线目标**。

通知入口打开紧凑通知列表，显示可公开的来源、摘要、发生时间与已读状态。没有通知时展示“暂无通知”；加载失败保留可验证数据并提供重试，过期或撤权内容不继续使用旧摘要。点击通知保留来源对象和返回位置，重新鉴权后跳到任务、讨论或邀请确认处。读取通知只改变已读状态，不自动接受邀请、转移责任或完成任务。

来源不存在、已删除或无权访问时显示无法打开的通用反馈，并提供返回工作区；无权时不泄露对象名称、ID 或删除细节。若通知属于另一有效团队，明确显示将进入的团队并在用户选择后切换，保留原通知来源；无成员关系不尝试自动加入。

个人中心展示当前账号及设置入口。设置左侧按“个人设置：个人信息、我的责任”和“团队设置：团队信息、成员”分组；“我的责任”虽然位于个人设置，仍是 Team-bound 数据。团队设置中，管理员可看到并执行允许的团队资料和成员管理动作；成员只看到允许读取的团队资料及自己的离开入口。菜单隐藏不是权限实现，直接访问和请求仍需服务端鉴权。设备撤销、离开团队及退出登录跳转对应模块流程。

### 3.5 我的责任

以下责任文档权限、版本和审计为**上线目标**；当前本地页面的编辑与 AI 建议展示不能证明这些服务端能力已上线。

“我的责任”标题右侧提供紧凑 Team Select，与工作区 `activeTeamId` 使用同一真相；标题、清单和写入目标必须指向同一 Team。切换前如有未保存责任草稿，用户需先保存或明确放弃；成功切换后清除旧建议和正文投影，失败保留原团队。页面不创建第二套团队状态。

每个 Team 维护一份 `responsibility_document`。页面使用全宽单列，一行一条展示责任；本人和当前团队管理员均可查看、人工新增、编辑和删除，其他成员不得借入口读取。人工保存携带文档 `revisionId`、最终文本、字段位置和幂等键；服务端按 D-26 的本人／团队管理员能力重新鉴权，原子更新文档与审计。删除只移除当前责任条目，不改写历史版本或相关 Task 事实。

AI 新增或更新只形成带具体依据的只读 `responsibility_proposal`，默认不展开、不写入。新增提议位于列表末尾，用户点击唯一“添加责任”加号后才加入正文；已有条目的更新提议通过行尾 Sparkles“AI 建议”展开，显示只读替换文本、依据、“更新”和“忽略”，用户明确选择后才写入或关闭提议。提议不能修改自身文本，人工改写走独立编辑；忽略不修改正文。

更新提议携带基准 `revisionId`、目标位置和目标原文快照。版本改变但同位置原文完全一致时可安全重绑定；目标原文已变化时进入冲突，禁止追加或覆盖，并提示重新核对。写入记录操作类型、更新前后文本、结果版本、依据和处理人；AI 不自动添加、更新或删除责任。

责任说明与 AI 提议都不改变 Task Owner、Participant、ACL、成员关系或历史责任，也不生成评分、效率画像或排名。空态说明当前团队尚无责任并提供有权新增入口；加载中不展示旧团队内容；失败保留草稿；无权限不泄露正文或建议数量。窄屏仍为单列，Team Select 和操作允许换行；键盘可展开建议、添加、更新、忽略和编辑，折叠内容不进入焦点顺序。

### 3.6 布局与中断恢复

**当前 MVP。** 桌面列表与详情分栏，窄屏逐层进入。首次进入显示工作区加载过渡，模块加载失败有重试入口；具体任务选择和筛选规则见模块 06。以下权限恢复与跨设备一致性为**上线目标**。

桌面采用主从两栏，列表与详情可独立滚动。窄屏采用单面板逐层进入，顶部保持当前团队与必要全局操作，从详情返回列表或我的工作时恢复来源位置。连接弹窗、通知和菜单使用可访问名称，键盘焦点按可见顺序移动；弹窗打开管理焦点、关闭后回到触发入口，返回详情后定位原任务项。

首次加载使用骨架或明确加载提示，查询失败可重试且不丢失搜索条件。刷新时根据当前权限恢复有效路径；任务失效、账号停用或成员关系被移除立即收口显示和操作。切换前未保存输入可在仍有权限的范围安全保留，跨账号或撤权后不能继续显示原内容。

## 4. 验收标准

当前 MVP 验收：默认进入任务；顶栏提供团队切换、通知、连接 AI 和账户菜单；设置与退出可用；新团队为空且可创建首个任务。不能把保留的“我的工作”组件、设备页或本地身份记为已上线入口与授权。

以下为上线目标验收：

- 顶部可以确认和切换团队、连接 AI/CLI、打开通知及个人中心，任务与我的工作复用同一工作区。
- 登录只恢复有效团队；成员关系查询失败不会误判无团队，无团队用户回到团队建立流程。
- 切换团队后所有可见数据和写入范围一致改变，旧响应不能覆盖新页面，CLI 上下文不会被静默切换。
- 首次空工作区沿用任务创建、成员邀请与连接 AI 入口；任务和通知各自有真实空状态，加载失败不显示为零或空。
- 通知跳转保持来源并重新鉴权，无权或来源不存在时可返回工作区；阅读通知不改变来源业务状态。
- 成员只能看到允许的团队资料，管理员管理动作受服务端权限约束；权限失效时界面与操作即时收口。
- “我的责任”位于个人设置但保持 Team-bound；Team Select 与 `activeTeamId` 同一真相，切换前保护未保存草稿。
- 责任一行一条，允许本人和团队管理员人工新增、编辑、删除；AI 新增／更新提议只读且只有明确添加、更新或忽略后才改变提议或正文。
- 旧更新提议通过 `revisionId` 与目标原文快照防止覆盖；责任正文及提议不会改变 Task Owner、Participant 或 ACL，也不形成评分画像。
- 桌面主从与窄屏单面板均可往返，列表条件和返回焦点可恢复，键盘可访问全部全局入口。
