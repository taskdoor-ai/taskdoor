# AgentDoor PRD 编写与维护说明

本目录用于持续维护 AgentDoor 的目标产品需求。Markdown 是唯一内容源；HTML 和模块索引均由构建脚本生成，不在生成文件中直接修改内容。

## 内容结构

每个功能模块只固定四个一级内容区块：目的、范围和边界、详细功能设计、验收标准。详细功能设计不强制套用更多固定章节，应按页面和页面内模块连续说明以下信息：

- 模块展示什么；
- 用户可以执行哪些操作；
- 每项操作的步骤和结果；
- 只有确有必要时，补充排序、分组、分页、状态、异常或权限规则。

同一功能的展示、操作和结果应写在一起，避免让读者跳转到文档其他位置寻找对应步骤。

## 图片规范

图片放在对应功能说明附近，存入 `assets/<module-id>/`。每张图必须包含清楚的替代文本、稳定图号和一句能独立说明图片用途的图注。图号格式为 `FIG-<模块缩写>-<三位序号>`，例如 `FIG-LIST-001`。

## 变更机制

语义需求变更必须在同一个 Pull Request 中同步更新：

1. 对应模块 Markdown；
2. 受影响的图片或示意图；
3. `CHANGELOG.md` 中的变更记录。

语义需求变更包括功能范围、交互、规则、状态、权限或验收标准变化。错别字、措辞润色和纯样式调整无需写入变更日志，由 Git 历史保留即可。

## 文件约定

- `index.md`：PRD 标题、说明和模块顺序。
- `modules/`：按模块拆分的需求正文。
- `templates/module-template.md`：新模块起稿模板。
- `assets/`：与模块正文一起维护的图片。
- `CHANGELOG.md`：语义需求变更日志。
- `public/prd/`：自动生成的完整 HTML PRD 和 AI 模块索引。
