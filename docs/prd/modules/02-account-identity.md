# 账号与身份

## 1. 目的

让用户进入自己的团队，并在无法登录时恢复访问。

## 2. 范围和边界

覆盖邮箱注册、Google 登录、邮箱密码登录、密码恢复和资料维护。已确认目标：新增 Google 登录；邮箱验证码在注册时收取，校验正确后才创建账号。以下为本轮流程设计，尚未接入真实认证服务。

当前本地演示仍为先填写资料、再进入验证码页；代码在验证码步骤才写入账号，但接受任意六位数字，没有真实邮件和验证码校验。登录与注册页现已展示 Google 双语入口；点击提示暂不可用，尚无真实授权跳转、身份校验或账号创建。旧认证截图已撤出，待重新采集。

认证页沿用语言偏好，默认英文；登录后可在账户菜单切换。

## 3. 详细功能设计

### 3.1 登录页

标题“欢迎回来”。顶部为“使用 Google 继续 / Continue with Google”，分隔线“或使用邮箱”，下面是邮箱、密码、“登录”、忘记密码及注册入口。Google 和邮箱表单共享登录成功后的团队去向。认证页不增加语言入口。

### 3.2 邮箱注册：在同一张表单完成验证

标题“创建你的账号”。顶部复用 Google 按钮，下面按顺序展示姓名、邮箱、邮箱验证码、密码；验证码输入框旁放“发送验证码”。主按钮为“验证并创建账号 / Verify and create account”，底部保留“已有账号？登录”。不再点击“创建账号”后跳到独立验证页。

填写邮箱 → 发送验证码 → 在当前表单填写六位验证码及其他资料 → 点击“验证并创建账号” → 校验成功并创建账号 → 自动登录 → 继续团队流程。

发送验证码仅要求邮箱格式正确，不要求先填写姓名或密码；发送成功后显示目标邮箱和重发倒计时。沿用六位数字、十分钟有效、三十秒后可重发的规则。验证码与邮箱、注册用途及本次请求绑定，重发后旧码失效；修改邮箱清空验证码和原验证状态，要求重新发送。姓名、密码及验证码全部填写后才可提交，输入满六位不自动创建账号。

服务端在同一次提交中校验资料、验证码、有效期及邮箱是否已注册，通过后一次性创建账号并消费验证码。发送邮件、填写验证码或前端格式校验都不创建账号，也不创建未验证账号、团队或成员关系。验证码错误、过期、超出尝试限制或用户放弃时，账号数保持不变。重试与重复点击不得创建重复账号；结果未知时确认原提交结果再继续。

### 3.3 Google 入口

登录、注册页均使用同一个“使用 Google 继续”入口。页面说明首次使用将创建 TaskDoor 账号。用户选择 Google 账号 → 服务端验证返回身份 → 已绑定账号直接登录；首次使用且无账号冲突时创建账号并登录。

本轮设计建议：Google 已验证身份成功后不再要求设置 TaskDoor 密码或重复收邮箱验证码；未取得可信的已验证邮箱时，不创建账号，提示改用邮箱注册。只获取登录所需基本身份信息。姓名可使用返回值，缺失时在创建前补填。

同邮箱已有邮箱密码账号时，不静默合并、不新建重复账号；提示先用原方式登录，验证原账号后由用户确认绑定 Google。取消、拒绝或验证失败返回原认证页并保留邀请上下文，不创建账号。Google 身份验证不能代替团队访问权限检查。

### 3.4 认证成功后的去向

有邀请 → 核对受邀团队、身份及邮箱 → 用户确认加入；无邀请且已有有效团队 → 返回工作区；无团队 → 创建或加入团队。邮箱和 Google 使用相同规则。定向邀请邮箱不符时提供切换账号，不能直接加入。注册、Google 跳转及登录切换均保留原邀请。

### 3.5 失败、恢复与输入体验

发送中显示“正在发送”，提交中显示“正在验证并创建账号”，禁用重复操作。发送失败不伪装成已发送；验证码错误或过期就地提示，保留姓名、邮箱和密码并允许重发。频率或尝试限制由服务端执行，明确可重试时间；具体阈值在接入时配置。已注册邮箱引导登录或找回密码。

刷新或验证码过期后可以重新发码，不恢复“已验证”的假状态；不把明文密码写入持久化存储。移动端保持单列，验证码支持整段粘贴和系统自动填充；键盘可依次访问所有字段与按钮，错误提示关联字段并将焦点移至首个错误。忘记密码仍通过独立恢复流程设置新密码，成功后返回登录；此流程不能创建账号。

### 3.6 个人资料与数据依赖

设置中修改头像、姓名和联系信息；退出登录仅结束会话。页面依赖注册验证码请求与校验、Google 身份验证及绑定、账号唯一性、会话和有效团队／邀请数据。真实邮件投递与 Google 回调需在实施阶段接通；当前 Mock 不能作为上线验收证据。



## 4. 验收标准

- 登录、注册页均展示 Google 入口；邮箱注册在一张表单完成收码与提交，不再后置跳转验证。
- 发码后、错误码、过期码、旧邮箱码、旧重发码及超限提交均不新增账号；有效码提交只创建一个已验证账号，重复请求不重复创建。
- Google 取消、无效返回或未取得可信已验证邮箱均不创建账号；有效的新身份创建一次，已绑定身份登录原账号，同邮箱冲突必须验证原账号后确认绑定。
- 两种认证路径均保留邀请；邮箱不符或邀请失效不能加入，认证成功也不能跳过团队权限检查。
- 发送失败、提交失败与结果未知可恢复；错误就地提示并保留合理输入，移动端、键盘与验证码粘贴可完成流程。
- 未验证时无会话、团队或成员关系；退出不删除团队任务。以上需真实服务验收，任意六位数字的本地演示不算验证通过。
