# 任务创建

## 1. 目的

把用户的需求整理为目标明确、可分工的任务方案，经用户确认后创建。

## 2. 范围和边界

- **对话创建**：支持需求补问、已有任务识别、任务拆解、人员推荐与方案编辑，最多四层任务。

## 3. 详细功能设计

### 3.1 整体流程

![任务创建流程：分析任务、生成目标与计划、推荐成员、动态规划，再由用户审阅并确认创建。](../assets/task-creation/task-creation-flow.svg)

*FIG-CREATE-001 · 四个规划步骤构成主路径；需求澄清、已有任务关系和单／多任务判断在对应步骤内处理。*

### 3.2 分步处理

| 规划步骤 | 系统处理 | 用户操作与结果 |
| --- | --- | --- |
| **1. 分析任务** | 提取目标、交付内容与限制。信息不足时补问；发现疑似重复任务或可能的父任务时，展示候选及原因。 | 补充关键信息；对候选任务选择查看已有任务、继续独立规划或作为子任务继续。没有对应分支时直接进入下一步。 |
| **2. 目标与计划** | 判断生成单任务还是主任务与子任务，并为每个任务生成目标、完成标准、关系、依赖、日期和预计投入。 | 审阅任务结构；包含可独立交付或分工的工作时按需拆解，整条路径不超过四层。 |
| **3. 成员推荐** | 按每个任务的目标、完成标准与所需工作匹配团队成员责任域，推荐负责人和参与者。 | 调整人选；未匹配时保持未分配，也可邀请团队外人员。详细规则见[成员、邀请与任务分工](09-member-collaboration.md)。 |
| **4. 动态规划** | 整理前置依赖与日期依据，标出需要用户核对的安排，汇总完整任务方案。 | 核对依赖、日期和投入；通过对话调整方案，重新生成前确认替换范围。 |

**审阅与创建**

四个规划步骤完成后进入方案审阅。用户可编辑任务结构、字段与人员；确认后，系统校验权限、层级、人员和日期，并统一创建整份方案。创建失败时保留当前方案，修正后重试。

**常见场景**

| 输入情形 | 处理方式 |
| --- | --- |
| “整理本次会议纪要” | 直接生成单任务。 |
| “做一次活动”但目标、交付不清 | 补问活动目的与交付内容后规划。 |
| 项目包含商务、内容、发布等工作 | 拆为主任务与多个可分工的子任务。 |
| 内容制作还包含脚本、具体交付项 | 继续拆解，整条路径不超过四层。 |
| 已有任务可能覆盖同一交付 | 提示疑似重复，由用户选择查看已有任务或继续新建，不自动合并。 |
| 需求可能属于已有项目 | 用户确认父任务后，作为其子任务规划。 |
| 没有匹配负责人 | 保持未分配，允许人工选择或邀请，不阻止创建。 |

### 3.3 生成的任务结构

方案包含一个或多个任务及其关系。**每个任务都有自己的目标与完成标准**，子任务不能只沿用主任务的描述。

| 内容 | 说明与编辑规则 |
| --- | --- |
| **任务名称** | 简短说明要做什么，可编辑。 |
| **目标（目的）** | 说明为什么做、希望达成什么结果，可编辑。 |
| **任务完成标准** | 有序列出可核对的交付或结果，支持新增、修改、删除和排序。 |
| **人员** | 一名负责人及多名参与者；负责人可为空，最终以用户选择为准。 |
| **子任务与归属** | 展示父子结构；挂在已有任务下时显示父任务路径，可在审阅时调整。 |
| **前置依赖** | 表达哪些工作需先完成；与父子归属分别设置，没有依赖时留空。 |
| **截止日期** | 可填写或留空；不得早于创建日，按团队时区判断。 |
| **预计投入** | 末级任务可编辑；父级汇总有效叶子、不重复累计中间层，未知不按零处理。口径见[任务进度与完成](12-task-progress-completion.md)。 |

### 3.4 规则与限制

- **人员生效**：创建者默认加入每个新任务的参与者；本人已为负责人则不重复显示。审阅时可移除自己，之后不自动加回。团队内人员随任务保存生效；团队外人员按团队邀请处理，接受前不视为正式任务成员。
- **最多四层**：根任务为第 1 层，每个任务最多一个同团队父任务，禁止自归属和循环。挂到已有父任务下时按绝对深度计算；第 4 层不能新增子任务，超限须调整后提交。历史超限数据不截断、不继续加深；四层只限制深度，不以案例任务数作为总量上限。
- **方案保留**：仅在当前对话内保留；切换方案步骤不丢失，退出对话、切换团队、刷新或关闭后不恢复。主动离开提示“未创建的方案将丢失”，取消离开则保留。
- **统一提交**：全部任务、关系与人员选择一起成功或失败，不留下半套任务或创建通知。同次重试不重复创建，已提交成功的任务不因退出而丢失。
- **独立邀请**：用户显式发出的团队邀请不因方案退出或创建失败撤回，也不因此提前创建任务。

### 3.5 异常处理

| 情况 | 系统响应与下一步 |
| --- | --- |
| 输入为空 | 提示填写需求，不开始规划。 |
| 正在规划或提交 | 显示处理中，避免重复发起同一次操作。 |
| AI 规划或重新生成失败 | 保留原输入与已有方案，可在当前对话重试。 |
| 人员、父任务或权限发生变化 | 提交时重新校验，定位需调整的项；保留方案，不提交部分任务。 |
| 层级或日期不合法 | 标记问题任务，用户修正后再提交；不静默删减或改写。 |
| 提交结果未知 | 先查询同一次操作的结果，再决定是否重试。 |

移动端与键盘操作均能完成补问、关系选择、方案编辑和确认，不依赖悬停才能看到关键操作。

## 4. 功能验收标准

- 信息明确时直接生成方案；缺失关键信息时先补问，回答反映在目标与完成标准中。
- 疑似重复与父任务候选均须用户选择；查看已有任务不会产生新任务，确认父任务后显示正确归属。
- 单任务、复杂拆解与多层方案均可审阅；每个任务具有自己的目标、完成标准与人员选择。
- 四层方案可创建；第五层、循环或跨团队父子关系拒绝整份提交，定位问题并保留方案。
- 未选负责人仍可创建，创建者默认能在“我参与”找到任务；选择本人负责时不重复列为参与者。
- 对话方案确认前不产生任务；退出后重新进入为空白对话，已确认成功的任务不受影响。
- 多任务方案任一项写入失败时，全部任务和关系均未创建；同次重试成功只创建一份。
