# 权限、异常与质量要求

## 1. 目的

让主要流程可靠、可恢复，并尊重用户的数据权限。

## 2. 范围和边界

- 本期采用团队身份与任务关系决定能力，不提供独立的任务 ACL 配置或**负责人**接手审批。
- 团队管理身份继续用于成员与团队设置，不在邀请表单分配。
- 管理员身份不自动获得任务删除权。

## 3. 详细功能设计

### 3.1 统一术语

| 术语 | 定义 |
| --- | --- |
| 任务完成标准 | 用户为任务定义的达成条件，逐条排列 |
| AI 标准评估 | AI 对单条任务完成标准的达成情况与依据的分析 |
| 人工确认 | 用户确认／撤销某条标准的达成，独立于 AI |
| 任务整体进度 | 依据标准对应工作量综合形成的阶段评估，不是确认条数比例 |
| 任务状态 | 用户选择的待开始、进行中、已阻塞、已完成、已取消 |
| 功能验收标准 | PRD 中供研发和测试判定软件行为是否符合要求的条件 |
| 团队邀请／待加入 | 邀请指定邮箱加入团队；不是邀请接受任务责任 |
| 任务成员 | 当前负责人和参与者；待加入团队的人不算正式任务成员 |
| 待确认方案 | 当前创建对话中的临时任务方案，退出后不恢复，确认成功才成为任务 |

### 3.2 默认权限

| 操作 | 负责人 | 参与者 | 其他团队成员 |
| --- | --- | --- | --- |
| 查看任务正文、讨论、文件 | 可以 | 可以 | 不可以；加入任务后取得访问权 |
| 编辑目标、标准、人员、日期、标签及依赖 | 可以 | 可以 | 不可以 |
| 修改状态、人工确认／撤销标准、触发 AI 分析 | 可以 | 可以 | 不可以 |
| 创建子任务、发布讨论、维护任务文件 | 可以 | 可以 | 不可以 |
| 编辑／删除讨论发言 | 仅自己的 | 仅自己的 | 不可以 |
| 删除当前任务及后代 | 可以，须二次确认 | 不可以 | 不可以，包括团队管理员 |
| 修改／删除只读活动或正式提交 | 不可以 | 不可以 | 不可以 |

#### 权限边界

- 团队有效成员可创建新任务。
- 团队邀请、成员移除和团队设置沿用管理员管理权限。
- 任何接口均校验当前账号及团队身份。
- 跨团队人员不能通过列表、搜索、文件、**通知**或 CLI 读取任务。
- 任务成员关系赋予表中能力，不另行配置 ACL。
- 失去关系后清除该任务缓存与访问。
- 没有成员的任务仅保留记录和空关系，本期不补充责任恢复或管理员代删流程。

待加入选择的落实归模块 09，删除分支权限归模块 13。CLI 代表实际用户执行同样能力，不能绕过上述限制，也不额外要求一套 Agent 专属审批。

### 3.3 最新写入与失败恢复

#### 并发保存

- 普通可编辑字段使用服务端最后成功保存的值。
- 提交只包含本次修改字段。
- 不同字段的并发修改都保留，同一字段后保存者覆盖先保存者。
- 不弹出通用冲突合并流程。
- 文件保存仍新增不可变版本，**人工确认**绑定标准版本，不能用旧确认覆盖已改标准。

#### 提交校验

- 服务端先检查操作时的成员资格、任务存在、层级及删除范围等业务条件。
- “最新覆盖”不复活已删除任务、不突破**四层**限制，也不跳过二次删除确认。
- 确认后范围变化需重新核对。
- **只读** AI 旧结果不属于人工字段覆盖规则。

#### 重试与失败

- **同一次操作**重试只执行一次，超时先查原结果。
- 整份任务方案创建、分支删除及其必要关系变化各自完整成功或完整**失败**。
- 活动与**通知**不能在业务失败时显示成功。
- 保存**失败**保留当前页面输入，创建对话退出后不恢复未确认方案。

### 3.4 基本使用与交付验证

- 加载、空结果、**失败**和无权限分别表达。
- 重要操作不能只靠悬停或颜色，键盘与窄屏能完成主要流程。
- 服务器响应已受理时不冒充全部完成。
- 查看任务、保存、状态变更及删除至少覆盖两个成员与 Web／CLI 的交叉操作。

## 4. 功能验收标准

- 同一任务中参与者可编辑与改状态，但不能删除整项任务；负责人可二次确认删除分支，非任务成员不能读取任务正文。
- A 改标题、B 改截止日期，两项都保留；A、B 改同一标题，以服务端后保存的值为准；文件历史版本不被抹掉。
- 撤权后的请求被拒绝，旧页面不能覆盖或复活已删除任务；同次重试不重复任务、文件版本或通知。
- Web 与 CLI 对同一用户允许和拒绝的动作一致；键盘与窄屏可完成确认、取消、保存和错误重试。
