# 成员、邀请与任务分工

## 1. 目的

让合适的人加入团队，并明确各自的任务责任。

## 2. 范围和边界

- 支持邮箱定向团队邀请；团队设置、任务创建和任务详情均可发起，受邀者通过专属邀请链接注册或登录后确认加入。
- 邀请先建立团队成员关系；任务**负责人**和参与者按 3.2 的任务人员规则生效，不增加独立的任务邀请接受或接手审批。
- 团队管理权限与任务**负责人**身份分开，具体权限归模块 15。

## 3. 详细功能设计

### 3.1 邀请加入团队

- 团队设置、任务创建和任务详情使用同一邀请表单：填写邮箱、选填名称，选择**成员／管理员**，默认成员。
- **所有有效团队成员均可邀请或重新邀请普通成员**；仅拥有者可邀请或重新邀请管理员，不能通过邀请授予拥有者身份。按当前账号在目标团队的有效成员身份校验权限，待加入或已失去成员资格的人不能发起邀请。受邀者接受后按邀请角色加入，团队角色不代替任务负责人或参与者身份。
- 人员选择允许暂不分配时，在其说明中提供独立的**立即邀请**操作；选择暂不分配与发出邀请分别处理，邀请操作不清空已有人员选择。不提供暂不分配时，邀请说明仍独立可达；搜索无匹配时可用已输入的名称或邮箱继续邀请。
- 邀请状态使用待加入、已加入、已拒绝、已撤销、已过期。
- 界面上的“待接受”仅指团队邀请。
- 有效邀请默认保留 **7 天**，服务端返回到期时间。
- 受邀邮箱经登录或注册验证并确认后成为团队成员。

#### 人数上限

- 每个团队最多 **50 人**，拥有者、管理员、成员和有效的待接受邀请共同占用名额。
- 已加入成员离开或被移除后释放名额；邀请被撤销、拒绝或过期后释放名额。
- 同一邮箱重复邀请不重复占位，接受有效邀请不额外占位。
- 达到上限保留邀请入口，提示人数限制并阻止新增邀请；团队设置与任务内邀请使用同一规则。
- 提交邀请和接受邀请时再次校验，不能因并发操作超过上限。

#### 重复邀请与失效

同一团队、同一邮箱只保留一份有效邀请；已是成员直接选择，不重复邀请。重新发送成功后旧链接失效，失败不撤销仍有效的旧邀请；拒绝、撤销或过期不能加入。重复接受返回原加入结果，不重复建立成员关系。

### 3.2 加入任务与维护人员

- 从团队有效成员中选择**负责人**或参与者，保存后直接生效，不要求对方再次接受。
- **负责人**至多一人，可未分配。
- 有任务人员维护权限时可直接移除当前负责人，不填写原因。保存成功后显示未分配，活动记录操作者、时间及前后负责人；保存失败保留原负责人并反馈失败，不显示成功或生成成功活动。清空负责人不扩大任务编辑、完成或删除权限。
- **负责人**不在参与者列表重复出现。
- 存在参与人时，任务详情保留头像摘要，并可展开**全部参与人名单**，逐人查看完整姓名。没有收起的头像时也可展开，名单总人数与当前参与关系一致；新增参与人继续通过人员选择操作完成。
- 有人员维护权限时，可从头像或完整名单行尾的小叉移除同一参与人，两处使用相同的保存与活动记录规则。名单行尾操作在桌面悬停或键盘聚焦时显示，触屏常显；只读用户仍可查看完整名单，但不显示移除入口。
- 允许移除最后一名参与人，移除后保留新增入口并将焦点返回该入口；移除其他参与人时保持名单可继续操作。有限定最少人数的人员选择仍遵守该下限，不因名单操作绕过限制。
- **创建者**的默认参与规则见[任务创建](07-task-creation.md)。
- 日常人员通过普通编辑维护；发布讨论时可通过 @ 自动加入同团队有效成员，不需要对方再次接受，也不额外限制发送者的团队角色，具体发布规则归[讨论与提及](10-discussion-notifications-activity.md#31-讨论与引用)。删除已发布消息不自动移除因此加入的参与者。离开或移除成员时按[成员退出](14-membership-account-exit.md)统一交接，不增加接手审批。

#### 待加入人员

- 从任务创建或详情邀请团队外人员时，记录其受邀邮箱及待加入的任务位置，不冒充正式成员或提前授予任务访问。
- 团队邀请接受后，若任务已创建、该选择仍有效且发起者仍有维护权限，则自动落实原**参与者**选择。
- **负责人**位置仅在仍未分配时生效，不覆盖期间已选的其他负责人。
- 选择已删除、任务已删除或发起者失权时，不再自动加入任务。

#### 邀请与任务创建顺序

邀请先被接受而任务尚未创建时，当前方案显示该人为团队成员，仍须确认方案才建立任务关系；方案已丢弃则只加入团队。加入团队本身不自动加入所有任务，只落实上述明确保存的选择。

### 3.3 按责任域推荐人员

根据任务目标、任务完成标准及所需工作，对照当前团队成员已填写或确认的责任域推荐负责人和参与者。人员选择列表保留推荐排序，不显示匹配度、推荐等级标识或匹配原因浮层；用户可搜索并自行选择。

#### 推荐限制

- 推荐不代表能力、绩效、可用时间或本人已同意。
- 不按在线时长或任务数量推断。
- 责任信息缺失时不编造匹配依据，允许人工选择或未分配。
- AI 推荐本身不保存人员关系。
- 只有用户确认后的责任更新才用于后续推荐，方案中的最终选择由用户决定。



## 4. 功能验收标准

- 普通成员、管理员和拥有者均可从团队成员页与任务内入口邀请或重新邀请普通成员；仅拥有者可选择管理员角色或重新发送管理员邀请。待加入、已退出或被移除者不能邀请，资料显示邮箱与成员邮箱不同不能替代实际身份判断。错邮箱、失效链接均不能加入。
- 立即邀请不触发暂不分配、不清空已有选择；邀请失败保留输入和原人员关系，取消邀请返回原人员选择上下文。
- 选择有效成员并保存后直接进入任务，不出现任务待接受／接手按钮；通过讨论 @ 加入时同样立即生效，不覆盖当前负责人或重复建立参与关系。
- 存在参与人时，无论数量是否超过头像摘要上限均可展开完整名单；头像与名单两处移除结果一致，只读不显示移除操作。移除最后一人后可继续新增，人数下限、键盘和触屏操作均保持可用。
- 移除负责人不出现原因字段或原因必填校验，保存成功及刷新后保持未分配；失败仍显示原负责人且可重试，无权限操作被拒绝，活动可追溯实际成功变更。
- 待加入人员在接受团队邀请前不能读取任务；加入后只落实仍有效的选择，已被占用的负责人位置不被覆盖。
- 人员列表保留基于责任域的推荐顺序，不显示匹配标识或原因浮层；责任信息不足时允许未分配，推荐结果不自动写入任务。

- **成员数量**：49 人时可邀请 1 人，第 51 个名额被拒绝；过期邀请释放名额，接受有效邀请不重复计数。
