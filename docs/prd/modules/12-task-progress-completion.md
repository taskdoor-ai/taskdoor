# 任务进度与完成

## 1. 目的

帮助用户判断还差什么，并由人确认结果是否达成。

## 2. 范围和边界

提供逐条 AI 标准评估、任务整体阶段进度、人工确认及辅助建议。历史耗时推荐另行规划。不提供强制完成核对或审批流程。

## 3. 详细功能设计

### 3.1 三类事实分别保存

| 内容 | 含义 | 更新方式 |
| --- | --- | --- |
| **AI 标准评估** | 每条完成标准的达成程度 | AI 根据相关内容分析。 |
| **人工确认** | 用户是否认可该条达成 | 用户确认或撤销。 |
| **任务状态** | 用户选择的任务阶段 | 用户自主设置。 |

三者分别保存。确认条数不等于工作量比例，“已完成”状态不将 AI 进度改为满值。

#### 任务整体进度

- 整体进度综合任务完成标准对应的工作明细及投入权重：内部按“各项预计投入 × 该项内容完成度”汇总完成量，再除以总预计投入。
- 界面使用四段进度条和阶段名称，**不显示精确百分比**。内部进度 `p` 按下表映射。
- **未知**单独显示，不进入 0 档。

| 内部进度 `p` | 界面阶段 |
| --- | --- |
| 0% ≤ `p` < 25% | 少量完成 |
| 25% ≤ `p` < 50% | 部分完成 |
| 50% ≤ `p` < 75% | 大部分完成 |
| 75% ≤ `p` ≤ 100% | 接近完成 |
| 无法评估 | 未知 |

AI 分析展开后展示整体阶段、**燃起图**、当前情况和下一步建议。燃起图按日期呈现总工作量、已完成工作量和 AI 预测，并标出计划完成日期与预测完成日期；没有有效历史数据时不生成预测曲线。

#### 单条完成标准

- 每条完成标准按与该条相关的任务内容和依据独立评估，使用与整体进度相同的四段区间。
- 标准前的四段圆环呈现 AI 判断；悬停或键盘聚焦后显示当前阶段和人工确认操作。
- 负责人和参与者可确认该标准已达成；确认后显示实心勾并更新已确认数量，再次操作可撤销。
- **AI 标准评估**与**人工确认**分别保存。人工确认不把 AI 阶段改为满值，AI 重新分析也不自动确认或撤销。

#### 工作量与范围

- 工作明细从任务完成标准反推，同一工作支撑多条标准也只计算一次，不将标准条数平均分权。
- 父任务按有效叶子去重汇总工作量，并用父任务标准核对覆盖范围。
- 父级尚有未被叶子覆盖的工作时标明待评估，不把叶子全完成当作父任务全达成。
- 缺少必要投入、依据或范围不匹配时，保留可核对的已知量，整体判断为**未知**，不用缺失项补零。

#### 评估限制

文件数量、讨论条数、时间经过和状态变化都不能直接推算完成量。历史与预测分别保存，范围变化只产生新快照，不改写过去的分析。人天为预计投入，不是实际工时。

### 3.2 重新分析触发条件

以下事件在保存成功后触发；同一批或短时间连续修改合并处理，仅分析受影响任务及必要的祖先任务。

| 变化 | 分析范围 |
| --- | --- |
| 正式任务创建成功 | 建立初始评估；没有完成依据时保持未知 |
| 目标修改 | 重新核对全部标准、范围及整体进度 |
| 标准新增／修改／删除 | 更新受影响标准与整体进度；仅调整顺序不重算 |
| 文件新增／新版本／删除或引用变化 | 更新引用该内容的标准、现状与整体进度 |
| 讨论新增／编辑／删除 | 更新现状和建议；影响完成依据时重算相关标准 |
| 人工确认／撤销 | 即时保存确认事实，再更新相关分析；不直接复制成人工或 AI 的另一种结论 |
| 子任务新增／删除或相关成果、进度变化 | 更新自身及受影响祖先；不重算整个团队 |
| 人员、截止日期、依赖变化 | 更新分工、时间判断与建议；不直接改内容完成量 |
| 用户主动重新分析 | 按当前任务最新资料重新分析 |
| 打开页面、切换 Tab、置顶、读通知、AI 结果自身更新 | 不产生新的分析循环 |

#### 任务状态的影响

- 单纯修改**任务状态**只更新状态展示。
- 不以状态证明内容完成。
- 已完成任务有上述内容变化仍触发分析，可能出现“已完成但有新增差距”的建议，系统不自动重开。
- 已**取消**或已完成任务保留历史和内容评估，不自动生成执行中的未来预测曲线。

### 3.3 结果与失败

- 每次结果保存输入版本、分析时间及可定位依据。
- 旧内容发生相关变化时标为**待更新**。
- 用户仍可编辑任务或设置状态，不等待 AI。
- 执行期间又有新修改，旧结果不能覆盖新内容对应的结果。
- 任务已删除或当前用户失权时停止展示相关结果。

#### 失败处理

- **失败**保留仍有权查看的旧分析，标明未更新并提供重试。
- 首次失败显示**未知**，不显示零。
- AI 只写评估与建议，不改目标、标准、人工确认、已确认估算、人员或**任务状态**。
- 需要调整任务时由用户在对应编辑入口保存。

### 3.4 状态与完成

- 状态操作归[任务详情](08-task-detail.md)。
- 全条**人工确认**、AI 接近完成、文件提交及子任务完成均不自动完成父任务。
- 用户可自行设为已完成。
- 内容后续修改不改变状态，**人工确认**失效规则只作用于被修改的标准。

### 3.5 个人工作安排

按本人负责／参与的任务建议关注顺序，并基于实际承担的工作给出责任补充建议；建议不自动调整任务状态或人员，责任更新经本人确认后才用于后续推荐。优先建议不改变现有列表筛选和用户选择。

## 4. 功能验收标准

- 确认 2/3 条标准不直接显示为整体完成 2/3；AI 阶段、人工数量、任务状态分别保留。
- 整体进度和单条标准均按 0%–<25%、25%–<50%、50%–<75%、75%–100% 映射四个阶段；无法评估时显示未知。
- 单条标准可查看 AI 阶段、确认达成并撤销；确认与撤销不改写该条 AI 评估。
- 整体 AI 分析可查看四段阶段、燃起图、当前情况和下一步；没有有效历史数据时不绘制预测曲线。
- 已完成任务新增一条标准后，状态仍已完成，新标准未确认且自动进入待分析；分析失败也不改变状态。
- 文件 v2 保存触发相关分析；v1 分析晚返回不得覆盖 v2 结果；未修改内容的页面刷新不重算。
- 只改截止日期不改历史完成量；权限撤销后旧依据不可继续展示，未知不冒充零。
- 同一工作对应多条标准或多个中间层时不重复累计；没有覆盖全部范围时不宣称整体已达成。
