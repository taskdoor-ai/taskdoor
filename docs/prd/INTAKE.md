# AgentDoor PRD 交接与提取流程

其他对话使用 [`templates/conversation-handoff-template.md`](templates/conversation-handoff-template.md) 输出交接摘要。原始摘要保存到 `docs/prd/intake/`，文件名使用 `YYYY-MM-DD-主题.md`。原始摘要是来源材料，不是正式需求。

## 提取顺序

1. **登记来源**：记录来源对话、日期、产品版本和代码基线；缺少基线的内容标为待确认。
2. **核对当前实现**：在摘要指定的工作区读取页面入口、组件、状态逻辑和相关测试。主工作区未提交改动不会自动出现在其他 worktree，必须单独核对。
3. **判断内容状态**：将内容分为已实现、已确认未实现、计划中、已移除和待确认。只有前两类可以进入目标 PRD，且必须明确当前实现差异。
4. **更新来源映射**：在 `source-map.md` 中登记决定来源、实现证据和取舍，不能只引用摘要而跳过代码证据。
5. **更新模块正文**：按“目的—范围和边界—详细功能设计—验收标准”修改相关模块；展示、操作、步骤和结果连续书写。
6. **更新图片**：优先从当前运行代码获取真实截图；无法直接触发的状态可以按当前组件生成状态示意，但必须在图注中标明，不能冒充已实现页面。
7. **登记语义变更**：在 `CHANGELOG.md` 中说明新增、修改、移动或删除的内容及影响。
8. **构建与核验**：重新生成 HTML 和 AI 索引，检查链接、截图、模块元数据以及首页阅读顺序。
9. **发布版本快照**：只有明确发布时才将当前内容固化为 MVP、1.0 或 2.0 的只读快照；普通编辑不得覆盖历史版本。

## 冲突处理

当摘要、代码、截图和旧文档互相冲突时，不做静默合并：

- 当前代码与实际页面决定“现在已经实现什么”；
- 用户明确确认的决定说明“目标应该是什么”；
- 旧 PRD、旧截图和旧组件只作为历史来源；
- 无法确认的内容进入待确认清单，不写成正式产品事实。

例如，任务详情当前实现为：子任务位于任务基础信息区域，右侧协作区保留讨论、文件和活动，诊断已经移除。旧版“五个协作 Tab”描述应作为已移除内容处理，不能继续进入当前 MVP 文档。
