# 四款产品的统一需求判定说明

本轮矩阵更新：Skilly、Observal 已列在 iFlytek 后方；Observal 八项需求采用同一判定口径，依据见 [Observal 核查](observal-assessment.md)。安装函数检查与整套服务运行核验分别记录；五款产品的最新 Star 见 [矩阵快照](matrix-community-snapshot.json)。

候选范围补充：以企业内部 Skill 管理为前提，iFlytek 与 Skilly 为直接同类产品；Observal 的独立 Skill 管理部分保留为相关综合平台候选。ClawHub 与单独安装工具不列入主要备选，见[候选范围复核](candidate-scope-review.md)。原有功能结果保留，不把资料筛选视为完整运行核验。

日期：2026-09-14。对应[技术选型报告](../2026-09-14-internal-skillhub-selection-report.html)。本说明依据已保留的固定版本源码和运行记录，统一评估口径，不增加新的产品运行测试结论。

## 统一口径

- **满足**：所需产品能力已经存在，使用现有功能或常规配置即可完成。网页确认、选择支持的归档格式、配置权限组等属于现成功能的使用方式。不能将需要编写身份适配或同步程序的对应需求归入此类。
- **二开可满足**：已有相关业务流程或接口，但仍需编写适配代码、补充功能或修复已定位的问题。该状态是技术可行性判断，不能当作改造已经完成。需要改代码的对应需求均不标为“满足”，不因产品不同而例外。
- **不满足**：缺少需求依赖的核心机制，或现有分发方式直接违背业务要求，需要另建基础能力或改变方案。并非断言项目永远无法改造，而是不能只凭“开源代码可以修改”就认定具有现成可复用方案。

同一要求不因产品不同而改变：SSO 按接入明道云评价，已有通用 SSO 不等于已有明道云接入。员工免注册在身份接入完成后评价：若现有登录即可自动建号和赋予默认成员权限，判为满足；若还需开发账户来源同步或自动启用处理，判为二开可满足。组织同步按明道云人员变动能否更新成员、权限和停用状态评价，不要求原样复制完整组织树。完整技能包以所需文档、脚本和素材能否交付为依据，不要求所有发布渠道和文件系统特性都相同。不同需求可依赖同一项适配，不能将重复出现的依赖重复估算为不同开发任务。

所有“满足”仍是产品选型判断；真实明道云租户、公司网络和公司实际技能任务尚未验收。原始记录中的“当前不满足”保留对原版缺陷的描述，主报告进一步区分其中可在现有流程上二开的项目。

## kms9/skillhub

- **明道云 SSO：二开可满足。** 已有 IdentityProvider 扩展及外部身份登录，但需要增加明道云适配。与 iFlytek、Skilly 使用相同口径。
- **员工免注册：二开可满足。** 外部身份首次登录已有自动建号及默认用户角色，但初始状态仅对指定来源自动启用，其他来源进入待审核状态。明道云员工直接可用还需补自动启用与准入处理，原版没有已核实的明道云配置开关。
- **内部隔离：二开可满足。** 已有账户、会话与凭据解析。需要将读取、搜索、文件和下载纳入员工鉴权，并补账户停用校验。当前公开读取和停用校验缺失的事实保持不变。本项是全公司内部内容保护，不据此认定已有部门隔离。
- **完整分发：二开可满足。** 已有上传、文件存储和打包下载流程；上传端筛选与后端类型白名单明确阻止图片、字体和样式。可在这些已定位环节补素材支持，不能将原版记为已通过完整素材分发。
- **版本管理：二开可满足。** 已有版本、负责人和更新回退，需要增加发布审批，并修复发布响应类型不兼容。审批为新增工作，未运行或验证任何改造后的审批流程。
- **CLI 自动授权：二开可满足。** 浏览器授权与本机回调已有实现，参数位置不一致已复现，正向对照已通过；这里明确评价修复可行性，原版自动授权仍失败。
- **部门权限与同步：不满足。** 没有现成部门权限及同步机制；即使补齐全平台读取鉴权，也还需另建部门授权与同步。

依据：[固定源码与原始核验](kms9-notes.md)、[CLI 与发布结果](kms9-cli-results.json)、[自动授权故障与正向对照](kms9-browser-auth-results.json)。

## Skilly

- **明道云 SSO：二开可满足。** 已有 Entra 登录，需增加明道云 Provider、映射身份字段并调整登录回调。不能因支持某种 SSO 就将明道云接入标为满足。
- **员工免注册：二开可满足。** 已有组织同步建号，员工不必自行注册，但登录回调只更新已有用户。接入明道云后，还需连接明道云用户来源并预先同步账户，不能只更换登录 Provider 就宣称员工免注册直接可用。此适配与组织同步项共享，不重复计工作量。
- **明道云部门同步：二开可满足。** 已有 SCIM 用户创建/更新、用户组创建、成员关系增删及停用处理，权限从成员关系与角色映射计算，可将部门映射为用户组。明道云仍需开发数据源适配。现成同步基础是相对 iFlytek 的优势，但不表示所有 SCIM 操作、完整组织树或明道云连接器已实现。
- **内部隔离、完整分发及版本管理：满足。** 根据原有授权、归档和版本验证。需要脚本直接执行权限时选 TGZ，视作使用已有发布方式，而不是核心分发能力缺失。
- **CLI 自动授权：二开可满足。** 现有网页身份和技能安装凭据可复用，但产品没有自有 CLI；需要新增登录及安装衔接工具，不能将网页生成命令或其他协议的授权流程当成原生安装工具自动登录。

依据：[固定源码与原始核验](skilly-notes.md)、[SCIM 接口](https://github.com/scalefocus/skilly/blob/225eeeb6f076c8f726a2e47f2c7b389b9e49b400/packages/worker/src/scim/router.ts)、[组织成员存储与停用处理](https://github.com/scalefocus/skilly/blob/225eeeb6f076c8f726a2e47f2c7b389b9e49b400/packages/worker/src/scim/store.ts)、[安装命令与凭据交接](https://github.com/scalefocus/skilly/blob/225eeeb6f076c8f726a2e47f2c7b389b9e49b400/packages/shared/src/external-tool.ts)。

## Agent Registry 开源版

- **完整分发：满足实际文件交付需求。** 普通文档、图片、字体和脚本的字节、目录和权限已有实测。素材必须以实际文件纳入源包；符号链接不会自动复制，维护者需预先将其引用的文件打包。素材交付能力不抵消客户端下载仍依赖源 Git 的问题，免 VPN 单独判为不满足。
- **版本管理：二开可满足。** 已有版本标记和固定版本获取，可补恢复旧版时的文件清理及发布审批。审批还依赖员工身份与权限体系，不能认为只改回退逻辑就满足整项需求。
- **身份、免注册、内部隔离、CLI 自动授权及部门同步：不满足。** 开源版缺少现成的员工登录与访问控制基础。保留接口不等于已有完整身份流程，商业版能力不纳入。

依据：[固定源码与原始核验](agent-registry-notes.md)、[原始测试日志](agent-registry-test-results.txt)。

## 推荐结论

iFlytek 与 Skilly 都具备完整分发、内部权限和版本管理，明道云接入均需要二开。iFlytek 已有通用身份绑定和首次登录建号，接入身份源后无需另建账户预置流程；Skilly 的登录依赖预先同步的用户，优势是已有人员、用户组和停用同步基础。当前以员工免注册和技能分发为核心、部门同步按需扩展，因此倾向 iFlytek；若组织同步是首要要求，或维护团队以 TypeScript 为主，则优先考虑 Skilly。不能据此声称 iFlytek 全面更强或实际总开发成本更低，团队能力和真实接入工作量尚未确认。

iFlytek 的明道云 SSO、CLI 自动授权及部门同步均为“二开可满足”；员工免注册为“满足”，仅表示身份接入后可直接复用现成的自动建号与默认成员权限，不表示明道云已接入。完整分发、访问隔离及版本管理沿用已有运行和源码依据。Skilly 的账户来源适配与部门同步适配可能复用，同样不将两行状态作为两份独立开发成本。

kms9 的若干缺口可在现有流程上开发或修复，但涉及多个主要使用环节；Agent Registry 的源 Git 依赖及员工身份基础缺失仍与本次需求不匹配。不采用满足项简单计数或未经依据的打分代替选型判断。
