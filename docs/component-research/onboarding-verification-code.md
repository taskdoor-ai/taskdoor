# 登录验证码输入与视觉细节

日期：2026-09-08

本文记录第一轮验证码组件优化。后续按用户要求改为独立邮箱密码登录／注册，移除了步骤条和常驻演示控件；最终页面及验证记录见 [登录注册与团队引导预览](../superpowers/plans/2026-09-08-onboarding-preview.md)。验证码组件继续用于注册确认与密码重置。

用户要求检查登录引导的视觉并优化细节。原单输入框使用 `000000` 占位，容易误读为预设验证码；纯字距无法表达当前输入位置。原各阶段按高度居中，实测邮箱页切验证码页时标题上移约 40px。

候选：

- 原生单 Input：无需依赖，粘贴简单，但当前六位输入的进度和定位不清楚。
- [Base UI OTP Field](https://base-ui.com/react/components/otp-field)：当前已安装版本提供 Root/Input，支持整串粘贴、自动填充、方向键与退格。采用现有依赖，未升级包。

选择 `VerificationCodeInput` 封装：六个原生输入，首位关联可见 Label，后五位有位置名称；错误绑定字段，未填满六位禁用提交；不自动提交。外观继续使用 TaskDoor 字体、间距、边框与语义色。页面保留此前 21st 简洁单列表单结构，统一表单宽度和顶部锚点，避免跨阶段跳动；不增加营销内容。

同时修复刷新后重新获取倒计时复位：从已保存的验证码有效期还原 30 秒冷却时间，专项测试覆盖刷新前后及冷却结束。此状态仅用于本地预览，不作为真实身份验证或服务端限流。

验证：10 项专项测试与构建通过。1280px 桌面下，邮箱页与验证码页的表单容器顶部均为 142px；390px、320px 页面无横向溢出，长团队名收敛显示。浏览器验证整串含空格粘贴、退格后禁用提交、错误提示、恢复输入后正常提交；刷新后剩余 29 秒且重新获取仍禁用。引入新依赖入口时 Vite 热更新曾短暂产生旧 React 模块日志，完整刷新后的再次验证没有新增错误。
