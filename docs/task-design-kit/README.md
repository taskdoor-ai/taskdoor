# TaskDoor 任务产品方案与 Skill 包

> 当前任务工作区基线（2026-09-20）：任务列表、筛选、详情收起、AI 分析、子任务时间轴、燃起图与 Mock 数据的最新确认规则统一见 [11 任务工作区与详情交互基线](11-task-workspace-detail-interaction-baseline.md)。后续设计、实现和验收优先读取该文件；历史决定若与其冲突，以该基线中明确替代的规则为准。

> 详情完成进度与子任务减法（D-190，2026-09-02）：任务详情现状区收敛为“当前情况／下一步建议／完成进度”三列；第三列把账本完成百分比、细进度条和燃起图上下排列。右侧不再重复顶部已有的 TaskStatus，也不展示预计人类工时及其分布。完成进度只取“已验收 EWD／当前范围 EWD”，示例标记约束整列，无有效历史不补 0% 或空列；顶部已完成状态与未完成账本冲突时只提示待核对。子任务列表每项只显示图标、名称与负责人，名称进入详情；正式负责人优先，只有无正式负责人时才展示待接受提议人。状态、期限、完成标准、依赖、箭头、更多菜单和行内操作不重复展示。D-170 的四列只作为历史呈现保留，其复盘账本和真实性边界继续有效。

> 我的工作依据权限边界（D-187，2026-09-02）：行动项“依据”区只展示权限过滤后的事实文本，移除全部“查看”、箭头、锚点、整行点击以及任务／动态／讨论／文件深链；即使是前置任务，也不默认假设当前成员有权限进入。当前行任务仍只从任务名称进入。数据层继续保留经 ACL 过滤的来源引用、版本、输入快照时间和权限决策，用于排序、失效与审计；无权来源不得泄露名称、ID、状态或缓存内容，也不能被推断为已满足或无风险。依据分条、默认两条与更多收起、更新时间和不自动写入等规则继续有效。

> 我的工作 AI 分析规则（D-186，2026-09-02）：清单前默认收起的入口更名为“AI 分析规则”，展开仅保留“排序／范围”，不再设置“生成”类别。任务状态、期限、依赖、完成标准和可见记录等分析输入并入“排序”，正式责任、未收口核对、待接受不计入、左侧筛选不影响、Task 去重及建议不自动修改任务等边界归入“范围”。入口仍按 D-176 位于更新时间之前，D-169 的时间语义和真实 AI／生产边界不变。

> Mock EWD 全叶子覆盖（D-171，2026-09-01）：本地 Mock 的叶子任务只要完成标准、执行方法和估算记录有效，就展示预计人类工时，“待开始”等 TaskStatus 不再成为不可估的理由；状态与工时不互相反写。父任务只汇总叶子，不重复累计；无显式历史仍不画燃起图，所有 Mock 工时必须标“演示估算”。当前 fixture 为 `multi-team-v15-mock-effort-coverage`：215 条 Task，团队分布 59／50／51／55，159 个叶子均有有效演示 EWD；内容电商 11 个叶子补齐标准、方法和估算，香氛收尾合计 43h、新品发布会合计 26h。v14→v15 只映射已有节点，仅修复其他估算字段未编辑且仍按叶子自身目标生成的旧 `scopeKey`，并为 11 个目标叶子的缺失定义和未显式填写的估算补 fixture 值；用户估算、显式清空、用户任务与删除都保留，不追加或复活节点。D-170 的复盘账本和无历史不画图继续有效，当前详情呈现以 D-190 的三列为准，D-139／D-140 其余边界不变。

> 详情四列与复盘 Mock（D-170，2026-09-01；可见结构已由 D-190 替代，fixture 覆盖与后续迁移已由 D-171 替代）：D-170 当时把任务详情现状区排为“当前情况／下一步建议／完成状态／燃起图”四列，并为 `weekly-retro-notes` 提供 3 个叶子、7h 演示范围与 2h 示例验收账本。当前只保留其连续现状、候选行动、复盘账本、无历史不画图和真假来源分离原则；状态与预计人类工时不再于右侧重复，完成百分比与燃起图按 D-190 在第三列上下排列。D-170 当时的迁移目标为 v14，当前 v15 与安全迁移以 D-171 为准；名称、目标、完成标准、属性行和四个内容 Tab 不变。

> 本次创建对话（D-166 / D-173，2026-09-01）：创建页“AI 帮你改”使用视口右侧固定面板，页面滚动、外部点击、焦点移出或 Tab 离开不收起，关闭按钮或 Esc 才明确关闭。每轮固定为“用户输入 → AI 思考规划 → AI 回复”：思考规划直接复用创建正文“正在生成方案”的同一过程组件与逐步骤展开／收起交互，不再另做思考卡；运行时整段和当前步骤默认展开，步骤按实际进度逐条追加，只显示已完成与当前步骤，未到达步骤不显示“待处理”行、占位或可访问内容，头部仍保留当前步骤／总步数。进入终态后整段默认收起一次，重新打开后每个实际到达步骤仍可独立回看，之后不因步骤或应用状态刷新覆盖成员选择；停止或失败不补出未来步骤。运行中不提前显示回复，终态后才追加回复。底部直接复用新建任务的输入组件，不展示预设提问，Enter 发送、Shift+Enter 换行，生成时同一发送按钮切换为停止。候选差异和应用动作留在可滚动历史区。创建正文只显示初始／补问重规划运行中的临时过程，完成后及所有调整轮次仅在面板历史出现。候选仍先预览、明确应用，最新草稿与手工编辑优先；“思考过程”不等于内部思维链，不展示隐藏日志、系统提示或伪造工具调用。记录不跨刷新、取消或最终创建持久化，也不恢复全局聊天页、历史侧栏或真实 AI 能力。该项仅在创建态局部替代 D-151 的锚点、过程入口及自动折叠规则，已有任务详情不变。

> 多团队本地 Mock（2026-09-01）：应用中的团队、复杂任务树、任务文件、动态讨论、EWD 和燃起图统一遵守[多团队 Mock 数据与燃起图契约](10-mock-data-and-burnup-contract.md)。当前版本为 `multi-team-v15-mock-effort-coverage`；v14→v15 采用 map-only 安全迁移，修复未编辑的旧自目标 `scopeKey` 并补齐 11 个目标叶子的缺失定义／估算，保留用户估算、显式清空、用户任务和删除，不复活节点。v7→v14 的扩容与复盘迁移作为历史链路保留。所有内容都是高拟真合成数据，团队切换只切换本地演示数据域，不代表生产权限、真实 AI、真实验收或外部系统已经接入。
