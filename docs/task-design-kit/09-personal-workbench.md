# 我的工作：先知道接下来做什么

更新日期：2026-09-02。依据：[D-154 / D-156 / D-158 / D-160 / D-163 / D-164 / D-165 / D-167 / D-169 / D-172 / D-174 / D-175 / D-176 / D-177 / D-178 / D-186 / D-187 / D-188](../product-v2/09-decision-register.md)。用户明确要求以本人全部负责任务为基础的个人 Dashboard，并纠正入口应在任务列表上方叫“我的工作”，不应有独立的“工作台／任务”Tab。D-156 修订入口和内容层级，D-158 融合左侧个人入口与标签分组，D-160 增加状态／标签多选，D-163～D-174 逐步收敛任务信息、AI 建议、状态与文字层级，D-175／D-176 恢复规则入口并固定在更新时间之前，D-177／D-178 收敛连接 AI 弹层与最小任务列表上下文，D-186 将规则入口改为“AI 分析规则”，D-187 移除工作台依据区的全部“查看”跳转，D-188 进一步将每条优先项收敛为顺位、任务名称和优先原因。D-154 的个人范围、来源与安全边界继续生效。本轮是本地原型，不代表接通真实 AI、日历、生产 ACL 或自动调度。

## 设计依据与取舍

2026-09-01 的历史结构曾将每行拆为“任务信息”和“AI 建议”，展示当前情况、真实状态、优先原因、下一步建议和依据。D-188 已将这一行内结构替换为更精简的优先任务清单：每项可见内容只有顺位、任务名称和优先原因，不设“当前情况”、状态徽章、“下一步建议”或“依据”区。页面仍不设到期／协作／核对等顶部分段或筛选，也不另设“顺序待判断”“待核对记录”区域。执行、协调和核对记录继续进入同一顺序，任务、状态、期限、依赖、完成标准、动态、讨论与文件只作为排序和审计输入。这只更新展示和记录投影，不宣称接通个人优先级 AI、日历或新的组合评分算法；D-154 的范围与真实性边界不变。本文中早期看板引用按 D-161 的移除决定处理，本次不恢复看板。

D-165 建立的“优先原因只回答为什么排在这里”继续有效：将直接影响当前顺位的已证实信号压缩为一句判断总结，不写成操作指令。D-188 移除了专门承载具体日期、前置状态和记录原文的“依据”区，也不再显示“下一步建议”。必须让用户知道的未知、过期或受限边界可在优先原因中简短表达，但不得把完整依据、隐藏的下一步或受限对象信息重新塞回该句。当前本地原型使用确定性记录规则生成该摘要并继续标明未接入真实 AI，不把模板结论冒充模型推理。

同日后续视觉修订：界面采用白色与浅蓝表面，不使用深蓝色。顺位 1、2、3…统一使用同尺寸浅蓝圆形底，不补零，也不显示“先处理／接着做”。所有任务行使用同一种 hover／键盘聚焦反馈，取消只有首项才出现的 Spotlight 动态光斑或背景。D-188 后行内只通过顺位、任务名称与优先原因的对齐、留白和轻分隔表达层级，不再渲染状态徽章、第二层建议卡或依据展开区。色彩、光影与动效不代表新增 AI 分析、任务状态或执行能力，不扩展导航与数据范围。

同日头部与文字修订：页面不再把“我的工作”和“建议优先顺序”做成两个独立区块，改为一个紧凑头部直接衔接行动清单，并移除大 Logo。规则入口当前按 D-186 显示“AI 分析规则／排序、范围”，其与更新时间的位置沿用 D-176。该时间是本次排序和分析的时点，不是任一任务的最新动态时间，也不能写成模型生成、实时同步或真实 AI 分析时间。头部右侧“连接 AI”按 D-177／D-178 复用共享四产品弹层并只带入最小正式负责任务列表。D-188 后任务行为“顺位／任务名称／优先原因”，不显示额外表头；任务名称与优先原因保持可扫读的字重层级，窄屏通过换行或上下排列保留字号。“近期协作动态”继续不设独立区块；任务动态仅作为排序和审计输入，不在工作台展示来源文本或跳转。

同日数据语义修订：行动投影仍读取来源任务的真实状态；即使该行由父任务协调、子任务阻塞或完成边界核对触发，也不能借用另一个任务的状态。D-188 只取消状态的行内展示，不删除或改写状态真值。来源状态缺失、无效或当前不可访问时不猜成“进行中”；若该未知会改变排序，优先原因只表达“状态待核对”等必要边界。状态／依赖冲突不用危险红色伪装成系统错误，也不因压缩成优先原因而泄露受限对象。分析数据更新时间绑定输入快照，只有任务字段、依赖、完成标准、可见讨论／动态／文件等输入实际变化并形成新投影时才更新；进入页面、重绘、hover 或输入未变化的周期刷新不得制造新时间。

呈现文案后续修订：预置任务本身不附加“Mock”“示例”“演示”等测试注释，日期也不加括号后缀。D-188 后来源不在任务行显示，但数据层仍保留来源类型、引用、版本与快照时间。D-172 移除页面级“本地数据 · AI 未接入真实服务”状态文字；D-177 由共享四产品弹层集中表达真实性边界，D-178 只增加当前用户正式负责任务的最小列表快照：产品选择、复制内容与尝试唤起均不证明握手、真实 AI 分析或自动写回；任务行不反复打测试标签，也不能把预置数据冒充生产同步结果。

用户进来的第一件事是决定“我接下来要做什么”，随后才需要知道“为什么先做它、去哪里继续”。上一版先按能力拆出行动、提醒、摘要，再把长内容收起，仍要求用户自行拼接任务与判断；仅减少字数没有改变这个负担。

本次以实际工作为组织单位：先让用户辨认任务和下一步，再给足以做决定的理由与来源。截图中的“风险识别、成功标准检查、每日协作摘要”是能力方向，不等于三个必须占据首页的区块；只有它们影响具体行动时才进入当前阅读路径。下表是基于用户问题的设计推导，不声称已经有用户研究、生产 AI 或提效实测支持。

| 展示的信息 | 用户此刻的问题 | 数据依据 | 支持的动作 | 不展示的损失／收敛方式 |
| --- | --- | --- | --- | --- |
| “我的工作”入口与本人范围 | 我如何从个人全局进入具体工作？ | 左侧与 Dashboard 均按当前稳定成员 ID 的有效 ownerId 取范围；搜索、状态与标签只筛左侧任务索引 | 从个人视角进入具体任务，再回到同一索引 | 入口、重复标题与分隔线会把同一工作区切碎；搜索、筛选和新建同一工具行，其下单独“我的工作”，不再重复“我负责的任务” |

视觉层级服务于这条阅读顺序：合并后的紧凑头部用“{当前用户名}，这是你今天需要关注的任务”说明个人视角，右侧提供带文字的“连接 AI”按钮；不保留大 Logo、关注项数量副信息或另一个“建议优先顺序”头部。首条任务前先显示默认收起的“AI 分析规则”，其后显示输入快照更新时间。任务行按顺位、任务信息、AI 建议三列顶对齐，不显示额外表头。任务信息列承载任务名称、当前情况和真实状态；AI 建议列只显示“优先原因／下一步建议”及细分隔后的依据列表。每条依据只陈述一个权限过滤后的可核事实，工作台不显示“查看”按钮或任何任务／动态／讨论／文件深链；需要处理时只能从当前行任务名称进入当前任务。截止、前置和标准缺口等不同事实仍分别表达；默认最多两条，更多依据通过同一展开入口收起。冲突事实使用常规正文色和明确措辞，不用危险红色替代语义，也不因移除跳转而补出不可见对象的名称、ID 或状态。

## 定位与入口

“我的工作”位于任务列表上方并默认选中。桌面左侧任务索引保持可见，右侧按选择展示个人 Dashboard 或原任务详情；顶栏只保留团队、通知与账户工具，不再出现“工作台／任务”Tab。不恢复旧模块侧栏、注意力地图、顶栏入口或一级 AI 连接页；D-172 只在 Dashboard 头部保留局部连接按钮，D-177 要求该按钮复用任务／讨论已有的四产品 `AiConnectionDialog`，D-178 要求带入 `personalWorkbenchModel.ownedTasks` 的最小正式负责任务列表。D-155／D-157 的讨论与任务上下文连接保持原有边界。个人视角帮助选择工作，详情说明单项任务当前情况，两者不建立第二份 Task 真相。

D-158 的当前顺序为顶部同一工具行依次为搜索、筛选按钮、新建加号，其下单独“我的工作”，再接分组列表，不重复“我负责的任务”标题，也不以分隔线割裂入口与任务。左侧固定本人有效负责范围，无负责人切换；筛选入口使用 ListFilter 图标按钮，无障碍名称与悬浮提示均为“筛选任务”，多选结构按 D-160。按已有标签分组是用户要求；无标签筛选时以首个非空标签归入唯一展示组，标签始终选填，无标签归“未打标签”；组名前复用对应标签已配置的图标与颜色，“未打标签”使用中性图标。无标签任务同样可创建、搜索和打开，不建立 `primaryTag`、Folder 或 TagGroup，不改其余标签、标签顺序或父子关系。组可收起；搜索临时展开匹配组，清除搜索恢复用户的折叠选择。

D-160 的轻量筛选浮层分为状态与标签两组多选：维度内 OR、维度间与任务搜索 AND，空选不限；“未打标签”与所选标签取 OR。标签项复用配置图标和颜色，仅数量较多时提供标签搜索。选择立即生效且浮层不关闭，条件在外部可见并可逐项移除；重置条件只清状态和标签，保留任务搜索、查看位置与折叠偏好，管理标签为二级入口。过滤匹配任务全部 `labels`；有标签筛选时按原数组首个命中的所选标签临时归组，每 Task 一处，清除后恢复默认组。这样既能按任一标签找到任务，又不复制任务或改变业务标签。该筛选只服务左侧任务索引，不改变右侧 Dashboard 的完整行动顺序，也不增加负责人或高级条件编辑器。

## 内容组织规则

| 对象 | 必须表达 | 不应表达 |
| --- | --- | --- |
| 行动 | 每个 Task ID 一行，呈现本人执行／协调／核对记录的下一步及短理由；所有可处理事项进入同一连续顺位，证据缺失、过期、合法无截止时间和仅需核对记录的事项也以具体动作入序；进入同一个原任务 | 把全部未结束任务称为“今天必须完成”，把建议当已排定日程，另设分类筛选或待核对区，或默认改变负责人、完成状态 |
| 建议顺序 | 在合并所有动作后统一排序；逾期、当日承诺、阻塞、依赖、完成边界、资料缺口、未来期限及当前责任均可成为依据。核对记录按事实紧迫性进入顺序，不机械追加到末尾 | 将行动类型当成互斥分类或可相加指标；把无截止时间等同于日期缺失、低优先级、无须处理 |
| 行动理由 | 将已知期限、阻塞、前置待核对、完成依据缺口、状态冲突与未知压缩为一句判断总结，说明为什么当前事项排在这里；多信号最多合并与当前顺位直接相关的事实 | 直接复述具体日期、把下一步动作写成优先原因、按风险／标准／摘要能力名称硬拆固定区块，或把缺证据判为不合格、没有记录判为无风险 |
| 变化与依据 | 与本人工作相关、可定位且有绝对时间；用于解释行动，完整记录留在原任务活动，示例明确标识 | 把修改估算称为新建任务，以当前状态推算历史完成时间，把旧示例称为今日变化；复制全量流水或制造无来源的摘要 |

每条依据在数据层保留来源引用、版本与快照时间，但工作台只显示权限过滤后的事实文本，不渲染引用或跳转。默认先显示排序所需的主依据及一条补充依据，超过两条才收起其余内容。冲突、关键风险与未知不能全部藏入展开区；无权读取的依赖只表达“资料当前不可用”等边界，不泄露名称、ID、状态或缓存内容。

“近期协作动态”不再作为独立区块或汇总流水；确实改变行动判断的动态只进入对应任务的依据文本。待接受负责人提议仍可从其独立 disclosure 进入原任务，但待接受不计入有效负责数或行动数量，查看提议不代表接受，也不产生新的审批对象。

本人任务范围按 Task ID 去重；已完成任务可作为状态或变化依据，只有存在需本人处理的冲突时才生成核对记录，不恢复执行建议。未进入行动顺序不表示任务不重要，空列表也不代表本人没有工作。任务数仅为对象概况，不能冒充工作量完成率；左侧原列表始终承担自主查找任务的入口，右侧不是另一份全量任务列表。

## 范围与依据

- 以当前用户稳定成员 ID 与 Task 的有效 `ownerId` 确定本人负责范围；不按姓名、创建者或参与者身份猜负责人。待接受人选不算已负责；无法解析归属时明确未知。左侧也固定该本人范围，不提供负责人切换；Dashboard 读取完整本人任务集，不受左侧搜索、状态、标签或分组折叠影响。
- 本人负责父任务但子任务由他人执行时，父任务体现协调或结果核对；子任务投入不整体计作本人执行负荷。父子同时由本人负责也不重复累计同一叶子工作量，不把所有参与者平均分摊 EWD。
- 复用 D-152 的当前情况、可见文件／讨论／活动和模拟叶子事件；任务字段变更后两处同步采用同一现状来源，旧示例判断按依赖版本标为过期，不另生成互相矛盾的摘要。
- 预置记录与当前字段使用同一真实业务文案，不在任务行附加测试注释；页面不再显示旧的本地数据状态行，服务边界由共享四产品连接弹层集中说明。连接上下文只取 `personalWorkbenchModel.ownedTasks` 的 ID、名称和真实状态，空列表只标 `meta=0`；不把其他投影字段或占位任务混入。从当前字段得出的判断注明依据，缺失信息保留未知。时间推导使用明确时钟，不能把历史事件称为今天发生，也不伪造“AI 刚刚分析”。
- 首条任务前的“更新于……”只表示当前排序／分析投影所使用的输入快照时点。只有任务字段、依赖、完成标准、可见讨论／动态／文件等输入实际变化并形成新投影时才更新；页面进入、普通重绘、hover、展开收起或输入未变化的周期刷新不得改写。它不复制任一任务的最新动态时间，也不声称模型刚完成分析或生产数据已实时同步。前面的“AI 分析规则”默认收起，展开仅显示“排序／范围”；展开／收起不改变该时间。
- 无截止时间是合法任务状态，仍按阻塞、依赖、完成边界与当前责任参加排序；默认行动清单不专门展示“无截止时间”。无法解析或不完整的日期是依据缺口，二者不能混为一谈。
- 当前行动排序只解释已有期限、明确阻塞、待核对事项等可见依据；真实组合级优先级算法、权重和质量指标仍待确认。D-153 的 EWD 是预计人类总投入，不是剩余投入；缺真实日历、本人可用时间或分人剩余工作量时，不输出负载、忙闲、完成概率或精确排程。
- 建议只帮助用户判断，不自动改任务、验收、指派、通知或启动 Agent。生产范围需先鉴权再汇总；本地按 `ownerId` 筛选不等于已经通过 ACL 验证。

## 导航与边界状态

| 情况 | 行为 |
| --- | --- |
| 打开任务或返回 | 使用原详情及稳定 Task ID；从列表头部回“我的工作”保留其查看位置，任务列表保留搜索／状态／标签／折叠／滚动，不为 Dashboard 卡片复制详情 |
| 无本人任务／无当日行动 | 明确说明当前可见范围和缺少可依据的行动；保留查看任务入口，不展示“今日已全部完成”或无关示例 |
| 证据不足／摘要过期 | 显示未知或旧截止时间，回退当前可核事实；不因为重新渲染而把更新时间改成刚刚 |
| 加载／失败 | 保留可读数据并标来源时间；失败不显示空范围、已同步或新分析。仅本地数据时不模拟不存在的服务请求 |
| 无权限／归属无法确认 | 不泄露受限任务名称、正文或缓存；不能将缺失数据解释为零任务、零风险 |
| 窄屏／键盘 | 纵向阅读，文字换行；建议内容保持直接可见，被收起的其余依据均可用键盘展开，入口与返回可达，不依赖悬浮内容或通过缩小字体压缩页面 |

## 验收

1. 左侧依次为搜索→“筛选任务”按钮→新建加号的工具行、单独“我的工作”、按标签分组的本人任务，无“我负责的任务”重复标题或割裂分隔线，顶栏没有“工作台／任务”Tab；创建、标签管理、原详情与返回上下文保留，不新增旧模块侧栏、看板、顶栏连接入口或一级 AI 连接页。Dashboard 头部保留 D-172 的局部连接按钮，按 D-177 复用 D-155／D-157 已使用的四产品 `AiConnectionDialog`，并按 D-178 带入最小正式负责任务列表。
2. 左侧与 Dashboard 只取当前稳定用户 ID 的有效负责范围，无负责人切换；搜索、状态和标签只筛左侧任务索引，不影响 Dashboard。状态／标签多选遵循 OR／AND，空选不限，“未打标签”可并选；即选即生效且浮层不关闭，条件可移除，重置不清搜索、查看位置或折叠偏好。标签匹配全部 labels，标签筛选生效时按原数组首个命中的选中标签归组，每 Task 一处，清除恢复默认；无标签可正常进入列表，同名成员、参与者和待接受人选不被误计为本人负责。
3. 第一阅读层能说明本人接下来执行、协调或核对什么；紧凑头部不重复 Logo、关注项数量或“建议优先顺序”。首条任务前先显示默认收起的“AI 分析规则”，再显示输入快照更新时间；规则只按“排序／范围”说明口径，不把本地规则冒充真实 AI。右侧保持一条连续行动顺序，每个 Task ID 以顺位、任务信息、AI 建议三列组织；优先原因、下一步建议与依据均为静态说明。依据默认最多两条、更多可展开，但依据区不得渲染“查看”按钮、锚点或其他任务／动态／讨论／文件深链；数据层仍保留受权限过滤的来源引用。当前任务只通过任务名称进入，受限依赖不得泄露名称、ID、状态或缓存内容。默认清单不设任务期限列，仅在会改变行动时于优先原因和依据中体现逾期／今日截止。
4. 父任务协调与子任务执行不重复计量；无日历或剩余投入时不报负载、忙闲、完成概率，首页没有个人总燃起图。
5. 风险、完成标准与协作变化服务具体行动，不强制分成三个独立模块，不重复同一问题；未进入执行建议的严重状态冲突仍作为核对事项保留。每项显示来源任务真实状态；状态缺失或无效时显示“状态待核对”，不得留空或猜测默认状态。完成依据缺失保留“待核对”，不自动判为失败或通过；冲突以常规正文色和明确文案表达，不使用危险红色整段强调。依据中的变化带绝对时间并区分真实记录与示例，但不提供来源跳转；待接受提议仍由其独立 disclosure 处理。
6. 示例、推导、未知与过期清楚区分；任务修改后首页与详情不继续引用旧结论。建议与标准检查不自动写入任务、通知或调度，不新增审批对象、勾选验收或责任转移。
7. 空、失败、受限及窄屏状态不误报正常或完成；键盘可完成主要导航与展开，返回保留原有上下文。

这是本轮设计与验收目标，不是生产或真实模型质量的通过报告；不改变 D-139／D-140 未被后续明确替代的其他限制。
