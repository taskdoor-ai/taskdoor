# 任务详情：打开即可了解当前情况

更新：2026-09-02。依据：[D-152 / D-159 / D-168 / D-170 / D-190](../product-v2/09-decision-register.md)。用户要求所有任务呈现当前情况；最新修订把详情现状收敛为“当前情况／下一步建议／完成进度”三列，并让完成进度与燃起图在第三列上下排列。真实自动估算和模型摘要尚未接通；当前实现只投影本地已保存字段与明确标注的演示来源，不能声称生产能力已具备。

## D-190：完成进度与燃起图同列

- 第一列“当前情况”和第二列“下一步建议”沿用 D-170 的可核事实与候选行动边界。
- 第三列“完成进度”先展示账本完成百分比与细进度条，再在下方展示 EWD 范围／已验收双线燃起图。百分比只取“已验收 EWD／当前范围 EWD”，不按 TaskStatus、任务个数或预计工时分布推算；示例标记位于完成进度标题旁，约束整列而非只约束图。
- 右侧不再重复顶部属性行已有的 TaskStatus，也不展示预计人类工时、说明图标或子任务工时分布。无有效历史时不留空列、不补 0%；若顶部已完成状态与未完成账本冲突，只提示待核对，不重复状态值。
- 子任务列表每项只展示图标、名称与负责人；名称进入子任务详情。正式负责人优先于待接受变更提议，只有无正式负责人时才展示提议人并标“待接受”。状态、截止时间、完成标准、依赖、箭头、更多菜单和行内操作不在列表重复。

## D-170：四列呈现与复盘账本（历史）

- 第一列“当前情况”承载一句可核摘要，并把已完成事实、差距、风险、阻塞和近期变化作为连续明细呈现；不再显示“已完成内容／需要关注”等次级分组名。底层投影仍保留原分组，供个人工作等其他表面消费。
- 第二列“下一步建议”给出具体候选动作、责任人或待明确责任，并保留任务、标准或讨论入口；建议不形成正式指派，也不自动改状态或期限。
- 当时第三列“完成状态”读取当前 TaskStatus，并在有效 EWD 可用时展示预计人类工时、已验收工作量与范围；当时第四列“燃起图”展示 EWD 范围／已验收双线。D-190 已替代这两列的可见结构，但继续保留 TaskStatus 与 EWD 完成度不能互相推导、无历史不补图、缺估保留未知的底层边界。
- 名称、目标、完成标准、属性行和讨论／子任务／文件／活动 Tab 不变。本修订局部替代 D-168 的可见结构，不删除底层事实，也不恢复逐项验收或新增诊断入口。

## D-159：真实数据与精简呈现（保留的数据基础）

- 2026-09-01 的 D-159 曾把预计人类工时、说明图标和可展开的子任务分布合并至右侧工作量区域；D-190 已从详情首屏移除这些内容。底层估算、来源和创建阶段呈现继续保留，不用 Mock 图数据回填当前估算，也不拿当前估算改写历史完成率。
- D-159 的叶子工时占比条只用于解释预计工时分布，不是完成度。D-190 仅复用细条形视觉来显示“已验收 EWD／当前范围 EWD”，并与燃起图使用同一账本；不能与工时分布或任务个数完成率混用。

- 标准只取当前任务定义，缺失或清空不补示例，预制现状不回填。后续更正（2026-09-01）：已有 Mock 任务的固定燃起历史恢复展示，并明确标注“示例”；不能把演示历史冒充真实验收，也不能给无历史任务补曲线。
- 预计投入只展示有效系统估算的成本结果，以人时表达；不让用户填写工作方式、理由或手工确认。部分数据写明“已估部分”，缺失显示“暂无法估算”，过期显示“需重新估算”。内部保留依据与版本，既有手填值不改称系统估算，也不删除历史。
- D-170 之前，详情先后使用“三组列表”和“当前摘要＋已完成内容＋下一步计划”。现在已完成事实与风险边界都收进第一列“当前情况”，第二列改为“下一步建议”，不再显示旧分组名。已完成子任务仍分别列出并保留入口；剩余与取消数量保留在摘要中，未经核对的讨论只能作为有来源的记录，不能据此认定已完成。宽屏使用 D-190 的三列与细线区分信息，窄屏纵向阅读；不加统计卡墙。
- 当前状态与子任务状态只作为记录事实，不能证明交付已验收。明确传入的已保存成员讨论可署名引用并定位原文，不对内容作未经实现的 AI 判断；缺少记录时简短说明缺口，下一步推导须写为建议。
- 通用兜底摘要必须从当前任务真实状态生成，并保持状态语义：已取消说明停止范围与需保留结果待核对，不写“正在推进”；已阻塞说明阻塞原因与解除条件待核对，不回退成普通无进展文案。状态改变后摘要同步改变，不能继续沿用上一状态的动作语气。
- 来源时间只取合法记录时间，不补造生成时间；有子任务且明确提供真实或 Mock 趋势数据时才显示辅助图，两种来源清楚区分。`mock` 工时必须显示“演示估算”，`example` 历史必须显示“示例”；无数据不造曲线，也不放空图。
- 用户要求真实自动估算与摘要；服务选择和配置仍待明确。本次没有调用旧接口或将本地规则冒充模型。历史讨论和文件可能承载用户编辑，保留原数据，但不作为现状摘要的默认真实来源。

以下保留 D-152 的完整设计背景；其中示例呈现、手工估算入口、无历史图表提示与重复状态标签，以本节 D-159 修订为准。

## 目标与边界

有权限、没有参加最近讨论的人，打开任务后即可知道已经完成什么、还差什么、最近有什么变化、有什么风险或阻塞，以及接下来谁做什么，据此判断自己是否需要介入；不必先读完讨论或再开一次 Review 会。

当前情况是所有 Task 的基本信息，不是新“概览”或“诊断”Tab。有子任务的主任务与中间层可用燃起图辅助解释范围和交付趋势；普通任务与末梢子任务不显示图表或“暂无趋势”占位，但同样完整说明当前情况。叶子工作量仍参与上层汇总。个人 Dashboard、真实 AI 分析、逐项验收和生产权限接入不在本轮范围。

## 信息层级与呈现

```text
任务 / 父任务 / 当前任务                归属与返回
名称 · 目标                            完成标准按需展开
负责人 · 参与人 · 状态 · 期限 · 标签      既有属性和编辑入口
当前情况          下一步建议          完成进度
摘要＋事实明细    候选动作＋来源      百分比＋细进度条
进展／差距／风险  不形成正式指派      范围／已验收燃起图
  差距／风险／变化：并入摘要或行动依据，不另设一列
讨论（默认） / 子任务 / 文件 / 活动
```

名称、目标、属性和三列现状在同一阅读顺序中呈现；当前情况与下一步建议用紧凑文本组织，完成进度与燃起图在第三列上下排列但不做统计卡墙。长标准、历史数据、来源和完整变更按需展开。三列位于 Tab 上方，切换 Tab 后仍可查看；子任务列表只保留一份。

| 信息 | 用户需要作的判断 | 依据与限制 |
| --- | --- | --- |
| 现状摘要 | 目前处于什么阶段，是否有事情需要介入 | 汇总可核事实；不从“进行中”直接推出按时或正常，不生成健康分 |
| 交付进展 | 已有什么结果、距离完成还差什么 | 对照完成标准和文件／交付记录；标准定义不等于已经满足，Task 完成状态不自动证明验收 |
| 风险／缺口 | 当前承诺受到什么影响 | 具体阻塞、期限冲突、证据不足；没有记录不等于无风险，无更新不等于停工 |
| 下一步 | 谁应做什么，解决哪个问题 | 复用已有行动、责任事实或标明建议；人选未接受、责任未知时如实说明，不自动指派 |
| 最近变化 | 近期变化如何影响当前安排 | 可展开定位对应任务与事件；无真实时间不能写“今天新增”或“最近完成” |

完成标准继续按 D-149 / D-150 编辑定义，不恢复逐项勾选、AI 自动验收或审批状态机。来源入口应定位原对象，不能用看似可点击的文案代替尚不存在的跳转。

## 数据与燃起图口径

“当前字段”指原型当前保存的 Task 数据，不等于生产业务事实；预制摘要与模拟事件另标“示例”。两者不得相互覆盖或用演示文本补全真实空值。

| 数据 | 必须保留的含义 |
| --- | --- |
| 当前 Task 与子任务 | 稳定 ID、层级、名称、目标、完成标准、状态、负责人／待接受关系、期限；子任务是否存在由任务关系判断，不由是否有历史点判断 |
| 证据来源 | 可见的讨论、文件版本、交付或活动记录及其时间；摘要只陈述来源能够支持的内容 |
| 现状摘要 | 来源类型、依据范围、截至／更新时间、依赖的任务与证据版本，以及未知或过期原因 |
| 范围与完成事件 | 叶子任务 ID、发生时间、事件类型、当时有效 EWD 及确认状态；保留新增、移出、估算修订、验收与重开的区别 |

燃起图沿用 EWD h 的“当前范围／已验收”双线，父级只汇总其范围内叶子，不重复计入父级工作量。完成百分比、进度条、父图、子层趋势、近期变化和叶子记录从同一组事件推导，不能各算一套。没有子任务或没有显式历史时不渲染第三列，也不补线或补 0%；显式历史只有一个点时说明“历史不足”。权限或覆盖不足导致无法确认子任务范围时，不能把未知解释为“没有子任务”。

“近 7 天新增／完成”是解释趋势的事件摘要，不是任务项数完成率。新增与移出分别说明，估算修订不能冒充新增任务；完成计入沿用“已验收”口径，重开需体现撤回。用事件有效时间生成阶梯变化，保留范围或净已验收下降；不按当前状态或今天的估算反写历史。缺估不当零，只有一个点不画完整趋势；完整算法继续见 [EWD 方案](06-ewd-design.md)。本地模拟验收事件不代表已接通生产验收流程。

本轮香氛 Mock 用同一条时间线表现初始 6 项、两次新增至 8 项、三次交付验收与没有新交付的日期；普通任务和末梢任务没有图表，其他没有历史的父任务明确保留未知。范围增长而完成未跟上、取消及重开等作为后续补充情境，不声称每个任务已有这些记录。其中“没有新交付”只能说明记录变化，不能判定成员没有工作。近期变化首版展示非初始的模拟新增／验收事件；决定、期限等真实本地修改仍在活动中查看，不冒充已被自动归纳。

## 状态与更新

| 状态 | 应呈现的内容与行为 |
| --- | --- |
| 正常且有依据 | 简短现状、关键进展／缺口、具体下一步；显示来源和截至时间，不强行凑风险 |
| 新任务或空内容 | 呈现已有目标、标准与属性，明确尚无交付或动态记录；不回填别的任务示例 |
| 未知或覆盖不足 | 指出缺少哪类数据，保留可核事实；不显示 0%、无风险、按时或“全部完成” |
| 数据过期 | 当前任务、子项或摘要依赖的证据变化后，旧示例结论标为过期并回退到当前可核事实；历史可按原截止时间查看，不冒充新结论 |
| 加载／失败 | 当前字段仍可读；有旧摘要则注明旧时间，失败不更新“截至时间”或显示假成功。本地无服务时不伪造生成动画或刷新请求 |
| 无权限或来源撤销 | 不展示受限正文、名称、详情或残留缓存；说明可见范围不足，不泄露受限对象来解释缺失。生产 ACL 尚未接入，不能把 Mock 可见性当安全验证 |
| 窄屏／键盘 | 按详情容器宽度转为纵向，摘要先于图；长名称与属性换行，展开、来源及 Tab 可聚焦操作，不依赖悬浮才能读数 |

修改目标、标准、状态、人员、期限或子任务后，不继续沿用依赖旧内容的预制风险、行动和完成结论。示例失效与历史事件不足分别说明；前端重新读取当前字段不称为“AI 已重新分析”。新增讨论、文件或活动只有实际被纳入摘要依据后，才能声称摘要已经更新。

## 验收

1. 普通任务、末梢子任务、有子任务但无历史的主任务均展示“当前情况／下一步建议”；只有存在子任务且显式历史有效时才增加“完成进度”第三列，并在该列上下展示百分比、进度条与本层燃起趋势，不出现空图或伪造 0%。
2. 首屏无需切 Tab 即可按“当前情况／下一步建议／完成进度＋燃起图”理解进展、关键差距／风险或未知；右侧不重复 TaskStatus 或预计人类工时，不显示“已完成内容／需要关注／下一步计划”等旧分组名，完成标准仍可阅读与编辑，不新增概览／诊断页或 Dashboard。
3. 父图某次新增或完成可定位同一事件对应的子任务；汇总不重复累计父子工作量，不把估算增加写成新建任务，不把执行声明当验收。
4. 修改任务或子项后，旧示例摘要明确过期，页面使用当前字段；清空标准不回填示例，示例不会被保存成实际任务字段。
5. 无历史、单点、缺估、无证据、过期、受限及失败状态不会产生伪造趋势或正常／完成结论；来源和时间可见，差异能定位。已取消摘要不出现进行中／继续推进语义，已阻塞摘要明确阻塞原因与解除条件仍待核对。
6. 讨论仍默认，子任务／文件／活动和既有编辑可用，返回保留列表上下文；子任务列表每项仅显示图标、名称、负责人，名称可进入详情，待接受负责人可辨；窄屏与键盘可阅读、展开、定位来源。

以上是本轮可观察目标，不是已经运行的验证报告。真实模型质量、服务端历史聚合、验收状态映射、ACL、跨端更新及“减少会议”的用户效果仍需各自证据。
