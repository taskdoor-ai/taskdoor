# 产品方案：从空白信息架构到可核验任务执行

> 状态：会议方向整理 + 可编辑设计默认。当前正式规则仍以 product-v2 的决定台账为准。

## 1. 目标与非目标

目标用户：有明确工作需求的创建者、结果 Owner、协作者、借助个人 AI 执行任务的成员。解决四个问题：需求写了但目的不清；复杂任务无法落到单一负责人；协作沟通不及时导致重复任务；执行进度缺乏可核验依据。

成功表现：用户能很快知道这是什么任务、为什么做、谁负责、下一步是什么；简单任务不被复杂化；复杂任务有可独立交付的结构和真实依赖；确认前可改；执行结果能回到任务并供人验收。

本轮不做：界面改造、后端接入、自动分配、云 Agent 调度、员工效率分析、复杂首页仪表盘、自动创建下一周会议。

## 2. 任务创建：同一个对话，不同意图

```text
用户输入
  → 识别创建 / 编辑 / 查询 / 不明确
  → 读取服务端授权上下文
  → 提炼目的与边界，判断规模
  → 简单：Tips；复杂：独立结果 + Owner 候选 + 依赖
  → 权限内查重与计划校验
  → 输出可编辑草稿、短理由和关键问题
  → 用户确认具体版本
  → 服务端复核 ACL / 依赖 / 版本 / 幂等
  → 正式写入与回执
```

不是固定展示八步“思考动画”。界面只报告实际发生的动作，例如“已找到 2 个相似任务”“缺少成员职责，暂未推荐”。展示判断摘要，不输出内部思维链；尚未调用检索不能显示“正在比对全团队任务”。

### 简单任务

一人一天内可自主完成、没有独立协作交付点时只生成一个 Task；标题、目的、达成标准、Tips、候选 Owner、期限建议。校对一份通知约 2h，不再拆“阅读、修改、检查”，也不创建一个内容相同的子任务。

### 复杂任务

按可独立交付结果拆分，不按固定“分析／执行／验收”模板。每项有一个 Owner 候选和自己的完成证据，继承主任务目的，不重新推断子任务背后的商业战略。依赖使用稳定临时 ID，用户排序不能改变依赖指向；服务端检查循环、悬空引用和权限。可并行就不强行串行。

### 查重

服务端按当前 principal、组织/团队/对象 ACL 生成可见集合，再做相关性检索。题目相近不等于重复，结合对象、交付物、时间范围、状态及 Owner 解释。只返回可见任务，不暴露其他团队存在某任务、相似数量或秘密标题。

候选动作：查看已有任务、补充已有任务、继续新建并说明区别。AI 不自动合并、不删除、不加入他人任务。无法查重显示未检测/部分覆盖；若正式创建仍允许继续，用户需确认该风险，系统保留事件。

### 编辑与查询

查询不生成创建计划；编辑必须锁定可见 taskId 与 revision，产出变更提案而非覆盖整棵任务树；模糊“把那个提前”先确认对象。首版 planner Skill 只处理 create，其他意图回交路由，不假装已经实现统一编辑查询服务。

## 3. 详情和工作区

详情结构采用设计 Skill 的 D04–D09。Heading Card 只承担身份与快速理解，不承担所有分析。讨论是高频交流入口；子任务和文件独立；诊断与子任务同级。日志低频但可追溯。

诊断必须有“结论—证据—覆盖—下一步”：范围增幅、交付证据不足、真实依赖阻塞等。证据失效显示更新时间，不用过期结果宣称“健康”。无人讨论不意味着停滞；未连接不意味着工作没做。

首页回归任务列表，保留筛选、搜索和当前范围；创建入口的最终位置待 D-140 重审后确定。个人重要/紧急分析在工作区层级按需访问，不放回首页默认大图，不下沉到每个子任务。

## 4. Agent 执行回传（协议提案）

拆开三个事实：连接可用性、执行报告、业务验收。状态事件至少包含：eventId、taskId、taskRevision、principalId、agentId、runId、sequence、occurredAt、receivedAt、eventType、summary、evidenceRefs、schemaVersion。principal 身份、receivedAt 由服务端验证/生成，不信任客户端自报。

回传入口需要验证：授权范围、协议版本、任务存在及当前 revision、去重 eventId、run 内序号与乱序、允许的状态迁移、证据访问权、重试幂等和撤销授权。重复事件不重复计算进度；过期事件不覆盖新状态；跨任务证据不能越权链接。

心跳另用连接会话报告：sessionId、agentId、protocolVersion、capabilities、lastSeenAt、connectionStatus。心跳间隔、失联阈值、留存和谁可见需技术/产品确认。服务端接收时间优先于客户端时钟；默认仅在连接设置、排障和相关任务的数据新鲜度处展示，不做成员在线排行榜。

执行完成报告先成为“待核验交付事实”，是否映射成现行状态由产品确认；不能自动改成业务验收通过。EWD 采用设计 Skill 的口径，云 Agent 不报告“我运行了 30 秒，所以节省 20h”。

演进：个人连接校验 → 可信任务回传 → 有授权、可撤销的云运行 → 必要的配额、重试、审计与治理。后两项为后续方向，不提前放进 MVP 导航。
