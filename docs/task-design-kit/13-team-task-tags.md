# 团队任务标签管理规则

> 2026-11-11，本地 Demo 已支持团队共享目录、任务内新建、按创建者管理及 AI 标签建议。

## 标签归属与权限

标签属于一个团队，任务选择器、筛选和 AI 读取同一团队目录。标签记录保留稳定 ID、创建者的成员身份、名称、图标和颜色。创建者由应用根据实际操作者记录，AI 代建时记录授权本次操作的成员。

| 操作 | 有效普通成员 | 团队拥有者和管理员 |
| --- | --- | --- |
| 查看团队目录、选择可用标签筛选 | 当前团队 | 当前团队 |
| 创建团队标签 | 可以 | 可以 |
| 修改名称、图标或颜色 | 自己创建的标签 | 当前团队所有标签 |
| 删除团队标签 | 自己创建且未被任务使用的标签 | 当前团队所有标签 |
| 给任务贴标、移除或更换标签 | 按该任务的编辑权限 | 按该任务的编辑权限 |

可编辑任务的成员可使用团队内任意标签。移除任务上的标签只解除这条任务的关联。历史记录的创建者无法可靠核验时，由团队拥有者和管理员维护。创建者离开团队后，标签和已有引用继续留在团队，其维护权限随团队成员资格失效。

## 新建、修改与删除

- 复用任务详情的标签选择器。成员搜索并选择已有标签，也可输入新名称并直接新建到当前任务。新建标签与贴标一起保存，失败时保留输入和已选项。团队目录沿用现有管理入口。
- 团队内按规范化名称查重，去掉首尾空格，统一全半角和大小写。同名时复用已有标签。改名或调整外观沿用原标签 ID，团队内已有引用显示更新后的定义。
- 管理页每行展示垃圾桶图标。无删除权限时按钮置灰并禁用。有权限时，确认提示说明受影响的任务数量。回收站中可恢复的任务也计入标签使用情况。
- 确认删除时一次性移除目录记录、当前团队所有任务及可恢复任务上的标签关联，并清除相应筛选条件。删除后再次使用同一名称时，新标签获得新 ID，从空关联开始。筛选结果始终受任务读取权限约束。
- 旧归档标签兼容加载到团队目录，保留已有的任务关联，直到成员显式删除。迁移时只保留可核验的创建者。未贴到任务上的个人标签仍是个人数据，进入团队目录需要成员主动创建。

## AI 的触发和保存

| 时机 | AI 如何处理 |
| --- | --- |
| 创建任务，或任务名称、目标、完成标准有实质修改并保存 | 读取当前团队标签，优先推荐适用的已有项，沿用其图标与颜色。找不到合适项且主题适合重复分类时，可建议一个新名称及图标、颜色。标签可以留空。 |
| 成员采纳建议 | 已有标签建立任务关联。新标签与当前任务关联一起保存。草稿中的建议可跳过，接受一条建议仅授权保存该条。 |
| 成员明确要求改名、调整外观或删除 | 核对操作人是否有权执行目标操作。删除前说明任务上的关联也会清除，经用户确认后交由应用执行。 |

AI 沿用请求人的团队和任务权限。目录读取失败时保留任务草稿和已选项，待重试后继续推荐。保存前重查成员资格、操作权限、标签是否仍存在和同名冲突。目录或任务变化使建议过期时，提示重新核对并保留用户输入。保存新建建议时发现同名标签，复用现有记录及其外观。

创建 Skill 的读取、输出和外观值见[团队任务标签参考](../../skills/agentdoor-task-planner/references/team-task-tags.md)。

## 本地验收

1. 普通成员能修改自己创建的标签。自己创建且无任务使用的标签可删除，使用中或由其他人创建的标签显示禁用的「删除」。团队拥有者和管理员可删除当前团队所有标签。创建者未知或离队时，普通成员无法接管标签。
2. 管理员确认删除使用中的标签后，目录、任务、回收站中可恢复的任务、筛选及已有标签候选均移除该标签。成员在单个任务上移除标签时，其他任务仍可使用该标签。跨团队读写被拒绝。
3. 创建任务可以跳过标签。已有合适标签时 AI 优先复用，只有明确且可复用的主题才建议新标签。用户采纳前目录和任务标签不发生变化。
4. 确认时遇到同名标签，复用已有记录。候选被删除或用户失去权限时，保留原任务和未提交输入，并提示重新选择。桌面、窄屏及键盘可搜索、选择、新建和退出，返回时保留原任务或有效的筛选条件。
