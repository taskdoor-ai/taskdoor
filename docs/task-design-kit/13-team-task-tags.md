# 团队任务标签管理规则

> 2026-11-11，本地 Demo 已支持团队共享目录、任务内新建、按创建者管理及 AI 标签建议。

## 标签归属与权限

标签属于一个团队，任务选择器、筛选和 AI 读取同一团队目录。标签记录保留稳定 ID、创建者的成员身份、名称、图标、颜色和归档状态。创建者由应用根据实际操作者记录，AI 代建时记录授权本次操作的成员。

| 操作 | 有效普通成员 | 团队拥有者和管理员 |
| --- | --- | --- |
| 查看团队目录、选择可用标签筛选 | 当前团队 | 当前团队 |
| 创建团队标签 | 可以 | 可以 |
| 修改名称、图标或颜色 | 自己创建的标签 | 当前团队所有标签 |
| 归档团队标签 | 自己创建的标签 | 当前团队所有标签 |
| 给任务贴标、移除或更换标签 | 按该任务的编辑权限 | 按该任务的编辑权限 |

可编辑任务的成员可使用团队内任意启用标签。移除任务上的标签只解除这条任务的关联。历史记录的创建者无法可靠核验时，由团队拥有者和管理员维护。创建者离开团队后，标签和已有引用继续留在团队，其维护权限随团队成员资格失效。

## 新建、修改与归档

- 复用任务详情的标签选择器。成员搜索并选择已有标签，也可输入新名称并直接新建到当前任务。新建标签与贴标一起保存，失败时保留输入和已选项。团队目录沿用现有管理入口。
- 团队内按规范化名称查重，去掉首尾空格，统一全半角和大小写。已有启用标签时复用该标签。命中已归档标签时提示归档状态，同名新建不能绕过其维护权限。
- 改名、调整图标或颜色沿用原标签 ID，同团队已有引用显示更新后的定义。归档退出新的选择和推荐，历史任务上的标签仍显示且可筛选。筛选结果始终受任务读取权限约束。
- 旧任务上的标签继续显示和参与筛选。迁移目录时，只写入可核验的创建者。未贴到任务上的个人标签仍是个人数据，进入团队目录需要成员主动创建。

## AI 的触发和保存

| 时机 | AI 如何处理 |
| --- | --- |
| 创建任务，或任务名称、目标、完成标准有实质修改并保存 | 读取当前团队启用标签，优先推荐适用的已有项，沿用其图标与颜色。找不到合适项且主题适合重复分类时，可建议一个新名称及图标、颜色。标签可以留空。 |
| 成员采纳建议 | 已有标签建立任务关联。新标签与当前任务关联一起保存。草稿中的建议可跳过，接受一条建议仅授权保存该条。 |
| 成员明确要求改名、调整外观或归档 | 核对操作人是否有权维护目标标签。已授权具体操作时执行，仍需选择目标或确认改法时先给建议。 |

AI 沿用请求人的团队和任务权限。目录读取失败时保留任务草稿和已选项，待重试后继续推荐。保存前重查成员资格、任务编辑权限、标签状态和同名冲突。目录或任务变化使建议过期时，提示重新核对并保留用户输入。保存新建建议时发现同名启用标签，复用现有记录及其外观。

创建 Skill 的读取、输出和外观值见[团队任务标签参考](../../skills/agentdoor-task-planner/references/team-task-tags.md)。

## 本地验收

1. 普通成员 A 创建并贴标，成员 B 可在自己能编辑的任务上使用和移除该标签。A 可修改或归档自己创建的标签，B 对目录的同样操作被拒绝，管理员可维护。跨团队读写被拒绝。
2. 归档后，已有任务仍显示并可按该标签筛选，新任务选择器和 AI 候选中不再出现。创建者未知或离队时，普通成员无法接管标签。
3. 创建任务可以跳过标签。已有合适标签时 AI 优先复用，只有明确且可复用的主题才建议新标签。用户采纳前目录和任务标签不发生变化。
4. 确认时遇到同名启用标签，复用已有记录。标签被归档或用户失去权限时，保留原任务和未提交输入。桌面、窄屏及键盘可搜索、选择、新建和退出，返回时保留原任务或筛选条件。
