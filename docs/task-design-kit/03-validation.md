# 验证记录

> 2026-08-31 · 本地文档、Skill 与合成示例验证；不是生产验收或模型准确率报告。

## 1. Skill 行为对照

先由独立助手在未读取新 Skill 的情况下处理场景，再读取 Skill 重新处理。此方法来自 writing-skills；只用于检查规则能否改变具体决策，没有授予其修改应用或执行真实任务的权限。

| 场景 | 无 Skill 的基线输出 | 带 Skill 的输出 | 本轮结果 |
| --- | --- | --- | --- |
| 明天演示，团队已做首页地图与 AI 侧栏 | “明天交付的演示保留已完成模块”，保留折叠地图、通知侧栏、右侧洞察 | 任务列表 + Heading Card + 独立诊断；既有低频通知入口可保留 | 纠正以沉没成本保留铺陈的偏差 |
| 完成2h，未完成18h | 主指标10%，但另保留“子任务完成率50%” | 仅把10%称为工作量进度；数量不作为进度条；估算未确认则标预览 | 纠正并列指标误导 |
| 2h通知校对 | 创建一个与主工作等价的子任务 | subtasks=[]，执行步骤放Tips | 纠正过度拆分 |
| 李青校对，王明只是发起 | 选李青；此项基线已正确 | 继续选m2，明确不代表接受 | 保持正确边界，没有伪称新增改善 |
| 无日期、查重服务不可用 | 日期null、查重not_checked；基线已正确 | 日期null、unavailable、needs_clarification，最多两个关键问题 | 明确状态与确认门槛 |
| 心跳昨晚中断 | 不推断停滞；基线已正确 | 只认为连接/数据可能过期 | 保持正确边界 |
| D-140仍生效，团队催恢复入口 | 未纳入首轮基线 | 停在提案，要求明确替代范围和后端校验 | 仅记录带Skill验证，不虚称对照提升 |

日期反例检验发现：第一版复杂示例写“9月4日前”，却将验收放到9月4日并标记ready。已修正为输入明确说“9月4日当天结束前”，并让独立助手复读确认一致。另测试原歧义输入，应 needs_clarification，追问是否包含当天，不把9月4日当确定排期。

### 日常讨论约束补测

用户明确要求设计 Skill 约束双方探讨后，补测“明天演示、老板觉得普通、已有注意力地图，想加AI灵感卡/地图/团队活跃排名，先讨论不改代码”。无 Skill 基线回复“这三块里，我更看好已有的注意力地图”，并建议灵感卡；它已正确质疑活跃排名，未要求修改代码。更新后回复“已经做过不代表该保留”，主动指出与首页列表方向的冲突，给出围绕列表与必要上下文的最小替代，并询问真实未解决问题。

再测试用户希望重新讨论首页原则：助手允许重开讨论、厘清取舍、明确新原则及替代范围，不把 Skill 当作否决权，也不把讨论当实施授权。设计 Skill 格式检查通过。此补测验证具体讨论行为，不代表对所有未来对话作保证。

## 2. 确定性检查

复现：

```bash
python3 docs/task-design-kit/validate_kit.py
```

脚本依赖当前环境已有 `jsonschema`，不联网、不调用模型、不写业务数据。换环境需自行提供该依赖；本轮没有安装依赖或修改 package.json。

结果：4个测试方法通过；验证3个示例、查询分流、子任务重排；13种非法变体被拒绝：外部成员、轻任务冗余拆分、循环依赖、悬空依赖、不存在的日期、负EWD、产生外部动作、伪造查重成功、未查重直接ready、扩大团队范围、编造可见匹配、子任务晚于父期限、子任务递归goal。

两个 Skill 均通过 skill-creator 的 quick_validate（名称、frontmatter 与脚手架检查）。这些检查不证明提示词准确性。示例校验器只覆盖本包明确的不变量，不是完整生产校验器，也不能验证会话身份、真实 ACL、签名、人员接受或原子事务。
