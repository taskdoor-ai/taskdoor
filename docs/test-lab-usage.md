# 自动化测试工作台使用说明

本地入口：`http://127.0.0.1:5173/test-lab.html?page=cases&core=1`。服务未启动时在项目根目录执行 `npm run dev -- --host 127.0.0.1`。

## 运行

1. 在用例库勾选“验收用例库”，查看结构完整的验收场景（按当前未归档的用例展示）；也可以按团队、测试能力、分类和关键词筛选已有用例。
2. 打开用例，检查团队责任、初始任务、输入需求、逐步预期、自动断言和人工核对项。编辑后保存才能影响后续运行。
3. 点击“批量运行”，勾选所需用例，或全选当前筛选结果（每批最多 1000 个用例），点击“配置运行”。选择最多 5 个模型；配置页显示组合数和计划调用数。模型列表可在“模型与 API”维护。
4. 点击“开始运行”发出真实模型请求。服务顺序执行全部组合；一个用例失败不阻止其他组合。支持多步骤用例；运行队列最多 5000 个用例与模型组合。模型须支持当前 PPIO Responses 接口。
5. 在运行报告查看同批模型对比，点击矩阵单元查看该模型的实际输出和逐项验收差异。可导出完整 JSON 报告。

## 结果口径

- 执行完成率：返回有效 JSON 且无调用错误的步骤 / 计划步骤，不代表语义正确。
- 断言达成率：通过断言 / 全部计划断言。未执行、字段缺失和未知不算通过。
- 自动达标率：结构与全部断言通过的用例 / 本模型计划用例。
- 最终验收：自动达标且人工语义核对通过；人工通过不能覆盖自动失败。
- 未返回 Token 用量显示未知。耗时为实际步骤调用耗时之和，包含失败调用，不是模型速度排名。

同批保存用例、团队和 Skill 内容快照，并固定判断时间。预期结果和验收断言不会发送给模型；前置条件漂移会阻止整个批次入队。编辑数据不会改变历史报告。重跑使用当前版本，形成新批次，不和旧批次混算。

## 分类管理

用例库顶部的“管理分类”支持新增名称和测试方向说明，以及编辑、重命名。空分类也会持久保存并出现在筛选和用例编辑器候选中；重命名同步更新当前用例的分类和版本，历史运行快照保持原样。编辑用例时可以选已有分类或输入新名称。

新增 150 条用例覆盖 10 个行业团队，每个团队 15 种边界变体：指定负责人、暂不分配、需求不明、不设日期、避免重开历史成果、父项目归属、三种状态下的独立进度、冲突纠正、资料权限、责任纠正、两种终态退出推荐，以及受阻时保留完成量。它们使用各团队实际的样例资料、人物、任务和事件，不以改名称代替场景变化。

## 基础样例

| 用例 | 重点 |
| --- | --- |
| 01 单一交付 | 一个脚本任务、匹配内容负责人、避免过度拆解 |
| 02 跨岗位交付 | 统筹加三个交付任务、按责任分工、独立验收 |
| 03 能力缺口 | 无合适成员时保持未分配，不虚构人员 |
| 04 查重复用 | 保留历史成果，同时覆盖新需求 |
| 05 决策冲突 | 识别旧文件与当前要求冲突，引用双方依据 |
| 06 执行阻塞 | 缺少当前必需输入且实际不能继续时判断阻塞 |
| 07 进度与状态 | 已知完成量独立于正式状态 |
| 08 核对撤销 | 保留有效已知量，撤销项未知，整体比例不沿用 |
| 09 范围变化 | 范围缩减与新增完成量分开计算 |

这些是可编辑的合成验收样例。首次升级仅追加一次，不覆盖原用例或重建用户删除的核心用例。团队数据仍可修改；运行前应检查是否适合发送至已配置的模型服务。

任务拆解专项：在分类中选择“任务拆解与分配”。新增 100 条覆盖 10 个行业团队，包含单一结果、平行交付、三层任务树、交付依赖、指定责任、暂不分配、范围排除、同义合并、多轮缩减与验收粒度。节点数与责任字段自动验证，层级、依赖和交付语义需按预期逐项人工核对。

## Skill 包和版本

Skill 管理中按文件查看入口、共享规则、引用契约和 few-shot。点击“编辑当前版本”可修改正文、新增相对路径文件、从草稿移除非入口文件；脚本作为文本资源保存，不自动执行。保存只创建新的不可变版本，不覆盖旧版本或工作区。每版记录来源版本、整包校验值与逐文件内容校验值；编辑时显示新增、修改、删除文件数量。重复路径、目录穿越、缺入口或无效 JSON 会拒绝保存。旧单文档版本仍兼容。

用例编辑器每一步分别选择“测试技能”和“Skill 版本”：跟随默认、工作区或明确保存版本。固定复现请选择明确保存版本；工作区内容会随代码改变，实际入队时仍固定快照。版本默认值变化只影响后续入队，已有队列和报告保持原包。

2026-09-23 的候选包增加当前 PRD 契约和六类 few-shot 正反例。它保留现有协议及校验器，并明确四层上限、关系确认、已确认责任域和独立进度语义。结构与版本测试不能代替真实模型语义验收，生产采用前应使用测试库完成选定模型的逐项验收。

## 两个 Skill 入口

当前 Skill 库仅展示“创建任务”和“任务分析”。前者覆盖理解、拆解、分配和方案调整；后者统一当前情况总结、进度和下一步建议，问题核对是分析的内部环节，工时计算作为内部引用。两个入口默认使用“双Skill整合版-2026-09-23”。旧版诊断、责任、排序和计算规则仅保留历史兼容，不再作为新用例的可选 Skill；已有固定版本用例与报告不自动改写。

## 基础创建范围

创建任务当前只测本次需求、团队成员和正式责任；模型输入中的历史任务、讨论、文件、活动及其引用和版本均为空。保留 103 条基础创建／拆解用例，需要历史复用或重规划的创建用例已归档，历史报告不变。新建用例默认基础创建模式；任务分析仍读取原有可见资料。多轮创建只保留本次草稿对话，不引入过往业务记录。

## 按团队创建测试运行

进入「测试运行」点击「创建测试运行」，依次选择团队、执行成员、创建任务或任务分析，批量勾选当前范围用例，再选择模型。全选只作用于当前筛选结果；切换团队、成员或类型会清空选择。运行前可展开每条用例的输入、预期及 Skill 版本。

运行列表每行代表一个批次。进入「查看结果」比较模型的完成率、断言达成率与最终验收，再点击某条结果查看输入需求、预期与实际输出及人工核对。

### 分步运行与分页

用例库仅用于搜索、筛选、导出及新增/维护用例；创建运行统一从「测试运行」进入。创建流程为选择团队与成员、分页选择用例、按厂商选择模型。用例库每页 20 条，运行用例选择每页 10 条，跨页保留勾选。

模型列表读取当前服务的完整模型目录并与本地配置合并，可按厂商和名称筛选。无法从 ID 识别的服务商别名不推断厂商。目录存在不等于账号有调用权限，也不代表所有模型支持当前文本测试协议。Codex / Claude Code 工具执行器尚未接入。
