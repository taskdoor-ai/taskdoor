# AgentDoor 任务中心化产品改造 TODO（历史草案）

> 本文由一次未经充分确认的实现尝试产生，其中“允许无 Owner 创建”和“Todo 迁移为 Task”与当前产品决策冲突。当前实施请以 [产品定义 V2](./product-v2/README.md) 和 [改造路线](./product-v2/08-delivery-roadmap.md) 为准。

> 基线：2026-08-26 会议纪要。目标是用“任务 + 文件”两个稳定对象，覆盖个人备忘到复杂团队协作。

## P0：本轮 Demo 闭环

- [x] 创建前展示可编辑草稿，AI 产出只作为建议。
- [x] 允许没有拥有者、参与者、文件和子任务的轻任务创建。
- [x] 创建按钮只校验任务名称，不以传统项目字段阻断用户。
- [x] 将创建流程中的“待办”统一表述为“子任务建议”。
- [x] 弱化周期和截止日期，默认使用“按需推进”。
- [x] 丰富成员 Mock：正式职责、动态职责、近期活动、当前工作和可投入情况。
- [x] 推荐人员时展示判断依据，并标记建议可删除、可改派。
- [x] 创建成功页兼容零成员、零文件、零子任务。

## P1：统一底层对象

- [ ] 将独立 Todo 数据迁移为带 `parentTaskId` 的 Task。
- [ ] 任务列表支持无限级父子关系、折叠和面包屑。
- [ ] 文件引用从目录归属中解耦，支持同一文件被多个任务引用。
- [ ] 文件增加远程引用、版本、权限、摘要和按需获取状态。
- [ ] 任务变更统一写入 Commit：字段修改、子任务变化、文件版本和责任变化。
- [ ] 建立 Decision Ledger，关联结论、证据、确认人和被替代版本。

## P1：AI 复杂度分流

- [ ] 输出内部复杂度指纹：目标清晰度、依赖数量、涉及角色、证据规模和风险。
- [ ] 轻任务默认只给标题和一条建议。
- [ ] 标准协作任务建议相关人员、文件和少量子任务。
- [ ] 复杂任务生成可删减的任务树、探索问题和阶段建议。
- [ ] 所有建议保留“接受 / 修改 / 暂不采用”的反馈，用于后续推荐。

## P1：动态职责与智能点将

- [ ] 区分正式职责、任务临时责任、AI 推断职责和代理关系。
- [ ] 从任务完成、文件审核、关键决策和历史交付周期生成职责证据。
- [ ] 推断职责具有置信度、有效期、证据和人工确认状态。
- [ ] 分配时轻量提示匹配原因、当前承诺和个性化工作量预估。
- [ ] AI 推断不得自动扩大成员权限或审批范围。

## P2：证据驱动推进

- [ ] AI 根据文件、动态、子任务和决策证据建议阶段变更。
- [ ] 阶段迁移由人确认，不依赖看板拖拽。
- [ ] 阶段结论自动形成可追溯 Commit，并生成下一阶段候选工作。
- [ ] 接入本地 Agent 时只传任务 File List 与必要上下文，不克隆完整文件树。

## 暂不开发

- 自定义视图和重型看板。
- 独立项目、计划、里程碑对象。
- 强制开始时间、截止日期和详细排期。
- 全量本地文件实时同步。
- 独立工作量管理模块。

## 验收场景

1. 输入“提醒我周五确认会议室”，不选人、不选文件、不拆任务即可创建。
2. 输入“三天内完成伙伴复训课”，AI 只给完成建议，用户可全部删除。
3. 输入“处理优惠券重复核销”，AI 推荐人员、文件和子任务，但创建不受这些建议约束。
4. 输入“大促整合营销”，任务能够通过子任务递归生长，不引入项目对象。
