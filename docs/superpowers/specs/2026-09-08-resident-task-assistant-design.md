# TaskDoor 常驻任务助手需求与设计

> 历史方案，已于 2026-09-16 撤回。产品负责人要求移除独立 AI 助手模块，恢复此前的创建任务流程；下文为历史设计与当时实施记录。当前决定见[产品决策台账](../../product-v2/09-decision-register.md)中的 `D-RESTORE-TASK-CREATION-2026-09-16`。

日期：2026-09-08。状态：本轮需求分析已获产品负责人同意，授权先写文档再开发。

实施状态：首版本地原型已开发；验证结果与未验收项见第 10 节及实施计划。

## 1. 对象、用户与目标

对象是当前团队内的 Task，子任务仍为 Task。面向创建者、负责人和参与者，在浏览页面时完成“了解情况 → 起草方案 → 更新任务 → 跟进结果”。解决创建、诊断、修改分散、分析后无法继续操作、任务背景反复交代的问题。

成功证据：用户能在右侧助手查询任务、汇报当前任务情况、确认并执行增删改；变化同步到原任务列表、详情和活动记录；切换页面不会改错任务，失败不会伪装成功。

## 2. 首版范围与后续范围

首版交付页面右侧固定入口、可收起侧栏、团队／单任务会话、任务查询与情况汇报、创建和批量拆分、字段修改、删除预览确认、文本文件辅助更新、方案修改和执行反馈。会话和草稿按当前用户、团队、任务范围保存。桌面页面与助手可同时操作，窄屏助手占满可用宽度。

现有项目是浏览器本地数据原型。首版读写现有本地任务数据并复用可恢复的存储事务。按 2026-09-15 用户要求，助手输入框与快捷入口统一运行本地演示，不调用真实 API，也不在无法识别输入时回退到模型。六个创建示例复用已有演示引擎，查询与汇报基于当前记录；超出演示支持范围时给出可继续操作的提示，不伪造理解或执行成功。真实生产服务的身份认证、服务端 ACL 和跨客户端同步不因本次原型开发而视为上线。

附件首版支持可读取的 Markdown、纯文本、CSV、JSON、HTML 文本；只在本次会话作为资料读取，不自动发布到共享任务文件。PDF、Office、图片的内容提取需要独立接入，选择不支持文件时说明原因，不伪装已读取。

后续范围：事件触发的持续分析、通知去重与解决回访、团队记忆、保存为参考、相对期限模板、生产权限与 MCP 接口。后台分析上线时必须同时交付提醒和结果回访，不先做无闭环的主动提示。

## 3. 最小布局

右侧固定“TaskDoor 助手”入口；展开侧栏包含：

1. 标题与右侧操作：依次为“新建对话”、历史对话、收起。新建对话使用方框铅笔图标，并提供悬停提示和可访问名称；输入框移除创建任务的“＋”，工具顺序为“@ 引用任务、附件”。
2. 统一助手标题：所有页面均展示“TaskDoor 助手”，标题下以灰色单行说明展示团队名；任务详情页不改成任务名，不展示“返回团队”或独立范围卡片。团队名超长时省略并可悬停查看全名；具体任务在汇报入口、用户请求和结果中明确。
3. 对话正文：文本结论、可进入详情的任务列表、可编辑的变更方案、真实执行结果。
4. 输入与附件：自然语言继续处理，上传资料辅助提取。点击 @ 或在光标处输入 @ 展示可搜索的当前团队任务列表；选择后仅插入引用，用户发送后再处理。引用保留 Task ID，随草稿和历史恢复；不跳转页面、不切换会话、不把引用当成修改授权。
5. 空会话快捷动作：任务情况、查询我的任务、整理我的工作等少量与范围相关的动作。发送后不重复铺设能力卡片。

以上均来自当前页面、任务数据或本次会话。复用标准列表、按钮、表单与现有设计 token，不新增仪表盘、评分、地图或助手内的重复图表。

## 4. 上下文与会话

- 团队范围支持当前可见团队任务的检索、汇报和批量处理，不能越过团队边界。
- 任务范围以明确 Task ID 绑定；读取自身与有权可见的相关子任务、依赖及所需资料。查询其他任务可以显式指定。
- 页面从 A 切到 B，不自动替换正在处理 A 的会话。标题始终显示团队名，不增加任务专属标题或“切换到当前页面任务”提示条；任务对象在请求与结果中明确，A 的草稿仍保留在 A 的会话中。
- 团队切换隔离会话、上传资料、未执行方案；迟到的响应不能写入另一个团队。
- 新建对话保留当前团队或任务范围，显示空会话与快捷入口，聚焦输入框。原消息、未确认方案、输入草稿和附件完整保存在历史，不带入新对话的上下文；空白对话重复新建不制造多条空历史。处理中点击新建会停止旧请求，迟到响应不得写入新对话；文件读取期间暂不可新建。
- 历史作为独立视图占满助手正文区域；打开时隐藏欢迎页、聊天正文、页面范围切换提示和输入框，不与新对话叠在一起。提供“返回对话”，再次点历史图标或按 Escape 也返回当前会话。
- 历史以首条用户消息为标题，附范围和待确认方案提示。纯空白会话不列入历史；未发送的输入或附件以草稿保留。点击记录后退出历史视图，恢复原消息、方案、步骤、输入和附件，可接着聊天。恢复旧对话时先保留当前对话，同一方案只保留一份可操作记录，仍须经过快照检查和用户确认。刷新后可以继续恢复，旧版按范围保存的历史兼容。
- 关闭面板不丢输入、方案或对话，也不重复发出请求。刷新恢复已保存会话；中断请求标记可重试，不能显示已执行。
- 个人对话默认本人可见。任务更新进入共享任务事实，分析不自动发布为团队讨论。

## 5. 能力与闭环

| 能力 | 输入示例 | 输出与后续 |
| --- | --- | --- |
| 查询 | 我有哪些进行中的任务、本周到期的任务 | 明确筛选范围的列表，可进入任务，空结果不伪造任务 |
| 情况汇报 | 这个任务现在怎么样 | 状态、近期记录、已知进度、阻碍、下一步，保留依据链接和检查时间 |
| 创建／拆分 | 创建周报；按 15 个产出物拆成子任务 | 可编辑草稿，确认后写入，保持当前父任务和团队 |
| 修改 | 将这三个任务延期到周五 | 精确目标及旧值／新值，确认后记录活动并同步页面 |
| 删除 | 删除主任务及其子任务 | 展示主任务，默认展开「子任务」名单；数量仅在卡片标题展示，按钮固定为「确认删除」。确认后删除整个任务树，并移除其他任务对它们的前置依赖；其他任务保留。 |
| 文件更新 | 根据会议纪要更新当前任务 | 资料提取形成方案；支持继续对话修改，确认后写入 |

任务情况中的人工记录与 AI 估计分开；未知进度不补 0%，状态“已完成”不自动等于正式验收完成。没有排期／工作量基准时不能仅按时间流逝推断落后。诊断作为情况分析子能力；展示结论、依据与拟执行动作，不展示模型内部思考链。依赖是参考关系，前置未完成不自动标阻塞。

## 6. 变更与确认

- 查询、分析和草稿生成直接执行。明确单项低风险命令可直接执行的产品原则保留；首版涉及写入统一使用紧凑变更预览，避免本地解析或模型推断跳过核对。
- 批量创建、人员分配、从资料推断的更新：一次审阅后统一执行。继续对话可改方案，原方案应被标记替代，不能反复点击执行。
- 创建没有指定负责人时归创建者；指定当前团队成员并确认后直接分配，不生成接收方 inbox 二次确认。存量离职交接可暂空，不把此规则扩大为任意清空有效负责人。
- 删除展示明确影响；不凭模糊匹配删除。有多项同名候选时先让用户定位。
- 执行前核对当前任务、团队、人员和方案涉及的数据快照。过期方案要求重新生成／核对，不能覆盖新数据。
- 批量先完整校验再作为一个本地事务保存，失败保留方案且不发布内存成功态。防止双击、刷新后重复执行；结果中提供操作明细与任务链接。
- 创建、修改及删除引起的关联变化记录为任务活动；AI 对话本身不自动写入讨论。

## 7. 已确认替换关系与迁移

本次用户同意前轮分析并授权实施，以下作为本轮产品规则：

1. 常驻助手统一承接任务分析和后续动作，替代 D-191／D-192 对诊断只能只读且无后续处理的限制。现有诊断入口在迁移期间可作为带上下文唤起助手的快捷入口，原分析算法可复用。
2. 本次助手经创建者确认的创建／分配采用直接指派与创建者兜底，局部替代 D-189 在此创建路径中的默认空负责人及提议／接受要求。存量责任历史与其他旧入口不做隐式批量迁移。
3. 现有创建页和手工字段编辑继续可用；助手操作复用同一任务事实。外部“连接 AI”仍是外部工具连接，与内置助手区分。
4. 事件通知和任务参考按本文件第二节分期，不能把后续设计描述为已经接入。

## 8. 状态要求

正常：结果可继续操作。空：明确无结果并保留输入。加载：显示实际处理中，可停止；不编造已检查步骤。失败：说明未执行，保留输入、资料和方案并可重试。无权限／不可见：拒绝引用或修改，不能泄露内容。过期：标明方案需重新核对。移动端：侧栏全宽、输入可用、可返回。键盘：入口和所有动作可聚焦，Escape 收起并恢复入口焦点；输入支持 Enter 发送、Shift+Enter 换行及中文输入法组合态。

2026-09-15 补充：助手的团队／任务欢迎页在常用操作下方增加“创建任务示例（用于演示）”，复用原创建页的六个示例（单任务、复杂项目、需求不明确、相似任务、关联已有任务、负责人待定）。常用操作采用单列布局，示例保持紧凑两列布局，示例按钮显示场景及说明。点击只把需求填入团队范围的新对话，可修改后发送；发送后由本地演示引擎生成草稿，沿用澄清、关系选择和确认保存流程。相似或关联候选必须匹配当前团队的实际任务 ID，缺失时如实说明。原团队会话、个人草稿及附件保留到历史，当前任务会话不受影响；连续切换未修改的示例不制造多余历史。窄屏允许内容区滚动，输入区保持可用，按钮支持键盘聚焦与选中状态。

数据依赖：当前团队／用户、团队可见 Task 与成员、任务定义／状态／期限、现有任务资料及活动、版本快照、本地可恢复事务。运行演示不需要模型服务配置。读取和变更必须使用同一组实际任务 ID；生成方案与确认写入分开处理。

- A 任务对话中打开 B 页面，确认修改仍只影响 A。
- 切换团队后看不到另一团队会话；旧请求不能在新团队落入方案。
- 创建 15 个子任务，预览可修改名称、负责人、日期；确认一次后生成 15 个，重复点击不产生重复记录。
- 修改任务后原列表、详情、活动一致；存储失败不显示成功。
- 删除父任务时列出后代与依赖影响；范围变化使旧确认失效。
- 输入框与快捷入口均不请求真实 API；六个创建场景及连续澄清可用，无法识别的指令如实说明，不能伪造完成。
- 文件内容可以参与方案，失败保留原资料；不支持格式明确提示。
- 收起、刷新后能找回会话与草稿，过期草稿不可直接覆盖当前任务。
- 仅运行新助手关键行为及直接关联的最小验证，再做 TypeScript／构建与浏览器主流程检查；不运行全量测试或双重审查。

## 10. 本轮实现与交付边界

已实现右侧常驻入口与可收起面板、用户／团队／任务会话、统一的本地演示入口、查询与情况汇报、可编辑的增删改和批量子任务方案、文本资料辅助、确认提交、去重及失败回滚。通过常驻助手内带任务名称的汇报入口查看情况，任务详情顶部不再重复放置“任务情况”按钮。已保存的诊断与文件摘要参与报告；主结论简短展示，完整依据折叠保留。已有演示账本进度注明来源与截至日期，不充作实时进度或 AI 估计。

创建方案支持负责人、期限、完成标准与父子关系，确认后直接写入同一任务状态并记录活动。所有首版写入均须确认；事务层校验生成的方案，响应生成器不直接操作存储。未知成员、跨团队任务、不合法日期／依赖和过期方案会被拒绝。支持 15 个子任务完整批量准备、事务失败回滚与同一方案重复提交去重。

验证：26 项助手测试及 10 项直接关联诊断渲染测试通过，构建通过；浏览器已检查查询、报告、草稿、切页范围、桌面／窄屏及键盘收起恢复。另有 6 项旧工作区渲染测试与本轮开始前的工作区改动不一致，保留并记录于实施计划。实际浏览器“确认执行”因自动审批认为未授权创建该测试数据而被拦截，写入链路改用隔离内存测试完成；实际保存后的浏览器刷新未验收。

2026-09-15 本地演示切换验证：19 项相关测试及应用 TypeScript 检查通过，覆盖六个创建场景、连续澄清、关联后修改、无网络回退、取消、查询汇报、个人排序和隔离内存中的确认写入。浏览器已验证复杂项目生成八项草稿，以及目标、交付两轮澄清后生成可编辑方案；保留确认环节，未写入页面测试任务。

首版仍使用当前浏览器的原型数据与会话存储，不提供跨用户共享、跨标签页事务锁或跨设备同步。助手已移除前端真实模型请求路径；历史服务端模型代码不参与当前助手演示。处理时显示本地流程的步骤与实际完成结果，可取消；完成后保留可展开的步骤记录，不展示或模拟模型内部推理。后台事件通知、接收方 new 标记、团队记忆／保存为参考、PDF／Office／图片提取、生产权限及 MCP 服务端按后续阶段推进。

### 2026-09-15：处理过程与完成回看

沿用回复正文上方的轻量处理行，不另加卡片或助手署名。创建任务复用原创建页的业务步骤：分析任务（目标与交付范围）、目标与计划（主子任务拆解、完成标准、执行建议与预计投入）、成员推荐（草稿中的负责人建议与参与安排）、动态规划（截止安排与前置依赖）。完成记录列出对应草稿中的实际任务数量、任务名和人选。当前以固定 Mock 草稿逐步演示，不进行真实查重、人员匹配或模型调用。查询与汇报保留各自的信息整理过程。

- 加载时默认展开紧凑步骤列表，标明处理中、已完成、待处理；用户可随时收起或停止。
- 创建草稿处理完成后自动收起为“处理完成 · 4/4 步”，点击或键盘 Enter / Space 展开各步结果。原始依据在展开内容底部继续折叠，正文直接呈现结论。不展示“本地演示 · 步骤记录随本轮对话保存”说明。
- 需求不明确时仅保留“核对必要信息”；相似／关联示例停在“分析任务 → 核对任务关系”，记录等待用户的选择，不把后续拆解和找人显示为已完成。“处理完成”不等于任务已创建。草稿仍需最终确认。
- 中途停止或失败保留已完成的步骤，当前步骤标为已停止／未完成，后续仍为待处理，不伪装成已完成。可在保留的输入上修改后重发。
- 步骤与本轮回复一起保存。刷新、切换范围、新建或恢复历史不丢失；刷新时尚在运行的记录转为已中断，恢复原输入。新对话不接收旧请求的迟到结果。
- 历史回复若未保存步骤，不补造过程：展开时展示原有依据，或说明“这条历史回复未保存处理步骤”。
- 窄窗口按单列显示，长摘要换行；阶段状态由辅助技术播报，减少动态效果时关闭旋转动画。

### 2026-09-15：创建方案的主次布局与固定演示

创建方案沿用原创建页面的主任务与子任务分区。依据草稿的父子引用组织，不把“第一项”一律当作主任务：主任务默认展开，显示整体目标；所属子任务另起浅底区域，以白色紧凑列表展示名称和负责人，逐项展开修改。关联到已有任务的单项明确标为子任务。所有操作继续放在方案卡片内。

- 每项展开后，顶部显示负责人头像与姓名、唯一的截止时间入口和参与人。负责人复用人员选择控件；收起的子任务行也显示负责人头像。参与人复用原有头像组，可查看更多、添加或移除。头像宽高、最小宽高与布局占位统一为 28px，保持圆形；收起行使用 22px。成员名称不带“我”，换负责人时从参与人中排除同一成员。
- 对话中主任务、子任务及负责人变更方案的人员列表复用系统 PersonPicker：搜索姓名／职责／邮箱、圆形头像、姓名、匹配百分比、建议理由与选中状态。按匹配度排序，理由通过星芒按钮查看；当前匹配度及说明使用固定演示数据，修改任务不触发真实匹配，未配置演示数据的成员不补造分数。参与人可多选或暂不分配，选择仅更新草稿；邀请入口保持隐藏，空选项说明为“暂时留空，之后可以再选择成员”。
- 主内容直接显示目标、完成标准、执行建议、预计投入。子任务的主目标保持继承，以一行折叠入口查看，不重复展开大段目标。
- 主任务和子任务的标签直接放在顶部参与人下方，沿用系统标签颜色与图标。移除“更多信息”折叠区及其投入依据、长引用说明；展开的草稿标题行用关闭图标保留移除操作，被子任务或前置依赖引用时禁用并提示原因。创建方案与卡片内的人员选择弹层移除邀请入口；没有匹配成员时展示空结果。截止时间仅在顶部修改。
- 固定示例保留原有 Mock 投入估算；主任务仅汇总后代叶子任务，不重复计入主任务。信息缺失显示待评估，交付范围修改后原估算需复核。
- 创建示例按预设场景展示。普通单任务、复杂项目不根据实际任务名称临时查重，不因之前演示创建过同名任务而跳到其他分支。相似和关联选择仅出现在对应的固定示例；仍校验引用可用、草稿结构和用户最终确认，未接入真实模型。
- 历史草稿也使用新布局，已保存的字段不凭空补值。纯交互稿 `assistant-creation-interactions.html` 同步主子任务分区及字段布局；模板选择仍需用户选择、调整草稿后最终确认。
