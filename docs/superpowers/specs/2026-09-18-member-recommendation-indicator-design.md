# 成员推荐度图标设计

## 对象与目标

- **对象：** Task 负责人和参与人选择器中的成员推荐提示。
- **用户：** 正在为 Task 选择负责人与参与人的团队成员。
- **本次决策：** 移除常驻百分比，用同形星芒的颜色强弱表达三档推荐度。
- **成功证据：** 用户无需读取数字即可快速感知推荐强弱；不会把推荐度误解为人员排名；鼠标、键盘和辅助技术均能取得准确说明。

## 展示规则

1. 每位具有推荐结果的成员只显示一个 `Sparkles` 星芒图标，不显示百分比、常驻等级文字或图例。
2. 三档图标的形状、尺寸和星芒数量完全相同，只使用同一紫色语义的深、中、浅区分推荐度；不使用红黄绿，避免把推荐度误读为人员状态或绩效。
3. 推荐档位为 `high / medium / low`。它表达系统对本次 Task 人选的推荐程度，不表达成员能力，也不形成第一名、第二名等名次。
4. 鼠标悬浮或键盘聚焦图标时显示 Tooltip。Tooltip 先说明“推荐度较高 / 推荐度适中 / 推荐度较低”，再显示当前已有的具体推荐理由。
5. 图标按钮的无障碍名称包含成员姓名和推荐程度；推荐理由继续由 Tooltip 提供。触摸设备点击图标可打开同一提示。
6. 成员排序仍按内部推荐依据排列，同档成员保持原始团队顺序；界面不暴露精确分数。
7. 已选成员只显示 Combobox 勾选，不同时显示推荐度星芒；取消选择后恢复星芒。

## 档位生成

当前原型继续使用任务描述与正式责任文本的直接命中作为演示依据，但不把命中数量伪装成精确概率：

- `high`：至少三项直接命中；
- `medium`：一至两项直接命中；
- `low`：没有直接命中，推荐理由明确提示需要结合实际经验与可用时间核对。

内部可以保留命中数量用于稳定排序，但组件只接收档位和理由，不再依赖或渲染百分比。

## 状态与边界

- 没有推荐结果时不显示星芒，不把未知显示成低推荐。
- 成员处于邀请中、不可见或范围选项时，沿用现有规则，不显示推荐度。
- 推荐理由缺失时不显示一个无法解释的推荐图标。
- 深色主题和高对比度下仍使用既有设计 Token 派生三档颜色；焦点环不随推荐档位变浅。
- 推荐度变化只更新图标颜色和 Tooltip，不自动选择、取消选择或分配人员。

## 最小验证

- 单元测试覆盖三档生成、同档稳定排序和无直接命中不再得到中档。
- 渲染测试确认百分比消失，三档使用同一个 `Sparkles` 图形，并具有推荐程度、成员姓名和理由。
- 键盘聚焦检查 Tooltip 可打开且焦点清晰；不运行与本改动无关的全量测试。
