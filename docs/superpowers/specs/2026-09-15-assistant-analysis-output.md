# 助手分析的目的与输出模板

日期：2026-09-15。依据本轮用户要求，替代旧稿中分开的情况汇报／诊断入口及“全部任务排优先级”的入口说明。

## 入口与目的

| 入口 | 说明 | 用户读完要能决定什么 |
| --- | --- | --- |
| 汇报「任务名称」的情况 | 看看最近的进展，有哪些值得关注的事 | 近期有什么变化，有哪些需要进一步判断的事及其影响 |
| 整理我的工作 | 找出你最近需要关注的任务，决定先做什么 | 当前用户应该先关注哪件事，为什么，以及从哪里开始 |

任务汇报绑定对话的任务 ID；个人工作覆盖当前团队中本人负责或参与的全部未完成、未取消任务，不受页面任务或列表筛选限制。分析只给建议，不自动修改任务或联系成员。

## 任务汇报模板

### 本次调整解决什么

用户在助手小窗口中查看汇报，需要快速知道最近推进了什么，以及有哪些需要判断或协调的事。原实现把活动长文、冲突长标题、文件名、逐字段依据、影响和建议全部平铺；记录一多，重点被原文挤走。详情已有的状态、进度和日常下一步无需再抄一遍。

### 展示顺序与内容

1. **任务名称、范围与一句重点**：名称只在标题显示一次；标明近期范围（默认截至检查日的近 7 个自然日）、是否包含子任务。概括当前有依据的主要关注点；不能从没有发现推断一切正常。
2. **值得关注**：有依据才出现。先显示实际阻碍，再显示待核对冲突与协作问题，默认最多 3 项；更多事项每次展开 3 项，也可收起。每项使用统一的短标题、必要的差异事实、影响、针对性建议。例如：

   ```text
   1  行动项 A03 的交付日期不一致       待核对
      交付日期：9/18 与 9/17
      影响  当前资料不能作为一致的执行口径。
      建议  核对两份记录，统一适用日期后再执行。
      › 查看依据                         2 条
   ```

   文件名、完整结论、双方记录及原始取值均在该项的「查看依据」内，默认收起；不能为了简短而删除另一方依据。仅当已有事实采用明确的“核对项／取值”结构，才提炼主文的差异；无结构时保留原意，不猜取值。标签「待核对／执行受阻」为次级文字，不能把潜在风险画成已阻塞。当前任务名不反复出现，子任务发现额外注明所属任务。
3. **近期进展**：重点是变化摘要，不是完整活动流水。默认列 3 条，按记录时间倒序，其他记录每次展开 5 条，显示剩余数量；展开后可以收回。每条先显示变化文字，再用小字显示日期、子任务来源；点击这一行可以看完整记录。去重限定同一任务、同一时间分组、相同文字，不跨任务合并相似内容。长文只缩略展示，完整原文始终保留。

### 内容很多、内容不足时

- 近 7 天很多：默认数量不增加，不把几十条原文一次性塞进聊天；展开按钮显示剩余条数。
- 重复动态：合并展示并注明合并数量，处理记录里保留全部原始动态。
- 7 天以前的记录：「更早的记录」默认折叠，不混入近期进展；其中尚未解决、有依据的关注事项仍可纳入上方分析。
- 日期无法识别或晚于检查日：「日期待核对的记录」单独收起，不冒充最近已发生的工作。
- 无关注事项：省略整个栏目，不补“无冲突／无阻碍”。
- 无近期动态：不能写成“最近没工作”。有关注事项时照常分析；资料整体不足时用一句话说明无法补充判断。
- 证据不完整：在依据展开区说明限制，不能伪造第二份资料或自动形成最终决策。

### 交互与依据

状态、负责人、截止时间、进度表和通用下一步继续由任务详情承载。汇报只引用解释发现必需的字段；不新增一份状态卡、日程表或固定五段诊断。所有分析 actions=[]，不自动修改任务、指派人员或发送提醒。

加载及失败沿用本轮处理步骤。处理完成后仍可展开查看步骤；「查看依据与原始记录」保留完整快照。相关任务继续使用折叠链接。小屏使用单列列表、细分隔线，原文折叠区不横向溢出；展开与收起按钮支持键盘，移动端保留触摸目标。

新汇报将结构化内容和本次对话一同保存，从历史打开时按当时快照展示，不拿最新任务数据偷偷重算旧报告。旧版纯文本历史继续可读，并将原有引用依据默认折叠；不伪造旧报告未保存的时间范围或剩余条数。

当前仍是本地演示：使用已有动态、已有发现和确定性的去重／文字缩略，不调用真实模型，不把文字截取宣称为 AI 语义归纳。后续语义归纳也必须保留每条摘要对应的原始记录，并以同一主题／交付而非纯时间机械分组。

## 我的工作模板

开头：`截至 {日期}，在 {团队} 中，你负责或参与的 {N} 项工作尚未完成。下面按近期关注的建议顺序排列。`

输出为有序列表，每项固定展示：

```text
1 任务名称（点击进入任务）
   负责人 · 当前状态 · 截止日期（未设置时如实说明）
   依据：一个关键问题，加一项最相关的紧迫原因；通常 1—2 行。
```

个人工作列表只展示任务信息与依据，移除“建议先做”及其内容。依据标签与正文同行，优先保留具体问题，再补充逾期、已阻塞等最相关的一项事实；没有具体问题时最多列两项关键理由。省去“已保存分析”等前缀，不重复上方完整截止日期，也不拼接全部优先级和依赖信息。原对话数据保留，旧历史采用同样的简洁展示，不重算历史排序。用户需要的是可核对的判断摘要，不是模型内部思维过程；资料不足如实说明，前置未完成不说成已阻塞。

排序同时考虑有效期限、已记录阻塞、决策冲突、已有高优先级标记、下游依赖影响及待审核事项。没有依据时明确重要性／紧急性待判断。保留现有确定性排序，在原有字段排序上补充已保存问题的影响：实际阻塞信号取一次最高值，待核对冲突／问题增加关注信号；同一问题不重复累加。该顺序是当前资料下的建议，不代表经过校准的最优排程，不改变正式任务优先级。

所有合格任务按 ID 去重并保留完整顺序；“最近关注”不是仅筛选最近新建或本周到期的任务。依据优先使用已保存的具体问题。调整建议顺序不修改任务字段。

## 数据与验收

复用当前任务字段、成员、活动、进度摘要以及已有诊断的结构化发现（类型、结论、影响、建议、证据）。团队页面也须提供这组分析资料，不能只有打开某个任务详情才能得到个人关注理由。

输入框和快捷入口共用本地演示输出与同一模板，不请求真实模型 API。报告依据当前字段及已保存的记录和分析资料，不声称进行了新的模型推断。旧历史可继续读取；不存在或无权查看的任务不得出现在结果中。读取资料失败时不伪装成空结果，旧报告不宣称是新分析。

最小验证覆盖：近 7 天边界、重复记录与跨任务区分、更多进展不丢失、更早和日期异常分组、关注事项及双侧证据保留、无发现不生成状态表和通用建议、缺资料不等于正常、个人候选与排序理由、同名任务按 ID 定位、结构化历史快照恢复。只运行相关测试和类型检查，不运行全量测试。
