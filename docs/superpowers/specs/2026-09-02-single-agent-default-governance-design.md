# AgentDoor 默认单 Agent 执行规则设计

日期：2026-09-02  
状态：待产品负责人书面审阅

## 问题

项目治理文档允许把工作拆给多个 Agent，并允许按风险自动增加非作者 Reviewer。与当前会话的主动多 Agent 调度叠加后，即使是局部小改动，也可能产生不必要的并行定位、独立复核和整合等待，使流程与任务规模不相称。

## 已确认方向

AgentDoor 项目默认由当前 Agent 单线程完成。任务可并行、较复杂或存在多个检查面，都不能单独构成创建子 Agent 或 Review Agent 的授权。只有用户在当前任务中明确要求使用子 Agent、并行执行或独立 Review 时，才可以创建对应 Agent。

## 修改范围

1. 在 `AGENTS.md` 增加直接执行约束：默认单 Agent；没有用户明确要求时，不创建子 Agent、Review Agent，也不把普通验证包装成独立 Review。
2. 从项目工作宪章中删除允许 AI 调度多个 Agent、把工作拆给子 Agent以及自动增加非作者 Reviewer 的执行规则。
3. 从精简工作流程中删除按 C2/C3 自动增加非作者 Reviewer 的要求，保留当前执行者的必要自检、最小充分测试，以及用户明确要求的独立审查。
4. 同步治理 Revision 与决策台账，避免旧规则继续作为可执行依据。

## 保留边界

- 不删除产品中的多人协作、Participant、Task Owner、Handoff 等业务能力定义。
- 不取消用户、产品负责人或安全审批工具必须作出的决定。
- 不取消作者自检、相关测试、失败说明和高风险动作的确认要求。
- 不修改全局或系统级指令；项目规则只约束 AgentDoor 工作区内的默认执行方式。

## 验收

- 项目执行规则不再授权自动创建子 Agent 或 Review Agent。
- `AGENTS.md` 明确要求：除非用户当前任务中明确授权，否则始终单 Agent 执行。
- C0-C3 仍按风险选择验证强度，但风险升级不会自动转化为创建 Reviewer Agent。
- 搜索项目级规范时，不再出现与上述默认规则冲突的执行条款；历史工作记录和产品研究材料不作追溯改写。
