# 新建任务 Mock 移除执行建议设计

> 2026-09-03 用户决定更新：创建任务时恢复「执行建议」，位于完成标准下方、预计投入之前。主任务和展开子任务复用现有 `executionTips` 数据，支持编辑、清空及随任务保存；空值只提供选填入口，不编造建议。此更新替代本文关于创建页隐藏执行建议的决定，不改变已创建任务详情页的展示。

## 背景

新建任务的 Mock 规划结果当前会为主任务和子任务生成 `executionTips`，并在方案确认界面展示“执行建议”折叠区。此次调整用于精简 Mock 测试体验：新建任务只保留目标、完成标准、预计投入、人员和依赖等必要信息，不再生成或展示执行建议。

## 目标

- 新建任务 Mock 的主任务和子任务界面不再出现“执行建议”。
- Mock 规划结果不再产生可见的执行建议内容。
- 新建任务的 Mock 过程说明不再宣称会整理执行建议。
- 保持既有任务与持久化数据兼容。

## 非目标

- 不删除共享任务模型或 `TaskDraft` 中的 `executionTips` 字段。
- 不迁移、清空或改写既有任务中的执行建议数据。
- 不改变既有任务详情、AI 调整或其他非新建任务流程的字段契约。

## 交互与展示

新建任务方案确认界面中，主任务和展开后的子任务均不渲染“执行建议”折叠区。页面不会用空状态或其他模块替代该区域；完成标准之后直接进入预计投入或后续属性。

该规则仅作用于新建任务体验。共享任务字段组件仍可为其他调用方保留执行建议能力，但新建任务调用方显式关闭该能力。

## Mock 数据与兼容策略

Mock 规划器和新建任务示例初始化时，将主任务及子任务的 `executionTips` 设为空数组，不再填充演示文案。新建任务表单内部仍保留该字段，以兼容现有类型、序列化和后续接入真实规划器时的旧数据。

保存新任务时继续按现有规则序列化 `executionTips`；在本次 Mock 流程中其值为空数组。这样无需数据迁移，也不会改变已有数据读取能力。

## 文案调整

新建任务 Mock 的过程反馈中，将“整理目标、完成标准、执行建议与预估人类投入”收敛为“整理目标、完成标准与预估人类投入”。其他页面和既有任务文案不在本次范围内。

## 验证

采用最小必要验证：

- 新建任务主任务区域不出现“执行建议”。
- 展开子任务后不出现“执行建议”。
- Mock 规划结果的主任务和子任务 `executionTips` 为空。
- 新建任务过程反馈不再包含“执行建议”。
- 既有序列化契约仍保留 `executionTips` 字段。
