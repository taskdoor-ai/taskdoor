# 侧边栏新建对话与任务创建设计

## 背景与目标

在现有左侧窄导航栏中，团队图标下方、首页入口上方增加“新建对话”入口。用户通过自然语言描述想推进的事情，系统以对话方式补齐信息，生成可编辑的任务草案，并在用户明确确认后创建正式任务。

本次设计恢复一条经用户明确确认的任务创建路径，替代当前“任务意图输入壳不提交”的限制；现有任务列表、任务详情、单一负责人、参与人和标签模型继续复用。

## 已选方案

采用“独立对话页 + 消息流内嵌结构化草案卡”。

未采用独立确认页，因为页面跳转会打断对话上下文；未采用右侧常驻草案面板，因为它会显著压缩内容宽度，并增加移动端适配成本。

## 导航与页面结构

- 左侧窄导航栏在团队图标与首页按钮之间增加新建对话按钮。
- 按钮使用对话加号图标，提供 `aria-label`、标题提示、键盘焦点态和与其他一级入口一致的激活态。
- 点击后把主内容区切换到新的 `conversation` 一级区段，并关闭移动端导航抽屉。
- 新建对话页初始显示简短引导语，底部输入框自动获得焦点。
- 输入框支持多行；Enter 发送，Shift+Enter 换行。空内容不可发送。
- 页面采用居中单列消息流，输入区粘附在主内容区底部；移动端包含安全区内边距。

## 对话与草案交互

第一版使用可预测的本地演示流程，不伪装成已接入真实模型：

1. 用户发送需求，消息进入对话流。
2. 系统根据当前内容生成一次补充提问或任务草案。
3. 信息不足时优先追问影响创建的关键字段；演示流程至少允许用户继续补充一轮。
4. 信息足够后，在消息流中展示任务草案卡。
5. 用户可直接编辑草案字段，或通过“继续调整”返回输入框继续描述修改。
6. 只有点击“确认创建”才写入正式任务。
7. 创建成功后显示成功回执，提供“查看任务”入口，并清理当前待创建草案，避免重复提交。

## 任务草案字段

草案包含：

- 任务名称（必填）
- 任务目标（必填）
- 负责人（必填，默认当前用户）
- 参与人（可选，不包含负责人）
- 开始时间（可选）
- 截止时间（可选；若两者都有，不能早于开始时间）
- 标签（可选，复用当前扁平标签目录）

草案卡复用现有成员选择、标签选择和日期控件的视觉与数据约定，不引入父任务、附件或关联任务。

## 组件边界

- `WorkspaceSidebar`：只负责入口展示和导航事件，不持有对话状态。
- `TaskCreationConversation`：负责消息列表、输入框、草案阶段和成功回执。
- `TaskDraftCard`：负责草案字段编辑、校验与确认事件，不直接写入任务数据。
- `App`：持有当前一级区段，接收已校验草案，将其转换为现有 `TaskNode` 并写入 `workspaceNodes`，随后负责打开任务详情。

这样可以把会话表现、草案编辑和正式写入分开，防止输入消息或未确认草案意外成为正式任务。

## 数据流与持久化

- 对话消息和未确认草案只保存在当前 React 会话状态中；刷新页面后不恢复。
- 正式创建继续写入现有 `workspaceNodes` 状态，并通过现有 localStorage 持久化机制保存。
- 新任务 ID 在确认时生成；确认前不分配正式 ID，不写活动记录，也不触发负责人或参与人语义。
- 创建后的任务状态使用现有默认初始状态；负责人默认当前用户，可在草案中更换。
- 参与人邀请在当前本地原型中记录为待确认状态，不表现为对方已接受任务。

## 异常与边界处理

- 任务名称或目标为空时，确认按钮不可提交，并在字段附近说明原因。
- 截止时间早于开始时间时阻止创建。
- 负责人不得同时出现在参与人列表中；更换负责人后自动从参与人中移除该成员。
- 连续点击确认通过提交锁避免重复创建。
- 写入失败时保留草案并显示可重试错误，不清空用户输入。
- 离开未完成对话时，第一版不弹阻断确认；切回后在同一前端会话内保留内容。

## 可访问性与响应式

- 新入口、发送按钮、草案操作均可通过键盘使用，并有可见焦点态。
- 消息列表使用适当的日志语义，新消息通过非打断式 live region 通知。
- 自动聚焦只发生在用户主动进入新建对话页时，避免导航后抢夺屏幕阅读器焦点。
- 小屏幕下草案字段改为单列，底部输入区不遮挡最后一条消息。

## 验收标准

1. 截图红框对应位置出现新建对话入口，桌面和移动端均可用。
2. 点击入口进入独立对话页并聚焦输入框。
3. 输入非空内容可以发送；Enter 发送，Shift+Enter 换行。
4. 对话可产生包含七类字段的可编辑任务草案。
5. 未点击确认前，任务列表和 localStorage 中不出现新任务。
6. 必填字段和日期校验通过后，确认创建只生成一条任务。
7. 创建成功后可跳转到该任务详情，并能在任务列表中找到它。
8. 现有首页、任务、连接 AI、通知、主题和个人设置入口不受影响。

## 验证计划

- 运行 TypeScript 构建和现有设计检查。
- 手工验证桌面端入口、键盘发送、草案编辑、确认创建和详情跳转。
- 手工验证窄屏导航抽屉、单列草案和底部输入区。
- 回归检查现有一级导航、任务列表筛选和任务详情。

## 非目标

- 不接入真实 AI 服务或流式回复。
- 不保存或展示历史对话列表。
- 不支持附件、父任务、关联任务或复杂拆分。
- 不向真实成员发送通知或邀请。
- 不修改独立 MCP 的任务创建契约。
