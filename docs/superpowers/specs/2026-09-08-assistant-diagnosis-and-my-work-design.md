# 助手内的任务诊断与个人工作建议

日期：2026-09-08。状态：设计草案，待评审；本轮不修改应用代码。

更新：本文件保留早期讨论。2026-09-15 用户已要求诊断合入任务汇报，并明确个人关注列表须直接说明排序原因；当前入口、输出及实现以[助手分析的目的与输出模板](./2026-09-15-assistant-analysis-output.md)为准。

逐步操作、确认边界、异常状态和样式尺寸见[助手交互流程、规则与视觉规范](./2026-09-08-assistant-interaction-spec.md)。本文件保留能力范围与总体方案，具体交互以该规范为准。

用户已明确的方向：AI 诊断、当前用户值得关注的任务、“今天干点啥”及重要／紧急程度分析，都应在右侧常驻助手中支持。本文件给出入口、范围、结果与后续操作设计；新增呈现和迁移细节尚未视为已批准实施。

## 1. 产品定位与本轮判断

同一个助手承担两层工作：跨任务帮助用户选择现在先推进什么；进入具体任务后，说明当前情况、发现阻碍与冲突，并协助处理。查询、分析、变更继续使用同一组任务事实。

情况汇报、诊断和个人推荐是不同问题的回答：汇报讲现状，诊断讲问题与依据，个人推荐比较不同任务。诊断发现可以成为推荐依据，但不能把所有问题都换成一份情况摘要，也不能将逾期清单直接命名为“今天干点啥”。

现状核对：现有助手可汇报并引用已保存诊断摘要，但还没有完整诊断结果交互；原诊断 Tab 仍独立存在。旧个人工作台仍使用偏重期限的排序代码，并未实现 9 月 3 日文档中的本人负责／参与范围、状态白名单和重要／紧急双维度规则。因此这次需要接入统一的分析能力，不能只搬运旧界面。

## 2. 最小入口与范围

保留一个常驻面板、一条对话和一个输入框。标题下方明确显示“当前团队 · 我的工作”或具体任务。团队范围查询和增删改继续保留，个人推荐始终明确针对当前用户。

| 入口／表达 | 范围 | 默认结果 |
| --- | --- | --- |
| 今天干点啥 | 当前团队、本人的工作 | 建议先处理的 3 项，支持查看其余推荐 |
| 哪些任务值得关注 | 同一个个人候选池 | 按建议顺序给出需要关注的任务及原因；不因多个问题重复出现同一任务 |
| 按重要和紧急程度分析 | 同一个个人候选池 | 分开解释两种判断，默认仍使用连续任务列表；按用户要求可分组比较 |
| 诊断这个任务 | 当前任务与有权查看的后代 | 结论、影响、下一步与可展开依据 |
| 这个任务现在怎么样 | 当前任务与相关记录 | 简短情况汇报；有发现时可继续诊断或处理 |

非任务页面首次打开默认是“我的工作”，空状态保留“今天干点啥／值得关注／创建任务”三个入口。任务会话空状态为“任务情况／诊断任务／拆分任务”。进入对话后，用一个紧凑的“快捷操作”菜单保留这些能力，不在每条回复后重复铺设功能卡片。

本轮建议的入口迁移：任务详情的独立“诊断”Tab 改为“AI 诊断”按钮，点击直接在右侧绑定该任务并运行诊断；不再维护一份完整的平行报告。旧“我的工作”入口如保留，打开助手的个人建议；若以后需要宽屏展示，则读取同一分析结果。

## 3. 今天干点啥：从判断到行动

候选范围遵循已确认的 `PERSONAL-PRIORITY-2026-09-03-v4`：当前团队、本人负责或参与、状态为待开始／进行中／已阻塞的可见任务。列表上的搜索和标签筛选不暗中缩小分析范围；待审核、已完成、已取消不混入这个推荐池，但用户可以显式查询或诊断这些任务。

默认先给一句总体判断，再展示最多 3 项。三项是初始展示数量，不代表今天能完成三项。每项为一个连续列表条目：

1. 顺位与任务名称：名称打开原任务；同 Task ID 去重。
2. 一句优先原因：说明关键影响与现在需要处理的原因。
3. “重要性／紧急性”的简短事实说明：例如“影响本轮投放决策／今天需确认预算”；缺证据显示“待判断”，不补成不重要或不紧急。
4. 一句下一步：明确是本人执行、协调，还是核对记录。
5. 一个“继续处理”动作：带入此任务与当前建议；依据默认折叠，用户也可以追问为什么排在前面。

允许继续说“先处理第二项”“先排本周”“我今天只有两小时”“这件事今天先放后面”。引用第几项时绑定该条消息里的 Task ID，重新排序后不能误指另一个任务。

调整今天的建议顺序只改变这次个人安排，不自动修改任务标签、期限、状态或负责人。用户说“这件事不归我”时核对其负责人／参与关系；如需改变正式责任，转为变更方案。没有可核对的剩余投入与可用时间时，只给顺序和待确认假设，不保证两小时可以做完，也不自动创建日历安排。

## 4. 重要与紧急分开判断

| 维度 | 需要回答 | 输入事实 |
| --- | --- | --- |
| 重要性 | 这件事对目标和其他工作有什么影响 | 任务目标、关键交付、已确认的协作影响、已有标签的明确含义 |
| 紧急性 | 现在不处理会发生什么，多久发生 | 有效期限、正在发生的损失或风险、当前明确在等待本人处理的事项 |

已有标签可作为重要性参考；“内容制作”等普通分类标签不算高重要性，没有标签也不代表不重要。参考依赖未完成只提示核对，不能直接证明工作停等，更不能自动标记任务阻塞。

计算统一承接 [协作任务全流程 PRD 第 7.6 节](../../product-v2/PRD-AgentDoor-协作任务全流程.md)：重要度为目标影响、已确认协作影响与标签参考的组合；紧急度取期限压力、当前风险、待本人处理三项的最高值。同一事实不得在紧急度内重复加分。

文档中的 60% 重要度／40% 紧急度，以及分项档位，仍是待验证初始参数。本轮不将其重新表述为已确认权重。排序计算使用固定规则版本，模型基于相同事实解释，不能每次自由改权重。默认不给用户看分数、概率或四象限仪表盘；用理由说明差异。缺失事实不作为加分依据，界面必须同时保留未知边界，不能用零分表示确定不重要。

“哪些任务值得关注”与“今天干点啥”共用这一套候选与判断：前者强调关注原因，后者进一步组织当前可执行的下一步，不维护第二套互相矛盾的排名。

## 5. 诊断：完整报告放进任务对话

用户点击“AI 诊断”或直接提问后，助手先给短结论和覆盖范围，再按实际受影响任务展示发现。重点支持执行阻碍与决策／记录冲突；目标澄清、任务拆分仍由通用助手处理，不为了展示诊断数量而包装成故障。

每条发现展示：

- 结论作标题，例如“两个文件里的预算上限不一致”。
- 影响：会影响什么目标或后续工作；无法确认影响时如实说明。
- 建议：现在应该核对或推进什么。
- 依据：默认折叠，定位至有权读取的记录、文件和版本；冲突保留两侧事实，不能只展示模型判断。
- “继续处理”：围绕这条发现继续对话；需要改任务时生成现有的可编辑变更预览。

主任务汇总当前可见子树，发现只生成一次并绑定实际任务。上级汇总和子任务会话引用同一个发现及事实版本，避免两份结论或解决状态分叉。

处理链路为“诊断 → 讨论或补充资料 → 形成方案 → 用户确认 → 保存成功 → 重新检查相关发现”。不设置与任务事实无关的“标记已解决”。只有相关事实不再支持原判断，才能说明问题已消除；打开过报告、生成过草稿或点击过处理，都不算解决。

## 6. 会话与更新规则

- 我的工作会话按用户／团队保存，任务会话按用户／团队／Task ID 保存。个人建议进入具体任务处理时切换到该任务会话，保留原建议入口和可返回路径；个人安排不复制为共享任务讨论。
- 浏览 A 任务时说“我今天先做什么”，按明确意图进入“我的工作”并显示范围变化；原任务的未执行方案保留在原会话，不带到个人范围继续执行。普通页面导航仍不暗改会话范围。
- 主动点击或发送指令触发分析。同范围、同事实版本可以复用结果；资料、成员关系、状态、期限、标签、依赖或日期变化后，标记结果有更新并可重新分析，不在用户阅读时悄悄改顺位。
- 用户在助手中确认保存后，刷新受影响的诊断与个人建议。旧回复保留当时检查时间及版本，不覆盖历史；从旧回复继续操作前核对最新任务事实。
- 后台持续检测和主动通知属于后续接入；本轮设计不宣称已有定时分析、个人日历或生产权限服务。

## 7. 必要状态与验收

正常：结论短、依据可展开、可继续处理。空：明确候选为空或当前可见范围未发现问题，不宣称任务健康或全部完成。加载：真实处理中，可停止并保留历史。失败：显示失败，旧结果标注旧检查时间，不冒充新分析。资料不足：指出会影响判断的缺口。不可见：不暴露对象名称和内容。过期：提示重新分析，变更继续进行快照校验。手机：结果为单列条目，依据就地展开；菜单、展开、输入与关闭支持键盘，Escape 恢复入口焦点。

关键验收场景：

1. 参与但不负责的合格任务进入个人推荐；已完成任务不挤入今日安排。
2. 高影响但没有截止的任务有机会排在低影响例行逾期任务前；重要／紧急原因可追溯。
3. 缺少重要性资料时显示待判断；不因记录缺失而生成确定的低重要性结论。
4. 父子任务不会重复展示同一诊断发现；参考依赖不被自动解释为阻塞。
5. 从第二项推荐进入诊断、形成方案、确认后回看推荐，实际修改仍对应同一 Task ID。
6. 只调整“今天先做哪个”不写任务字段；读取建议、展开依据不触发消息发送或任务修改。
7. 保存失败、权限变化、数据过期和停止分析均保留输入与历史，不能显示已完成处理。

## 8. 实施顺序建议

先接通独立诊断意图、结构化发现和处理闭环；再同步现有个人推荐规则并在助手里支持今日安排与关注查询；最后迁移旧入口，确保旧工作台与助手共用结果。本次评审重点是个人建议的呈现密度、诊断入口迁移和初始排序参数验证，尚未授权本轮代码变更。

## 9. 2026-09-10 快捷入口调整

任务会话首屏的“拆分子任务”替换为“整理我的工作”，副文案为“为我的全部任务排出优先顺序”。团队首屏的个人安排入口也统一使用此名称；任务拆分能力仍可通过自然语言调用。

点击后切换到当前团队会话，按重要性和紧急性分析本人负责或参与的全部未完成、未取消任务，不限于当前页面任务、子任务或本周到期任务。原任务会话及未确认草稿保留。沿用任务列表展示完整建议顺序，完整依据中逐项说明排序原因与下一步；资料不足注明待判断。整理结果只作为本次建议，不修改正式任务字段。
