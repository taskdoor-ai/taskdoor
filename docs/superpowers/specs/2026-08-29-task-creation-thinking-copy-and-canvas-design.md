# 任务创建思考文案与详情画布设计

## 目标

直接优化现有任务创建流程，不新增示例页。五个快捷示例都应展示与实际草案一致的分析过程、人员匹配结果与任务结构依据；输入框分析时不再出现滑动边线；右侧任务详情使用覆盖整个可滚动画布的轻量渐变。

## 交互与文案

任务创建过程统一为四步：

1. **分析任务目标**：说明识别出的目标、时间和交付物。
2. **分析团队情况**：说明已结合成员责任、当前任务和近期相关经验。
3. **匹配合适人员**：展示实际匹配到的人员，并用责任命中、当前工作或近期经验解释依据。
4. **生成任务结构**：说明主任务与子任务数量、拆分维度以及并行和前置依赖数量。

五个快捷示例必须根据各自生成的草案和人员建议产生不同内容，不能继续共用“8 位成员”“按责任范围核对负责人”等固定文案。完成态与处理中使用同一套步骤结构，完成态展示最终实际结果。

## 视觉

- 删除 `.animated-agent-chat[data-state="analyzing"] .animated-agent-chat-shell::before` 的滑动进度线及对应关键帧。保留静态边框、聚焦描边、发送按钮状态和工作流进度反馈。
- `.task-plan-panel` 的背景使用多层渐变，覆盖整个面板及滚动区域；hero 和 body 继续透明以显露统一画布，避免出现上半段有色、下半段纯色的断层。

## 范围

只修改任务创建的五个快捷示例、工作流展示和任务详情面板样式。不替换团队成员、工作区历史任务、任务详情或其他页面 fixture。

## 验证

- 静态契约测试验证四个步骤、动态人员依据、动态任务结构描述、无输入框滑线和整幅渐变。
- Mock 助手测试验证五个快捷示例均能产生相应草案和人员建议。
- 运行类型检查、相关测试与生产构建。
