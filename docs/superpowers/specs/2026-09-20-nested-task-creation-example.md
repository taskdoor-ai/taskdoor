# 多层级任务创建示例

用户明确要求直接加入现有创建页面，可点击体验。对象是确认创建前的任务草稿；用户需要看清任务归属并逐项核对，避免多层子任务被平铺或创建后丢失关系。

- 保留原“复杂项目 · 共 8 个任务”，新增“多层级项目 · 4 层任务”。新品达人带货项目包含 1 个主任务、9 个子任务、6 个叶子，最深 4 层（含主任务）。
- 复用主任务信息与现有子任务编辑器。子任务区域使用递归列表、缩进、细连接线；不增加流程图、侧栏或额外页面。
- 首次展示全部分支，详情仍默认收起。左侧箭头控制下级，右侧“详情”编辑当前项；提供展开全部、收起全部。父项显示直接子任务数，底部统计所有层级，与折叠状态无关。
- 窄屏缩小缩进，保留负责人、详情与分支控制。分支按钮支持键盘，提供展开状态及受控区域标识；隐藏分支保留编辑状态。
- 创建前草稿以稳定 clientId 关联上级，提交时转换索引，保存时转换为真实 parentTaskId；草稿历史读取保留关联。无效上级与循环归属阻止创建并保留草稿。
- 父项工时由后代叶子汇总；移除父项连同整个分支删除，按钮明确告知下级数量，并清理其余任务的失效依赖。示例日期留空，不伪造排期、完成量或预测。
- 沿用现有生成加载、失败重试及编辑禁用状态；没有子任务时沿用现有添加入口。成员失效沿用原校验，不另造权限语义。

验收：入口可用；四层归属可见；分支折叠不改变总数；最深层信息可编辑；创建与恢复后父子关系一致；父项移除无孤儿和失效依赖；工时只汇总叶子。默认工作区种子数量不变。

实现：`taskCreationScenarios.ts`、`nestedTaskCreationScenario.ts`、`taskCreationHierarchy.ts`、`TaskCreationPlanEditor.tsx`、`TaskCreationSubtaskEditor.tsx`、`workspaceTaskCreation.ts`。定向数据验证：`server/taskCreationHierarchy.test.ts`。
