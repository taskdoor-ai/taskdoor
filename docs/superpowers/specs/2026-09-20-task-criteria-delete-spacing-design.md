# 完成标准删除与输入留白设计

## 对象与目标

- **对象：** Task 详情中的行内完成标准编辑器，以及复用同一字段组件的完成标准编辑场景。
- **用户问题：** 最后一条完成标准没有删除入口；输入文字距离聚焦边框过近；添加时的占位说明与已填写完成标准在视觉字号和节奏上不一致。
- **本次决策：** 允许删除任意一条完成标准，包括最后一条；删除最后一条后保存为空，只保留“添加”入口；统一输入值、占位说明与只读内容的排版，并增加输入框内部留白。
- **成功证据：** 用户能够明确删除最后一条并刷新后保持为空；输入文字与边框之间有稳定留白；占位说明切换为实际内容时字号和行高没有跳变；键盘操作和保存冲突保护不退化。

## 交互规则

1. 每一条完成标准都提供删除按钮，不因当前只剩一条而隐藏。
2. 删除非最后一条后，焦点优先进入同位置的下一条；删除末行后进入上一条。
3. 删除最后一条后，编辑器立即提交空数组。行和输入框消失，仅保留“添加”入口。
4. 删除直接提交删除后的值，不依赖被删除输入框触发失焦保存，避免旧状态被重新保存。
5. 点击“添加”后创建一条空输入并聚焦；空白条目仍不能作为有效完成标准保存。
6. 保存期间、数据冲突或只读状态继续沿用现有禁用与冲突保护规则。

## 数据规则

- `[]` 是合法的“尚未设置完成标准”状态，不再强制至少保留一条。
- 非空数组中的每一项仍需去除首尾空白，并拒绝纯空白项。
- 从有值删除为空时，目标 Task 的 `completionCriteria` 保存为 `[]`。
- 变更活动保留原完成标准作为 `before`，`after` 记录为 `null`，表达该字段已清空。
- 清空完成标准只修改当前 Task 的定义和更新时间，不改变 TaskStatus、负责人、进度或子任务关系。

## 视觉规则

1. 输入值与占位说明统一使用完成标准正文的排版：`14px` 字号、`1.7` 行高和同一字体族；输入值出现后不得产生字号或行高跳变。
2. 占位说明显式继承输入框的字号、行高和字重，不依赖浏览器或基础组件的默认 placeholder 样式。
3. 输入框文字与左右边框保持 10px 内边距，上下保持 6px 内边距。
4. 移除 Task 详情上下文中将该输入框横向内边距覆盖为 `0` 的规则，避免局部样式抵消字段组件的留白契约。
5. 输入框仍自动增高，不固定为大尺寸表单；多行内容按原逻辑展开。
6. 左侧勾选图标与单行输入内容垂直居中，不因增加内边距而上浮。
7. 删除按钮继续使用行尾 `X`，默认弱化，行 hover 或按钮键盘聚焦时清晰显示。
8. 空状态不渲染占位输入框和勾选图标，只显示紧凑的“添加”入口。
9. 移动端继续满足现有最小触控高度，增加留白后不缩小触控区域。

## 状态与异常

- **正常：** 修改文字后按原失焦方式保存；删除使用删除后的值立即保存。
- **空状态：** 显示“添加”，不显示伪造的空标准。
- **保存中：** 输入、新增和删除全部禁用。
- **冲突：** 若服务端／本地状态已变化，沿用“完成标准已被其他操作更新”的提示，不覆盖新数据。
- **保存失败：** 恢复删除前的标准并显示错误，让用户能够重试；不把失败的删除伪装为成功。
- **只读：** 不显示新增或删除按钮。

## 最小验证

- 字段渲染测试确认唯一一条也有删除按钮，空数组且关闭初始空行时只显示“添加”。
- 数据测试确认 `validateTaskCriteria([])` 返回空数组，非空数组中的空白项仍报错。
- 保存测试确认从一条删除为空后仅更新目标 Task，活动记录的 `after` 为 `null`。
- 组件契约测试确认删除使用删除后的值提交，不依赖失焦时的旧闭包状态。
- 样式测试确认输入值和占位说明均为 `14px / 1.7`，输入框具有 6px 纵向、10px 横向内边距，Task 详情中不存在归零覆盖，并保留焦点与移动端规则。
- 只运行完成标准相关测试和目标组件类型检查，不运行全量测试。
