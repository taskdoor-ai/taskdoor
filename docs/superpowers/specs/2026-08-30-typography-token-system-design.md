# TaskDoor 排版 Token 通用规范

日期：2026-08-30  
状态：方向已确认，待实现

## 1. 目的

建立一套跨页面、跨业务组件复用的排版规则，让设计和开发通过语义 Token 选择字号，而不是根据当前画面临时指定数值。

这份规范只定义通用规则，不记录某个页面、某个模块或某种空状态的具体布局。

## 2. 基本原则

### 2.1 按语义选择，而不是按视觉猜测

组件应先判断文字承担的职责，再引用对应 Token：

- 页面标题使用标题 Token；
- 正文使用正文 Token；
- 按钮、筛选器、字段名使用控件或标签 Token；
- 时间、计数和补充信息使用辅助文字 Token。

同一种语义在不同页面保持一致，不因容器大小或开发习惯随意改变。

### 2.2 字号、行高和字重是一个整体

排版层级不能只定义字号。每个语义层级必须同时定义：

- 字号；
- 行高；
- 默认字重。

业务组件不应引用字号 Token 后，再自行随机设置行高和字重。

### 2.3 组件尺寸不决定文字层级

按钮的 `sm`、`default`、`lg` 等尺寸用于控制高度、内边距和图标尺寸，不用于隐式切换文字语义。

例如，小高度按钮与常规按钮都属于“控件文字”，应使用同一控件排版 Token；只有信息职责发生变化时，才允许改变文字层级。

## 3. 语义层级

| Token 角色 | 字号 / 行高 | 默认字重 | 典型用途 |
| --- | --- | --- | --- |
| Display | 40 / 44 | 650 | 核心数据、少量展示型标题 |
| Title 1 | 28 / 34 | 650 | 页面主标题 |
| Title 2 | 22 / 28 | 650 | 核心区块标题 |
| Title 3 | 18 / 24 | 600 | 面板标题、卡片组标题 |
| Body | 15 / 24 | 400 | 正文、主要说明 |
| Body Small | 14 / 21 | 400 | 次要正文、紧凑信息 |
| Label | 13 / 18 | 550 | 按钮、筛选器、字段名、标签 |
| Caption | 12 / 18 | 450 | 时间、数量、来源、辅助信息 |
| Code | 12 / 18 | 500 | 等宽数据、代码内容 |

产品界面的常规文字不新增低于 `12px` 的规格。历史遗留的小字号采用渐进迁移，不以兼容旧样式为由继续扩散。

## 4. Token 契约

### 4.1 基础 Token

每个层级统一提供三组变量：

```css
--ad-text-{role}
--ad-leading-{role}
--ad-weight-{role}
```

示例：

```css
--ad-text-label: 13px;
--ad-leading-label: 18px;
--ad-weight-label: 550;
```

### 4.2 组件语义别名

通用组件不直接重复选择基础层级，而是优先使用组件语义别名：

```css
--ad-control-font-size: var(--ad-text-label);
--ad-control-line-height: var(--ad-leading-label);
--ad-control-font-weight: var(--ad-weight-label);
```

这样可以在不逐个修改业务组件的前提下统一调整控件排版。

后续只有在出现稳定、跨模块复用的语义时，才新增别名；不能为单一页面或单个卡片创建专属字号 Token。

## 5. 组件使用规则

- `Button`、选择器、筛选器和输入控件统一引用控件排版 Token。
- 标题组件根据内容层级引用 `title-*`，不根据视觉空间随意缩放。
- 标签和字段名引用 `label`，时间、计数、来源引用 `caption`。
- 业务 CSS 不新增 `font-size: 13px` 一类裸值，应引用 Token。
- 图标尺寸独立于字号 Token，但需与对应文字的行高保持视觉对齐。
- 组件可通过内容语义切换排版角色，不通过页面名称或业务类型切换。

## 6. 治理方式

- `styles/agentdoor-tokens.css` 是 Token 的唯一实现来源。
- `docs/agentdoor-design-system.md` 是人可读的唯一通用设计说明。
- 新增通用组件时必须先复用现有语义 Token。
- 确实缺少语义层级时，应先说明跨模块使用场景，再扩展 Token。
- 历史样式按触达范围逐步迁移，避免一次性引发全站视觉回归。
- 自动化测试应验证共享组件引用 Token，而不是绑定某个页面的具体布局。

## 7. 本轮落地范围

本轮仅完成排版基础设施的第一步：

- 补齐现有排版层级的行高和字重 Token；
- 增加控件排版语义别名；
- 让共享按钮使用控件排版 Token；
- 在本轮被修改的业务组件中引用这些 Token；
- 更新通用设计系统说明与对应测试。

具体业务模块的入口位置、空状态结构和文案属于功能实现，不进入本通用规范。
