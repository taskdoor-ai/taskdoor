日期：2026-09-15。依据：用户确认设计模板呈现、权限内的保存提示及管理员观测方式。本稿细化交互，不代表正式功能、组织权限政策或后台发现服务已上线。

可点击设计稿：`public/task-template-design.html`。

对话内推荐与选择模板的补充设计稿：`public/assistant-creation-interactions.html?case=template-choice`，见第 11 节。此补充更新文档和独立流程稿，不代表助手已连接正式模板库。

## 1. 本次取舍

- 对象是一份主任务及其子任务，携带可复用的完成标准、执行提示和依赖关系，前台统一称为「任务模板」。任务拆解的结果就是子任务；细小操作放在执行提示中。
- 用户包括形成做法的成员、使用模板的成员、具有发布权限的维护者及管理员。发布能力与管理员身份分开，维护者也可以直接发布获授权的团队内容。
- 「我的任务」标题栏在新增按钮左侧提供同尺寸的「任务模板」图标入口；加号直接创建空白任务，负责人、参与人、日期及业务内容为空。
- 保存提示依附于具体任务的复盘结果，展示依据；不设置独立的助手洞察模式，不在 AI 刚生成普通拆解时提示保存。
- 创建者保留底层记录，不恢复详情中的创建者字段。
- 管理员复用模板页面的管理视图，不增加独立观测大屏或成员排行榜。

## 2. 页面及主要动作

| 页面 | 支撑的动作 | 信息来源 / 不显示的损失 |
| --- | --- | --- |
| 任务复盘 | 理解为什么值得沉淀，主动整理或忽略 | 已确认复盘和当前可访问来源；缺少依据无法判断建议价值 |
| 模板列表 | 找回、搜索、选择模板 | 授权后的模板元数据；缺少固定入口必须翻找原任务 |
| 模板详情 | 判断是否适用，查看主任务、子任务和完成标准 | 同一模板版本；缺少详情会造成盲目套用 |
| 保存预览 | 核对正文并选择实际允许的受众 | 通用内容草稿及发布能力；避免将读权限当成共享权限 |
| 本次方案 | 改主任务及子任务内容、人员和日期，确认创建 | 模板版本及本次输入；避免照搬旧人员和排期 |
| 管理视图 | 处理团队建议、维护模板、查看采用及变更 | 当前账号获授权的组织记录；个人数据不进入管理统计 |

列表采用名称和适用场景优先的紧凑行。范围与更新时间为次级信息，「使用模板」为主要动作。详情复用任务 Heading Card 和子任务列表：名称、目标、完成标准、负责人、参与人、截止时间位置、标签、执行提示；子任务按图标、标题、负责人展示，点击进入详情。模板范围在卡片上方，维护人和来源在底部，避免混入任务责任字段。

保存预览与任务方案使用标准弹窗。正常路径为：任务复盘 → 查看依据 → 整理为模板 → 核对正文和受众 → 保存 → 模板详情；或模板列表 → 使用模板 → 同样式的可编辑任务草稿 → 确认创建 → 结果。本次取消独立的达人数量／推广方式表单；是否直播由增删相应子任务表达，目标由用户直接修改，不自动拼接文字。

## 3. 发现的依据和提示

首版可验证两类信号：

1. 用户在任务中明确确认复用意图，例如「以后写脚本就按这个顺序来」。这足以建议保存个人方法，不应称为多次验证。
2. 有权限核实多次实际任务的交付结构或处理规则相似，并能解释一致点和适用条件。仅任务标题相似不成立。

固定案例采用三次团队推广复盘及一份个人脚本方法。任务复盘旁只显示一句理由和「整理为模板／查看依据／忽略」。打开依据不创建模板，保存模板不创建任务。

个人忽略只处理本人的提示，不替管理员处理团队建议。个人保存不让管理员知道这份私人资产，也不把团队候选标为已经发布。明确保存为团队模板，才更新团队沉淀状态。同一依据未变化时不反复提示；后台事件通知属于正式服务的后续接入。

正式识别若发现已有同类模板，应先提供查看、在有编辑权限时更新或另存。当前固定稿重点展示保存和复用，尚未演示自动查重与合并，不能据此宣布该能力完成。

## 4. 权限约定

| 演示角色 | 可以查看 | 可以保存或维护 | 管理视图 |
| --- | --- | --- | --- |
| 普通成员林洁 | 团队已共享模板、本人个人模板及获授权任务 | 个人模板 | 无 |
| 维护者许宁 | 团队已共享模板、本人资产及获授权任务 | 本人个人模板；获授权团队正文的发布；自己维护的团队模板 | 无组织观测入口 |
| 管理员周岚 | 团队已共享模板及获授权管理记录 | 获授权的团队发布、维护人调整、停用及恢复 | 有；不自动获得他人个人模板、私人对话或源任务访问权 |

普通成员保存时仅提供「仅我」。具有发布权限且正文可向团队共享时才提供「当前团队」。来自私人方法的案例仅允许个人保存。角色切换属于设计稿评审工具，不属于正式产品入口。

生产系统需分别校验：来源读取、模板正文保存、面向指定受众的共享、模板读取与编辑、任务创建、管理记录读取。模型只接收过滤后的来源；客户端的角色开关和可见 ID 不能实现生产授权。

模板正文独立获得共享授权后，来源任务仍按原权限访问。模板管理权不等于来源任务权限。授权变化时不显示不可见来源的标题、数量及摘要；未提交草稿重新检查后才能继续。不得把清除个人姓名视为内容已获共享授权。

采用记录与任务详情分开授权：固定稿中有一条获准查看的团队采用事件，但其任务详情不可见，因此只显示「任务详情受限」，不显示该任务名称。记录中不带私人聊天正文。

## 5. 管理员观测

原方案在模板列表提供「管理模板」入口；本次按用户要求移除列表右上角入口，单个模板详情的更多操作仍保留维护能力。

- 顶部小型汇总：可用团队模板数、当前可处理的团队沉淀建议数、成功采用次数，全部按授权后的数据计算。
- 团队模板列表：名称、状态、维护人、成功采用次数及「记录／管理」。
- 沉淀建议：理由、当前可访问的依据、处理状态及查看处理；权限消失的建议不展示受限摘要。
- 记录弹窗：获授权的采用事件、内容更新和管理动作。未发生事件时如实显示空。
- 管理弹窗：调整维护人、停用和恢复。停用只影响新采用，不修改已经创建的任务。

成功采用按一次确认并成功保存的任务方案计数，主任务及其子任务作为一组计一次。打开页面、点击使用、预览及创建失败不计入；个人模板不进入团队统计。已完成任务的数量只能作为执行信息，不直接证明模板有效。

## 6. 状态与交互边界

| 状态 | 设计表现 |
| --- | --- |
| 正常 | 可从任务保存，从固定模板入口找回，适配后创建；清晰区分保存模板与创建任务 |
| 空 | 模板为空说明从任务整理；搜索无结果保留关键词并提供清除 |
| 加载 | 显示加载状态，计数未完成时不显示零；不编造已分析步骤 |
| 读取失败 | 保留搜索条件，原位置提供重试 |
| 保存／创建失败 | 保留本次输入，说明尚未写入；重试成功后移除提交入口 |
| 无权限 | 受限来源正文不显示，保存范围只提供有能力的选项；管理员也遵循此规则 |
| 版本已变化 | 创建前停止提交，显示版本变化及具体更新，保留手改内容；核对后继续 |
| 移动端 | 导航压缩、列表按名称优先换行，详情单列，弹窗独立滚动，按钮触达高度至少 44px |
| 键盘 | 控件可聚焦，子任务标题使用按钮打开详情，人员候选用原生 details 和单选／多选；原生 dialog 限定焦点，Escape 返回并恢复入口焦点；提交中冻结动作 |

模板更新形成新版本，已创建任务保留采用版本；不更新历史任务。任务负责人始终不由模板的维护人或创建者自动代入。从来源任务首次整理时默认清空人员；用户明确设置并保存的默认人选可以在复用时带入，且允许逐项替换或一键清空。

## 7. 独立设计稿与系统接入的区别

`/task-template-design.html` 仍是固定数据和内存交互的独立设计稿，刷新后重置。它不读原应用存储，不发送通知，不写真实模板、任务或邀请。实际系统接入见第 10 节。

可体验范围：模板列表／搜索／详情、保存与取消、个人／团队范围差异、主任务与子任务字段编辑及保存结果、人员选择／替换／清空、修改／删除／补充子任务、删除撤销、同级前置依赖、创建结果、角色切换、管理记录／维护人／停用恢复、错误及版本变化分支。

当前系统已实现浏览器本地持久化、任务实例化及有证据的重复结构发现。服务端授权、跨用户同步、后台发现、组织共享政策、自动合并与生产撤权仍需服务端接入，不能以客户端交互代替。

## 8. 主任务、子任务与空值的详细约定

本节落实用户确认：「任务拆解就是子任务，样式与我的任务和子任务一致，内容和人员可以替换或为空」。覆盖此前独立步骤面板、每行一个步骤的文本框及强制填写业务字段的设计。

### 8.1 视图与操作

| 位置 | 最小布局 | 主要操作 |
| --- | --- | --- |
| 模板详情 | 模板元数据条 → 主任务 Heading Card → 子任务列表 → 维护信息 | 使用模板；有维护权限时编辑模板 |
| 子任务详情 | 所属任务、主目标、完成标准、前置依赖；负责人／参与人／日期位置／标签；执行提示 | 返回模板或使用模板 |
| 整理／编辑模板 | 模板名称、适用场景、可见范围 → 同样式的主任务和子任务 | 行内改字段、增删子任务、保存；进入子任务时隐藏模板元数据，保持专注 |
| 使用模板 | 可编辑主任务 Heading Card → 子任务列表 | 直接修改、增加、移除，确认创建；无额外需求向导 |
| 本次子任务编辑 | 与模板子任务详情相同的字段 | 返回主任务保留草稿；移除子任务可撤销 |
| 创建结果 | 主任务及其子任务，显示已选择／待接受／待定的负责人 | 点击进入对应任务，继续补充 |

Heading Card 按现有 `TaskDetail` 的图标、标题、目标／完成标准字段及属性行组织；子任务列表按 `TaskSubtaskList` 的 64px 左右行高、图标、可点击标题和右侧负责人组织。桌面不另外增加流程图、编号步骤卡或独立模板编辑器的视觉语言。实现稿为独立 HTML/CSS/JS，生产接入时复用或提取真实组件，避免两套样式长期漂移。

模板不展示进度、实际工时、已完成状态或原任务讨论记录；本次创建草稿的初始状态为待开始。创建者只保留底层记录，不在详情恢复该字段。

### 8.2 字段映射与默认值

| 字段 | 模板内 | 复用后 |
| --- | --- | --- |
| 模板名称 | 查找用的元数据，唯一必填项；不要求组织内唯一 | 不自动代填用户已经清空的任务名称 |
| 适用场景 | 可修改、可留空 | 用于判断模板是否适用，不替代任务目标 |
| 任务名称 | 主／子任务分别编辑，允许为空；空时展示「未命名任务」占位 | 复制模板值；可替换／清空；占位文案不作为存储值 |
| 主任务目标 | 可替换、可留空 | 复制后可改，不强制从描述、旧项目或输入条件补齐 |
| 子任务主目标 | 读取所属主任务目标，不重复存一份可编辑目标 | 随本次主任务目标变化；主任务为空时显示尚未设置 |
| 完成标准 | 主／子任务各自独立的条目数组，逐条增加、修改、移除；可无条目 | 保留实际填写值，空白条目不生成默认标准 |
| 执行提示 | 各自独立，可编辑／清空 | 原样复制并可调整；不自动补写“通用步骤” |
| 负责人 | 单选可清空；从历史任务整理时为空；用户显式设置后才保存为默认建议 | 不默认当前用户、创建者或维护人；可替换／清空；其他成员需遵循任务既有责任接受流程 |
| 参与人 | 多选可逐人移除或清空；初始为空 | 复制明确保存的建议，可替换／清空；不从负责人或原项目自动推导 |
| 截止时间 | 使用同一属性位置，显示「使用时设置」；不沉淀旧项目的具体日期 | 初始为空，本次主／子任务分别填写，可清空 |
| 标签 | 可编辑／清空 | 复制后独立修改 |
| 前置依赖 | 关联子任务稳定 ID，不用标题或行号识别 | 创建时映射到新任务 ID；删掉子任务时同时清除对它的依赖 |

主任务没有子任务也可保存或创建；新加子任务的内容、人员和日期全部为空，不生成虚假的完成标准。模板内容为空不意味着任务已满足完成条件，后续执行与验收仍遵循任务的实际规则。

### 8.3 人员与权限

- 模板维护人负责维护模板；任务负责人负责交付任务，字段、权限和数据分别保存。
- 人员选择沿用头像、名称、加号入口；负责人单选、参与人多选，选择器内提供「清空」。主任务编辑顶部的「清空全部人员」同时清除主任务和所有子任务的人选。
- 选择器只列当前创建范围中允许选择的成员。生产提交时再次检查成员状态及可见权限；无法继续选择的人选不能自动替换为当前用户，应提示核对并保留其他输入。
- 保存人选只是模板里的默认建议，不发送任务通知或协作邀请。只有真实任务创建并进入责任分配流程时，才按现有规则处理邀请；对方尚未接受不能展示已承接。本稿创建结果用「待接受」表示其他负责人的待确认安排，不发送真实邀请。
- 源任务读取权、内容共享权、选择团队成员的能力分别检查。默认清空人员不是授予正文共享权限的替代方案。

### 8.4 草稿、依赖与版本

主任务与全部子任务作为一份草稿编辑，切换详情立即保留本次输入。关闭／取消放弃本次草稿，不修改原模板；保存失败仍停留在草稿，可原位重试。

移除子任务后提供撤销，并同步清理引用它的前置依赖；撤销恢复该子任务和相关依赖。固定稿仅允许选择排在前面的同级子任务作为依赖，避免循环；生产应复用现有依赖选择与校验机制，不将该演示限制扩展为产品规则。

保存模板形成新版本；使用时先复制采用版本，再编辑草稿。确认创建前发现版本更新时停止提交，显示具体变化，保留手改字段；用户核对并选择保留本次修改后才能继续。已创建任务保留采用版本信息，模板更新不回写任务。

一次成功确认创建主任务及其子任务计一次采用；中间点击、编辑、失败、处理版本冲突都不计数。生产需要原子写入与幂等键，避免部分创建或重复计数。

### 8.5 数据依赖

- 模板元数据：`id / name / desc / scope / maintainerId / version / status / sourceRefs`，来源引用单独检查访问权。
- 模板正文：`mainTask` 和 `subtasks[]`；每个对象包含稳定 `id`、名称、完成标准数组、执行提示、负责人建议、参与人建议、标签；子任务包含所属关系及前置依赖；目标由主任务持有。
- 创建草稿：模板 ID、采用版本、主任务与子任务的副本、各自本次日期及修改结果。空字符串／空数组为明确值，不能通过 `value || default` 恢复被用户清空的内容。
- 任务实例：新任务 ID、主子关系、映射后的依赖、实际责任安排／待接受建议、创建者和来源模板版本；不以模板维护人作为责任默认值。
- 编辑权限与成员候选由服务端能力返回；当前稿使用固定成员、内存对象和模拟角色展示交互，不能作为授权实现。

## 9. 本次最小验收

只对本设计稿的变化做必要验证，不运行主应用全量测试或双重审查。

1. 主任务、子任务展示与编辑采用一致布局；主目标继承，子任务标准独立。
2. 替换并清空名称、目标、标准、提示、负责人、参与人后，切换主／子详情、保存／复用／创建不恢复默认内容。
3. 允许无子任务及空子任务；增加默认为空；删除／撤销及依赖引用保持一致。

## 11. 助手创建对话中的模板选择（2026-09-15）

### 11.1 本次决定与目标

用户明确要求：助手在理解本次需求后告知有可用模板，是否采用交给用户选择，不能直接创建。对象是当前用户有权使用的模板版本及一份本次任务草稿；成功证据是用户能理解推荐理由、选择使用或跳过、修改方案，并在最后一次明确确认后创建。

该设计补充第 10 节的系统模板库，以及第 8 节的模板字段规则。普通任务创建、模板库直接使用和对话中的推荐共用已有任务与模板数据，不新增一套模板副本；本轮仅更新设计文档和独立演示稿。欢迎页不增加第三张模板快捷卡片，也不恢复“创建任务”快捷卡片。

### 11.2 入口与最小布局

主要入口是创建对话中与用户需求相关的推荐。输入框「＋ → 使用模板」和明确表达“用某模板”可作为主动入口，复用同一授权模板列表；主动入口属于设计范围，本次固定稿不展示搜索器。

- 尚无需求时，先询问用户想完成什么；选了模板但未描述本次用途时，保留引用，等待用户补充，不自行生成与用户无关的工作。
- 有可核对的适用关系才推荐，不能仅凭任务标题相似。推荐不自动选择、不生成可执行创建动作；最多展示三个有依据的候选，只有一个就只展示一个。
- 卡片采用现有浅色渐变、名称优先和紧凑元数据：模板名、个人／团队范围、子任务数量；一段适用理由说明哪些内容可沿用、哪里需要调整。
- 「查看模板内容」只读展示选定版本，返回保持原对话。卡片内部底栏放「不使用，继续规划」与「使用模板」；不使用“立即创建”。按钮不能悬在卡片外，手机端可换行且触达高度至少 44px。
- 采用后，草稿顶部轻量标注「参考：模板名 · vN」，可查看或重新选择。任务内容沿用原有主任务／子任务编辑卡片，不另开参数向导。模板来源不混入任务负责人、任务名称或目标。

固定例：用户说“安排秋季防晒衣达人推广，这次只做短视频，不做直播”。助手推荐「新品达人带货项目」：商品准备、达人合作、内容发布和复盘与需求对应，直播环节可以在本次方案中移除。

### 11.3 流程与动作边界

| 当前状态 | 用户动作 | 助手响应 | 是否创建任务 |
| --- | --- | --- | --- |
| 已描述需求 | 收到模板推荐、暂未选择 | 展示理由与两个选择，等待用户 | 否 |
| 推荐中 | 查看模板内容、返回 | 只读预览采用版本，保留需求 | 否 |
| 推荐中 | 使用模板／明确说“用这个模板” | 记录所选 ID 与版本，按本次需求生成可编辑草稿 | 否 |
| 推荐中 | 不使用，继续规划 | 不带模板引用，按原需求继续形成草稿 | 否 |
| 采用后仍缺关键条件 | 补充回答 | 只询问影响本次结构或交付的缺口；已明确内容不重复问 | 否 |
| 草稿中 | 改字段、增删子任务、继续对话 | 更新本次草稿与依赖，不修改原模板 | 否 |
| 草稿中 | 重新选择／返回方案 | 保留手改内容；换来源时先核对调整，不静默覆盖 | 否 |
| 草稿中 | 确认创建 | 校验本次方案与采用版本，再一次保存主任务和子任务 | 是，成功后才显示结果 |
| 提交失败 | 重试 | 保留同一方案和操作标识，成功前不计采用 | 仅重试成功时 |

用户主动指定唯一可用模板已构成“选择”，无需再要求点击一次同义按钮，但仍不等于最终创建授权。没有采用、点了查看、沉默或继续讨论都不能视为选择。拒绝一次后，相同需求下不反复推荐同一模板；用户之后主动要求时可以重新选择。

生成草稿时引用所选模板，依据本次需求展示实际调整，如“移除直播环节”。人员沿用第 8 节明确保存的默认建议并可清空，日期只使用本次明确填写的值；不把维护人、旧项目人选或旧日期自动带入。空字段不补虚构目标与标准。从任务详情发起也不自动决定新任务归属，按用户明确意图处理已有主任务或独立任务。

成功结果保留实际采用版本；一组主子任务只计一次采用。查看、选择、调整和失败均不计采用。不使用模板的方案不记录采用来源。后续模板更新不回写已创建任务；修改本次方案也不更新模板。

### 11.4 异常、保存与验证要求

- 没有适用模板：按当前需求继续，不铺空推荐卡片。读取失败：如实说明，可重试或不使用模板继续；不能把失败称为没有模板。
- 模板停用、失权或版本更新：停止旧版本提交并保留草稿；失权不继续展示受限正文。版本变化展示差异，由用户核对后继续，不能静默替换手改内容。
- 取消、切换范围或返回：推荐与采用决定按会话保存；不替另一团队复用模板，不因返回页面而自动执行。加载可停止，不编造已完成步骤。
- 窄屏：卡片与输入区正常滚动，无横向溢出；推荐、预览、返回、两个选择和最终确认均可通过键盘访问，关闭预览恢复触发焦点。
- 最小验证：查看和两个选择均保持新增数量为零；使用后才有引用和适配草稿；跳过后草稿没有模板引用；重新选择保留编辑；取消不创建；失败可重试；确认成功只产生一次结果。

独立流程稿新增第 07 个案例，使用本页固定模板和内存任务。可体验推荐、只读查看、使用／不使用两条分支、字段编辑、重选返回保留草稿、取消、模拟失败与最终确认。它不读取正式模板库、不调用真实模型、不写任务存储，也不发送邀请。自动推荐、模板搜索、任意自然语言适配以及版本／权限变化仍为上述设计要求，不能据固定案例宣称已接入。

本轮最小验证：脚本语法与变更格式检查通过。浏览器核对了推荐、只读查看、使用／跳过均不新增任务；模板草稿移除直播且保留来源版本，独立草稿不引用模板；两条草稿之间重选可恢复手改完成标准；保存失败保持新增 0 项，重试确认后新增 1 个主任务和 4 个子任务且不再提供确认按钮；跳过后取消不创建。441px 窗口下推荐卡无横向溢出，两个选择按钮均为 44px 高。本轮未运行应用全量测试，未修改实际任务数据。
