# 任务列表默认个人范围与看板视图设计

## 背景

当前任务列表默认展示全部任务，负责人筛选使用普通枚举下拉，结果区仅提供列表形态。用户希望进入页面时先看到自己的任务，负责人选择与产品内其他人员入口保持一致，并先增加一个与任务详情内看板一致的状态看板视图。

## 目标

- 任务页首次进入默认展示当前用户负责的任务。
- 负责人筛选复用共享 `PersonPicker`，统一人员身份、搜索、键盘和弹层体验。
- 在保留现有列表的前提下增加状态看板视图。
- 列表与看板消费同一组搜索和筛选结果，任务入口保持一致。

## 非目标

- 本期不支持看板拖拽。
- 本期不在卡片内编辑状态、负责人、标签或日期。
- 本期不增加时间轴、日历、画布或用户自定义视图。
- 本期不记忆用户上次选择的视图；每次进入任务列表仍以列表为默认视图。

## 交互设计

### 默认个人范围

`App` 初始化任务筛选时，以当前用户 ID 作为 `owner`。当前用户仍由应用的统一身份上下文提供，不在任务页复制姓名常量。进入任务页后，标题数量、列表内容和看板内容都反映当前用户的任务。

用户可在负责人选择器中切换到其他成员或“全部人员”。切换只改变任务结果，不改变当前登录身份。

### 通用人员选择器

负责人筛选使用现有 `PersonPicker`：

- 触发器展示当前选择的头像、姓名和展开图标。
- 弹层支持按姓名、职责和邮箱搜索。
- 人员行沿用共享头像、双行身份信息、当前选中态和键盘行为。
- 筛选专用的“全部人员”作为明确选项出现。它不伪装成真实成员，也不复用“暂不分配”的任务分配语义。
- 成员数据来自 `collaborationMembers`，避免从当前任务结果反向推导人员清单；即使某成员暂时没有任务，也能被选择。

为保持 `PersonPicker` 的业务语义清晰，在共享组件中增加可配置的范围选项，任务页将其配置为“全部人员”；不在任务页自绘第二套下拉，也不改变现有“暂不分配”选项的语义。

### 视图切换

筛选栏右侧增加“列表 / 看板”分段切换：

- 默认值为“列表”。
- 切换视图时保留搜索词、状态、负责人和标签筛选。
- 两个切换按钮使用 `aria-pressed` 表达当前视图，并提供清晰的聚焦态。
- 看板不使用分页；它展示当前完整筛选结果。列表继续沿用现有分页。

### 看板视图

看板与任务详情中的 `TaskOverviewWorkspace` 看板保持同一视觉语言：

- 状态顺序固定为：待开始、进行中、待审核、已阻塞、已完成、已取消。
- 只渲染当前筛选结果中有任务的状态列，避免大量空列。
- 列头使用同一状态色点、状态名和数量徽标。
- 列使用相同边框、安静表面、圆角和横向滚动行为。
- 卡片使用同一高度层级和元信息节奏，展示任务名称、状态、截止时间和负责人头像。
- 点击卡片调用现有 `onNodeSelect`，进入同一任务详情。
- 本期卡片使用按钮语义，不出现拖拽光标或可编辑暗示。

为了避免样式逐渐分叉，应提取或共享详情看板的状态顺序、状态 tone 映射和可复用样式类。列表级看板可以拥有适合全局任务数据的卡片组件，但不能复制一套不同的看板视觉规范。

## 组件与数据流

1. `App` 持有 `taskFilters`，使用当前用户 ID 构造初始筛选。
2. `App` 将当前用户 ID 和 `collaborationMembers` 传给 `WorkspaceList`。
3. `WorkspaceList` 对全部 Task 执行一次搜索、状态、负责人和标签过滤，得到 `visibleNodes`。
4. `WorkspaceList` 内部持有局部 `view: "list" | "board"`，只决定结果投影，不改变过滤结果。
5. 列表视图把 `visibleNodes` 交给 `WorkspaceDirectoryView`；看板视图把同一数组交给新的任务看板组件。
6. 两种视图通过同一个 `onNodeSelect` 打开任务详情。

视图状态保持在 `WorkspaceList` 内即可，因为它不需要跨页面共享，也不需要持久化。

## 空状态与边界

- 筛选结果为空时，两种视图都显示“没有匹配的任务”，并提示调整搜索或筛选。
- 看板在窄屏维持列宽并横向滚动，不把多列压成不可读的窄卡片。
- 如果负责人数据中找不到当前用户，筛选仍保留当前用户 ID，并由通用人员组件显示可理解的回退名称；正常场景由成员目录保证当前用户存在。
- 本地同步数据没有远程加载错误态；未来成员目录远程化后，加载与错误状态应在共享 `PersonPicker` 层处理。

## 验收标准

1. 进入任务页时，负责人默认是当前用户，结果只包含该用户负责的任务。
2. 负责人触发器和弹层复用共享人员组件，可搜索并选择成员，也可选择“全部人员”。
3. 列表与看板切换不清空任何筛选条件。
4. 看板列顺序、颜色、卡片与任务详情看板一致。
5. 状态、负责人、标签和搜索条件同时作用于两个视图。
6. 看板卡片点击后打开正确任务详情。
7. 空结果、键盘操作和窄屏横向浏览可用。

## 测试策略

- 单元测试：默认负责人筛选构造、任务过滤、状态分组和固定状态顺序。
- 组件测试：人员选择“全部 / 当前用户 / 其他成员”，视图切换保留筛选，看板列和卡片渲染，空状态。
- 回归检查：现有任务列表分页、任务详情打开、详情看板和 `PersonPicker` 的其他调用方不受影响。
- 手工检查：桌面与窄屏、鼠标与键盘、浅色与深色主题。
