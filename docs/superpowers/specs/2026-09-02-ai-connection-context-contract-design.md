# 连接 AI 上下文合同设计

## 问题与决策

当前连接 AI 弹窗使用同一个展示组件，但不同入口的真实载荷范围不一致。任务入口会默认打包讨论、文件元数据、子任务和旧前置关系；弹窗又以“任务信息、协作记录、关联任务、文件引用”等抽象分类概括，用户难以判断边界，也可能在没有明确需要时传出过多信息。

本次决策是为每个入口定义固定载荷合同。做法参考用户提供的 Linear issue 示例中的“当前 issue + 直接父 issue”结构，但该示例仅作为上下文打包范式，不执行其中的 issue 或分支指令。弹窗只呈现合同概览；实际传输内容也必须按合同收敛。

成功证据：用户从任一现有入口打开弹窗时，能立即确认会传哪些对象和字段范围；复制后的上下文与概览一致，不包含合同之外的任务、讨论、文件或关系。

## 通用合同

1. 当前对象必须存在，并使用入口专属的明确字段投影；不得直接序列化包含活动、文件等嵌套数据的整个对象。
2. 关联上下文最多一层，只沿产品中明确的直接归属关系加入。归属不等于依赖，不沿引用继续递归展开。
3. 原文仅在它就是当前对象时带入，例如当前讨论、被回复内容、未发送草稿或未来明确选择的文件内容。文件正文不得因文件属于任务或被提及而自动带入。
4. 人员的正式状态与待接受提议分开；缺失、无权限、未定位、版本未核验和时间未知均保留缺口，不补成已接受、最新或不存在。
5. 实际载荷先生成清单，再由同一份清单生成弹窗概览和 AI 导出，禁止展示与发送使用两套独立推断。
6. 连接只复制并尝试打开工具，不代表客户端已安装、已连接、已接单或会自动写回。

## 入口合同

### 当前任务

当前对象为任务字段投影：Task ID、名称、目标、状态、期限、标签、正式负责人、待接受负责人提议、参与人及邀请状态、完成标准和执行建议。空字段不以示例值补齐。

存在直接父任务时，仅附父任务的 Task ID、名称、目标和状态。父任务由任务详情调用方以明确的任务投影传入；不得仅凭面包屑文字推断。团队、目录或其他非任务层级不冒充父任务。

不带入任务讨论、文件列表或文件元数据、直属子任务、旧前置关系、依赖摘要、AI 洞察、提交记录、变更流水和旧任务摘要。

### 当前讨论

当前任务背景只带 Task ID、名称、目标、状态和完成标准。当前讨论原文保留作者、时间、稳定记录 ID 与回复关系。

从主讨论连接时，加入同一讨论串的回复，不加入其他讨论串。从具体回复连接时，加入当前回复及可定位的祖先链，不扩展同级回复。从回复编辑器连接时，加入被回复原文与非空的未发送草稿。

仅当这组讨论明确引用文件时，附文件名、可定位 ID、记录版本和更新时间等未核验元数据；不带文件正文、预览或任务中的其他文件。

### 我的工作

当前对象为当前用户正式负责的完整任务列表。每项只含 Task ID、名称和真实状态，不受页面搜索、状态或标签筛选影响。

不带入任务详情、期限、当前情况、责任类型、讨论、文件、优先级理由、下一步建议、其他成员任务或待接受负责人提议。没有正式负责任务时传入空列表，不生成占位任务。

### 未来对象入口

文件或选中文本入口只带当前文件引用或明确选择的原文，以及所属任务的 Task ID、名称和目标。不得默认加入任务其他文件、无关讨论或整个工作区。新增入口必须先增加独立合同和针对性测试，不能复用任务入口的宽泛上下文。

## 弹窗概览合同

“带入的信息”区使用紧凑列表，每行包含：对象类型、用户可识别的名称、实际字段范围或关系范围。不展示具体字段值、讨论正文、文件元数据明细或“查看具体内容”。

- 当前任务入口：显示“当前任务”；存在直接父任务时再显示“父任务”。
- 当前讨论及回复入口：显示“当前任务”和“当前讨论”。讨论行说明包含当前讨论、回复、祖先链或草稿的实际范围。
- 我的工作入口：显示“我的任务列表”，说明任务数量及每项字段范围。
- 不存在的可选对象直接省略；已知缺口在对应对象行中说明，不用 `0` 冒充未知。

工具选择卡片只保留真实 Logo、产品名称和选中控件。删除 ChatGPT、Claude Code、CodeBuddy、Cursor 名称下方的能力说明；保留工具区统一的安装与连接状态提示。

## 状态与安全

- 加载：当前实现不新增异步读取，不引入虚假加载状态。
- 空值：保留字段缺失事实；概览只列实际会发送的字段范围。
- 无权限：不加入无权限对象，并在调用方可识别时显示范围缺口。
- 来源损坏：保留原始 ID 和缺口说明，不使用其他记录正文补齐。
- 数据过期：任务快照、文件版本和时间继续明确标为未核验。
- 移动端：对象行切换为单列；工具卡片缩短后仍保留触摸目标和键盘焦点。
- 关闭与失败：沿用现有 Base UI 焦点恢复、剪贴板失败重试和“尝试打开”表述。

## 数据结构

`AiConnectionRequest` 增加必需的上下文清单。每个清单项同时持有实际导出数据和预览描述；`buildContextPrompt` 从清单生成待分析 JSON，`AiConnectionContextPreview` 从同一清单生成对象级摘要。

现有 `workObject + context + contextPreview` 在迁移期间可以保留兼容，但三个现有构建器必须改为使用共享清单创建请求。迁移完成后，旧的分类摘要推断只作为兼容回退，不再被现有入口使用。

任务详情调用方负责传入直接父任务的最小投影；任务请求构建器不从 `pathItems` 猜测父任务字段。讨论构建器继续只消费当前页面已提供的任务活动快照；“我的工作”继续消费正式负责任务列表投影。

## 验收与验证

1. 当前任务连接不再导出全部讨论、任务文件、直属子任务或前置关系；有直接父任务时只附四个父任务字段。
2. 讨论、回复和草稿入口继续导出各自合同内的原文与关系，不扩散到其他讨论或任务文件。
3. 我的工作继续只导出正式负责任务的 ID、名称和状态。
4. 三类入口的弹窗都使用对象级概览，不显示分类摘要、具体值、正文或展开入口。
5. 四个工具卡片只显示 Logo 和产品名称；键盘选择和选中状态保持可用。
6. 概览中声明的对象和字段范围与导出的上下文逐项对应。
7. 运行连接弹窗、任务、讨论和我的工作四组针对性测试，以及应用侧 TypeScript 检查；不运行全量测试或双重审查。
