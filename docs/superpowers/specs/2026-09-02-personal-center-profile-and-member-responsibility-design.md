# 个人资料与成员责任编辑设计

## 对象与目标

本次改造面向使用设置弹窗维护个人资料和团队成员信息的用户。

当前个人信息页包含与此处核心动作无关的“工作身份、时区、关于我”，但缺少可维护的头像；成员列表能看到责任，却无法直接修正；“我的责任”页团队选择器里的 Logo 增加了无必要的视觉噪声。

成功证据：用户可以上传并保存自己的本地头像，只看到姓名和邮箱两项基础资料；管理员可以在成员列表中原地修改某位正式成员在当前团队的责任；团队切换器仅显示团队名称。

## 决策与范围

### 个人信息

- 页面采用单列布局：头像、姓名、邮箱、保存区。
- 移除“工作身份”“时区”“关于我”的界面字段，但保留旧数据的兼容读取，避免破坏已有本机状态。
- 头像显示为较大的圆形预览，旁边或覆盖一个明确的编辑按钮。按钮打开本地图片选择器。
- 接受常见浏览器图片格式。读取失败、类型不受支持或体积超限时不覆盖现有头像，并显示就地错误。
- 选择图片后仅更新草稿预览；点击“保存个人信息”后，与姓名一起写入现有浏览器存储。
- 邮箱按参考布局显示为只读文本，不在本次提供修改能力。
- 保存后的头像同步用于设置侧栏和应用内当前用户的 `PersonAvatar` 展示。

### 成员责任

- 责任是“成员在某个团队中的责任”，保存到团队成员关系，而不是成员的跨团队资料。
- 正式成员的责任默认沿用现有成员资料；一旦编辑，使用当前团队成员关系上的责任覆盖值。
- 只有当前团队管理员可以编辑。受邀但未加入的成员不提供编辑入口。
- 责任文本旁显示小型铅笔按钮；按钮在悬停、键盘聚焦时清晰可见，并具有可读的无障碍名称。
- 点击后只让当前行进入编辑态，一次最多编辑一行。编辑态提供输入框、保存和取消。
- 保存时去除首尾空白并持久化；空内容允许保存，回到展示态后显示“未填写责任”。
- 保存失败时保留编辑内容并给出错误；取消时恢复进入编辑前的内容。
- 切换团队或重新加载后读取对应团队的覆盖值。

### 团队切换器

- “我的责任”页的团队选择器触发器只显示团队名称与下拉箭头。
- 下拉选项也只显示团队名称，不显示团队 Logo。
- 团队选择、未保存责任拦截和键盘操作维持现状。

## 数据与组件边界

- `PersonalCenterState.profile` 新增可选的头像 Data URL 字段。
- `TeamMembership` 新增可选的团队责任覆盖字段。
- 现有状态校验和旧版本迁移接受缺少新字段的历史数据；新字段存在时验证其类型。
- `PersonAvatar` 接受可选自定义图片地址；没有自定义头像或加载失败时继续使用现有生成头像。
- 个人资料表单负责图片选择、草稿预览、校验与保存。
- 成员面板负责单行编辑状态、权限判断和保存，不修改全局成员基准数据。

## 异常、响应式与可访问性

- 头像选择失败、图片超限或本机存储失败时显示明确错误，旧值不丢失。
- 没有管理员权限时，责任保持只读且不渲染编辑按钮。
- 小屏幕继续使用单列个人资料；成员责任编辑器与操作按钮在责任列内换行，不产生横向滚动。
- 编辑头像、编辑责任、保存和取消均可通过键盘触达；保存或取消责任后焦点返回该行编辑按钮。
- 图片加载失败时保留姓名生成头像作为回退。

## 验收与验证

- 个人信息界面不再渲染“工作身份、时区、关于我”，邮箱只读。
- 本地图片选择后出现预览，保存并重新加载状态后仍能显示。
- 当前用户头像在设置侧栏和应用内头像组件中使用保存值。
- 管理员可点击责任编辑图标，保存或取消单行修改；普通成员和受邀成员不可编辑。
- 修改后的责任只影响当前团队，并可从浏览器存储恢复。
- “我的责任”团队选择器的触发器和选项中均无团队 Logo。
- 相关定向测试先失败再通过；最后执行类型检查和与本次改动直接相关的测试。

## 非目标

- 不上传图片到服务端，不建设头像裁剪器或媒体库。
- 不开放邮箱修改，不删除历史状态中的兼容字段。
- 不改变“我的责任”正文编辑、AI 建议或团队角色管理。
- 不执行全量测试或双重审查，除非用户另行要求。
