# 任务模板：发现—沉淀—复用

> 历史方案，已于 2026-09-16 撤回。任务模板功能、专用示例数据与独立设计稿已移除；下文仅保留历史记录，不作为当前产品需求或实施计划。以[产品决策台账](../../product-v2/09-decision-register.md)中的 `D-REMOVE-TASK-TEMPLATES-2026-09-16` 为准。

日期：2026-09-14。状态：用户已明确三步产品方向；本文件将原五项流程能力方案收敛为任务模板方案。用户随后明确要求保留任务列表加号的直接手动创建，并增加模板洞察快捷示例；这两项已实施，见第 9 节。正式模板库、持久化与共享权限仍是方案范围。

## 1. 本轮明确的方向

围绕 **发现—沉淀—复用**：

1. 发现：助手在对话中提示用户，当前做法或任务拆解是否值得保存为模板。
2. 沉淀：用户确认保存；产品页面提供入口，展示有权使用的模板。
3. 复用：创建任务时，可以基于已有模板适配本次需求。

前台统一称为“任务模板”，列表行中简称“模板”。模板保存任务拆解、执行步骤和判断方法；SOP 是其中可复用的内容，不另建一套同级功能入口。

本稿替代原方案中前台统一叫“流程”、主要从助手菜单找回资产、将五项能力分别铺开的建议。模板在产品页面可以直接找回；对话继续承接发现、保存和适配。

用户是形成做法的人，以及以后执行同类工作的人。成功证据是：成员从对话中保存一份模板，有权限的同事从产品入口找到模板，按本次条件调整后创建任务。

## 2. 发现：在对话中提示保存

### 2.1 提示时机

在对话中已经形成清楚且可能再次使用的任务方案、拆解结构或执行方法时，助手可以在该结果旁给出一句提示和“保存为模板”动作。用户也可以直接说“把这个保存为模板”。

不必等任务完成，也不以跨任务挖掘为前提。来自未执行方案的模板明确保留其来源性质，不能称为经过实践验证。若引用多次历史任务说明重复，必须具有当前用户可访问的真实证据。

示例仅说明交互：

> 这套活动筹备的拆解可以用于后续同类活动，是否保存为模板？
>
> 保存为模板 · 暂不保存

同一份方案未发生实质变化时不反复提示。不合适时不显示保存建议；用户主动保存仍可进入预览。已有类似模板时说明相似之处，由用户选择使用已有模板、更新自己有权编辑的模板，或另存。

### 2.2 操作边界

点击“保存为模板”进入当前内容的保存预览。来源是用户最近一次编辑后的方案或明确选定的实际任务，不使用较早的模型回复覆盖用户修改。

查看建议不保存；保存模板不创建任务。如果对话里同时有待创建任务方案，两种动作分别表明结果，保存模板不会自动执行任务创建，也不会丢掉原任务草稿。

## 3. 沉淀：轻量保存与产品入口

### 3.1 保存预览

同一编辑区内展示名称、适用场景、任务拆解和步骤，次要信息按需展开。底部保留共享范围与一个“确认保存”动作。预填信息可直接编辑，也能继续通过对话调整。

| 保存内容 | 处理方式 |
| --- | --- |
| 模板名称、适用场景 | 说明什么工作可以使用、关键前提是什么 |
| 任务与子任务结构 | 保留独立交付、完成标准和明确的依赖；细小操作放进执行建议 |
| 步骤与判断方法 | 保留操作步骤、为什么这样拆、什么情况下需要增加或跳过某项 |
| 可替换条件 | 将具体客户、项目、人选和日期转为本次需要确定的内容 |
| 来源、维护人与范围 | 记录精确来源及版本、保存者或维护人、谁能查看使用 |

不照搬旧任务状态、已完成记录、审批结论或敏感业务资料。相对日期需要明确的参考节点，没确定日期时可以先不排期。用户无须先配置参数表或编写分支表达式，助手负责识别并在使用时核对。

初期范围建议为“仅我”和“当前团队”；对有共享权限的人提供团队范围。保存动作一次核对具体内容和受众，结果进入相应的模板列表。读取来源的权限不自动产生共享权限。

### 3.2 产品页面入口

建议在任务页面顶部、“新建任务”附近增加“任务模板”入口，打开标准模板列表。这一入口负责发现和找回已有资产，是用户明确要求的产品入口；具体放置位置仍可随页面布局调整。任务列表原有加号继续直接新建一个空白任务，不承载模板选择或助手启动。

列表提供搜索及“全部／我的／团队”范围筛选，所有结果先按权限过滤。每行显示模板名称、一句适用说明、共享范围和维护信息；点击进入详情，主要动作是“使用模板”。编辑、另存和停用放在有权用户的菜单中。模板少时可以先不显示额外筛选。

| 页面部分 | 支撑的动作 | 数据与删除损失 |
| --- | --- | --- |
| 任务页面的模板入口 | 直接找回可复用模板 | 当前团队与用户；删除后必须翻找聊天历史 |
| 搜索与模板列表 | 找到适用模板 | 已授权的模板元数据；删除后无法有效选择 |
| 模板详情与拆解列表 | 判断是否适用，进入创建 | 同一模板版本的内容；删除后只能盲目套用 |
| “使用模板”动作 | 将选定版本带入创建 | 模板 ID、版本、当前团队；删除后无法完成复用 |

详情使用任务与步骤列表，不另设 SOP 编辑器或流程图画布。助手中可直接引用相同模板，产品列表与对话不保存两份相互独立的副本。

## 4. 复用：基于模板适配本次任务

支持两个起点：在模板列表点击“使用模板”；或在助手对话中发现适用模板，说明理由并推荐使用。任务列表加号保留直接手动创建，不在点击后增加模板选择步骤。

两个起点共用同一份模板列表和同一创建流程：

1. 选择模板，只带入模板 ID 和具体版本，展示适用理由。
2. 用户描述本次需求，助手结合已有上下文核对不同点；仅补问会影响拆解的条件。
3. 按本次目标、角色、日期与业务分支生成现有可编辑任务方案，说明关键增减。
4. 用户可增删步骤、调整子任务、人选和日期。修改先作用于本次方案。
5. 用户确认后创建任务，记录采用的模板版本与实际创建结果。

例：使用“活动筹备”模板创建线上分享会时，适配后的方案可以去掉现场布置，增加直播测试。是否包含这些工作由用户本次需求和确认后的方案决定，不因为模板里存在某项就强制保留。

从固定父任务进入时，保留父任务与其主目标，比较已有子任务后起草缺失工作。模板的参考目标不覆盖父任务目标。角色需映射到本次有权选择的成员；不直接继承历史负责人。

采用模板不增加当前用户的操作权限。用户调整本次方案不会修改原模板；需要沉淀改进时，再明确选择更新原模板或另存为新模板。普通创建不强制用户做一次模板维护。

## 5. 权限、版本与数据规则

模板可见范围、来源内容共享策略和创建任务权限分别校验。模型负责发现、提炼和适配，确定性服务负责身份、授权、引用、版本和正式写入。

- 保存预览与共享正文按实际受众检查；原对话默认个人可见，明确保存的模板内容才按确认范围共享，不能连带分享整段对话。
- 列表、检索、详情、来源引用和使用记录不能泄露不可见任务的标题、数量、正文或参数。
- 每次模板更新形成可追溯版本。已创建任务记录实际采用版本，后续更新不静默修改这些任务。
- 模板停用、失权或来源授权变化时，重新检查受影响的正文、摘要、缓存及未提交方案；旧对话不能绕过当前权限。获得独立共享授权的通用正文与受限案例分开判断。
- 确认创建时再次检查模板可用性、目标任务快照、成员、依赖和参数权限。创建结果与采用记录一致提交，失败保留草稿，重复点击不重复创建。
- 已保存或已被使用不表示做法已验证，也不表示组织已发布强制标准。

底层最小数据包括模板身份与范围、版本内容、来源引用、采用记录，以及用于防止重复提示的个人处理记录。来源需要对象 ID 和版本，不能只依赖不可定位的摘要。

之前已只读核对代码；以下是可衔接的基础，不代表新功能已实现：

## 7. 状态与最小验收

| 状态 | 用户体验 |
| --- | --- |
| 正常 | 保存后可从产品列表找到；使用后进入可编辑方案；确认创建后展示真实任务 |
| 空 | 无模板时说明可以在助手中将方案保存为模板；无匹配时保留搜索和直接创建 |
| 加载 | 展示真实处理状态，防止重复保存／创建；分析与适配可停止 |
| 失败 | 保存失败保留预览，适配失败保留本次需求，创建失败保留方案；不伪装成功 |
| 无权限 | 不返回受限内容；说明当前操作不可用，不能提供无实际能力的授权按钮 |
| 过期 | 模板或目标任务变化时说明影响，保留手改内容，核对后重新提交 |
| 移动端 | 模板列表和详情单列，适配返回助手，返回时保留选择和草稿，无横向溢出 |
| 键盘 | 列表、详情与保存动作可聚焦，展开状态可读，关闭后恢复焦点，支持中文输入 |

首版验收按完整三步进行：

1. 对话中形成未执行方案也可提示保存，来源性质准确，保存以用户最新编辑为准。
2. 保存模板不创建任务、不丢待创建方案；暂不保存后不反复提示同一内容。
3. 保存结果能从任务页面入口找到；有权同事可见、无权成员不可见。
4. 从模板列表或对话中的模板推荐进入都可完成适配，并使用同一任务确认流程；列表加号仍直接创建一个空白任务。
5. 本次条件能改变拆解；手工修改保留，原模板不被修改；既有父任务和子任务关系正确。
6. 保存／创建失败、重复提交、版本变化、失权与撤权处理符合规则。
7. 窄屏和键盘可以完成保存、查找、选择、适配与确认。

只执行实际改动所需的最小必要验证；不自动运行全量测试或双重审查。

## 8. 后续再扩展的能力

跨任务自动挖掘、后台持续发现、采用效果分析和主动更新建议，可在三步闭环有真实使用后扩展。首版已经包含对话中的发现提示，不能把“发现”推迟到这些后台能力完成之后。

待确定的细节：任务页面入口的具体位置、团队模板的发布与维护权限。以上已给建议默认值，不构成对组织权限政策的自动确认。


## 9. 本轮交付：手动创建与模板洞察示例

用户确认的范围是任务列表加号直接创建，以及助手中的可点击快捷示例。

- 「我的任务」旁的加号点击即保存一个「未命名任务」并打开详情。归属当前团队，状态待开始；负责人、参与人、目标、完成标准、标签和日期留空，留待用户填写。创建时单独记录当前用户为创建者。保存失败回滚并提示错误。
- 助手欢迎区及已有对话的输入区提供「模板发现示例」。案例展示新品达人推广的拆解、保存建议、名称／场景／步骤编辑、再次发现已有模板，以及按 4 位达人和是否直播适配方案。适配预览复用现有任务方案编辑组件。
- 示例支持暂不保存、取消编辑、重新体验及返回对话。保存要求名称、场景和至少一个步骤；空字段提示错误并保留输入。返回保留真实会话、未发送草稿和待确认方案，Escape 返回对话并恢复输入焦点。
- 示例采用固定数据，不读取实际任务来声称发现重复，也不调用模型、写入真实模板或创建正式任务。界面明确说明保存／创建仅在示例内生效；不模拟组织权限已获授权。无网络加载或模板过期状态，正式能力仍按第 5–7 节设计。

最小验证：手动创建相关测试 9 项通过，覆盖保存与失败回滚；构建通过。隔离浏览器中验证加号新增且仅新增 1 个任务、详情为空白、刷新仍保留；验证示例保存时空名称拦截、修改后保存、排除直播后得到 1＋4 方案、手改任务名称保留到演示结果，真实列表数量不变。390px 预览和结果可操作；返回与 Escape 保留未发送草稿。未运行全量测试或双重审查。
