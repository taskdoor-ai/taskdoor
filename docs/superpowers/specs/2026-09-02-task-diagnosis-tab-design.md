# 任务诊断 Tab 设计

## 2026-09-03 用户确认的调整（优先于下方历史方案）

- 决策内容冲突以“两个当前适用文件表达不一致”或“交付／执行文件违背当前任务完成标准”为主要样例；核对同一对象、合同版本、批次或结算期，不能混用已归档、被替代或不可读内容。
- 讨论中的建议、异议和进展不自动代表已生效决定。保留讨论数据，但不据此预填冲突，也不以“讨论说已统一”代替文件或标准实际更新。
- 结果任务的 mock 将预算、授权、结算口径写入实际可读文件；文件与标准可以独立支持诊断，不强制补入无关目标或讨论。
- 依据在原有“查看依据”中按文件、任务等实际来源分组，显示所属任务、文件名或字段名及原文；只展示存在的分组。展开后明确指出冲突点，执行阻塞则说明阻塞原因。
- 本次不改变依赖检查和正式完成状态一致性检查，也不增加新的诊断入口、业务处理状态或自动验收动作。
- 验收重点：删除讨论不影响成立的文件冲突；只有不同建议不报冲突；修改、删除或归档关键文件后重新计算；当前实现仍是本地示例格式核对，不宣称通用语义理解。

## 对象、用户与本次决策

- 对象：一个 Task、其当前可见的完整后代任务树、前置依赖和每个范围任务已提供的决策依据。
- 用户：需要判断任务能否继续、应依据什么继续的 Task Owner 与有权成员。
- 本次决策：任务分析分为两层。“我的工作”负责跨任务推荐顺序；任务详情新增与子任务同级的“诊断”Tab，负责单任务执行分析。
- 成功证据：用户能从诊断结论理解具体阻塞或冲突，并能展开核对原始依据；页面不要求用户理解后台评分，也不把建议冒充任务变更。

## 首版范围

诊断首版只包含两类发现：

1. 执行阻塞：检查当前 Task 及其全部可见后代 Task 的真实依赖、前置完成状态和日期顺序。
2. 决策冲突：检查正式完成结论与当前子任务状态的确定冲突，或接收至少包含冲突两侧可定位依据的结构化结论。

责任缺失继续在任务属性呈现；验收证据缺口需等完成标准与证据建立可靠关联后再进入诊断。首版不展示健康分、完成概率、成员评价、泛化协作建议或无法定位依据的 AI 文案。

## 信息结构

任务详情页签顺序：

`讨论｜诊断 N｜子任务｜文件｜活动`

诊断页由三部分组成：

1. 标题与结果数量：任务诊断报告；分别显示执行阻塞与决策冲突数量。
2. 覆盖说明：说明检查了当前任务、多少个子任务、可见依赖及已提供决策依据；子任务数量包含全部后代层级，只有可信快照提供时间时才显示“依据截至”。
3. 问题列表：当前任务自身的问题在前；子任务问题按实际受影响任务分组，显示从当前任务起算的相对路径。每项把完整诊断结论直接作为标题，只在下方展示影响、文本建议和默认收起的依据，不再重复设置“结论”字段。

每项唯一交互为原生 disclosure“查看依据”。展开后只显示事实句列表；每条事实下方可用弱化元数据标明来源对象，不设置“前置任务／当前任务／现行决定／新提议”等证据标题或角色栏，也不提供改期、改依赖、发起讨论、一键修复、忽略或手工完成按钮。

## 判断与依据生成规则

诊断类型只允许“执行阻塞”和“决策冲突”。类型属于问题卡，完整结论属于卡片标题；依据本身不再产生新的类型、标题或 AI 解释层。

### 执行阻塞

- 必须同时存在当前任务或任一可见后代任务的正式前置关系，以及至少一项可见前置任务尚未完成的状态记录，才生成执行阻塞。
- 普通未完成阻塞的最小依据为：一条完整的依赖关系事实，以及每项未完成前置的当前状态事实。
- 只有前置与消费任务都有可比较截止时间、且前置截止晚于消费任务时，才在依赖关系事实中补充消费任务截止，并在前置状态事实中保留前置截止。
- 若消费任务已标记为已完成但前置仍未完成，不再展示执行阻塞，而是生成“完成结论与前置记录冲突”。
- 依赖不可见或不存在时只记录 Coverage 缺口，不把未知补成未完成，也不展示对象名称或缓存状态。

### 决策冲突

- 必须有两个不同来源对象支撑互不相容的正式记录，单条讨论、单份文件或 AI 推测不能形成决策冲突。
- 完成状态冲突使用完成记录与仍未结束的前置／后代任务状态作为两侧事实。
- 外部结构化冲突保留两侧原始事实句及各自来源对象；来源角色只参与后台校验，不作为界面标题展示。
- 多项事实共同支撑同一结论时全部列出并按判断顺序排列，不以概括文案替代缺失依据。

### 依据呈现

- 每条依据固定为“完整事实句＋来源元数据”，事实在前，来源弱化显示。
- 来源只表达记录来自哪个 Task、文件或活动；没有可信时间／版本时不补造。
- 当前页面已经明确的信息不单独重复；只有参与状态或日期比较时才进入事实句。
- 依据不是相关资料列表，也不是模型推理过程；删除任一关键事实会使结论无法成立或需要改变。

## 数据与判断边界

- 执行阻塞读取稳定 Task ID、`dependsOnTaskIds`、TaskStatus 和可用截止时间。未完成前置形成阻塞；前置截止晚于后续截止时明确指出时间顺序冲突。
- 任一 Task 的诊断范围为自身及全部可见后代；叶子任务只诊断自身，中间任务只聚合自己的子树，主任务聚合完整任务树。父子归属本身不作为执行依赖。
- 每条发现只生成一次并绑定实际受影响 Task；进入该 Task 时作为自身诊断呈现，进入任一包含它的上级 Task 时按同一发现标识聚合呈现，不复制出平行报告。
- 已取消的消费任务不继续产生等待前置诊断；已完成的任务若仍存在未完成前置，转为“完成结论与前置记录冲突”，不能静默消失。
- 任一父 Task 已完成但仍存在未完成／未取消的后代 Task 时，形成归属于该父 Task 的“完成结论冲突”。
- 外部提供的决策冲突至少包含两个不同来源对象；缺少冲突两侧依据时不展示。
- 引用的依赖不可见或已经不存在时，只显示覆盖不完整，不推断该依赖已完成、任务无风险或任务健康。
- 诊断结果随源事实重新计算，不建立独立的已处理／未处理业务状态。

## 重新计算触发条件

诊断只在已经保存或同步成功的源事实变化后重新计算，不随输入框草稿、展开依据或普通页面浏览反复触发：

1. 进入或重新进入“诊断”Tab：读取当前最新可见快照，补齐离开期间已经同步的变化。
2. 当前任务变化：状态、截止时间或前置依赖保存成功。
3. 后代任务变化：任一层级新增／移除任务，或其状态、截止时间、前置依赖保存成功；相关任务自身及所有可见上级任务的诊断重新计算。
4. 可见前置任务变化：状态、截止时间、删除／恢复或可见权限变化。
5. 决策依据变化：正式决定被新增、撤回或替代，或构成冲突两侧的文件／活动版本完成同步。
6. 服务端推送相关任务或依据的新版本：生产环境接入实时事件后，用新版本重新计算；失败时保留失败／过期语义，不把旧结论冒充当前结果。

不会触发重新计算的动作：展开或收起“查看依据”、切换卡片焦点、尚未保存的编辑草稿、与诊断两类问题无关的普通讨论或文件浏览。问题条件消失后不再展示；若状态变化制造了新的正式记录冲突，则替换为对应冲突，而不是直接清空。

## 状态

- 正常：展示发现数量、覆盖说明和按严重程度排列的问题。
- 空结果：说明当前可见范围内未发现执行阻塞或决策冲突，同时明确不代表完成或验收通过。
- 覆盖不完整：保留已核对结果，并说明有多少依赖不可见或缺失；不展示受限对象名称、ID 或缓存状态。
- 加载：未来接入异步诊断服务时保留当前任务信息，只在诊断面板显示加载状态。
- 失败：说明本次诊断未完成，不能回退展示旧结果为当前结论。
- 数据过期：保留快照时间并标记过期；源数据变化后重新诊断，旧结论不能继续宣称有效。
- 无权限：只说明诊断范围受限，不泄露被拒绝对象的任何业务信息。
- 移动端：问题内容改为单列，依据入口保持至少触控尺寸，不产生横向滚动。
- 键盘：诊断参与现有 Tab 的左右方向键、Home、End 切换；依据 disclosure 可通过键盘展开与收起。

当前本地原型同步使用现有可见数据，只实现正常、空结果与覆盖不完整；加载、失败、数据过期和无权限状态随真实诊断服务与 ACL 接入实现。

## 验收项

- 所有任务详情稳定显示“诊断”Tab，位于“讨论”之后、“子任务”之前。
- 四套现有团队 Mock 分别至少有 50% 的任务基于已有状态、前置关系或结构化冲突形成非空诊断；无成立事实的任务保持空结果，不为演示覆盖率伪造问题。
- 平台、制造与客户成功各至少有一个决策冲突子任务样例；两侧依据可定位到对应 Mock 文件和活动原文，并以同一发现标识聚合到全部祖先任务。
- 叶子 Task 能识别自身未完成前置；任一父 Task 能递归识别全部后代内部的未完成前置。
- 子任务自己的结构化冲突在子任务详情和所有包含它的上级任务诊断中使用同一发现标识；上级按受影响任务分组，不把任务路径混入依据标题。
- 前置日期晚于后续截止时显示具体日期依据和顺序冲突。
- 完成任务仍有未完成前置时展示决策冲突；前置完成或依赖被移除后，原阻塞随重新计算消失。
- 决策冲突没有至少两侧依据时不展示。
- 每项把完整结论作为标题，只展示影响、文本建议和“查看依据”；诊断页不重复“结论”字段，也不出现直接编辑或闭环动作。
- 展开的依据不出现证据标题或角色栏；每条只展示完整事实句及可信来源元数据。
- 空结果、缺失依赖和可信快照时间使用各自真实语义，不补造健康结论或分析时间。
- 诊断 Tab 保持现有鼠标、键盘与窄屏页签行为。
