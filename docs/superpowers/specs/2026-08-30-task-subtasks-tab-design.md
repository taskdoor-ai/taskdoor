# 任务详情子任务 Tab 设计

## 目标

在任务详情导航中增加“子任务”Tab，为当前任务的直接子任务提供紧凑、可快速进入的列表视图，同时保留概览中已有的子任务看板与依赖画布。

## 范围

- 任务详情 Tab 顺序调整为：概览、子任务、文件、活动。
- “子任务”Tab 的数量徽标显示当前任务直接子任务的数量。
- 列表只展示当前任务的直接子任务，不递归展示更深层后代，也不混入父任务、依赖任务或其他相关任务。
- 概览中的现有子任务看板、筛选器和依赖画布保持不变。
- 本次不增加创建、排序、批量编辑或树形展开能力。

## 界面与交互

“子任务”Tab 使用独立的 tabpanel。顶部显示标题、数量说明和一句简短用途提示，主体为单列列表。

每个列表项展示：

- 任务图标与名称；
- 当前状态；
- 负责人头像；
- 截止时间。

整行作为一个可聚焦的打开入口；点击或使用键盘激活后，通过任务详情现有的 `onOpenRelatedTask(taskId)` 回调进入对应子任务。Tab 本身沿用当前左右方向键、Home、End 的键盘切换机制和 ARIA 关联。

当当前任务没有直接子任务时，tabpanel 显示明确的空状态，不展示无效列表容器。

## 数据流与组件边界

`TaskDetail` 继续以 `childTasks` 作为当前任务直接子任务的唯一数据源：

1. 使用 `childTasks.length` 生成 Tab 数量徽标。
2. 将 `childTasks` 传给专用的子任务列表渲染单元。
3. 列表项使用已有 `TaskRelationSummary` 字段，不引入新的持久化数据结构。
4. 点击列表项调用 `onOpenRelatedTask`；回调缺失时列表项保持可读，但不可执行跳转。

列表视图与 `TaskOverviewWorkspace` 相互独立：前者服务快速浏览和进入，后者服务进度与依赖关系观察。

## 视觉约束

- 复用现有设计令牌、任务状态色、任务图标和人员头像组件。
- 列表保持单列、紧凑、清晰分隔，不复用概览卡片网格，避免两个入口视觉上完全重复。
- 在窄屏下允许次要元信息自然换行或收紧，但任务名称与打开入口仍保持清晰。

## 异常与边界状态

- 无子任务：显示空状态，Tab 数量为 0。
- 缺少打开回调：列表仍展示，交互入口禁用并提供正确语义。
- 截止时间为空或未设置：原样展示任务摘要提供的占位文案。
- 子任务数据更新：数量和列表随 `childTasks` 属性重新渲染。

## 验证

- 单元测试验证 Tab 顺序、子任务数量、空状态和仅展示直接子任务。
- 交互测试验证点击列表项会传出正确任务 ID，缺少回调时不会误触发。
- 键盘测试验证四个 Tab 的 ArrowLeft、ArrowRight、Home、End 导航。
- 运行类型检查和现有测试，确认概览、文件与活动面板行为不回归。
