# 任务活动三类动态设计

## 对象、用户与本次决策

- 对象：一个任务中已经真实发生并可见的任务信息变更、讨论和文件活动。
- 用户：需要快速回看任务发生过什么的 Task Owner、参与人及其他有权成员。
- 本次决策：任务活动只使用“任务信息、讨论、文件”三种类型。类型表示动态发生在哪类对象上；“修改时间、变更状态、发表回复、提交文件”等继续作为具体动作，不再被抽象成类型。
- 成功证据：用户能通过三个稳定胶囊快速区分活动来源，同时仍能从动作文字理解具体发生了什么；活动记录保持只读，不产生可选中的卡片状态。

## 问题与边界

此前实现直接按照“状态变更、时间变更、文件提交”等具体动作配色。这会把“类型”和“动作”混在一起：同属任务信息的每个字段变化都可能继续增加颜色、筛选项和样式规则。

本设计只解决任务活动的分类与呈现，不改变讨论、文件和任务信息本身的编辑能力，也不增加新的业务状态。AI 建议、诊断结论和系统推测不属于已经发生的用户活动，不能为了补齐时间线而写入三类活动。

## 类型定义

### 任务信息 `task`

表示当前任务属性或定义发生了真实变化，包括：

- 状态、开始时间和截止时间；
- 名称、目标、范围和完成标准；
- 负责人、负责人提议和参与人；
- 标签、优先级、图标和背景等任务属性。

具体动作仍显示为“修改任务时间”“变更任务状态”“更新负责人”等，不统一改写成“任务信息变更”。只有已经保存或同步成功的变化才生成活动；未保存草稿和没有实际差异的编辑不生成记录。

### 讨论 `discussion`

表示成员在当前任务中发布了讨论或回复，包括：

- 发布一条新的成员讨论；
- 回复已有成员讨论；
- 回复带有来源上下文的旧记录。

活动页只展示作者、时间、动作和必要的正文摘要，并提供进入原讨论的入口。完整正文、回复串和讨论操作仍留在“讨论”Tab，不在活动页复制整段会话。

### 文件 `file`

表示当前任务中的文件发生了真实操作，包括已有的文件提交，以及未来接入真实记录后的上传、编辑、重命名、移动、删除或恢复。

活动页展示动作和文件名。文件仍可用时可进入“文件”Tab 打开对应文件；文件已删除、归档、无权限或缺失时明确显示不可用，不把失效入口伪装成可点击文件。

## 现有事件映射

| 现有事件 | 活动类型 |
|---|---|
| `status-change` | 任务信息 |
| `schedule-change` | 任务信息 |
| `title-change` | 任务信息 |
| `goal-change` | 任务信息 |
| `owner-change` | 任务信息 |
| `owner-proposal` | 任务信息 |
| `participant-added` | 任务信息 |
| `participants-change` | 任务信息 |
| `tags-change` | 任务信息 |
| `appearance-change` | 任务信息 |
| `task-definition-change` | 任务信息 |
| `member-post` | 讨论 |
| `member-reply` | 讨论 |
| 文件或代码提交记录 | 文件 |
| `ai-insight` | 不进入任务活动 |

新增事件必须先明确它操作的对象，再映射到三种类型之一；不能仅为新动作新增第四种颜色。若事件不能可靠归入三类，先保持不展示并补齐数据语义，不使用“其他”掩盖未知。

## 信息结构与文案

活动 Tab 内标题改为“任务活动”，说明为“谁在何时做了什么，按时间从新到旧记录。”

筛选固定为：

`全部活动｜任务信息｜讨论｜文件`

每条活动的主行固定为：

`作者　类型胶囊　具体动作　　　　　　　　　发生时间`

例如：

- `周岚　任务信息　修改任务时间`
- `周岚　任务信息　变更任务状态`
- `陈默　讨论　回复了周岚`
- `周岚　文件　提交召开九月达人池决策会交付确认.md`

类型胶囊只使用三套稳定语义色：任务信息使用蓝色、讨论使用青绿色、文件使用紫色。具体动作不再单独决定颜色。活动条目本身只读、不可选中，鼠标点击空白区域不产生选中态；程序定位活动时也不绘制整条蓝框。条目中的真实链接和按钮继续保留键盘焦点反馈。

## 计数、排序与去重

- 活动 Tab 的数量等于当前用户可见的三类活动总数，不再只统计任务信息和文件变更。
- 所有类型合并后按可信 `createdAt` 从新到旧排序；没有可信时间的旧记录保持稳定相对顺序，不用“刚刚”“今天”等旧文案补造绝对时间。
- 同一讨论在“讨论”Tab 展示完整内容，在活动页只展示一条摘要与定位入口；回复各自形成活动，不在摘要中重复展开回复串。
- 同一文件在“文件”Tab 展示当前内容与版本，在活动页展示发生过的真实操作，不复制文件正文。
- 任务信息编辑仍发生在任务详情属性区，活动页只展示保存后的前后值。
- 同一来源事件使用稳定事件 ID 去重；任务信息、讨论和文件来源即使原始 ID 相同也不能互相覆盖。

## 数据边界

活动投影至少需要：稳定事件 ID、任务 ID、活动类型、具体动作、作者、可信发生时间，以及该类型所需的最小内容。

- 任务信息：变更字段及真实前后值；没有差异时不生成事件。
- 讨论：原讨论或回复 ID、正文摘要所需原文及可定位的父记录 ID。
- 文件：文件 ID、文件名、动作和当前可用性；不能只凭文件名假定文件仍存在。

类型是展示和筛选投影，不替代底层具体事件。底层继续保存足够精确的动作，以支持审计、定位和未来文案调整。

## 状态与可访问性

- 正常：混合展示三类活动，胶囊和筛选使用相同类型定义。
- 全部为空：显示“还没有任务活动”，说明任务信息修改、讨论或文件操作发生后会记录在这里。
- 筛选为空：显示“没有这类活动”，并允许切回全部活动。
- 加载：接入异步服务后保留活动区域结构，只显示加载状态，不回退成空记录。
- 失败或数据过期：明确说明活动未完整加载或快照已过期，不把旧数据冒充当前完整记录。
- 无权限：只统计和展示当前用户可见活动；不泄露不可见讨论、文件名、成员或活动数量。
- 移动端：主行允许作者、类型和动作自然换行，时间移至下一行，不产生横向滚动。
- 键盘：筛选器、讨论入口和文件入口可操作；只读活动条目不进入 Tab 顺序，也不显示可选中卡片样式。

## 非目标

- 不新增“进展、计划、协作、交付”等二级类别。
- 不按每个具体动作分配独立颜色。
- 不把活动页改成讨论页或文件版本页。
- 不在活动页提供编辑、撤销、删除活动或批量选择能力。
- 不把 AI 建议、诊断推测或未保存草稿记录为已经发生的活动。

## 验收项

- 活动类型只有“任务信息、讨论、文件”三种，筛选项、胶囊和计数使用同一映射。
- 状态、时间、目标、负责人等现有变更全部归入“任务信息”，但保留各自具体动作文字和真实前后值。
- 成员讨论和回复进入“讨论”类型；活动页只显示摘要和定位入口，完整讨论不重复展开。
- 文件提交进入“文件”类型；文件可用时能打开，不可用时明确禁用。
- `ai-insight`、未保存草稿和无真实差异的编辑不进入活动。
- 三类活动按可信时间统一排序，旧相对时间不会覆盖真实记录顺序。
- 活动总数包含当前可见的三类活动；切换筛选后只改变列表，不改变底层记录。
- 任务信息、讨论和文件分别使用蓝色、青绿色和紫色胶囊，新增具体动作不新增颜色。
- 活动条目没有选中态或整条蓝色焦点框；条目内可操作入口仍有清晰键盘焦点。
- 空、筛选空、加载、失败、过期、无权限、移动端和键盘状态使用各自真实语义。
