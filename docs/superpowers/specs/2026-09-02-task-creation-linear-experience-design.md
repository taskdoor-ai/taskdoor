# 任务创建分步纵向体验设计

## 对象与本次决策

对象是从任务列表进入“新建任务”的团队成员。本次新增一个可对比的“分步方式”：系统在用户输入需求后，内部依次完成目标整理、人员匹配、拆分判断和子任务规划；页面只逐步呈现由这些判断产生的真实任务内容。

现有 `TaskCreationPage` 及其默认入口完整保留。用户进入创建页后，通过顶部标准 Tab 在“当前方式”和“分步方式”之间切换；默认仍为“当前方式”。本次不在任务列表增加第二个新建按钮，也不替换现有流程。

成功证据：用户能在同一纵向页面内直接检查和修改主任务、协作成员与子任务，并清楚区分“生成中的思考状态”和“最终会被创建的任务信息”。

## 设计原则

- 页面是一份逐步增长的纵向文档，不是卡片集合。
- 生成时可以短暂说明当前正在思考什么；完成后只保留任务内容，不保留步骤编号、步骤标题或“已生成”状态。
- 建议、事实与决定分开表达：人选是建议而非已接受；拆分结论必须附依据；创建前所有内容仍是草稿。
- 生成顺序本身承担过程反馈，不另叠加一套工作流卡或 Agent 轨迹。
- 两种体验复用相同任务数据、校验和提交能力，实验只比较信息组织与交互节奏。

## 入口与页面结构

新增 `TaskCreationExperience` 作为创建页外壳：

1. 顶部保留返回任务列表路径。
2. 路径下方显示“当前方式 / 分步方式”Tab。
3. “当前方式”渲染现有 `TaskCreationPage`。
4. “分步方式”渲染新的 `TaskCreationLinearPage`。

两个页面在本次创建会话中都保持挂载，非当前页面隐藏并停止焦点、live region 和弹层活动。切换模式不会清空各自草稿；关闭创建会话或切换团队仍沿用现有重置边界。本次不把模式选择写入本地偏好。

## 分步方式的信息顺序

### 0. 输入需求

初始页面只显示简洁标题、大输入区和“开始拆解”动作，不显示快捷示例。输入提交后，原文缩成页面开头的“原始需求”，提供“修改需求”入口。重新提交会重新生成该模式的草稿；生成失败时保留上一份有效结果。

### 1. 目标与验收标准

先展示系统理解出的任务名称、目标和完成标准。字段可以就地编辑。缺少会改变任务结构的关键信息时，在这里插入“补充信息”步骤；回答后继续生成，不把用户带到另一张表单卡。

### 2. 寻找参与者

分别展示负责人建议和参与人建议，包含姓名、建议角色与可验证依据。没有合适人选时明确显示“暂不分配”，不伪装为空数据。所有人选都标注“建议中，尚未接受”。用户可更换负责人、增删参与人或邀请新成员。

若规划器发现可能属于已有任务，在此步骤之前插入“确认任务归属”。用户可以选择作为已有任务的子任务，或继续独立规划；该选择只改变草稿归属，不修改已有任务。

### 3. 是否拆分（内部阶段）

系统根据范围、交付物、并行性和依赖判断是否拆分。该判断只参与生成过程，不在结果页形成“是否拆分”任务模块。

无需拆分时直接呈现主任务并允许手动添加子任务；需要拆分时直接进入真实子任务列表。

### 4. 子任务规划（内部阶段）

系统内部确定拆分维度、建议顺序、可并行关系和必要的前置依赖。结果页不重复展示规划摘要，而是将顺序和依赖直接体现在真实子任务中。

### 5. 逐个生成子任务

子任务按规划顺序逐个追加。每项默认是一行摘要，包含名称、一句话目标、负责人和展开控制，不使用思考阶段编号、独立卡片背景或悬浮阴影。

展开后在原位置显示可编辑的完整信息：

- 名称、目标、完成标准与执行建议；
- 负责人、参与人、截止时间与标签；
- 工作量与前置依赖；
- 移除子任务和针对该子任务的 AI 调整入口。

一次可以展开多个子任务，方便对照。收起后未保存或同步失败的修改必须在摘要行提示，不能隐藏错误。

### 6. 确认创建

所有必要步骤完成后，页面底部出现普通确认区，汇总将创建的主任务与子任务数量、未分配任务数量和人选待接受状态。确认动作复用现有校验与一次性创建逻辑。

生成未完成、存在字段错误、任务关系待决定、AI 调整运行中或子任务修改未同步时，确认按钮不可用并显示具体原因。创建成功后提供“查看任务”和“继续创建”。

## 生成节奏与状态

新的纵向页面复用现有 `planTaskCreation` 产生的澄清、关系决定和 `CreationForm`，前端只负责把结果按阶段呈现。顺序展示是界面反馈，不表示启动了多个 Agent，也不表示成员已经参与。

正常生成时：

1. 当前步骤显示轻量加载状态和具体动作，例如“正在核对目标是否可验证”。
2. 步骤完成后正文进入页面，下一步骤紧接着开始。
3. 生成过程中允许“停止”；停止后保留已出现内容和原始需求。
4. 页面通过非打断式 live region 通知当前步骤，不抢夺键盘焦点。

步骤揭示节奏使用可取消的前端播放控制；最终表单始终来自同一份规划结果。编辑任一已完成步骤会更新同一份 `CreationForm`，不会生成相互冲突的快照。

## 组件与职责

### `TaskCreationExperience`

- 管理模式 Tab 和两个页面的活动状态。
- 保持两个页面实例和各自草稿。
- 确保隐藏页面不可聚焦、不可播报，也不能保留打开的弹层。

### 现有 `TaskCreationPage`

- 保持当前视觉、状态与行为。
- 只接收外壳传入的活动状态；不改写为新流程。

### 新增 `TaskCreationLinearPage`

- 管理分步方式的需求、规划、播放、编辑、停止、错误和创建结果。
- 复用 `planTaskCreation`、`CreationForm`、成员/标签数据、校验和创建回调。
- 将内部规划阶段映射为任务内容的逐步可见状态，不渲染阶段壳层。

### 新增线性章节组件

最小拆分为主任务内容、协作成员、线性子任务编辑和确认区。拆分判断与子任务规划保留在状态机中，不对应可见组件。每个组件只处理一类真实任务信息，使用显式属性与回调，不读取全局状态。

## 数据与提交边界

- 两种模式都使用现有 `TaskPlanDraft` 和 `CreationForm`，不增加第二套正式任务结构。
- AI 或 Mock 规划结果始终是草稿；只有用户明确点击确认后才写入 `workspaceNodes`。
- 主任务和全部子任务继续由现有回调一次性创建，依赖使用 `clientId` 在提交时解析。
- 人员推荐不写成已接受状态，参与人继续遵循现有待邀请语义。
- 本次不修改任务详情、任务列表、MCP 协议、历史任务数据或团队成员 fixture。

## 视觉与响应式

- 使用标准 Tab、标题、正文、分隔线、列表和展开控件。
- 页面不显示内部阶段的 `01/02/03/04`、阶段名称或完成状态；字段名和真实子任务名称承担信息结构。
- 章节不使用带圆角边框的卡片容器；子任务摘要不使用独立卡片背景。
- 只在状态、主动作和焦点上使用路线色，避免每一步使用不同装饰色。
- 桌面端正文保持可读行宽；移动端单列排列，属性和操作自然换行。
- 粗指针设备的 Tab、按钮和展开控件满足最小触控高度。
- `prefers-reduced-motion` 下取消位移动画，只保留即时内容切换。

## 完整状态

- **正常**：任务内容按内部生成顺序出现，已出现内容可编辑，完成后不残留步骤壳层。
- **空**：初始只显示需求输入；无子任务时不显示空的子任务规划。
- **加载**：仅当前章节显示加载状态，后续章节不占位。
- **停止**：保留原始需求和已显示章节，提供继续生成或重新开始。
- **失败**：在失败章节原地说明问题并提供重试；上一份有效草稿不清空。
- **无权限/成员不可用**：邀请动作不可用并说明原因；现有成员选择与任务创建仍可继续时不整体阻塞。
- **数据过期**：已有任务、成员或关系在确认时变化，阻止提交并要求重新确认受影响部分。
- **移动端**：保持相同步骤顺序，子任务展开内容单列显示。
- **键盘**：Tab 顺序遵循视觉顺序；展开控件提供 `aria-expanded` 与目标关联；生成状态不自动移动焦点。

## 验收标准

1. 从任务列表进入创建页时默认显示“当前方式”，现有创建流程可继续使用。
2. 顶部 Tab 可以切换到“分步方式”，切回后两个模式各自的草稿仍在。
3. 分步方式不显示快捷示例或卡片式方案；内部按“目标整理 → 人员匹配 → 拆分判断 → 子任务规划”推进，但结果页不得显示这些阶段的编号、标题和完成状态。
4. 需要澄清或确认已有任务归属时，在纵向流程中插入对应步骤并可继续。
5. 无需拆分时不生成空的规划模块；需要拆分时不重复展示规划摘要，直接逐个显示真实子任务。
6. 子任务摘要可独立展开、收起和编辑完整信息，未同步修改不会因收起而消失。
7. 人员建议包含依据并明确尚未接受；无匹配人选时显示未分配。
8. 停止或失败后保留需求和已生成结果，可以从失败处重试。
9. 只有完整有效的规划可确认创建；创建结果继续使用现有任务数据和父子关系。
10. 移动端和键盘可以完成模式切换、输入、补充、展开、编辑与确认。

## 最小验证

- 增加静态契约测试，验证新外壳保留旧页面并提供两个 Tab，分步页面不使用现有卡片式方案组件。
- 增加线性阶段映射的单元测试，覆盖无子任务、多个子任务、澄清和关系决定。
- 增加相关渲染测试，覆盖逐步揭示、停止/失败、展开属性和确认禁用条件。
- 运行受影响测试、TypeScript 检查和生产构建。
- 不因本功能自动运行全量测试或双重审查。

## 非目标

- 不删除、重构或视觉调整现有创建流程。
- 不为任务列表增加第二个新建按钮。
- 不保存用户默认创建模式。
- 不接入多个 Agent，不代表成员自动接受任务。
- 不新增关系图、进度卡片、历史快照或跨设备草稿同步。
