# 登录注册与团队引导预览

对象：首次注册及返回 TaskDoor 的用户。用户要求采用常规 SaaS 登录注册，本版以此替代此前的统一邮箱验证码向导。成功证据是登录注册入口清晰，验证完成后才能创建或确认加入团队，已有账号重新登录保留团队。

- `/login`：邮箱、密码、密码显隐、忘记密码、注册入口。
- `/signup`：姓名、邮箱、密码，一次填写；邮箱验证码确认后直接进入「创建你的团队」。创建页不展示「加入已有团队」入口，通过邀请链接进入的用户继续走团队邀请流程。
- `/forgot-password`：邮箱验证、设置新密码、返回登录。
- `/onboarding`：首次进入显示登录；无团队账号验证后直接进入创建表单，可切换至邀请加入；邀请上下文跨登录注册保留。
- 用户后续指定参考 Moxt：登录注册页改为左插画／右表单双栏、浅灰底、白色圆角卡片和绿色按钮；手机端隐藏插画栏并保留表单卡片。移除步骤条、独立姓名步骤、全局场景切换与预览工具栏。字段标签、自动填充、错误关联、密码显隐和六位验证码输入支持键盘操作。

实现复用已有 Button、Input、DropdownMenu 与 Base UI OTPField。最终视觉依据和原创插画提示词见 [Moxt 参考记录](../../component-research/onboarding-moxt-reference.md)。早期 21st 结构参考：[Clean & Minimal sign in](https://21st.dev/@preetsuthar17/components/clean-minimal-sign-in)，未复制第三方源码，无新增依赖。

数据边界：独立设计预览，sessionStorage v3 保存本次会话账号与团队。口令经 WebCrypto PBKDF2 处理后才进入预览状态，原文不持久化；这不是服务端鉴权。邮箱验证接受任意 6 位数字，不生成或发送验证码；邀请使用本地测试数据，不发送邮件，不创建真实团队。真实账号、邮件、邀请服务与正式工作区连接待接入。

预览入口 `http://127.0.0.1:5173/login`。验证码填写任意 6 位数字；示例账号 `zhoulan@example.com` / `Agentdoor123`；示例邀请 `https://agentdoor.local/t/ark/join/demo-valid`。需要示例邀请辅助时可显式使用 `?preview=1`。

2026-09-16 用户要求简化验证码体验：注册、受邀注册和找回密码统一接受任意 6 位数字，取消固定验证码与过期拦截，移除固定验证码填入按钮；仍保留六格输入及原有重发交互。

2026-09-16 用户要求团队引导衔接主工作区：创建或确认加入团队后直接打开现有双栏任务工作区，取消「团队已准备就绪」中转页。新建团队使用独立 ID，任务、通知和个人标签初始为空，不注入示例任务或模板。当前账号与所加入团队通过本地会话衔接，刷新和退出后重新登录保留团队；账号资料与团队目录分别保存，原有演示团队保留。

邀请注册页和加入确认页的卡片只显示团队名称和加入身份，不展示具体邀请人；邮箱验证后显示「立即加入」，确认后进入对应团队。设置中的通用邀请链接使用当前站点 `/signup?invite=…`，与邮箱邀请共同支持注册承接；本地邀请仍需在保存了团队数据的同一浏览器中体验，跨设备邀请及生产鉴权待服务端接入。

进入工作台的加载状态统一为全屏居中的品牌标识、团队名称与轻量旋转提示。工作台模块加载完成后在当前页面切换，不再整页刷新，不设置人为等待时长；失败时停止加载并提供重试入口，减少动态效果偏好下停止旋转。首次打开页面复用同一加载组件。

验收：`npx tsx --test server/onboardingPreview.test.ts` 10 项通过，覆盖登录不自动注册、重复注册、短密码、验证码错误与过期、刷新倒计时、邀请确认与限制、团队持久化及密码重置。`npm run build` 通过。浏览器已实测注册→邮箱验证→创建团队→退出→重新登录、验证码错误、密码显隐、重置密码、邀请确认并加入；1280px 桌面及 390px／320px 窄屏无横向溢出，本轮浏览器检查无新增错误。按项目约定只做本次范围内的验证，未运行全量测试或双重审查。

用户后续确认：演示账号 `zhoulan@example.com` 模拟刚注册的用户，初始无团队。无团队登录／注册完成直接进入创建团队。按最新要求，创建页移除「同事已经有团队了？加入已有团队」整行入口。状态版本迁移只重置旧版演示账号的团队关系，保留其他账号；迁移后新建／加入的团队正常持久化。
