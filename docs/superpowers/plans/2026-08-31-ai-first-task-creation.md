# AI-first 任务创建 Implementation Plan

> **For agentic workers:** 使用已确认的当前会话方案逐项实施；解析适配与界面并行，主线程复核后集成。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新建由 AI 理解、必要补问、关系判断、候选规划和人工确认驱动，用任务式页面呈现，不提供空白手工创建入口。

**Architecture:** 新增纯函数规划适配层，复用五个明确 Mock 场景与既有 CreationForm；将编辑器从页面编排中分离。仅最终确认调用既有本地创建回调，旧聊天归档、Stable ID、人选接受和存储失败边界保持不变。

**Tech Stack:** React / TypeScript、现有 Motion、21st 适配的成员及日期选择器、Radix Accordion、Node test runner。

## AI 协作原则的本轮落点

用户补充的《TaskDoor AI 协作能力参考》用于判断在哪些环节减少人工工作，不视为扩大实现范围的指令。创建阶段对应必要补问、合理拆分、职责推荐、重复与归属判断、真实依赖，以及只调整受影响字段；本轮均只验证明确 Mock 场景。后续可比较形成可用方案的耗时、补问轮数和返工次数，本轮没有做真实模型质量或用户提效实验。

进展摘要、阻塞诊断、Agent 接力、交付检查与生产写回属于创建后的能力，不在本轮新增；原参考文件的“已实现”和测试数量不作为本项目已验收证据。
