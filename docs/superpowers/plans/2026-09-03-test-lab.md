# AgentDoor 测试工作台实施计划

> 使用 Superpowers 的任务拆分、测试优先和定向验证流程；用户已确认方案。项目约定优先：原目录实施，保留已有改动，不提交、不全量测试、不双重审查。

**Goal:** 在 `/test-lab` 提供可管理团队、成员责任、任务、用例与真实模型运行报告的独立测试工作台。

**Architecture:** React 页面 + Vite 本地中间件，原子 JSON 文件存储于 `data/test-lab/`，不接触原产品 LocalStorage。服务端加载 PPIO 环境变量、Skill 和规则；模型无工具，不可写业务数据；报告与预期分离。

**Tech Stack:** 现有 React、Vite、TypeScript、Zod、Node fs；不增加数据库或登录依赖。仅供本机测试，非生产鉴权系统。

## 共享合同

- `/api/test-lab/bootstrap` GET：`{state,config,skills,csrfToken}`；config 只有地址、模型、Key 是否存在、每批上限和输出上限。
- `/api/test-lab/state` PUT：`{expectedRevision,teams,cases}`，409 保留原数据；不允许客户端写 runs。
- `/api/test-lab/view?teamId=&actorId=` GET：服务端裁剪的团队任务与证据视图。
- `/api/test-lab/runs` POST：`{caseIds,requestId}`，同 requestId 幂等返回，无自动重试，串行队列，每批最多 5 例。GET bootstrap 查看报告。
- `/api/test-lab/runs/:id/cancel` POST；`/api/test-lab/runs/:id/review` POST `{verdict,note}`。
- `/api/test-lab/library/import` POST：导入已有规划库且标为待核对、默认不运行；保留原输入及独立期望，不发送期望给模型。
- 所有写请求必须同源、JSON、自定义 CSRF 头；本机 Host 限定。导出为无密钥团队／用例 JSON；导入通过同一严格校验。
