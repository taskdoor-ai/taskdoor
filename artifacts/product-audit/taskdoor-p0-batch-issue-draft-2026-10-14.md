## 1. 创建预览离开前确认丢弃（PRD-0167）

确认创建前的输入、对话和预览方案尚未写入正式任务。用户返回任务、关闭创建、打开其他任务或模块、切换团队时，需要先知道本次未创建内容会丢失。

- 有非空输入、对话或方案才显示确认；空白创建页和成功创建后的离开不弹窗。
- 继续编辑、按 Esc 或关闭确认弹窗，保持当前位置、输入、编辑后的方案和人员选择。
- 明确放弃后才执行原离开动作，清理本次创建会话；重新进入为空白。
- 生成请求在放弃后失效，迟到结果不恢复旧方案；创建失败仍保留方案，可以重试。
- 内部步骤切换或回到仍保留本次会话的输入步骤不视为放弃；刷新／关闭浏览器沿用原生未保存提示。

**PM demo 已实现**统一离开确认：当前运行页面已核验空白返回、非空输入取消、预览取消保留标题与标准、丢弃后新建为空白、生成中放弃后不回填旧结果、切团队取消保留原团队与输入。新增 9 项定向检查、应用类型与结构检查通过；存储失败有定向检查，未在运行 UI 模拟。正式项目此前已有会话取消及晚请求保护，但缺少覆盖离开出口的统一丢弃确认，接入后需逐出口验收。任务确认保存后，目标、标准、人员及初始 AI 估算仍按既有要求保存；预览尚未保存不等于这些字段无需存储，本次未修改初始估算链。

确认创建的保存接入另保留现有缺口：初始预计投入在审阅中隐藏，但必须随创建保留为 AI 估算与创建基线；PM demo 当前仍清空 `effortEstimate`，正式 AI 创建适配仍有完成标准、参与者和预计投入未完整落库的接线差异。复用正式已有存储能力，不能以增加离开弹窗代替创建保存。此项沿 PRD-0162 跟进，本轮不改估算或创建提交链。

负责人允许为空：demo、正式手工创建和正式后台均已支持。正式 AI 方案确认环节的 `proposalProblems` 仍把空值判为 owner 错误并禁用确认；应仅验证已选负责人，提交未分配值转 null，并移除强制选择文案。规划 Skill 的 Schema／运行校验已支持 null；本轮正文只补齐用户暂不分配、预览主动清空后不自动补人的例外，不改变产品规则。

## 2. 名称与目标失焦保存成功反馈（PRD-0165）

PM demo 已实现：有效修改保存成功后，字段旁显示勾与“已保存”，约 2 秒后淡出；再次编辑清除，名称／目标及不同任务独立。未修改、尚在保存或保存失败不显示成功，不新增每次失焦的全局成功 Toast。

正式项目已有真实失焦保存与失败提示，本项是补齐成功反馈，不重做保存后台。正式接入应以真实写入回执为准，不凭乐观界面显示已保存。已有定向本地检查及运行证据见[实现矩阵](../../docs/prd/current-implementation-matrix.md)的 PRD-0165。

## 3. @ 同团队成员自动加入参与者（PRD-0166）

**PM demo 已实现**任务讨论、回复和文件讨论的统一发布：能发布当前任务讨论的成员可 @ 同团队有效成员；被 @ 者不是当前负责人或参与者时，在发布成功后自动加入当前任务参与者。草稿不加人，失败保留输入并回滚；消息与新增人员、活动及提及事件成组保存，重复 @、已有关系和重试去重。不额外增加加人角色、审批或任务接受流程。

当前本地正式项目源码仍要求被提及者已有任务访问权，尚不能据 demo 实现认定正式项目完成。正式项目按已确认规则跟进，并验证发布后访问生效、事件及提及提醒；demo 已保存提及通知事件，通知中心消费按用户决定不跟进；正式接入复用现有通知服务。

## 4. 重新分析接入真实任务分析 Skill（ANA-1，PRD-0167）

点击重新分析应重新执行 **`agentdoor-task-status-analyzer`**，复用已经维护的 Skill、Prompt、共享规则及输出契约，以任务最新已保存且当前用户有权读取的上下文调用真实 AI；返回结果须通过校验并保存，才能更新界面并提示成功。仅重读记录或模拟数值重算不算重新分析。现有 Skill 已覆盖以下五个维度，服务必须同时校验、保存并返回同一输入版本的结果：

| 维度 | 接入要求 |
| --- | --- |
| 任务总进度 | 保存有效原始进度／工作量及 0、25、50、75、100 的展示分档，四段展示；未知为 null |
| 单条完成标准进度 | 按稳定标准 ID 与独立标准版本逐条返回 AI 评估；不以确认条数计算总进度 |
| 当前情况 | 返回当前结果、缺口与必要说明，不用固定套话替代真实分析 |
| 下一步建议 | 返回针对当前结果与缺口的具体行动 |
| 燃起图 | 使用真实已保存工作量历史、创建基线与有据预测；保留原始量，不用分档数字倒算曲线，无历史不编造图 |

四段的显示规则已经在 Skill 内：AI 0% 四格均不亮，50% 亮两格，80%／99% 展示为 75% 亮三格，只有有效 100% 亮四格。AI 100% 不等于人工确认或任务状态完成，不自动改这两类事实；未知不能当成 0%。此前“未完成也满格”仅指旧分档将 AI 原始低于 100% 的结果显示四格，不能用于否定进行中任务的有效 AI 100%。

- 保留仍可读的旧结果供分析期间阅读；失败／超时标记未更新并支持重试，首次失败保持未知。
- 输入版本、权限或人工确认在执行中变化时，旧结果不得覆盖新内容或用户确认。
- 已完成／已取消任务同样可重分析内容，不自动重开，不生成执行中的未来预测。
- 输出只展示结论和必要说明；内部保存输入版本与依据，不新增来源清单或逐句跳转。

**本地正式项目尚未接入真实 Skill**：`apps/web/src/ai/index.ts` 的 `repredictTaskProgress` 仍调用 `mockRecalculatePrediction`，详情终态分支仍仅刷新；测试工作台的 Skill 加载、模型调用和输出校验已存在，但不等同于产品服务接线。此项记录正式项目待接入，本轮不发起模型请求或新增服务。

## 5. 正式服务接入已有职责分析 Skill（RESP-2）

复用 **`agentdoor-responsibility-advisor`**，不另建职责分析规则。已有 Skill 已定义当前用户当前团队的每日检查、用户主动重新分析、自动更新配置、编辑暂停、版本冲突和真实写入回执。

- 后端持久保存本人当前团队的自动更新配置与版本；页面开关读写真实配置。
- 按既有每日规则核对证据变化，无变化复用有效结果；主动重新分析可立即执行。
- 配置开启时，由服务核验授权、有效版本和证据后应用建议；关闭时交给用户审阅确认。编辑期间暂停，配置未知或版本冲突保留建议。
- 复用正式已有职责正文保存与冲突处理，实际写入成功才报告更新成功；成员推荐只读取已保存职责。

本地正式界面的开关仍是临时页面状态，真实职责正文保存已接接口；缺口是配置、Skill 调用和服务调度接入，不是缺少 Skill 或整个保存后台。

## 接入验收与参考

1. 创建页有预览时测试返回、关闭、其他任务／模块与团队切换；取消保留所有编辑，放弃后重新进入为空白，旧异步结果不回填。
2. 空白、内部步骤切换及创建成功不误弹；创建失败仍保留方案。
3. 名称和目标只有真实保存成功才显示就地反馈；无变化、失败、再次编辑和切任务不误报。
4. @ 非任务成员发布后加入参与者并可访问任务；草稿／失败不加人，已有人和重试不重复，提醒与活动去重。
5. 重新分析确认实际调用真实 Skill 与模型，五个维度同版本返回；结果校验、权限／版本保护及持久保存完成后才提示成功，终态同样实际分析，AI 进度不代替人工确认或任务状态。
6. 职责配置刷新后保持；每日与主动分析调用已有职责 Skill，开／关按既有规则应用或审阅，编辑暂停和版本冲突不覆盖当前文本，真实保存成功才提示更新。
7. 正式 AI 确认创建允许空负责人；已选失效人员拒绝，未分配提交 null，不自动塞回推荐人员。
