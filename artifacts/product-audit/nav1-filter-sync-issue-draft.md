# Issue：搜索筛选后保持列表与详情一致，优化无结果空状态

目标仓库：`nocoly/taskdoor`。已发布：[issue #44](https://github.com/nocoly/taskdoor/issues/44)。

## 问题

用户修改搜索或筛选条件时，需要立即看到对应结果。目前左侧列表与右侧详情可能不同步：列表已变化，详情仍停留在旧任务；没有结果时，详情也可能保留旧内容。

同时，两侧空状态说明偏长，桌面出现不必要的折行。将这两个改动串在同一条流程中：**优先展示用户已选择且仍匹配的任务；没有有效选择时，有结果打开第一条，无结果清空详情并展示简短空状态。**

## 产品变更

### 1. 搜索与筛选结果同步详情

- 用户在搜索或筛选结果中主动打开某个任务，正常展示该任务详情；只要该任务仍在当前结果中，自动选择不能将其覆盖为第一条。
- 桌面切换团队、任务范围（全部／我负责／我参与），或修改搜索、状态、标签、日期条件后，当前打开任务仍在新结果中，则继续展示该任务；仅调整排序或刷新任务数据时也遵循这一规则。
- **第一条只作为自动兜底**：没有选中任务，或原任务已不在当前结果中时，才打开第一条。按列表实际展示顺序选择，置顶区优先。
- 没有结果时清空详情。结果恢复后，没有有效选择则打开第一条。
- 自动更新详情时，保留搜索和筛选条件，并保留当前输入框或筛选控件的焦点，支持连续输入。手动打开任务沿用既有导航焦点规则。
- 移动端在列表中筛选时保持列表视图，由用户主动打开详情。

### 2. 无结果时的空状态

- 左侧显示“没有匹配的任务”，保留“查看全部任务”按钮；说明改为：**试试其他关键词或清除筛选。**
- 右侧清空旧任务，显示“选择任务，查看详情”；说明改为：**选择任务，查看目标、讨论和进展。**
- 英文说明同步缩短：左侧 `Try new keywords or clear filters.`，右侧 `Select a task to view its details.`
- 桌面两处说明各用一行展示；窄屏允许自然换行，保证完整可读，不截断或溢出。

## 验收

| 场景 | 预期结果 |
| --- | --- |
| 在搜索或筛选结果中主动打开第二条或其他任务 | 正常展示点击的任务；仍匹配当前结果时不自动跳回第一条 |
| 手动选中第二条，再修改搜索或筛选；原任务仍匹配 | 保留第二条的详情 |
| 修改搜索或筛选，原任务不再匹配，仍有其他结果 | 打开新结果第一条，置顶区优先 |
| 当前没有选中任务，但桌面列表有结果 | 自动打开第一条 |
| 搜索或筛选后没有结果 | 右侧清空旧任务，两侧展示上述空状态 |
| 无结果后修改条件，重新出现结果 | 没有有效选择时打开第一条 |
| 连续输入关键词，或使用键盘调整筛选 | 列表与详情持续同步，焦点留在当前控件 |
| 仅排序或刷新数据，当前任务仍匹配 | 保留当前选择 |
| 刷新后当前任务不再匹配 | 有结果打开第一条，无结果清空详情 |
| 桌面切换中英文 | 两侧空状态说明各占一行 |
| 窄屏查看空状态／移动端筛选 | 文案完整可读；在列表筛选时保持列表视图 |

筛选验收覆盖团队、任务范围、搜索、状态、标签与日期；自动选择不修改任务内容。
