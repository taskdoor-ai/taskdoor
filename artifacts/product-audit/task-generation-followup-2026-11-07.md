已完成的交互与讨论草稿调整见[已提交的 #77 汇总](product-sync-pending-issue-2026-11-05-02.md)第2、7、16项。新建入口统一、候选列表可操作、讨论模式能够预填草稿，分别有其已完成范围，不能据此认定完整生成链路已接通。

## 当前事实

| 链路 | 当前实现 | 尚缺部分 |
| --- | --- | --- |
| 主任务单行创建 | 两个入口共用列表输入及提交，普通入口通过本地 `planTaskCreation` 整理后保存 | 普通入口尚未实际调用主任务生成 Skill，不能把本地规划当作生产模型接入 |
| 直接创建子任务 | 共用单项 Skill 的 `prompt` 模式；输入本次需求、父任务名称／目标／完成标准、日期时区、有效成员及职责、标签 | 尚未带相关讨论、文件有效正文、已有子任务及引用任务目录；简略需求的处理也未与讨论模式完全统一 |
| 从讨论创建子任务 | `discussion` 模式读取选中与同串讨论、实际可读引用任务定义和父任务事实，成功结果有可编辑草稿 | 本轮没有完成一个供所有入口共用的完整任务上下文读取层 |
| 动态 AI 建议 | 子任务页签已展示候选并提供添加／忽略、来源讨论过期校验和本地防重保存；页面候选仍来自指定演示数据 | 保存事件驱动的真实模型调用、多源输入、结果持久化及动态刷新尚未接通；评测中的模型调用不等于产品页自动运行 |

## 后续补齐工作

- [ ] **统一任务上下文读取。** 根据当前任务身份和读取权限，提供当前定义、相关讨论及回复、相关文件的有效正文／版本／读取状态、已有直属子任务、正式成员职责和有实际引用关系的约束。保留来源身份和版本；文件名不能冒充已读正文，不读取整个团队历史。
- [ ] **统一手动生成的上下文底座。** 直接创建额外提供本次需求，讨论创建额外提供选中消息；两者复用上述可读事实，并统一名称、目标和未知字段的处理。现有生成取消、用户输入保护、来源变化和保存校验继续保留。不要把父任务字段机械复制为子任务的新承诺。
- [ ] **接通普通主任务生成。** 将单行入口接到正式任务生成服务及当前主任务 Skill；同步 Skill 与单行入口的职责、输入及输出约定。入口交互统一与真实模型接通分开验收。
- [ ] **接通动态建议调度。** 在任务首次保存及相关定义、讨论、有效文件、已有承接或推荐依据变化保存成功后，合并连续变化，读取最新授权快照，调用 `taskdoor-decompose-task`，只更新确实受影响的候选。具体事件边界沿[现行触发规则](../../skills/taskdoor-decompose-task/references/scope-and-triggers.md)，不因切换Tab或打开页面反复生成，也不盲目重算整棵任务树。
- [ ] **支持任务、文件、讨论等真实来源。** 当前页面候选模型强制带讨论消息身份；对接 `taskdoor.subtask-suggestions.v1` 时需要多源候选适配和版本记录。任务定义或文件产生的建议不能伪造为某条讨论。
- [ ] **持久化与防迟到。** 保存建议及其输入版本、已忽略／已承接的事项和处理记录；相关依据变化先停用旧建议，迟到结果不得覆盖新版本、人工编辑或已处理决定。无实质新信息时不恢复被忽略或已承接事项，失败保持待更新，不声称刷新成功。
- [ ] **复用现有确认保存。** 建议先作为候选展示；用户点添加前不生成真实任务。添加前复核最新来源、已有承接、权限、可选人员、日期和父链，并原子保存任务及处理记录。自动建议可以没有候选，不套用手动讨论草稿的强制补齐规则。

以上工作尚未实施或验收；后续完成并确定最终方案后，再更新本地待提交 issue 的对应原条目。
