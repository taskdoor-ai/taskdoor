# 我的工作推荐

在本人负责或参与的任务中，按 PRD 固定规则推荐现在先处理哪项，并用一句话说明原因和行动。

## 当前产品版本与示例

先读取 [当前 PRD 契约](../shared/current-prd-contract.md)，它替代旧快照中相冲突的业务语义；保留既有输出协议。遇到拆分、未知、版本修订或责任边界时，参考 [few-shot 正反例](examples/decision-pairs.md)。示例不是当前输入，不能复制其中的来源、人员、数值或结论。

## 规则依据

业务依据为 PRD **5.1–5.4、7.6**，见[完整评分规则](references/product-rules.md)。先读取[共用规则](../shared/product-rules.md)及[证据与更新契约](../shared/evidence-and-updates.md)。必须完整读取分档条件，不能只读公式后凭感觉打分。

输出协议：`agentdoor.personal-priority.v0.1`。评分规则版本保持 `PERSONAL-PRIORITY-2026-09-03-v4`；本次结构整理不改变 PRD 参数。字段见[输出契约](references/output-contract.md)。

## 输入要求

| 输入 | 用途 | 缺失时处理 |
| --- | --- | --- |
| 当前用户、团队、任务 ID、负责人、参与人、正式状态及版本 | 判断入选范围 | 关系或状态不明时不擅自入选，说明覆盖不完整 |
| 目标、完成标准、已确认目标关联、活跃下游必需交付 | 重要度 B、C | 无法归档的项暂取 0，标待核对 |
| 当前用户有权读取且关联到本任务的标签及含义 | 标签参考 P | 不明、冲突或不可读时不猜测加分 |
| 判断时刻、团队时区、截止日期或时刻 | 期限压力 D | 无效日期不补造，区分无期限和未读取 |
| 当前损失、有效阻塞或冲突、待本人处理记录 | 风险 H、等待 Q | 缺乏实际影响或本人行动时不凭状态名加分 |

## 执行流程

1. **确定候选。** 只保留本人正式负责或参与、状态为待开始／进行中／已阻塞的任务，按 Task ID 去重。待加入的团队邀请不等于正式负责或参与；任务内不存在负责人接手审批。记录排除原因。
2. **逐项取证。** 每个命中保存事实、来源版本、适用任务和有效性。按完整规则选择每个分项满足条件的最高档，重复文件和同一事件不重复计分。
3. **计算重要度。** `I = B + C + P`。B 是目标影响；C 是本项交付对活跃下游的必要性，不是本项在等几个前置；P 是已有标签的辅助参考。普通分类标签、父标签、颜色和数量不加分。
4. **计算紧急度。** `U = max(D, H, Q)`，三项不相加。没有日期仍可因持续损失或当前等待具有高紧急度；“已阻塞”、新上传文件和参考前置未完成都不能单独证明 H 或 Q。
5. **计算推荐权重。** `W = 0.6 × I + 0.4 × U`。未知分项暂取 0 并标待核对，不重新放大其他分项；AI 不调整系数或增加旧规则分数。
6. **稳定排序。** 依次按 W、I、U 降序；仍同分按可比较截止时间升序，无可比较日期排后；最后按稳定 Task ID 升序。用未舍入值排序，展示最多一位小数。
7. **解释行动。** 一句话结合最有贡献的重要度依据和当前紧急信号，指出本人可做的事。父任务说明统筹行动，子任务说明具体交付，不复制分数或重复推荐同一执行动作。

## 分档索引

下表用于检查数值范围，成立条件必须回到 PRD 原文。

| 分项 | 含义 | 允许分值 |
| --- | --- | --- |
| B | 目标影响 | 0、10、20、35、50 |
| C | 协作影响 | 0、15、30 |
| P | 现有重要性标签参考 | 0、20 |
| D | 期限压力 | 0、10、30、60、75、90、100 |
| H | 当前损失或执行风险 | 0、60、80、100 |
| Q | 待本人处理 | 0、60、80 |

日期按团队时区计算日历天；只有日期时当天结束前不算逾期，有明确时刻时超过该时刻才逾期。逾期天数不叠加。协作影响只数有必需结果依据的活跃直接下游，按 ID 去重，不累计传递链。影响两个下游可支持 C；下游现在停等本人且本人能行动，才另支持 Q。

## 输出要求

返回入选与排除清单、B/C/P/D/H/Q、I/U/W、逐项证据、未知因素、最终顺位和一句原因，字段见[输出契约](references/output-contract.md)。界面只显示顺位、名称和一句原因，明细用于“AI 分析规则”和复核。

资料不完整时返回 `partial`，说明仅对已知子集排序。推荐分数不是人员能力、绩效、完成概率或价值定论；EWD、提交次数、聊天频率、在线时长、人员历史速度均不参与加分。`writeReceipt=null`，不修改任务、标签或新增优先级设置。

## 更新与失效

负责或参与关系、状态、目标、下游影响、标签关联及含义、期限档位、当前影响或等待事实变化时更新；跨日或明确截止时刻经过时更新 D。相同有效输入和判断时刻产生相同顺序，刷新不改变分析时间。参数变更另升规则版本，不修改历史结论。

## 场景核对

关键服务故障无截止，B50/C30/P20、D0/H100/Q80：I100、U100、W100。例行内部整理昨天逾期，B20/C0/P0、D100/H0/Q0：I20、U100、W52。故障排前，不能把所有逾期任务先排完；本人参与的任务仍可入选，已完成任务排除。

提交前检查：入选关系与三状态正确；分档有据；公式可复算；同分顺序稳定；未知未被表述为低价值或无风险。
