# 我的工作推荐

推荐本人现在先处理哪项任务及原因。权重用于任务顺位，不代表任务价值的最终评价、人员能力、绩效或完成概率。

输出 `schemaVersion: agentdoor.personal-priority.v0.1`，固定规则 `ruleVersion: PERSONAL-PRIORITY-2026-09-03-v4`。

## 先读取与输入

完整读取 [证据与更新契约](../shared/evidence-and-updates.md) 和 [完整评分、排序与例子](references/product-rules.md)，不得只读取时间表或凭常识补分。

输入包括当前用户及团队、团队时区、实际判断时刻、任务负责人／参与人及状态、目标／标准及已确认关联、活跃下游必需交付、当前有权使用且关联到本任务的标签、截止时间、当前影响／风险、待本人处理事项，以及逐项证据版本与读取范围。可复用当前有效诊断，但诊断结论不自带分数。

## 计算顺序

1. **限定范围。** 本人负责/参与的，只有待开始、进行中、已阻塞这三种状态的任务参与排序。由受信适配层映射正式枚举，不把无法识别的值当作进行中；按稳定 Task ID 去重。左侧展示状态不替代服务端提供的推荐范围。
2. **重要度 I＝B＋C＋P。** 每项取满足证据条件的最高一档。B 为目标影响（0／10／20／35／50）；C 为已确认活跃下游所需交付的影响（0／15／30），不是自己在等几个前置；P 为已有标签参考（0／20）。任务没有独立优先级字段，符合条件的标签不叠加，不按颜色、父标签或他人私有标签加分。用户点名“重要”不能省略 B、C 的事实依据。
3. **紧急度 U＝max(D,H,Q)。** D 为期限压力（0／10／30／60／75／90／100），H 为当前损失或执行风险（0／60／80／100），Q 为确实待本人处理（0／60／80）。逐档条件以产品规则为准，三项不相加。没有日期仍可因实际损失或当前等待具有高紧急度；状态已阻塞、仅参考前置未完成、刚上传文件都不自动加分。
4. **推荐权重 W＝0.6×I＋0.4×U。** 60%／40% 及档位为统一初始参数，不能因某次模型判断改权重或额外叠加旧时间分。未知项暂取 0 并标待核对，不是“低价值／没有风险”，不重新归一化其余分项。
5. **排序。** W、I、U 依次降序；仍相同则可比较截止时间升序、不可比较排后；最后按稳定 Task ID 升序。用未舍入分值排序，展示最多一位小数。相同快照和有效时刻的排序稳定，不能由数组顺序或文案随机改变。
6. **说明行动。** 一句原因结合有贡献的重要度依据和当前紧急信号，并指出本人可做的事情；参与人也可被推荐，但建议必须对应其实际贡献。没有紧急信号就如实说明按目标／协作影响优先，不编造截止压力。前后代分别有依据，父项不复制子项分数或重复执行动作。

## 时间与未知

按团队时区比较日历日期；只有日期时当地当天结束前算今天到期，有明确时刻则超过该时刻后逾期。不猜年份、不凭无效日期加分。无截止与未读到截止分别记录。失效诊断、撤销确认和过期内容不能继续支持分档；每个命中都保留事实和来源版本。

缺少推荐范围／成员关系／任务状态等入选关键数据时不得声称完整排名；可排序已知有效子集，标 partial 与覆盖范围。任务 EWD、评论数、提交次数、在线时长、人员历史速度不用于加分。

## 返回 result

```text
{evaluatedAt, timezone, scope,
 rankedTasks: [{rank, taskId, taskVersion,
   factors: {B, C, P, D, H, Q}, I, U, W,
   hits: [{factor, score, fact, evidenceRefs}],
   unknownFactors, dueSortValue, nextAction, reason}],
 excluded: [{taskId, reason}], coverage}
```

同一项支持多个维度时分别写成立条件：影响两个下游可支持 C；下游当前已停等本人且本人能行动才支持 Q。界面只显示顺位、名称和一句原因，明细供“AI 分析规则”及可追溯记录使用，不展示成员评分。writeReceipt=null，不改变任务、标签或优先级设置。

## 何时更新与验证例

角色／状态、目标与下游影响、标签关联或含义、期限档位、当前影响和待处理事项、来源版本改变时更新；跨日和明确截止时刻也会改变 D。仅刷新不改变分析时间或历史记录。

本人仅参与的关键服务故障、无日期：核心目标 B50、两项已确认活跃下游 C30、有效重要性标签 P20；持续关键服务中断且需本人行动 H100、下游当前停等本人 Q80，D0 ⇒ I100、U100、W100。本人负责的例行内部整理昨天逾期，无下游／标签／其他影响：B20、C0、P0、D100、H0、Q0 ⇒ I20、U100、W52。故障排前，不把逾期直接放最前；已完成任务及本人无关任务不在候选集合。
