# 人员责任分析

识别本人实际承担的工作，将“我的责任”校准为有范围、有依据的责任说明，供后续成员推荐使用。

## 规则依据

业务依据为 PRD **2.5、7.9**，见[产品规则](references/product-rules.md)。先读取[共用规则](../shared/product-rules.md)及[证据与更新契约](../shared/evidence-and-updates.md)；输出按[字段契约](references/output-contract.md)组织。

输出协议：`agentdoor.responsibility-advice.v0.1`。规则版本：`RESPONSIBILITY-2026-09-08-v2`。

## 适用范围

- 分析当前用户在当前团队负责或参与、且有权读取的任务。
- 已完成任务可提供历史贡献；待开始任务只提供分工；已取消任务仅使用可证实的实际承担。不套用“我的工作”的三状态排序范围。
- 回答“负责什么、边界在哪里”，不评价能力、效率或绩效。创建时的人员匹配由创建任务 Skill 完成，不必先运行本 Skill。

## 输入要求

| 输入 | 用途 | 缺失时处理 |
| --- | --- | --- |
| 当前用户、团队、当前责任文本与版本 | 确定分析对象与对照基线 | 缺少身份或基线时返回待补上下文，不覆盖责任 |
| 本人任务、完成标准、分工、实际贡献、交付与讨论 | 证明本人承担了什么 | 可归属部分继续分析；其余标待核对 |
| 来源 ID、版本、时间、读取范围与有效性 | 引用、去重与判断时效 | 未读到不解释为不存在 |
| 历史建议、用户确认、修改、忽略与纠正 | 保留用户决定和责任边界 | 未提供时说明未读取，不假设没有反馈 |
| 最终操作、确认及真实写入能力 | 仅用于准备或执行更新 | 没有能力或确认时只保留建议 |

模式由调用方指定：`analyze` 分析建议；`prepare_update` 整理用户选择后的待确认操作；`apply_confirmed` 核对已确认操作并通过实际能力处理更新。未指定时使用 `analyze`，不得从文件正文推断写入授权。

## 执行流程

1. **固定范围。** 核对用户、团队、责任版本和读取覆盖，只使用当前可见的有效来源。成员名单、Owner 身份和任务完成状态均不能单独证明本人完成了全部成果。
2. **识别实际承担。** 对每条贡献提取承担人、具体结果、工作范围、来源和时间。区分本人报告、他人报告和已核实贡献；同一成果的版本、父子引用不重复计数。
3. **归纳责任边界。** 先应用用户已确认的纠正，再区分持续职责、阶段安排与临时协助。多个独立任务的同类贡献或明确长期分工可支持持续责任；一次帮忙不自动变为长期职责。
4. **对照当前责任。** 按下表选择操作，附原文、基准版本、建议文本、原因和依据。证据不足保留原责任，不为增加建议数量而改写。
5. **组织用户核对。** 用户可采纳、修改或忽略；确认绑定最终操作和文本。修改文本后原确认失效。未经确认的建议不参与正式成员匹配。
6. **处理更新结果。** 业务服务独立核对权限、版本和幂等后写入。只根据实际回执报告成功；版本冲突返回 `stale`，回执未知保留待核实，能力未接入明确说明。

| 操作 | 成立条件 |
| --- | --- |
| `add` | 持续承担或明确职责安排未被当前责任覆盖 |
| `update` | 有依据证明当前范围缺失、过宽、重复或已发生变化 |
| `deprecate` | 有明确职责撤销、转移或不再适用的依据 |
| `no_change` | 当前责任准确；无充分修改依据时保留原文并列明缺口 |

## 输出要求

每项建议包含操作、原责任与版本、建议文本、原因、团队和时效范围、任务及贡献依据、反馈依据和未知项。已有责任准确且无待核对项时返回 `no_change`；信息部分可用时返回 `partial`。

只有真实写回成功才返回 `applied`。本 Skill 不修改任务 Owner、参与人、任务状态或权限；确认责任不等于接受具体任务。字段、空值和确认绑定详见[输出契约](references/output-contract.md)。

## 更新与失效

实际贡献、分工、责任文本或用户纠正变化时复核受影响建议。忽略不等于否定，不凭同一来源重复推送；没有近期任务或来源失效不等于职责消失。来源撤销或权限变化后停用相关依据，保留用户当前正式责任。相同输入与反馈复用有效结果，刷新不制造新分析时间。

## 场景核对

- 原责任“内容制作”，两项独立交付均证实本人负责脚本：可建议细化脚本责任，引用两项贡献。
- 用户已说明直播协助只是临时安排：保留该边界，不把直播归为长期职责。
- 原责任已到 v3，候选仍基于 v2：先复核，不能用旧候选覆盖 v3。

提交前检查：每个操作有对应原责任或新增依据；贡献属于本人和当前团队；最终确认与文本一致；成功结论有真实回执。
