# 任务诊断

只识别两类问题：**执行阻塞、决策冲突**。说明受影响的工作、具体依据和可采取的行动。

## 规则依据

业务依据为 PRD **6.6、7.5**，见[产品规则](references/product-rules.md)。先读取[共用规则](../shared/product-rules.md)及[证据与更新契约](../shared/evidence-and-updates.md)；输出按[字段契约](references/output-contract.md)组织。

输出协议：`agentdoor.task-diagnosis.v0.1`。规则版本：`TASK-DIAGNOSIS-2026-09-08-v2`。

## 输入要求

| 输入 | 用途 | 缺失时处理 |
| --- | --- | --- |
| 当前任务、版本、目标、完成标准和时间 | 明确正在核对的同一事项 | 无法定位时返回待补上下文 |
| 实际执行记录、前置依赖、当前必需交付及其内容 | 判断工作是否因此无法继续 | 只有关系边或状态名时不能确诊阻塞 |
| 当前文件正文、任务要求、有效决定与来源版本 | 找出不能同时成立的内容 | 只有目录或文件名时标未读取 |
| 已有诊断、反馈、确认与替代关系 | 复核旧结论 | 已失效或被替代内容不支持当前结论 |

## 执行流程

1. **确定适用范围。** 核对双方是否涉及同一对象、版本、结果和有效期间。已被正式替代的旧要求不与当前版本制造冲突；讨论日期更新不代表旧标准已失效。
2. **判断执行阻塞。** 同时核对：工作已在执行；当前继续必须使用某项前置交付；该交付尚未满足；工作确实因此无法继续。引用工作、所需结果、缺失和当前影响。缺一项则列待核对，不确诊。
3. **判断决策冲突。** 列出两项当前适用的具体内容及出处，说明为何互相矛盾或不能同时满足。缺材料、未回复和信息未知不是决策冲突。
4. **合并同一问题。** 同一事项跨文件重复出现时合并，保留全部必要来源和受影响 Task ID。父子关系或相关文件数不放大问题数量。
5. **提出处理建议。** 阻塞建议推动缺失结果或确认替代；冲突建议核对哪项要求有效或选择如何调整。依据不足时不指定人，不自行裁定预算、范围、日期或责任。
6. **说明检查覆盖。** 完整读取且未发现问题才可说明在本次范围内未发现两类问题。部分读取仍可输出已证实项，但总体标 `partial`，其余待核对。

## 判定边界

| 情况 | 处理 |
| --- | --- |
| 待开始任务的参考前置未完成 | 不确诊执行阻塞 |
| 很久没更新、任务名含“紧急”或状态为“已阻塞” | 继续核对事实，不据此确诊 |
| 设计已开始，当前因缺少必要文案无法定稿 | 有对应依据时为执行阻塞 |
| 当前要求预算不超过 10 万，当前方案预算为 12 万 | 同一范围下为决策冲突，引用双方 |
| 方案只缺预算章节 | 信息缺口，不凭缺失制造两侧冲突 |

## 输出要求

`diagnoses` 每项只用 `execution_blockage` 或 `decision_conflict`，包含问题、受影响任务及结果、双方内容和来源、当前影响、建议行动。另用 `checks` 和 `unknowns` 区分已核对、未成立与未知。

字段细节见[输出契约](references/output-contract.md)。诊断不自动修改任务状态、前置依赖或文件；`formalStatusUnchanged=true`、`writeReceipt=null`。诊断可供助手形成后续变更预览，实际操作由独立受控流程完成，见[已确认的路径补充](../shared/assistant-path-rules.md)。风险排序分值由“我的工作推荐”按自己的规则计算，本 Skill 不附加第三种问题类型或自由风险分。

## 更新与失效

标准、交付、依赖或确认发生变化时只复核受影响项。来源撤销或权限丢失后不再引用；新的分析不能覆盖版本更新后的结论。

提交前检查：阻塞条件齐全；冲突双方具体且当前适用；每项有受影响结果及下一步；未知与“没有问题”分开。
