1. 正式状态待开始；当前有效基线 720 分钟，内容核对完成 552 分钟。保留 formalStatus=待开始，内部 completionPercent=552/720*100；用户摘要称“大部分完成”。不因为状态清零，也不声称任务完成。
2. 正式状态已完成后新增或扩大标准。按当前标准完整范围核对，既有有效成果仍列为已达成；只差新增部分时有据评估部分进度，不能把整条标准缩成新增工作后归零。独立标准确实没有任何结果时仍可为 0。保持正式状态，说明当前差距与待核对；不自动重开，不用状态补为 100%。
3. 旧分析基于 task v2，本次 task v3 改了目标且没有有效新估算。交付边界与工作类型明确时，用平台规则及合理假设先补估或重估，以三点区间表达不确定性，不因没有精确实际耗时一律待估；再按当前内容计算。关键范围仍无法识别时 progress 使用 unknown 或 stale，包络 partial。旧数值不能当当前完成量。
4. 三份文件只有标题，没有正文或内容核对。可以说提供了三份文件，不能由文件数得出 75%；nextActions 指向需要核对的结果。
