# 任务分析

按“当前情况、下一步建议、进度”回答任务现在怎样，以及接下来可以做什么；必要时先补齐当前范围的人工投入估算。

## 正式工具调用

先读取[正式 MCP 调用契约](../shared/production-mcp-contract.md)。正式环境从工具取得真实上下文，已授权的业务操作必须通过工具执行并核对回执；以下旧 JSON 输出约定用于隔离评测或未执行提案，不能当作工具入参或写入结果。本 Skill 的分析边界仍保留：分析不自动授权修改状态、发送消息或确认完成。

## 当前产品版本与示例

先读取 [当前 PRD 契约](../shared/current-prd-contract.md)，它替代旧快照中相冲突的业务语义；当前分析输出按字段契约包含整体进度与逐条完成标准评估。遇到拆分、未知、版本修订或责任边界时，参考 [few-shot 正反例](examples/decision-pairs.md)。示例不是当前输入，不能复制其中的来源、人员、数值或结论。

## 规则依据

业务依据以[当前 PRD 契约](../shared/current-prd-contract.md)和[证据与更新契约](../shared/evidence-and-updates.md)为准；输出按[字段契约](references/output-contract.md)组织。[旧产品规则快照](references/product-rules.md)及[旧共用规则](../shared/product-rules.md)仅用于追溯，不作为当前输入、输出或业务规则。

输出协议：`agentdoor.task-status-analysis.v0.1`。规则版本：`TASK-ANALYSIS-2026-10-14-v9`。

## 适用范围

分析当前任务及与本次问题有关的子任务、讨论和交付。问题识别是本 Skill 内部环节，按[问题核对规则](references/problem-analysis.md)核对冲突、真实阻塞与正常等待，并直接组织到当前总结和下一步建议，不再调用独立诊断 Skill。需要计算进度时使用内部 [EWD 计算规则](../agentdoor-ewd-progress/references/output-contract.md)：当前估算有效则复用；估算缺失，或范围、实际工作条件变化使其失效时，先按 `estimate` 补估或重估，再按 `progress` 核对完成量，有真实历史时按 `trend` 解释变化。同一输入版本的有效结果直接引用，不重复计算。

创建 Skill 已生成并保存的初始投入是 AI 估算，不因创建确认而成为人工已确认估算。只有总量而缺少内部工作明细时，按当前目标、标准和已知工作条件补齐不重叠的明细；明细不会自动创建为子任务，也不要求先拆任务。当前信息不足时保留已知量和未知项，不能为得到进度数值补造估算。

本 Skill 产生分析与行动建议；任务修改由后续受控流程完成。分析可以进入助手的变更预览，但不能把分析文字当成已执行操作；助手路径的适用边界见[已确认的路径补充](../shared/assistant-path-rules.md)。

## MCP 字段适配

正式环境必须读取 [MCP 任务分析与完成标准](references/mcp-analysis.md)，按真实任务、标准、正文证据和版本组织分析；不能将本地字段直接发送到生产工具。当前没有分析回写工具时，仅返回分析结果，不宣称已保存。

## 输入要求

| 输入 | 用途 | 缺失时处理 |
| --- | --- | --- |
| 当前任务 ID、版本、正式状态、目标与完成标准 | 确定对象和结果边界 | 不能定位任务时返回待补上下文 |
| 当前讨论、活动、文件正文、交付与确认 | 判断已完成内容、缺口和变化 | 已知部分继续分析，未读取部分标待核对 |
| 子任务及范围覆盖 | 父任务汇总 | 不把局部子任务说成整个任务 |
| 当前有效诊断 | 排列下一步行动 | 需要时按诊断规则核对，不伪造服务结果 |
| 创建时 AI 估算、当前估算及其来源、确认状态、范围与版本 | 复用投入或判断是否必要重估 | 范围与工作条件足够时补估，否则保留未知；不覆盖人工已确认估算 |
| 估算明细、内容核对及历史快照 | 完成度和燃起图 | 缺明细时按当前范围补齐；无完成证据或历史时，对应完成量或趋势为 `null` |

## 执行流程

1. **核对版本。** 优先读取 `analysisContext` 的统一字段；离线兼容字段不覆盖其中的标准 ID、独立版本或读取状态。完整回显包络 `inputVersions`，不能自行删减未引用的输入版本。 固定任务、标准、文件和确认的有效版本，区分正式字段、讨论报告、内容核对与历史结果。新发言不自动替代正式状态或确认。
2. **说明当前情况。** 先写当前已有结果，再写未满足的完成标准、待核对事项和近期实质变化。引用具体内容和版本，不用“总体顺利”等空泛判断代替事实。
3. **确定下一步。** 有当前决策冲突先核对双方要求；有确证执行阻塞先推动缺失交付或确认替代；否则补齐尚未满足的结果。给出最直接可执行的行动，有依据时注明处理人。
4. **逐条核对标准。** 按 `criteria.items[].id/text` 与独立 `criteria.version` 返回 `criterionAssessments`，包含 0/25/50/75/100 或 null 的 AI 评估、依据和剩余缺口；人工确认原样保留且不由 AI 推导。
5. **核对估算并计算进度。** 先判断当前范围的估算是否有效，必要时补估或重估并通过可选 `progress.estimate` 返回 EWD 估算提案；人工已确认估算不得被本轮模型结果自动替换。仅文件新增或进度变化不代表需要重估，换人或日期变化本身也不重估。再使用同一当前输入版本和同一组 EWD 明细核对总量、已完成量、待确认量和完成度。已有有效结果原样引用；本次估算或计算标明来源，不能伪造调用或保存记录。
6. **解释燃起图。** 先读取[正式项目燃起图接入契约](references/production-progress-contract.md)，区分创建基线、历史完成量、计划量、未来预测、用户确认完成日期与计划差值。没有已保存工作量历史或正式起点时，`progress.comparison=null`，仍返回有据的当前进度；本轮分析观察与文件、讨论的时间不能充当历史或正式起点。创建基线只读取创建时保存的日期与估算，不用本轮估算回填。分别说明新增完成、范围增减和重估；只有一个时点或没有历史时，不推断收敛趋势。未来预测缺有据的执行与复核安排时保持未知；AI 判断 100% 不产生预测或人工确认完成日期。
7. **返回可继续处理的分析。** 三部分分别给出结果与未知项。一个部分不可用不阻止展示其他已知事实；整体有必要缺口时返回 `partial`。

## 输出要求

- `currentSituation`：一句摘要、已核对结果、未满足结果、待核对项、近期变化及证据。
- `nextActions`：具体行动、建议处理人、对应诊断类型及原因。补齐任务交付默认由当前有效负责人推进，`actorId` 使用输入任务的负责人 ID；有明确职责或讨论分工依据时可建议对应协作者。不能仅因未点名每项工作而把已知负责人留空。确实无负责人或无权判断的特殊行动，才使用 `null` 并说明待明确的分工。
- 人工确认是用户的独立决定，不能要求把尚未完成的标准提前确认。没有人工确认不等于缺少交付；先补齐和核对具体成果，已核对完成的标准可提示用户选择是否确认，不把确认写回当作本地分析行动。
- `progress`：当前有效性、EWD 结果来源或本次计算说明、版本、原始数值、`displayPercent` 分档百分比和趋势；本次补估或重估时，可选 `estimate` 复用 EWD 的完整估算结构，供应用校验后保存为 AI 估算。
- `criteriaVersion / criterionAssessments`：标准的独立版本、逐条 AI 分档百分比、依据、已达成内容和剩余缺口；不把确认条数当作整体工作量比例。
- `formalStatus` 原样保留；`formalStatusUnchanged=true`、`writeReceipt=null`。

具体字段见[输出契约](references/output-contract.md)。不得用时间流逝、子任务数量、上传次数或讨论活跃度另算百分比；不得把旧版 100% 填入当前进度。文件内容完成度不等于正式验收，状态“已完成”也不自动证明验收通过。

## 更新与失效

任务创建、目标或标准、文件、讨论、人工确认、子任务等保存成功事件，以及用户主动重新分析，由应用调用同一个 Skill；事件清单以当前 PRD 模块 12 为准。应用合并连续变化，只提交受影响任务与必要祖先的最新输入，并在保存结果前重新核对权限和版本。迟到的旧结果不得覆盖新版本、人工确认或已确认估算。Skill 只按本次输入分析，不实现定时器、事件订阅或后台调度；打开页面、标准仅重排、AI 结果自身更新不制造分析循环。

目标、标准、交付、反馈或确认变化时复核受影响部分。引用的诊断、估算与进度分别核对版本；来源失效时标记过期或未知，不拼接成一份“当前”结论。失败保留仍有权阅读的旧结果并标待更新，首次失败保持未知。当前估算更新形成新版本，不修改创建基线或任何过去观察点。

## 丰富证据与本地评测

读取 [证据场景与统一输入](references/evidence-scenarios.md)。按目标任务、相关子任务及正文明确涉及的材料限定读取范围；不读取、输出或维护已取消的前置依赖字段和关系边，也不保留空兼容字段。用户明确的材料要求、确认及交接顺序保留为业务正文，不转为关系边。测试预期答案不属于业务证据。文件正文失败、旧版替代、多人冲突和人工确认分别判断，不能用文件数量、发言多数或最后发言决定完成度。

## 场景核对

任务 v4 仍在进行中，讨论说“做完了”，当前文件却缺少风险预案；旧 v3 进度为 100%。应说明已提交主体内容、仍缺风险预案并建议补齐核对；当前范围及工作条件足够时先补有效估算，再核对完成量，仍有必要缺口时整体为 `null`。旧 v3 数值不进入当前进度，正式状态保持进行中。

提交前检查：三部分齐全；摘要有具体依据；下一步针对当前缺口；进度来源与版本一致；未知未写成零或完成。

问题识别的 few-shot 见[问题核对示例](examples/problem-analysis.md)。统一输出 currentSituation、nextActions、progress；内部核对不另外返回诊断 Skill 的包络或 diagnoses 顶层字段。

## 当前必填结构检查

新分析必须返回 result.criteriaVersion、result.criterionAssessments（覆盖全部当前可读标准），以及 progress.displayPercent、totalEwdMinutes、completedEwdMinutes、comparison。未知保留 null 或空数组并说明，不能省略字段。`progress.estimate` 是本次补估或重估时的可选提案字段，形状遵循 EWD 输出契约；未补估时省略或为 null。每条评估都返回 criterionId、text、criteriaVersion、state、percent、completedContent、remainingContent、pendingChecks、reason、evidenceRefs。旧示例未包含这些字段仅供历史阅读，不能作为当前生成模板。规则版本使用 TASK-ANALYSIS-2026-10-14-v9。

### 燃起图必须使用的字段形状

`progress.comparison` 为 null 或以下精确结构（分钟数与日期均来自业务记录；缺失的可选项省略）。不得换用 dueDate/predictedCompletionDate 或将 workload 改成汇总对象。日期差由前端程序计算。

```json
{
  "asOf": "YYYY-MM-DD",
  "explanation": "历史与预测的证据依据",
  "workload": [{"at":"YYYY-MM-DD","scopeMinutes":240,"completedMinutes":120,"scopeVersion":"scope-1"}],
  "creation": {"at":"YYYY-MM-DD","scopeMinutes":240},
  "expected": {"scopeVersion":"scope-1","points":[{"at":"YYYY-MM-DD","completedMinutes":120}]},
  "forecastTrend": {"asOf":"YYYY-MM-DD","scopeVersion":"scope-1","startMinutes":120,"points":[{"at":"YYYY-MM-DD","completedMinutes":240,"note":"已落实的交付与复核安排"}]},
  "timing": {"startOn":"YYYY-MM-DD","dueOn":"YYYY-MM-DD","forecastOn":"YYYY-MM-DD","scopeVersion":"scope-1","basis":"预测依据"}
}
```

示例数字只说明类型，不是默认值。workload 必须保留所有已读取的真实历史点。expected 是已保存计划曲线，不能用预测替代。forecastTrend 是未来预测曲线。没有人工确认日期时省略 timing.completedOn；不能返回 AI 推导的完成日。没有已保存计划时 expected.points=[]，scopeVersion 使用当前范围版本；没有可靠预测安排时省略 forecastTrend 并设 forecastOn=null。不要把未确认当作零工作量。

### 历史覆盖与已读文件

`coverage.history` 仅说明额外活动历史的查询覆盖，不否定已读文件中的真实历史。文件提供同一范围版本的工作量观察、已保存计划与已落实执行安排时，应保留这些记录，生成 comparison 及有据预测节点；不得因为未查询其他历史而丢弃。每个已落实的交付/复核节点均用于增量完成量预测，不能只保留最后完成日。未知额外历史明确说明，用户确认仍独立。
