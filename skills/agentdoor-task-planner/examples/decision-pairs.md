# 规划 few-shot：判断边界

以下是输入与决策示例，不是完整协议输出；最终仍须填全 planning-v0.2 Schema。示例 ID 仅用于理解，不能复制到当前请求。

## 单一结果与工作步骤
输入：整理一份客户沟通纪要，包含决定、待确认事项和后续行动，没有截止要求。
正确：一个纪要任务，三个可核对完成标准；阅读记录、编写、校对留在 tips。日期为空，责任不明可未分配。
错误：把阅读、写作、校对拆为三个交付，或者因没有截止日期阻断草稿。

## 多层与绝对深度
输入：已有第 3 层任务 p3，用户要在它下面建立“内容组”，再在组下建两份脚本。
正确：指出会出现第 5 层，建议两份脚本直接成为 p3 的第 4 层子任务，等待用户调整决定。保留全部交付意图，不默默删除脚本。
错误：只计算新增方案内部三层就判为合法。

## 疑似重复不是自动合并
输入：当前可见 t1 是本月已完成的商城图；用户说再做一张，未说明渠道或版本。
正确：给出 t1 与本次请求的相似依据，补问是查看原图还是做新版本；用户明确新渠道后才为独立差异形成草稿。
错误：自动重开 t1，或看到同名就断言无需工作。

## 用户选人与未分配
输入：已确认责任显示甲负责文案、乙负责视觉；用户明确指定乙负责文字脚本。
正确：乙为有效成员时保留用户选择，basis=explicit，说明当前责任只覆盖部分；不虚构已具备文案责任。用户要求暂不分配则 basis=unassigned。
错误：偷偷换回甲，或伪称乙已接受任务。

## 前置依赖不等于父子
输入：检查表与报告是两个独立结果，报告使用最终确认的检查表。
正确：两个平行交付，报告依赖检查表；各有目标、标准，不能因为依赖就将报告归属检查表。
错误：循环依赖、把父任务自动设为所有子任务前置。

## 多轮只替换草稿
输入：上轮提出 A/B/C 尚未确认；本轮用户删 C 并保留 A/B。
正确：形成 A/B 的替代草稿，沿用有效字段；不输出对正式任务 C 的删除或成功回执。
错误：把前轮模型候选当成已创建事实。
