# 复杂业务任务树离线评估集

2026-09-01。覆盖任务创建中的差异补充与既有任务重规划，不接运行时、真实任务库或外部写回。

所有业务事实、任务、客户、人员窗口、讨论、版本与数值均为合成。复用 `industry-fixtures.json` 的六个合成团队和十一条来源元数据；公开来源只支持通用流程背景，不能证明本组业务事实。此轮没有重新访问这些网页，保留原有 `accessedOn` 和 `verification` 字段作为来源集的既有核对记录，不宣称本轮进行了新的联网核验。

## 文件与使用边界

- `complex-fixtures.json`：原始任务、讨论、来源记录、历史、覆盖和授权输入。沿用 `sources / teams / scenarios` 结构，不放期待标签、建议变更或模型答案。
- `complex-expectations.json`：独立评估期待，仅供评分与证据复核。包含可接受意图和结果、受保护对象与人工语义检查，不要求固定措辞或固定候选 ID。
- 本说明：场景索引、装配方式、输入异常和协议表达限制，不注入被测模型。

本轮只交付语料与期待，不生成任何模型答案，不调用真实数据 API，也没有模型通过率。人工语义检查来自业务输入和 v0.2 契约；没有根据校验器代码倒推某个字符串或修改旧运行结果。

## 八个案例

每例有9至11个当前可见 Task，合计79个；父子全部放在唯一的 `context.tasks` 集合，使用 `parentId` 表达归属。各树目前有三层：根、业务分支、叶任务。新输出需要复用这些稳定 ID，不把全部任务重新生成一遍。

| ID | 行业与可见任务数 | 原始情境 | 当前可独立决策的范围 |
| --- | --- | --- | --- |
| COMPLEX-01 | SaaS，10项 | 数据准备与验证培训分属不同分支；UAT、培训演示和最终交接的真实输入已由交接回执明确，但现有依赖缺边。培训提纲可以独立准备，演示不要求等待UAT结束。 | 只补已有任务的必要依赖，保留日期、完成结果和责任。 |
| COMPLEX-02 | 新品导入资料，11项 | 三层资料树新增一份12条编号对照表；已有BOM、图纸完成，叶任务估算保留基线，历史另记48小时等待回执。 | 在样料资料分支补一个独立交付，再接入已有评审目录；不增加父层人时或制造流程。 |
| COMPLEX-03 | 电商，11项 | 新的包装说明同时供页面、客服、发货答复使用；图片和库存已经完成，页面与问答部分内容已有草稿。投放素材不使用包装参数。 | 只新增本批包装说明并调整三个已有消费者，沿用联动核对的传递依赖和原有日期边界。 |
| COMPLEX-04 | 内容服务，10项 | 两份有相同签署时间的批准回执明确相互冲突，后来入库的一份未记录取代关系。最新策划报告只是“看过了”。 | 用户仅要求整理回执差异表，供现有批准任务使用；此局部整理有充分事实，最终版本仍待有权方核对。 |
| COMPLEX-05 | 连锁运营，9项 | 当前页只返回31项目标树中的9项，三个直属分支可见，但后代、部分主题讨论及历史尚未完整读取。 | 整树重规划需要继续读取授权分页，不替缺失22项编造标题、进度和依赖。 |
| COMPLEX-06 | 移交协调，9项 | 本组任务树完整可见，必要外部前置仅返回不透明引用；外部正文、Owner、版本、状态与日期均未授权提供。 | 明确问题查看的排期依据不足；本组既有资料整理仍可继续，不越权补全外部对象。 |
| COMPLEX-07 | 新品导入资料，10项 | 现有矩阵与检查记录互相等待；另一样品资料索引仍依赖取消的旧A版任务。当前没有纠错或替代关系确认。 | 先诊断两类图问题及所需交付边界，不静默删边、换前置、重开或保证日期。 |
| COMPLEX-08 | 内容服务，9项 | 策划、作者和编辑都能改字，但结果责任不同。旧12人时表已经过期；作者仅确认一小时交接窗口，编辑窗口晚于硬截止，必要答复也晚于截止。 | 说明容量与时间冲突并保留锁定条件；不能按三人均分旧人时承诺日期。 |

前四例特意保留足够的局部决策依据。缺少完整日历、未知新叶项估算、尚未作出的最终版本批准，不应自动阻塞已有充分事实的局部整理与关系提案。后四例的缺口会影响用户当前请求中的整体重规划或必要前置，不能据此声称整树可确认。两组共同检验“有用地前进”和“保留真正阻塞”，不能只看是否提出了问题。

## 装配输入

1. 按场景 ID 深拷贝 `scenarios[].input`，只向规划模型提供当前这一例；不要发送本说明、其他案例或 expectations。
2. 对没有 `input.members` 的案例，在 ACL 为 verified 且团队位于授权范围内时，从该文件 `teams` 注入对应团队成员。六个共享团队及来源与原行业集保持相同。
3. **COMPLEX-08 必须保留自己的 `input.members`。** 它包含同一内容团队的六个原成员 ID，但使用本轮权威快照补充三个可用窗口；编辑的旧9月2日窗口及对应可用性证据已在该快照移除，并由来源说明撤回关系。不能再用共享团队覆盖此快照，也不能将新旧窗口拼接成更多容量。
4. 所有源 ID 只在已提供集合中解析。成员证据可来自本轮成员快照；任务、讨论、历史和业务来源使用 `complex01-` 至 `complex08-` 新命名空间。复用的团队成员与通用来源 ID 不表示复用了旧业务任务。
5. `currentTaskId` 均指向当前目标根；版本回显仅包含实际读取的 Task。第六例的外部引用不在 `context.tasks` 中，不能自动添加到版本映射或合成成可写任务。
6. 核对输出时先完成模型盲跑，再由不同阶段读取 expectations。确定性校验和业务语义复核分开记录；本语料本身不代表运行结果。

## 刻意保留的输入异常

以下不是数据制作遗漏，不应为让一个输出获得成功标记而改掉：

- **COMPLEX-05 的部分覆盖：** 本次读取回执明确9/31项及续读游标，但没有余下22项正文；可见父子引用自身完整，不通过放入缺失任务的伪正文营造全量上下文。
- **COMPLEX-06 的外部悬空引用：** `complex06-issue-review` 保留 `external:complex06-readiness-ref` 作为现有依赖；这是对外部前置的引用级可见性，不是完整任务可见性。不存在对应Task、版本或Owner。ACL verified仅覆盖本组，不能据此读取外部对象或移除依赖。
- **COMPLEX-07 的环：** `complex07-matrix → complex07-checklist → complex07-matrix` 是现有记录里的环。
- **COMPLEX-07 的取消前置：** `complex07-sample-index → complex07-old-a` 指向正式 cancelled Task。已完成的 `complex07-baseline-c` 是范围索引，不是供应资料的等价替代物。
- **COMPLEX-08 的日内冲突：** 截止是9月3日12:00，必要答复最早14:00，编辑窗口16:00至17:00。同一个 `dueOn` 日期不能抹去这些时刻。

若离线校验器对整个输入图无条件做DAG或可解析性校验，可能会在第六、第七例中直接报告输入问题，即使模型正确拒绝规划。应保留“输入异常已识别”与“候选输出不合法”的区别，不能通过改原始图、补造外部任务、放宽校验或强迫模型删边获得表面通过。本轮不修改校验器。

## v0.2 当前表达限制

1. **覆盖缺少子树和分页结构。** `coverage` 只有全局枚举，不能结构化说明哪些直属分支已齐、哪个后代页缺失。第五例暂以合成读取回执 `sourceRefs` 表达总项数、范围和游标，不自行扩充为运行时读取协议。
2. **外部引用与完整可见任务未分型。** `dependsOnTaskIds` 没有单独的外部引用摘要、授权层级、版本缺失状态。第六例因此保留原引用加读取回执；这不代表允许对悬空依赖生成可确认排期。受信服务未来需区分已授权摘要、只见引用和不可见对象。
3. **日内交接不能只用日期表达。** 输出 `schedule.startOn/dueOn` 是日期，缺少时刻精度与成员窗口关联。第八例把硬截止时刻保存于来源和约束，评估需要读这些事实，不能只比较日期字符串。
4. **可用性缺少统一过期语义。** 当前成员字段能提供时间和说明，但没有标准有效期或撤回关系。第八例使用真实时间边界、截至说明与替代证据；不得把旧窗口自动延长成当前空闲。

这些限制记录为评估发现，不据此修改本轮Skill、输出Schema、生产接口、产品责任语义或正式验收流程。

## 自检范围

自检包含场景与请求ID唯一性、任务/讨论/历史/来源引用、确认字段与快照值一致、成员和团队授权、时间不晚于快照、父子关系和深度，以及依赖图的正常项和明确列出的异常。第六例只有一个刻意的不可解析外部依赖；第七例只有预设环及取消前置，其余案例没有悬空依赖、依赖环或父子依赖。

此集是有目的的覆盖样本，不能给出行业总体准确率，不验证生产ACL、并发更新、真实幂等、成员接受或业务验收。
