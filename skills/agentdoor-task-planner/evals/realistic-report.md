# 高拟真任务规划验证报告

## 结论

这版 Skill **可以作为离线候选规划器，用于明天的人工验证**：它能读取多层任务、版本化文件、动态讨论、历史、确认字段和查重结果，给出不产生外部动作的候选差异。它目前**不能作为无人复核的自动创建或自动重排器**。

最终版 12 场景全量盲测的原冻结机器结果为 8/12。独立交叉复核发现装修复验遗漏了一条仍有效的正式复测边；修正评分规则后，用完全相同的输出重评为 **7/12**，与最终语义裁决 **7/12** 一致。五个失败都保留在归档中，没有改写答案或删除样本。

这 7 个通过场景覆盖：软件发布依赖补齐、完整空历史下的重复培训、下一批任务复用、客服事故只读判断、分页未读完时停止规划、门店延期重排、招聘入职日期变更。五个失败集中在复杂依赖影响：制造 DVT 漏前置、供应商 MSA 多加前置、内容上线核对重复直连、财务异常生产任务被重复改写、装修复验错误删除旧边。

## 验证方法

1. `validate_realistic_data.py` 先检查合成分类、团队与外部人员命名空间、任务父子树、依赖 DAG、文件与正文节选配对、讨论回复、历史、确认字段和评分引用。
2. `evaluate.py prepare --suite realistic` 把输入、协议和期望分别冻结；执行代理只读 Skill、必读参考和分配到的 `inputs/`，看不到期望、旧答案和评分实现。
3. 每案保留第一份 Schema 合法的完整 v0.2 输出。校验器只允许修正明确的 JSON、Schema 或输入不变量错误，不允许根据评分结果做语义修补。
4. 机器检查验证允许动作、更新范围、保护对象、依赖集合和必需来源；不同代理再交叉复核业务语义，并分别归因规划器、夹具和评分规则。
5. 评分规则发现错误时，冻结输入、输出和原报告保持不变；更正写入独立勘误，并用相同输出字节重评。

全程没有访问生产服务，也没有创建、指派、邀请、通知、验收或写回任务。

## 已经证明的能力

- 能把多层子任务的父子归属与产出依赖分开，不默认把任务树串成步骤链。
- 能读取文件状态和最小正文节选，区分旧版、草稿、批准文件、外部承诺与真实回执。
- 能区分正式决定、成员报告、未接受提议、撤回提议和任务正式状态。
- 能保护已完成任务、人工确认字段、正式 Owner 和旧版本历史，不为显示 AI 动作重开或复制工作。
- 能处理完整重复、部分重叠、不同实例、空历史和分页未读完；检索不完整时不声称“没有重复”。
- 能把外部客户、候选人、审计、物业和业主作为不可指派发言人，而不是推荐成 Owner。
- 能把等待时间与人类投入分开，把硬期限写成风险边界，不把 ETA 或承诺写成完成。
- 所有输出都是候选计划，`externalEffects` 为 none；没有把可审阅状态当成写入授权。

## 仍需人工把关的地方

1. **直接与传递消费。** 当用户说多个任务“消费一个版本”时，模型仍可能给最终闸门重复直连源任务。
2. **权威文件与团队加工结果。** 同一文件可以直接供 MSA 使用，也可以由所有人核对任务形成风险结论；模型偶尔会把二者串错。
3. **一个消费者需要多个独立结果。** 制造 DVT 同时需要 PCN 适用性和实际来料 COC 核对，模型会漏其中一项。
4. **旧边保留。** 新增证书不代表原正式复测不再被业主直接核对；没有明确失效来源时仍可能误删旧边。
5. **最小差异。** 已有生产任务的完成标准足够时，模型有时会为了表现“处理过”而重复改写它。

因此明天的合理用法是：让 Skill 生成候选，展示依据与字段差异，由用户确认后再交给独立写入层。不要跳过依赖图复核，也不要让候选直接触发任务创建、责任变更或通知。

## 尚未验证

- 真实二进制附件上传、下载、解析和 checksum 对实体文件的一致性。
- 生产 ACL、跨团队检索、分页服务、服务超时、版本漂移和权限撤回后的实际数据清除。
- requestId 幂等、并发重复创建、未知提交结果、事务回滚和刷新后的继续编辑。
- 真实成员日历、真实容量、成员接受、通知、外部系统和任务写回。
- 真实行业用户的业务验收；本轮语义复核者是独立 Codex 代理，不是行业专家或人工标注团队。

这些边界意味着 7/12 是当前合成语料上的候选规划表现，不是生产准确率，也不能支持“自动创建已可上线”的结论。
