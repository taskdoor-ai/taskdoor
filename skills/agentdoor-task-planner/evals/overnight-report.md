# 任务创建 Skill 扩展测试报告

测试日期：2026-09-01。测试对象为 [AgentDoor 任务创建与动态规划 Skill](../SKILL.md) 及 v0.2 契约。企业、团队、任务、讨论、历史和提交回执全部是合成数据；本轮没有访问生产任务服务，也没有创建、指派、通知或验收任何真实任务。

## 结果先行

首轮矩阵包含 60 个独立场景或连续会话轮次：24 个行业案例、16 个边缘案例、8 个复杂任务树案例、12 个多轮案例。按冻结评分并修正四项评分器的等价来源误判后，首次答案有 55/60 通过；其中 3 项是业务语义问题，2 项是协议格式问题。两个格式问题由校验器阻止继续流转，原答案和错误报告保留；只修协议字段后，多轮当前结果为 11/12，整套当前可评审结果为 57/60。

| 组别 | 数量 | 首次／原始结果 | 发现 |
| --- | ---: | ---: | --- |
| 六行业核心 | 24 | 23 通过，1 失败 | RENO-01 把“历史未读取”写成“没有同类历史”。 |
| 边缘 | 16 | 15 通过，1 失败 | EDGE-12 把一份术语表按翻译、复核阶段过度拆分。四项来源 ID 评分误判已用同快照等价证据勘误，未重新生成答案。 |
| 复杂树 | 8 | 8 通过 | 79 个既有任务节点上的跨分支依赖、三层树、多个消费者、分页缺口、外部前置、坏图和窗口冲突均通过独立复核。 |
| 多轮 | 12 | 9 通过，3 失败 | B1 查重回显集合错误；D2 把复杂旧树的一处差异标成 simple；C3 对执行中可定位的错字明细作了不必要的创建前阻塞。 |

这里的“通过”只表示冻结合成输入下，结构校验与独立 agent 语义复核均未发现问题。评审者不是行业用户，也未验证生产 ACL、检索召回、并发提交或真实写回。

## 修复与回归

根据真实失败做了窄修复，没有增加行业模板：

- 同一交付中的翻译、复核、协作和操作步骤不自动拆成子任务；只有结果能独立负责、验收、交接、复用或并行推进时才拆。
- 只有任务身份、结果边界、可行性、安全或硬期限缺口才阻塞；执行者可在任务内定位的素材、错字和普通检查明细写入 tips 或完成标准。
- `history=not_requested` 只能表述为未读取，不能推断企业内不存在同类历史。
- `duplicateCheck` 必须与输入查重候选一一对应并逐字回显覆盖说明；`complexity` 描述整棵有效任务树，而不是本轮差异数量。
- Owner 的职责证据必须覆盖整项结果；只负责版本、协调或一个环节的成员保留为参与者，缺少完整责任人时 Owner 为 `unassigned`／null。

第一次修订后运行 9 个目标及对照案例，8/9 通过。失败的 EDGE-12 已保持单任务，但仍把只负责版本交付的唐钰提升为整项 Owner。该结果被保留；补充整项责任边界后，用新的隔离执行 agent 和独立评审者再次运行 EDGE-12，1/1 通过。按每个目标案例的最新结果看，9/9 通过：

- 原失败：EDGE-12、RENO-01、MULTI-C3。
- 防止过度合并的正例：COMPLEX-02、COMPLEX-03、EDGE-07。
- 防止轻任务过度拆分的正例：CONTENT-01。
- 多轮对照：MULTI-C1、C2，覆盖稳定候选、模拟保存回执和重试复用。

这只是针对已发现问题的定向回归，不能替代重新运行全部 60 例。首轮、第一次修订失败和第二次修订结果分别归档，没有用最终答案覆盖旧失败。

## 覆盖内容

合成资料包含 6 个行业团队、36 名成员，并区分职责、边界、当前工作自报、有限协作窗口、未知容量和未接受提议。场景覆盖：

- 冷启动、既有任务重规划、下一批、纯查询、意图不清和无需修改。
- 同名不同客户／周期、完全重复、部分重叠、重复点击、保存响应丢失和不同 SKU 新实例。
- 完成／取消节点保护、人工确认字段、旧回复迟到、人工编辑、权限撤回和恶意资料指令。
- 无历史、历史未读取、部分历史、旧估算工具变化、EWD 与等待分离。
- 多负责人显示名冲突、没有合格 Owner、局部贡献者、成员容量未知和时间窗口冲突。
- 三层任务树、父层不重复估算、跨分支依赖、新产出被三个现有任务使用、旧坏图、外部不可见前置和分页未读完。
- 无效闰日、时区、硬期限与最早到货／授权冲突，以及不能从人数和工时保证日历日期。

## 尚未验证

本轮没有连接真实模型 API、任务数据库、组织通讯录、历史检索、权限服务或提交服务，也没有验证：

- 生产 ACL 与跨团队字段级脱敏是否正确。
- 检索召回、分页、超时重试和大规模数据上的延迟与成本。
- 幂等键、唯一约束、事务、并发版本冲突和部分提交恢复。
- 正式 Owner 接受、通知投递、真实状态回传和人工验收闭环。
- 人类行业专家、真实团队和真实用户对任务拆分与责任建议的判断。
- 本地回放页的自动浏览器交互；浏览器工具拒绝访问 `file://`，本轮只完成 HTML、内嵌 JSON 和 JavaScript 静态检查。

因此当前交付可用于离线验证候选规划质量和接入契约，不能表述为生产可创建、生产准确率或行业通用可靠性已经验证。
