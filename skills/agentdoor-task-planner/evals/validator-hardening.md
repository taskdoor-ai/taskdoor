# 确定性验证器对抗复核

2026-09-01。范围为离线 `validate_plan.py`、验证器测试与本报告。没有创建业务任务，没有验证真实身份或生产 ACL，没有改写历史试跑答案、夹具或冻结报告。`overlap.resolution` 是主任务根据新案例明确修订的协议，验证器仅落实其结构边界。

## 可复现缺口与处理

先运行独立变异，再修复。第一批新增 30 个测试方法在原验证器上得到 36 个失败断言、11 个异常；这些包含 subTest，不能将 47 称为失败案例数。第二轮另复现已完成祖先和无提案预览动作的 3 个失败断言。全部现已纳入回归。

| 原可观察问题 | 当前处理 |
| --- | --- |
| `proposal=null` 提前返回，跳过 ACL 范围检查；缺 ACL 时仍可引用任务、成员并打开任务 | 所有输出均检查快照范围。缺 ACL 的任务／成员／讨论／历史记录必须由调用方先清理，否则连 `baseTaskVersions` 的 ID 回显都会泄露对象。仅允许不指向对象的补读／澄清动作；调用方声明可访问的 `context.sourceRefs` 回执仍可引用 |
| 明示 `teamId` 不在授权范围的记录仍被接受；已授权其他团队任务可混入当前树修改 | 核对记录已提供的 `teamId` 与授权／ACL 范围；其他授权团队可读，但不可在当前团队候选中被修改或挂载新工作。不要求旧快照凭空补团队字段 |
| 任意嵌套 `payload.id` 被递归收为来源；同名来源可互相覆盖 | 仅登记契约声明的任务、成员、讨论、历史、sourceRefs，以及成员已读取 evidence 记录；指针不证明读取，任意嵌套 ID 不授予来源身份。拒绝这些来源之间及与 requestId 的 ID 歧义 |
| 非对象 ACL、标量查重、空确认字段等导致 `TypeError`／`AttributeError`；布尔版本可与整数相等 | 先验证后续真正消费的输入形状；合法可选 `confirmedFields=null` 等价于没有锁。版本要求非负整数且排除 bool，不让 Python 相等规则掩盖非法快照 |
| 未识别的确认字段别名被静默忽略；双份草稿没有确定优先级 | 仅接受已支持的字段及明确路径；正式 ownerId、平铺日期与候选字段的映射保持。未知路径要求调用方规范化，不能靠猜测词义绕锁。草稿先并入 context.tasks，保留稳定 new: ID 与版本，不合并两份冲突值 |
| 同一更新夹带未变化字段；平铺与嵌套日期互相矛盾 | 拒绝已确定与快照相同的更新字段，根目标按文本比较字符串／对象表示。双份日期不一致要求先规范化；未列字段保持不动，不修改传入对象 |
| 无关参考任务中的旧环、悬空项或坏日期阻止合法局部更新 | 在候选完成后的图上检查本轮目标及其父子、前置、后续使用者组成的连通影响范围。外部缺陷一旦被依赖引用就必须检查；未连通参考记录仍保持原样 |
| 1400 项依赖链触发 Python 递归限制 | 改为迭代拓扑检查。1400 项依赖 DAG／环、1100 级父链／远祖依赖均有回归；自环、悬空、取消前置、父子依赖与排期冲突仍拒绝 |
| 只检查直接父节点，已完成／取消根下的 open 子节点可继续新增孙任务 | 对新增工作检查所有祖先，防止间接扩大终态范围 |
| 没有提案时仍能返回 `review_proposal` | 必须存在提案才允许该展示动作 |
| JSON 重复键被默认 decoder 吞掉，非有限值和过深输入处理不一致；巨大整数经 float 转换溢出 | 公开 `loads_strict(text)` 与 `read_json(path)`，重复键、NaN、Infinity、指数溢出和过深 JSON 返回 ValueError。CLI使用相同入口；验证前亦检查已解码值。正的任意精度整数保持有限，不强制转 float |
| 合理部分重叠与直接重复此前无法区分 | 只对 overlap 接受 `propose_uncovered_scope`，要求完整查重和任务／子任务／讨论读取，绑定本轮真实 create 的 change ID，并同时引用既有任务及另一个可用来源／当前请求。所有 disposition 都检查错误关系、无效 ID 和来源；same_outcome／possible 不获此豁免 |

## 明确保留的合法行为

- 局部更新可以只改变一个字段，不要求复制整份 Task；旧 Owner、未改字段、输入对象不被修改。
- 部分读取时可保留 `needs_clarification` 草稿及补读建议，但不把重规划标成 ready。
- 新增子任务不清空父任务原有估算历史基线；只拒绝本轮再写父总量、造成父子重复计量。实际汇总是否忽略父级历史值仍由消费端验证。
- 已知 `0` 与 `-0.0` 均为非负数；未知估算必须是 null，不能用带符号零伪装未知。NaN／Infinity 并非 JSON 数值，始终拒绝。
- Owner 可暂为 null；未知成员、候选 basis 不一致、参与者列表内重复成员会被拒绝。是否应选某个人、是否重复列 Owner 的贡献，仍属职责与最小协作集合的语义判断。

## 尚未覆盖的真实边界

1. 输入仍是调用方提供的快照。`acl.status=verified`、成员可选性、来源可访问性、对象版本均未与生产服务核验；没有逐实体 teamId 或来源授权分类时，无法从内容标题判断真实权限。允许 sourceRefs 回执不代表已经认证其权限。
2. 来源 ID 存在不证明文字能支持结论；讨论是否可信决策、负责人是否合适、交付拆分是否必要、overlap 的新范围是否真实独立，必须独立语义复核。未加入关键词或标题正则冒充这些判断。
3. 图检查只使用实际提供的关系，不会发现输入遗漏的后续使用者或模型故意不写的必要前置。完整读取标记必须由受信服务产生，不能由模型自报。
4. `currentDraft` 的规范化由调用方执行；验证器拒绝第二份有效字段，不承担适配器、冲突合并或历史状态迁移。未知确认字段名同样需上游明确映射。
5. 有 JSON 嵌套深度 64 的防崩溃限制，但没有生产级字节数、对象总量、超时或进程隔离；长祖先链仍可能带来较高资源成本。压力测试不是服务可用性保证。
6. 不验证真实接受、写回、幂等、并发版本冲突、原子事务、最终 EWD 汇总或用户闭环；ready 仅表示这份候选满足当前离线可检查条件。
