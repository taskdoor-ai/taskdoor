# 团队标签建议

## 读取与匹配

1. 开始规划时读取调用方提供的当前团队标签目录 `teamTags`。活动标签至少有 `id`、`name`、`icon`、`color`。有权限的运行时可提供归档状态或创建者信息。目录经成功读取且为空时，才按空目录处理。目录缺失、读取失败或团队不匹配时，保留标签为空，并在需要时说明读取缺口。
2. 根据任务名称、目标和完成标准识别值得团队长期筛选的主题。先查找当前团队的同名或同义活动标签。引用目录中的标签身份，沿用原名称、图标和颜色。已归档的标签不作为新任务候选。编辑已有草稿时保留用户已选的标签及明确清空的结果。
3. 目录里没有合适项、主题明确且有跨任务复用价值时，可以提议一个新标签。名称去掉首尾空白，长度为 1–24 个字符。临时事项或缺少明确分类依据时留空。遇到同名归档标签时，提示该项已归档，由有权维护的人处理。

## 图标与颜色

给新标签提案从[标签外观库](tag-appearance.json)各选一个 `icon` 和 `color` 键。图标表达工作主题，颜色沿用团队同类标签的约定。通用主题可用 `tag`，无配色依据可用 `gray`。例如「开发」可用 `wrench` 和 `blue`，「代码审查」可用 `git-pull-request` 和 `blue`，「客户反馈」可用 `message-circle` 和 `orange`。图标和颜色辅助识别，任务状态、优先级及名称由各自字段表达。

## 采纳与权限

- 预览中的既有标签和新标签均为建议。用户采纳新标签后，由应用校验当前团队、有效成员身份、目标任务的编辑权限及最新目录，再按确认的名称、图标和颜色创建并关联。出现同名活动标签时复用现有项及其外观。标签选填。
- 有效团队成员可创建标签，并修改或归档自己创建的标签。团队拥有者和管理员可维护团队所有标签。应用记录实际采纳建议的成员为新标签的创建者。历史标签的创建者无法核实时，由拥有者或管理员处理。
- 给任务添加、更换或移除标签沿任务编辑权限。移除只解除该任务的关联。目录归档后，历史任务保留关联并可筛选。
- 创建或更新任务定义可触发推荐。只有明确的目录维护请求才触发改名、外观修改或归档。AI 沿用发起人的权限。创建任务 Skill 只返回建议，实际目录操作交给有对应能力的应用入口。

具体输出以[预览数据结构](task-preview.md)为准。标签建议单独表达，任务名称、目标和完成标准按实际交付编写。
