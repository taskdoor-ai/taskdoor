## 1. 五项截图能力：当前到底实现了什么

这里的“已有”只指检查到的本地代码与界面，不等于经过真实服务或用户闭环验收。截图中的 `IMPLEMENTED`、旧文档中的测试数量都不是本工作区生产能力的证据。

| 截图能力 | 当前实际能力与证据 | 真实接入缺口 |
| --- | --- | --- |
| 任务输入 | 已有输入、发起、必要补问、保留草稿和确认界面。[`planTaskCreation`](../../../src/lib/taskCreationPlanning.ts) 只精确匹配五个示例需求；其他文本返回不可解析。补问内容也是固定场景，不是通用意图识别。 | 将自然语言可靠区分为创建、局部调整、重规划、下一批、查询或待澄清；识别对象与周期，最多补问两个真正影响决策的问题。需要真实模型调用、版本化输入、异常处理及多轮上下文，不是再增加几个固定分支。 |

| 任务智能：Current Status、下一步、标签等 | [`getTaskSituationModel`](../../../src/lib/taskSituation.ts) 已按当前字段、子任务状态和明确传入的本地讨论记录生成确定性摘要、待核对项与下一步；源码明确不分析发言含义、不验收或改变责任。最新讨论可定位引用。标签来自场景种子和已有标签选择，见 [`allowedLabels`](../../../src/lib/taskCreationScenario.ts)、[`TaskDetail`](../../../src/components/TaskDetail.tsx)。 | 基于授权来源理解实际进展、阻塞、相互矛盾的陈述与可执行下一步；引用具体记录和版本，区分未知、过期、无权与无风险。智能标签须使用已有词表、避免同义重复且可纠正；摘要、建议或标签不能自动改变状态、责任或权限。 |

多语言是上述能力的横向质量要求，不替代第五项。当前创建语法和职责规则主要面向中文示例；不能据此声称跨语言规划已通过。任务主语言、专名、日期、ID 和完成标准在不同语言中的约束保持，需要独立案例与人工语义复核。

### 实际调用与数据边界

- 当前创建：[`TaskCreationPage`](../../../src/components/TaskCreationPage.tsx) → `planTaskCreation` → `playMockAiSteps` → 本地候选 → 用户确认 → [`App.createTaskPlanFromConversation`](../../../src/App.tsx) → `createWorkspaceTasksFromDraft` → 当前浏览器 `localStorage`。存储失败会保留草稿，但这不是服务端事务或跨端持久化。
- 当前 AI 修改：[`TaskAiAdjustmentPopover`](../../../src/components/TaskAiAdjustmentPopover.tsx) → 确定性修改解析 → 本地预览 → 明确应用。创建草稿中的应用不等于创建；已保存任务的局部应用也不是本页拟议的服务端重规划协议。
- 当前进度由 [`playMockAiSteps`](../../../src/lib/taskAiFeedback.ts) 定时播放。它说明演示步骤，不证明模型或检索工具实际执行。[`TaskCreationProcess`](../../../src/components/TaskCreationProcess.tsx) 只承载初始／补问重规划仍在运行时的正文临时 loading，结束即移除；正文入口和 [`TaskCreationHistory`](../../../src/components/TaskCreationHistory.tsx) 共同复用同文件导出的 `TaskCreationProcessView`。因此 D-166 / D-173 面板里的思考规划与“正在生成方案”保持同一九宫格状态、步骤计数、整体开合及逐步骤开合，不能另做历史卡；运行时整体与当前步骤默认展开，步骤按进度逐条追加，只渲染已完成与当前步骤，未到达的 `pending` 步骤不生成行、状态、占位或可访问树内容，头部仍保留当前步骤／总步数。终态整体默认收起一次，重新打开可回看实际到达步骤；停止或失败不补未来步骤。每轮仍按用户输入、思考规划、AI 回复排列，运行态不提前显示回复。所有 adjustment 的运行与结果只在面板历史。面板滚动区与固定输入区分离，底部直接复用 [`AnimatedAgentChatInput`](../../../src/components/AnimatedAgentChatInput.tsx)，不展示预设提问；但它仍不是可跨刷新、取消、最终创建或会话恢复的服务端审计。
- [`App.taskCreationExistingTasks`](../../../src/App.tsx) 传入任务概要、状态和子任务名称；没有把子任务的状态、标准、讨论、完成证据与对象版本一并交给当前规划器。看到某个已有任务名称，不等于已核对该任务覆盖范围。
- [`server/taskAssistant.ts`](../../../server/taskAssistant.ts) 存在旧模型代理插件定义，但当前 [`vite.config.ts`](../../../vite.config.ts) 未挂载，当前创建／修改链也未调用它。不能表述为“已有可用真实 AI API，只差换提示词”。
- 本地随机 ID 去碰撞、按钮防双击、JSON 签名和草稿恢复各有价值，但不分别等同于服务端幂等、授权确认、并发版本校验和持久恢复。

以上判断针对本次读取的工作区，不推断其他仓库、分支或线上系统。也不因为本页指出缺口就把这些能力加入当前生产实施范围。

## 2. 复用现有页面，呈现决策而非增加流程页面

保持左侧任务列表。右侧初始态复用输入框与呼吸背景；生成后保持“左边最新进度、右边唯一 AI 帮你改”的一行布局。步骤沿用可展开的纵向结构，不新增聊天页、诊断页、审批页或复杂关系图；不重新把原始需求铺在主方案或步骤上方。打开“AI 帮你改”后，浮层按轮次显示当前未完成创建的最初输入、后续用户输入和用户可见 AI 回复，底部输入固定并可继续对话；不增加全局历史入口或跨会话恢复。

摘要回答三件事：这次建议做什么、哪些已有工作保持不变、现在是否需要人作决定。过程展开后才显示读取范围、简短依据、对应对象入口和缺口；调整轮同时显示字段前后差异与应用状态。最多四条可核查依据，不展示内部思维链、隐藏日志、虚构工具调用或假百分比。用户原文继续保留在当前创建草稿中，只在本次对话浮层展示；主方案隐藏不等于删除。

候选仍放现有主任务与子任务卡片；新增／调整用轻量标记和前后差异，未受影响内容不再生成一份。收起子任务仍遵循简洁卡片，不重新塞入完成标准预览和大块投入文案。标准编辑留在展开区；投入缺失就显示未知，不为使卡片完整补数字。

| 情况 | 同一页面中的最小呈现 | 用户可以执行的动作与限制 |
| --- | --- | --- |
| 冷启动：授权范围确实没有相关历史 | “授权范围内未找到相关历史，先按本次需求整理。”展开显示检索范围和实际读取时间；人选、期限或投入缺依据则留空。 | 在原输入或同一 AI 调整框补充信息；确有阻断时最多问两个问题，再审阅候选。不能使用行业案例中的人物、KPI、历史做法填充事实。 |
| 没有历史上下文：尚未读、无连接或读取失败 | “还未核对已有工作，当前方案仅依据你的输入。”这不是“没有历史”。 | 提供可访问的已有任务、缩小范围或重试读取。可保留明确标注缺口的草稿；未完成重复与覆盖核对时，不给出“确认无重复”的状态。v0.2 离线验证不允许用风险确认豁免该校验；生产若另行允许带风险创建，需要独立服务端规则与真实用户确认，不能由模型代签。 |
| 发现可能重复 | 过程下方复用小型已有任务关系卡，说明重叠的业务对象、交付物、周期与关键差异；只显示有权对象。 | “查看已有任务”“沿用已有工作”；确认是新周期／新对象时独立创建，确有未覆盖结果时只补充该部分。选择沿用只打开或关联已有对象，不写出同一份任务；不自动合并、删除或覆盖。 |
| 只追加未完成工作／下一批 | “保留 3 项已完成、2 项进行中，仅建议新增 1 项。”只在候选区突出新增和确需调整的未完成项；展开依据能查看已沿用对象。 | 审阅差异，确认后仅创建新增项或更新获准字段。进行中任务先复用；被取消任务不自动恢复。若新要求让已完成成果需要返工，提出关联的新工作，并说明新边界，不悄悄重开或改写原完成记录。 |
| 讨论存在冲突 | “任务记录与最新讨论对交付范围存在分歧。”展开并列两个授权来源、作者与版本；明确正式字段、已确认决定、成员报告和未接受提议的区别。 | 在原流程内核对一个具体问题，或打开对应讨论；允许继续审阅不依赖冲突的内容，受影响操作暂不可确认。最新发言不自动压过已确认决定，状态“已完成”也不自动证明新要求已满足。 |
| 权限不足或已被撤销 | “当前可读取范围不足，无法核对相关工作。”不显示无权任务的标题、数量、成员或内容片段。 | 选取有权的任务范围；如产品已有权限申请入口则进入该入口，不能自动向他人发消息。撤权后停止相关读取／应用，重新校验来源链接；用户自己的输入可保留，无权对象内容不可继续作为可见证据。 |
| 数据或候选过期 | “相关资料已更新，此方案需要重新核对。”保留用户编辑和旧候选差异，不把旧回复覆盖到新草稿。 | “读取最新资料并更新差异”；只重核受影响范围，完成后重新确认。相关任务版本、讨论决定或权限变化时，旧确认失效。读取时间只表示当时快照，不能包装成实时无风险。 |
| 资料部分读取失败 | “已核对任务和子任务，讨论未读取完整；暂不能判断新增要求是否已确认。”依据中说明实际覆盖和缺口。 | 重试失败的来源，或明确缩小到不依赖它的范围；保留已输入内容。关键来源缺失时先给草稿或补问，不以空数组代表已读完。 |
| 生成失败／用户停止 | 左侧显示“调整未完成”或“已停止”，保留已有方案；只保留实际到达步骤，未运行步骤不显示。 | 原框继续输入或重试；停止本轮不撤销之前已经明确应用的修改。迟到结果按轮次 ID 丢弃，不能把停止当已完成。 |
| 提交失败／提交结果未知 | 明确区分“未提交成功”和“正在核对提交结果”。不在结果未知时给出新的空白创建流程。 | 先凭同一幂等键查询结果或重试同一载荷；已成功则显示服务端返回的原任务，确定未提交才允许再次提交。若系统采用可恢复事务，列明实际成功／待恢复项并继续同一事务，不能把部分成功报为全部成功。 |
| 无需修改 | “已有工作已覆盖本次要求，没有需要新增或调整的内容。”提供已有任务入口。 | 查看已有工作或补充不同范围；不为体现 AI 动作强行产生一个更新、同名子任务或假活动。 |

“保留草稿／继续审阅”不等于进入可确认状态：v0.2 的 `replan`／`next_batch` 仍要求当前根、直属子任务与相关讨论完整读取；存在阻塞缺口时不能提交一份伪装完整的重规划。部分重叠也要先核对并限定真正新增的范围，解决重复判断后才能确认新增，不能保留未解决的 `overlap` 再直接创建。

### 进度、停止和确认的含义

接入真实服务后，可沿用“读取相关工作 → 核对目标与覆盖 → 整理候选差异 → 校验结果”这些用户能理解的阶段。只有对应工作实际发生才进入并追加该步骤；实际收到跳过、无权或部分失败等终态事件时可如实呈现，尚未运行的步骤不生成行、状态或占位。具体阶段由服务端事件驱动，不继续使用计时器模拟完成，也不显示模型内部推理。

左侧始终显示最新一轮，右侧保留一个 AI 修改入口；原停止按钮保留。新轮生成时，之前已审阅的草稿仍存在。页面切换、取消及重试绑定具体轮次，不能误停新请求或用旧回包覆盖当前草稿。生产端是否真正停止执行须依据服务端回执，客户端中止网络连接不等于服务器已取消。

“停止生成”仅停止候选工作；提交已经开始后，应核对其状态而不是暗示业务回滚。已保存任务的正式操作只能由独立授权与提交边界执行。创建候选的“应用调整”只更新草稿，最终“确认创建”才进入写入边界；重规划已有任务则确认精确差异，不重新创建整棵树。

## 3. 生产服务需要读取什么

本节是接入设计。请求字段名、枚举及结构以 [v0.2 契约](planning-v0.2.md) 为准；下列安全边界不能仅靠提示词实现。

### 最小上下文包

| 输入组 | 最小内容 | 读取与降级原则 |
| --- | --- | --- |
| 请求与执行边界 | 用户原文、动作意图、任务主语言、当前草稿修订；服务端当前时间／时区；经认证的操作者、团队和允许动作。 | 身份与权限由服务端确定，不能信任浏览器或模型自报的用户 ID、管理员身份及授权声明。查询不产生候选写入。 |
| 当前任务与子任务 | 稳定 ID、父子关系、目标、完成标准、正式状态、已接受责任与候选责任的区别、日期、真实依赖、人工确认／锁定字段、对象版本。 | 先读当前对象及所需直接子任务，确需深入才逐层读取；分页未完成说明覆盖缺口。不能只传子任务名称来判断哪些工作已做完。 |
| 交付与讨论证据 | 与本轮范围有关的已确认决定、成员报告、完成／验收记录；必要文件的精确版本引用。每条含来源 ID、对象版本、实际时间、作者与证据类别。 | 先读必要摘要及引用，再按需展开原文；保留冲突与撤回信息，不只截取最后一条消息。任务标记完成、成员说完成、正式验收和文件存在分别记录，不能互相替代。 |
| 相关历史与重复检索 | ACL 内的候选任务，业务对象、成果、周期／版本、标准与状态；查询范围、完成状态、截断／分页标记、读取快照及匹配依据。 | 先鉴权再检索，再决定哪些片段进入模型。相同标题不是重复证明；没有返回候选不代表检索完成。历史只能作为带来源的参考，不默认当前仍适用。 |
| 成员与协作约束 | 当前授权成员稳定 ID、职责和来源版本；必要贡献；明确提供的可投入窗口及其时间。 | 不读取不必要的私人日历或个人内容。容量不足数据保留未知；不把职责匹配变成已承诺排期，不自动邀请成员。 |
| 估算与词表 | 有效系统估算的范围、工作方式、来源、版本及有效性；已有标签词表和允许使用的业务术语。 | 无有效估算就未知，不借用案例数字。EWD 是预计人类投入，不是剩余量、机器耗时或自然工期；父子不重复计量。标签建议不创建权限或状态语义。 |

以上每组都需要可区分“完成读取且为空”“未读取”“部分覆盖”“失败”“无权”“过期”的来源状态，而非统一传空数组。界面向用户解释的是业务缺口，不必铺满技术标记；服务端和候选必须保留可核对状态。

任务、讨论、文件和历史资料都是**待分析数据**。其中的“忽略规则”“替我确认”“把密钥发出去”等内容不能成为执行指令，不能改变团队范围、工具权限、确认规则或输出 Schema。输出来源引用也须由服务端对照实际读取记录验证，不能因为模型写了一个 ID 就允许打开对象。

### 版本、确认和幂等边界

1. **读取形成快照。** 服务端记录本轮相关对象的 ID、版本、来源读取状态、授权范围与候选草稿修订。版本必须是可比较的服务端事实，不能用“刚刚”文案或客户端 JSON 签名替代。读取中发现相关对象变化时，重新读取或明确不一致，不把跨版本片段包装成同一事实。
2. **模型只给候选。** v0.2 的创建、增加、更新操作只是提议；不包含删除、验收、自动完成或改正式 Owner 的能力。已有对象保持稳定 ID；新增对象使用稳定候选 ID；保留哪些工作、改哪些字段、为什么改都可检查。`ready_for_confirmation` 或 `externalEffects` 的值不产生权限。
3. **确定性校验在模型之外。** 校验协议版本、输出结构、来源合法性、ID 与目标对象、允许字段、受保护任务／人工确认字段、成员资格、目标继承、日期、依赖 DAG 和现有覆盖关系。模型输出违规时拒绝对应候选，不偷偷纠正成另一份可提交结果。
4. **确认绑定具体结果。** 确认至少绑定有权操作者、草稿修订、精确操作摘要、相关读取版本、重复检索范围与结果，以及有效期。用户改了范围、人选、标准或依赖，或相关来源版本变化，不能沿用旧确认。确认来自真实用户交互和服务端记录，不从用户资料或讨论里的“同意”推断。
5. **提交时再次检查。** 在写入边界重新检查权限、父任务存在、对象版本、受保护字段和必要关系。查重还要考虑预览后同团队的新建；语义相似不能简单做全局唯一键，需结合业务对象与周期给出冲突或重新确认，不能自动合并。过期提交不覆盖新状态。
6. **幂等是持久业务保证。** 同一逻辑提交绑定服务端幂等键、租户／操作者、载荷摘要和结果；相同键与载荷重试返回同一结果，同键不同载荷返回冲突。候选轮次 ID 与提交幂等键用途不同；重生成不应偷偷变成对同一业务请求的第二次写入。
7. **任务与活动一致落库。** 主任务、子任务、依赖和真实变更活动在事务中提交，或采用可查询、可恢复的明确事务记录。涉及通知时通过与提交关联的可靠投递记录去重；未授权通知不发送。返回实际创建／更新的 ID 和版本，刷新后可查询原结果，不凭前端乐观状态宣告全部成功。
8. **撤权、取消和旧响应有归属。** 服务端重验会话与权限，运行事件和结果绑定请求及快照。新请求取代旧请求时旧结果不可自动应用；取消候选不等于撤销业务提交。网络超时先核对提交结果，不能换新幂等键盲目再建。

这三个问题需要分别处理：**业务重复**是相同对象／周期／成果是否已有覆盖；**历史复用**是过去做法能否帮助当前工作；**请求重试**是同一笔写入是否已生效。它们不能共用一个“是否重复”的布尔值。

## 4. 影响真实辅助质量的风险与验证

| 风险 | 必须核对的行为 |
| --- | --- |
| 示例过拟合与行业迁移 | 不把达人带货的角色、任务拆分、GMV 或固定工时套给其他行业；冻结输入后独立生成，再用独立期望评分。改写同一示例成功不能证明任意需求可用。 |
| 没历史被当成没任务 | 对完成空结果、失败、截断、无权分别测试；缺来源时承认未知，不能因没有上下文而重复创建。 |
| 找到历史就照抄 | 对象、周期、标准、职责和法规／业务约束变化时，明确哪些可复用、哪些不适用；旧负责人或旧期限不默认仍有效。 |
| 已完成与未完成边界被抹平 | 重规划保持已完成对象及人工字段，进行中工作优先复用，返工明确成为新范围；讨论报告不直接当作验收事实。测试相互矛盾的状态、证据与新要求。 |
| “下一批”变成再次拆全部项目 | 从实际已有产出和缺口推导下一批；新增量最小，无变化可返回 `no_change`。测试相同输入重复发起、同周期重复与新周期合理复用。 |
| 推荐制造虚假承诺 | 角色关键词命中不等于胜任、空闲或已接受。无适合人选可空缺；每个参与人要有必要贡献；不得平均分总工时来保证期限。 |
| 范围膨胀与标准虚化 | 不添加未经请求的 KPI、阶段与产出；每项完成标准能核对结果，而不是“高质量完成”；轻任务不因模板多建子任务。 |
| 推断的摘要冒充事实 | Current Status 和下一步的事实能定位来源；缺口与冲突明确，标签没有状态／权限副作用；旧摘要不能在资料更新后仍标最新。 |
| 权限与提示注入 | 无权对象不进入检索返回、模型输入或可见证据；恶意讨论、历史文件和伪造引用不扩大工具权限。离线夹具通过不能替代真实 ACL 测试。 |
| 旧请求、并发与部分失败 | 人先修改、Agent 后返回时不覆盖；撤权与停止生效；响应丢失、同键重试、提交冲突均不重复任务、活动或通知。 |
| 看起来可运行就被当成已接入 | 记录具体模型版本、输入快照、输出、确定性校验、人工语义评分和失败案例；不把 Schema 合法、Mock 动画和截图“已实现”当真实服务或生产质量证据。 |

离线行业案例与 agent 试跑用于验证规划指令是否可执行、输出是否合约化及常见错误，不足以证明真实检索覆盖、鉴权、生产延迟、可靠写回或协作提效。多行业案例的合成数据必须与真实业务资料分离，不允许把期望答案传给待评估 agent 再宣称生成质量达标。

接入验收沿用 [AI 协作验收标准](../../../docs/task-design-kit/04-ai-collaboration-acceptance.md) 的分层：A01–A13 验证输入与候选质量，B01–B05 验证状态／建议／标签，C01、C03–C10 验证权限与写回；L1 的规则和组件证据不能替代 L2 真实服务，更不能替代 L3 用户从真实入口完成闭环。未做的层级标“未验证”，不提供未经运行的通过率或提效数值。

实现顺序应先固定授权上下文、来源与版本、确认及幂等提交，再接通真实模型和本页最小状态，最后验证多行业用户闭环。每一步都复用当前任务工作区；本文件不恢复隐藏入口，不改变正式 Owner／直接写入／验收语义，也不批准自动执行任务。
