## 6. 变更与确认

- 查询、分析和草稿生成直接执行。明确单项低风险命令可直接执行的产品原则保留；首版涉及写入统一使用紧凑变更预览，避免本地解析或模型推断跳过核对。
- 批量创建、人员分配、从资料推断的更新：一次审阅后统一执行。继续对话可改方案，原方案应被标记替代，不能反复点击执行。
- 创建没有指定负责人时归创建者；指定当前团队成员并确认后直接分配，不生成接收方 inbox 二次确认。存量离职交接可暂空，不把此规则扩大为任意清空有效负责人。
- 删除展示明确影响；不凭模糊匹配删除。有多项同名候选时先让用户定位。
- 执行前核对当前任务、团队、人员和方案涉及的数据快照。过期方案要求重新生成／核对，不能覆盖新数据。
- 批量先完整校验再作为一个本地事务保存，失败保留方案且不发布内存成功态。防止双击、刷新后重复执行；结果中提供操作明细与任务链接。
- 创建、修改及删除引起的关联变化记录为任务活动；AI 对话本身不自动写入讨论。

## 7. 已确认替换关系与迁移

本次用户同意前轮分析并授权实施，以下作为本轮产品规则：

1. 常驻助手统一承接任务分析和后续动作，替代 D-191／D-192 对诊断只能只读且无后续处理的限制。现有诊断入口在迁移期间可作为带上下文唤起助手的快捷入口，原分析算法可复用。
2. 本次助手经创建者确认的创建／分配采用直接指派与创建者兜底，局部替代 D-189 在此创建路径中的默认空负责人及提议／接受要求。存量责任历史与其他旧入口不做隐式批量迁移。
3. 现有创建页和手工字段编辑继续可用；助手操作复用同一任务事实。外部“连接 AI”仍是外部工具连接，与内置助手区分。
4. 事件通知和任务参考按本文件第二节分期，不能把后续设计描述为已经接入。
